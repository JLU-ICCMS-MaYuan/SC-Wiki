# PDF 解析管线

## 功能说明

本功能描述上传任务从文件接收到生成待校对草稿、再到提交落库与发布向量索引的完整处理链路，是 01 目录的主线文档。文件校验与摄入约束见 [PDF 摄入](pdf-ingestion.md)；晶体结构附件的审核与默认结构选择见 [上传、审核与默认结构](upload-review-and-default-selection.md)。

## 候选合并与完整性检查

当前科学整理复用候选去向，保留原记录、理由及原文来源；程序检查候选完整交代、实际目标和来源，不把整理后未再次出现的旧数字单独判为遗漏。原提取到确定性组装的真实漏项保护继续执行。相关原候选与整理理由进入已有字段科学核对，模型查证压力、方法和独立配对的合并关系；映射完整不授予科学通过。不增加独立核对轮次，当前版本有效结果仍复用。实现与验证边界见[#210](../../specs/210-candidate-coverage/spec.md)。

## 从 PDF 上传到审核入库的主流程

科学记录组装后执行 [#176 固定表单整理](../../specs/176-scientific-form-filling/validation.md)：LLM 联合候选与原文判断重复、方法及配对，并定向查缺；程序检查候选去向、来源和数值保留，随后继续最终 Claim 与字段核对。该职责与只生成论文信息的摘要调用分开。PDF 使用 IR 完整原块，不把 Markdown 定位注释作为证据；不从曲线提取 Tc。模型仍未能确定的内容保留具体诊断，既有草稿不会自动重写。

模型科学字段先按固定清单检查，再添加服务器生成的Tc分组和历史方法元数据；服务器身份不作为模型越界字段拒绝。合法空软件组在对应软件内补值，网格和带单位数量复用已登记字段类型。自动整理或字段核对出现技术失败时保留已有预览和结果，任务显示失败及原因；只有自动流程正常结束才显示待校对。详情、页面摘要与提交共用确定性派生规则，结构文件通过后其晶胞、体积与原子数不再被摘要误报待核对；真实文件变化仍使派生依据失效。摘要只读取投影字段，并在程序内按编号选择当前版本，避免大型来源JSON参与数据库排序。相关旧要求和验证记录见[#176全流程跟进](../../specs/176-scientific-form-filling/full-reparse-20261102.md)。

**[打开 HTML 交互流程图](pdf-review-flow.html)**：统一在“主流程”视图展示主干与主要分支；点击“01 解析与草稿”或解析节点，进入独立的[解析程序流程图](pdf-parsing-flow.html)页面；点击“批准前检查”，进入独立的[批准检查程序流程图](pdf-approval-check-flow.html)页面。子页面用处理节点、菱形判断及连线展示内部控制流、主要分支与失败出口，提供返回主图入口；其他主图节点仍可点击查看概要。HTML 与相邻 CSS、JavaScript 文件可直接本地打开，无需构建或联网。下方保留 Mermaid 图与文字说明，便于在 Markdown 中阅读。

解析程序图中的“生成字段核对结果与候选”可点击，在新标签页打开[字段核对内部流程](pdf-field-evidence-flow.html)，展开批次结果、受限补空、上下文关联、最终版本与来源核对。原始解析区域、采用文本、备选文本和题录来源仍随草稿保存；不再生成独立差异分类或责任待办。

字段核对页同时提供[逐字段规则库](pdf-field-evidence-flow.html#field-catalog)，覆盖题录、分类、叙述、材料状态、结构、四类物性记录、计算条件、开放扩展及独立谱处理。可按中文名称、实际字段键、区域、核对方式或报错关键词筛选；每项显示来源、程序检查、模型职责、候选规则、依赖、故障表现、修正路径及源码行号。目录区分专门过程、共用机制、程序派生与非科学审核元数据；提示词要求不写成程序已经强制保证。开放 payload 与未来自定义字段按模板覆盖，本机发布定义是只读快照，不代表所有运行目标都已有相同定义。

`generate_upload_suggestions` 按字段批进入统一模型工具循环，通常最多20项，含计算条件时最多12项；初始提供最多约120000字符的完整来源块及其余目录，模型可继续读取、搜索或查看原页。来源定位、值、配对、适用范围、补查及纠错由同一流程判断，程序不再用独立文本匹配重新裁决科学支持；实际来源身份、类型、权限、人工保护及版本仍由程序保证。有效结果复用，按批保存；技术未完成不清空其他成功项。初次提取、科学整理、专门归纳、程序派生和整篇批准保持独立，不能按流程框数推算模型请求次数。见[#194](../../specs/194-unified-model-review/spec.md)。

解析只读预览分区发布：题录流只更新论文信息；科学组装、整理和核对分别更新材料与条件。晚到的题录空列表不清空科学预览，失败保留已生成内容；ready后读取正式可编辑稿。阶段同步不新增模型请求或改变表单布局。见[#195](../../specs/195-parsing-preview-sync/spec.md)。

上传 PDF 后，系统先生成可校对草稿；上传者处理字段问题并提交，系统将论文写入 MySQL 等待管理员审核；管理员批准后，该版本才作为已审核数据对外提供。

**“写入数据库”有两个不同节点：提交送审时已创建待审核记录，最终批准时再确认正式内容、来源与审核历史，并标记为已批准。** 解析成功、保存草稿、字段核对通过，都不能代替整篇论文批准。

### 读图时需要区分的几个动作

| 动作 | 实际结果 |
| --- | --- |
| 解析完成、保存草稿 | 得到可继续编辑的内容。例如提取出某材料在某压强下的 Tc 及原文位置；仍未创建本次上传的待审核论文。草稿、文件、核对结果等可以分别持久化，不等于论文已批准。 |
| 字段核对与人工处理 | 判断当前字段的值、理由和依据能否用于送审。例如修改 Tc 后，只对受影响字段及真实依赖重新核对；同版本有效结果复用。正常输入和保存不启动模型核对。 |
| 提交送审 | 先保存，再检查格式和当前字段结果，必要时核对修改后的字段；全部满足要求才在事务中创建 `pending` 论文、材料状态、物性、结构和来源关联。结构只写入符合确认与校验条件的候选。 |
| 管理员批准 | 管理员和超级管理员是两个可执行审核的角色，不是必须依次通过的两级审批；不能审核自己的论文。当前工作台的编辑先暂存，批准事务将暂存内容、来源、审核历史及 `approved` 状态一并提交；检查失败则保留待处理输入。 |
| 拒绝后返修 | 由原上传者针对 `rejected` 论文发起。复用已有文件，在同一论文 ID 上提交新内容版本，回到 `pending` 再审；“退回待审核”只是保留待审状态，与上传者返修入口不同。 |
| 批准后发布向量索引 | 主业务数据的批准先提交，再执行向量发布。发布失败可以返回 `publication_pending`，已提交的批准不回滚，因此批准成功不代表问答索引已经建立。 |

待审核记录已入库，但不作为已批准科学数据进入材料检索、物性工具和统计。论文列表另按身份控制可见性：登录用户可以查看待审论文，匿名用户只看已批准论文，不能将“待审核”理解为“只有管理员能看”。

本节按当前代码核对主流程，未为编写文档重新上传真实 PDF、调用模型或执行审核。单字段的三个模型入口和结果复用规则见[逐字段审核流程图](../02_Decentralized_Maintenance_and_Verification/literature-and-record-review.md#逐字段审核流程图)，返修细节见[已拒绝论文返修](pdf-ingestion.md#已拒绝论文返修)。

## 入口与任务创建

### 科学图表标量读数（#227）

PDF提取在前置收录判断之前读取科学图表：模型结合原图、图注、正文/SI识别图型、材料、系列、物理量与条件，程序按坐标刻度或真实色标像素标定折线点、柱和热力格的读数。当前入口对应既有Tc、λ、ωlog和费米能级DOS来源；标量来源与α²F/phDOS曲线流程分别处理，共用原有校对和批准链。

明确数字标签保留报告值，坐标/色标估读保留约数与可解释读图精度。原图像素、坐标或色标、图号/面板、材料/系列/条件及标定事实保存在原文件身份下的DocumentIR来源块；块文字明确标注原图标定，元数据保留复现事实。读图分辨率与论文的物理测量误差分别保留。被遮挡、缺失或无法标定的点有原位来源及未解决原因。连续线按实际标记或明确条件读数，避免任意采样生成状态。

轴边界按图像位置统一验证并排序，刻度的物理值和升降方向保持原配对。主轴、条件横轴和色标共用边界验证，非法区间、刻度越界与数据越界仍拒绝；来源分别保留模型原始轴及实际标定轴。读图v4重新读取旧版本完成缓存，旧派生来源保留供已有引用，不批量改写历史科学值。实现及验证边界见[#227](../../specs/227-scientific-chart-reading/validation.md)。

独立面板裁剪不会扩大为整幅内嵌图；旧版本派生读数保留来源引用但不参与新提取。相同未读事实保持稳定块身份，全部原回执另留。IR写盘前完整校验；已知v2仅阅读顺序不同的完全相同机器未读重复块可在正常读取时保留原字节和恢复审计后有界恢复，其他来源或内容冲突继续拒绝。该恢复不授予字段支持或业务批准，见[#227验证](../../specs/227-scientific-chart-reading/validation.md)。

读图v5限定当前目标区域，区分目标未读与上下文说明；裁剪外相邻面板的说明保留在覆盖元数据中，不自动成为目标读取失败。真实逐点未读仍保留身份和原因，无面板且无目标未读理由不能宣称完成。旧版本来源/响应保留，重读不回填旧数值；未改变标定、科学字段或人工审核规则，见[#227数据模型](../../specs/227-scientific-chart-reading/data-model.md)。

正文共同概述与图中分材料结果按适用范围整理。前置判断考虑有效图中独立Tc；参考文献标题不会切掉后续SI图、表和附录，本文/引用工作的范围继续由既有模型判断。来源事实进入现有固定表单整理、字段核对和保存，不自动授予科学支持或论文批准。当前值匹配的约数限定在整理及公开摘要中保留；改值或清空不能从旧原文恢复。标准科学键和锁定摘要保持原契约。实施、实际验证及未完成业务范围见[#227](../../specs/227-scientific-chart-reading/validation.md)。

### 结构归属的原文查阅与预算（#224/#204）

结构归属先读候选几何所在的真实原页，其余原文保留可查阅目录，模型按需读取方法页或检索当前文件。未读目录不能当作引用，程序仍检查化学式、压力、物相、结构优化、准确晶格及每状态一份规范结构。来源身份和重复内容可无损传输去重；不可恢复的模型请求错误向上传播，保留检查点，避免以空结构完成态掩盖技术失败。预算不通过时保持必要原文与保护，完整来源不会由摘要替代。

### 文献类型与流程选择（#212）

本文主要贡献由模型按真实内容判断，并从已选来源中给出贡献编号；程序核验编号与正文归属。分窗流程判断及全文二级分类的汇总保留原编号的文件角色索引，区分正文贡献和SI支持，不增加汇总轮次；未改变来源门。未匹配暂停页可由上传者显式重新判断，沿用原模型、输入与草稿版本保护，不强制套用专用流程。章节小标题只是线索，缺少 Abstract、Results 等标题不会单独使有效结果失效。二级分类及后续字段核对沿用可定位的内容依据；历史分类及冻结快照不批量改写。

新任务先进行通用文本/IR读取，用本文正文及补充材料判断文章类型、主要贡献和超导机制，再选择程序登记的流程与对应表单。参考文献中的他人工作、软件名称或孤立公式不能单独决定本文适用性。当前只登记“常规超导理论计算”；匹配后才进入结构、领域候选、材料状态、填表、字段核对和谱处理，复用本轮读取制品。

未匹配、证据不足或判断调用失败进入 `needs_workflow`，处理状态为 `needs_input`。页面展示通用题录、原因和可下载的原文件，不加载科学编辑器或继续轮询，不提供手动套用当前表单的绕过入口。暂停保留已耗时间但不设置完整解析结束时间，活动和清理沿现有24小时机制；这不代表已永久收录。文件读取等技术失败仍进入 `failed`，可重试；尚未选定流程时不能改为手动填写专用表单。

流程身份和表单版本/摘要由程序生成，经草稿、正式提交元数据及整稿快照保留。整体保存继承服务器绑定，局部字段写入不能修改它。已有无绑定资料沿原版本化路径读取，不在打开页面时自动分类、重提或改写冻结历史；重新解析重新判断。未来新类型先复制现有流程作为开发起点，结合真实文献讨论、调试和验收后再登记，不提前建设全部类型。

实现依据：`parsing_workflows.py`、`upload_jobs._process_upload_task`、`paper_revisions.current_draft` 和 `manuscript_handoffs.record_handoff`。本次验证范围和未验收项见[#212验证记录](../../specs/212-typed-parsing-workflow/validation.md)，不以流程判断通过宣称整篇科学解析通过。

- 前端入口是 `/upload`。用户声明一组文件，每个文件带 `client_id`、`role`（`main` / `supplementary` / `attachment`）、文件名和大小；支持 PDF、TXT、MD、CIF、POSCAR，单文件最大 50 MB，同时上传最多 3 个。
- `POST /api/upload-tasks`（`backend/api/upload_tasks.py`）调用 `create_task`：任务状态存入 Redis（带 TTL），同一用户活动任务上限 100；`TASK_ID_PATTERN` 为 32 位十六进制。请求只保存文件声明，不保存界面语言或展示建议副本。
- 上传的原始文件落盘到 `upload_PDFs/{task_id}/`，状态中记录 `sha256`、大小和角色。
- “开始上传并解析”后，任务被推入 RQ 队列 `scwiki-upload`，由 worker 容器（`rq worker --with-scheduler scwiki-upload`）执行 `backend.ingest.upload_jobs.process_upload_task`（`backend/ingest/upload_jobs.py`）。
- 本地开发环境由 `watchfiles` 监视 `backend/` 下的 Python 源码；源码变化时完整重启上传 Worker 子进程，避免长期运行进程继续使用旧模块缓存。Docker Worker 仍随容器启动并使用既有并发配置。
- 上传 Worker 注册队列级异常回调：如果 RQ 在导入或调用业务入口前失败，且对应上传任务仍处于运行态，任务会以 `error_code=upload_worker_execution_failed` 进入可重试的 `failed`，保留失败前阶段并使用固定安全错误摘要；已经由业务流程写入的终态不会被覆盖。
- 入队时把当前请求的 LLM 配置写入独立的 `upload:llm:{task_id}` Redis 瞬态键；Worker 开始处理时加载该配置，解析成功、失败、取消或任务清理时删除该键。公开任务状态最多返回 `llm_provider`，不包含密钥或完整配置。
- `/api/upload-tasks` 在 Docker 部署中由 Go 未匹配路由转发到 Python FastAPI；前端按约 2 秒间隔轮询 `/api/upload-tasks/{task_id}` 与 `/parsing` 获取进度。

## 论文先行、分段执行与来源展示（#228—#230）

当前主入口先读取正文与补充材料，从原文独立填写论文级字段，核对并逐批保存；保存成功后才读取科学图源、判断适用流程并处理材料状态。不确定或缺依据可形成核对结论，技术失败停在论文阶段；不匹配流程时保留已完成的论文结果。论文阶段检查点绑定来源和模型，同输入可复用。材料阶段核对只处理材料字段，不再从状态静默重写已核对的研究材料清单，差异保留为对应字段问题；没有最终全表AI汇总或核对后合稿。上传、返修、正式创建及管理员科学数据保存也保留论文级清单的规范化当前值（包括显式空列表），漏传时沿已有稿继承；只有无绑定且缺该字段的旧请求才兼容派生。

科学分段保留完整原块和表行，正文不固定重复完整前页，附有限完整前文；表格必要邻页说明沿原规则保留。每任务最多两段并发，结果按原编号归位；请求上下文、连接和接收状态独立，上传模型请求共享Redis额度，沿当前上传并发配置。失败、取消及同输入检查点继续生效。并发不等于节省token，也不宣称固定提速比例。

#227读图先逐页扫描并登记图/面板，解析器图区仅作提示；每个目标区域独立读取。图中实际标定位置可在原图上下文中标记，原页轴与图例保留。文字来源在确定块内由程序计算唯一字符区间，区分精确和排版空白等价匹配，重复或未定位不取首个值。侧栏可关闭标记对照原内容；原件共享、图片按需渲染，未新增持久截图。侧栏规则只引用[#221](../../specs/221-scientific-field-sidebar/spec.md)。

界面保留兼容的任务大状态，并额外显示论文读取/填写/核对、图读取、适用性、材料提取/规划/填写/核对及失败暂停的实际阶段。实现和验证边界分别见[#228](../../specs/228-field-source-highlighting/validation.md)、[#229](../../specs/229-semantic-parallel-extraction/validation.md)、[#230](../../specs/230-paper-first-processing/validation.md)；本轮CaH6完整网页交接仍在验证，局部回归不代表整篇科学验收。

## 五阶段状态机

`process_upload_task` 把处理过程划分为五个阶段，`stage_index` 与前端“第 X/5 步”一一对应：

| 步骤 | status / stage | 行为 | 主要产物 |
| --- | --- | --- | --- |
| 1 | `saving_file` | 保存上传文件：接收文件并记录哈希 | 原文件及上传清单 |
| 2 | `extracting` | 读取文档与选择流程：通用读取、适用性判断及所选流程的来源准备 | 文档 IR、带来源正文及流程绑定 |
| 3 | `reading` | 分段提取与出处检查：提取科学候选、必要补证及覆盖检查 | `review_artifacts/{task_id}/` 分段候选、出处及覆盖记录 |
| 4 | `summarizing` | 填写表单与自动核对：论文级字段填写、材料状态与科学记录整理、字段核对、引用匹配及适用的谱处理 | 草稿、核对结果与解析制品 |
| 5 | `ready` | 等待用户校对 | 终态清理排程 |

五步条、任务列表和失败阶段提示共用上述显示名称，后台状态键和阶段编号保持原协议。第 3 步的分段计数只表示候选提取进度；全部分段完成后仍有出处／覆盖检查。第 4 步内部的 `paper_summary` 在科学表单整理与自动字段核对之前填写题录、论文总结和分类等论文级字段，并非核对完成后的最终全表汇总；后续依次进入材料状态与记录整理、字段核对、引用匹配、保存及适用的谱处理，具体当前位置沿用已有解析动态和预览提示。相关运行动态入口见 [#224](../../specs/224-resumable-model-requests/spec.md)。

`paper_summary` 是一次模型调用的阶段名，`paper.summary` 是表单中的论文总结字段；后者属于有来源支撑的归纳内容，不能把不要求逐字照抄理解为不需要科学依据。本次只修正显示名称及说明，不改变解析顺序、模型调用、字段契约或核对规则。

### 第 2 步：读取文档与选择流程（extracting）

- PDF 经 `pdf_extractor.py` 转为带页标记（`<!-- page: N -->`）的 Markdown；TXT/MD 直接读取；已提取过的文件直接复用缓存的 `.md`。
- CIF/POSCAR 原生附件不走文本提取，而是经 ASE 校验（`structure_extractor.build_structure_candidate`）生成结构候选；校验失败的候选标记为 `blocked`，等待人工处理。
- 任务解析生成的结构候选以 `material_state_ref="unassigned:*"` 标记，需在校对页「未分配结构候选」区分配到具体材料状态并确认（`material_state_ref` 变为 `material_states[N]`、`confirmation=confirmed`）后才会在提交时写入 `structure_models`；未确认的候选只作为附件文件保存，不落库。（[Issue #77](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/77)）
- 非结构 PDF 的正文还会经 `extract_structure_candidates` 从文本中抽取结构候选。
- 多文件任务逐文件处理并更新 `extraction_status`。新任务的角色由三个上传区域确定，服务端以 `file_role_policy=user-specified-v1` 标记并校验一个正文及角色/格式配对，直接使用指定角色，不推断、覆盖或暂停确认。无标记历史任务才保留旧评估与 `needs_role_review` 人工恢复，复用已有提取文本。`compare_file_identities` 随后按最终有效角色比较可信首页标题和论文自身 DOI，结果及来源/规则版本写入 `consistency`；页码、页眉页脚、通用 SI 标题、章节及参考文献条目不冒充身份，无法可靠识别则留空。未知不等于匹配，也不制造冲突。
- 文件身份检查不比较人工校对表单，不调用模型。真正冲突时，提交确认框列出具体文件、字段和两边值；确认令牌绑定当前差异、文件角色及哈希，过期确认不能继续。历史误报仅经已授权定向修正处理，不自动批量重写其他草稿。验证边界见 [#135 身份检查修复](../../specs/135-multi-file-main-detection/identity-consistency-validation.md)。
- 正文为空时直接失败（`论文正文为空，无法生成可校对草稿`）。

### 第 3 步：分段提取与出处检查（reading）

结构化候选先校验计算条件扩展结构，再执行方法语义与原文依据检查。扩展使用带非空键的对象数组；空值／空对象转为空数组，本次已识别的 `electron_phonon → phonon_method` 文本分组有界转为标准数组。其他对象形状、非对象数组项，以及没有阶段标记的已知条件扩展明确拒绝，避免结构错误使检查崩溃或绕过软件归属检查。现有有限纠错和失败次数不变，不能通过丢弃条件或撤销原文检查来获得成功。见 [#172](../../specs/172-phonon-method-parsing/spec.md)。

相关字段修复按 `AGENTS.md` 从必要正文／补充材料来源重跑受影响字段，复用未改动的文字提取，保留失败响应重放与真实字段重新提取两类证据。字段通过不代表全篇覆盖、正式提交或整站验收通过。

覆盖排除清单中只有表号而没有行号的提议不会使整篇提取失败，也不具有有效排除资格；保留诊断后进入逐行检查。未覆盖段落的分类读取完整目标、相邻页上下文和已有记录，不能把跨页续句或已有结果概述误作新数据。直接引句在分段阶段校验，改写公式、拼接文字或不属于声明来源的引句利用既有有限纠错处理，不能推迟到整篇汇总才发现。

- `chunker.py` 把合并前的各文件 Markdown 切成 `Chunk`，`_chunks_with_preamble` 为每个文件补一个前言段；分段清单写入 `review_artifacts/{task_id}/chunk_manifest.json`，每段状态在 `waiting / processing / completed / failed` 间流转。
- 读取前由 `_merge_extraction_windows` 把相邻小段合并为约 12000 字符的提取窗口（`EXTRACTION_WINDOW_CHARS`），页码取窗口起点所在页，再逐窗口调用 `_read_chunk`（使用当前请求选择的 OpenAI 兼容 LLM），减少过细分段造成的上下文断裂与调用次数。分段中的 AI 生成研究材料、方法和核心发现必须为英文；服务端在写入 `review_artifacts/{task_id}/chunks/` 前拒绝这些字段中的中日韩字符。论文标题、摘要和 `quote` 属于来源文本，保持输入语言，不翻译也不拦截；`quote` 可能来自 PDF 文本提取或 OCR，不承诺与扫描版逐字一致。
- 结构化PDF走`structured_chunks`：正常窗口48000字符，单次硬上限500000字符；表格按完整行拆分并保留真实表头、跨行单元格和页内说明，边界补充有界的完整邻页非表格原块。不能再拆的完整原块可超过正常窗口，超过硬上限则明确失败；原文与来源身份不因分段而改写。窗口回归通过不代表模型提取或整篇业务验收通过，见[#114](../../specs/114-multimodal-pdf-upload-agent/spec.md)。
- 分段结果以 JSON 存到 `review_artifacts/{task_id}/chunks/`；未能通过既有有限纠错的科学格式、来源及生成语言错误会使任务失败。不完整的排除提议单独进入覆盖审查，不等于科学结果可放行。
- 每完成一段更新 `completed_chunks / total_chunks`，前端进度条（如“4/28 段”）即来源于此。分段缓存契约版本为 14（`CHUNK_RESULT_SCHEMA_VERSION`），旧缓存重读时重新提取。

### 第 4 步：填写表单与自动核对（summarizing）

- `_summary_classification_candidates` 先过滤掉非当前论文的过期证据，再把分段候选交给 `complete_json(SUMMARY_SYSTEM_PROMPT, ...)` 汇总为一份结构化草稿。
- 理论论文的 `theoretical_subtype` 先检查主汇总给出的结论、理由与本文贡献引句；合格时采用首轮结果，不合格时才由专门 LLM 阅读有效正文与补充材料。参考文献不作本文贡献，只有软件名也不足以确认类型。重试仍无可靠依据时留给人工核对，已有首值保留为待审候选。（[#128](../../specs/128-fulltext-theoretical-subtype/spec.md)）
- 能定位的作者原词保留原语言，标题、摘要、作者、原始数值、单位和 `quote` 保持来源语言。Worker 以验证后的 canonical draft 预填选项框和输入框；某字段无来源依据时保持为空， 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../../specs/221-scientific-field-sidebar/spec.md)，本处不再独立维护。
- 主汇总同时提炼研究驱动力，按连续编号逐行输出并给出有效主文原句。程序检查格式和引句；首轮合格不发起专门调用，失败才定向重试，并把未读主文、模型未生成、引句未定位、格式不合格等原因分别记录。两次结果无法判优时保留首值和冲突提示。科学记录由分段候选经程序组装，主汇总不得改写 Tc、压力、方法及条件。
- 正文 PDF 在 Worker 中额外提交给本地 GROBID 的 `processFulltextDocument` 接口。GROBID 返回的 TEI `biblStruct` 会提取 DOI、题名、作者、年份和原始引文，随论文版本保存到 `paper_references`；GROBID 不可用或解析不完整时保存状态，不由 LLM 猜造引用边。（[Issue #81](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/81)）
- `_normalize_draft` 把草稿归一化为当前数据契约：论文元信息（含单选 `superconductor_kind` 和多选 Material family）、`material_states`（材料、压强/温度/磁场、计算与实验上下文、`tc_results`、More type labels）、分类证据等。旧草稿的状态级 `superconductor_kind` 只在读取时一次性提升：唯一的非 `unknown` 值保留，冲突时回退 `unknown`；新提交拒绝该旧字段。
- 化学式解析（`parse_formula_composition`）支持括号分组与 Unicode 下标，拒绝不配对或空括号；材料字段只在能唯一确定完整化学式时写入化学式（如 `(H2S)2H2` 不再截成 `H2S`），否则原文保留为材料名，替代式的元素数按组分统计；与空间群符号查表一致的空间群编号、晶系作为派生核对项随符号核对。（[Issue #120](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/120)）
- 汇总后执行查重：先按归一化 DOI（`normalize_doi`）查 `papers`，再按原始文件 SHA-256 查；命中即进入 `_handle_duplicate`，任务以 `duplicate` 状态短路结束。
- 草稿写入 Redis（`save_draft`），同时把 `ai_values` 与证据快照（分类证据、材料状态各字段证据）写入 `review_artifacts/{task_id}/result.json`。
- 当前本机 S3 模式下，Worker 从对象键按需取得原文件，解析产物完整上传后才把版本化 `artifact_manifest` 发布到任务状态；节点内 Markdown 与 JSON 仅供本次执行使用。正式送审的 `result.json` 使用按任务 ID 可找回的私有对象键，任务状态过期后审核 API 仍可读取。
- 理论二级类型的临时全文分析由服务端保存，含综合理由、可定位支撑片段、模型和来源版本；客户端修改当前值不能伪造分析资格。该字段的来源核对把片段标为全文归纳依据，不称论文逐字记载的枚举；仅 Methods 或软件名不能独立授予 `supported`。本机 H3S 草稿已定向复核为 `calculation`，理由同时比较结果、讨论与方法；正式已批准论文未批量修改。

### 汇总后、等待核对前：引用匹配

程序以已解析原引文确定明确的库内书目关系；疑难候选固定交给LLM2批量核对，并同时核对库内谁引用了当前论文。结果与理由按输入签名持久保存，完成后再进入ready。解析页可在新标签查看三列匹配结果；读取和普通保存不发模型。失败及停止沿#224既有机制处理，原始引文与用户草稿保留；尚未审核的论文不提前形成公开边。实现、隔离验证及业务迁移边界见[#225](../../specs/225-citation-matching-and-static-graph/validation.md)。

### 第 5 步：等待用户校对（ready）

- `processing_status=succeeded`，任务进入可校对状态；`_schedule_terminal_cleanup` 通过 RQ scheduler 排程终态清理。
- 取消（`cancelled`）与失败同样进入终态清理排程；业务解析异常使用 `error_code=paper_processing_failed`，RQ 入口边界异常使用 `error_code=upload_worker_execution_failed`，两者都记录 `failed_stage` 并可在文件仍有效时重新解析。清理由 `cleanup_upload_task` 执行。

## 任务详情入口

提取按表行联合读取表头、分组、单位、表题及表注，保留近似与原行身份；λ、ωlog 和 μ* 在逐结果边界归一化，不从状态级广播到不同方法。明确反向 Tc–μ* 配对使用两端控件，未配对范围只保留报告范围。过大结构化表按完整行组读取，无法分开的原块保留预算失败。

## 方法字段的适用范围

结构工作流关联只更新优化目标、实际几何约束与对应来源，不决定物性记录的近似。电子理论、声子技术和振动处理分别提取；EPC条件仅在其材料、相、压力、阶段及结果关系成立时复用。多压力图题中的单个标量不能任选压力；跨页文字须连同相邻页读取。

新生成不使用混装approximation；旧值只作历史读取。提取、整理、条件补空、局部写入及来源核对均检查类别与范围；明确电子—声子修正可保留，但不能靠自造引句建立关系。错类字段保留问题和原始响应，不删除带隙、DOS、Tc或人工记录来获得通过。详见[#181验收](../../specs/181-physical-method-scope/validation.md)。

## 新版字段与规范结构（#203/#204）

### AI生成时的固定字段限制（#205）

结构化PDF分段提取和科学候选整理通过严格JSON Schema限制输出，嵌套科学字段取自#203清单；模型不能创建人工扩展或服务器身份。字段结构不合规时本地拒绝，保留原响应，不为新增键再调用模型纠错；接口拒绝严格模式时明确报错，不静默降级。已有来源范围、科学语义判断与查源流程保持，结构合法不代表科学结论正确。

模型输出限制只作用于上述生成入口，人工新增仍通过既有入口保存和重读；其他普通JSON调用未被全局改为严格模式。不确定值可给候选或留空，理由及人工审核沿既有字段来源流程保存。当前LLM2流式接口已通过小型对抗/非法结构探测及真实CaH4来源提取与整理；其他供应商尚未证明支持。证据与验收边界见[#205验证记录](../../specs/205-ai-fixed-field-output/validation.md)。

### 字段核对的真实原页读取（#206）

统一字段核对向模型提供现有只读工具的严格参数定义。工具目录依据当前资料生成：文本窗口没有图块时不提供inspect_figure，只有任务PDF清单存在时提供read_original_page。文字页读取不代表看过图片，模型不能以figure_id等自造参数调用工具。

原页读取沿存储层核验文件身份、大小和SHA，再渲染指定PDF页面，将真实图像送入下一次模型请求；原生工具调用与返回使用同一调用编号配对，避免模型反复请求已返回的同页。来源动作记录文件SHA及页码，review_images_read在图像进入成功模型调用后才为true；仅渲染成功或调用超时不冒充已读。

## 采用图片来源与快照（#235）

字段核对的实际精读定位由服务端绑定到采用来源；正式交接先展开既有共享来源引用，再冻结当时的定位、解析结果和必要原件引用。原PDF、定位和结果长期保留，干净PNG按需生成并缓存，快照不嵌入base64或重复复制图片。图像缓存键按物理来源/页/框/渲染参数生成，业务file_id或父区域变化不重复生成同一像素。

历史查看按原快照权限，用旧原件和旧定位重建；不拿当前IR替代旧解释。公开RAG优先批准快照，读取图片前每次检查论文批准状态和来源归属；缓存命中不构成授权。没有新目录的旧记录保留有界原IR读取兼容。缓存缺失/损坏可以程序重建，不需模型重新定位；渲染版本或原件不一致则拒绝。

清理接口只处理明确定位的派生PNG及校验信息，不能删原件、历史引用或必要失败证据；不自动批量清理其他论文。实际SQL交接、原件替换、权限、重建和存储/耗时边界见[#235验收](../../specs/235-rebuildable-visual-sources/validation.md)。

来源/快照与谱的存储边界已在独立MySQL 8.4.2补验收：原六项专用验证实际通过，三组并发操作均只有一次成功写入；扩展79项零跳过。七项过期测试已按现行字段/工作稿/来源压缩契约修正，隔离源码综合525项通过。SQLite轮的MySQL专用跳过已有单独实跑证据；这不代替Flash科学读数或整篇业务验收，详见[补验收记录](../../specs/232-complete-pdf-regions/mysql-and-baseline-validation.md)。


### 图片工具目录与原文上下文选择

图片工具列出当前原始对象；有同页完整父表且其bbox包含单元格时，共用父表图片入口，孤立或越界单元格保留独立入口。IR、全文、图片、科学候选和历史引用继续保留。原文/OCR回执只返回当前原始文字，动作缓存按current-original-context-v2取源，历史动作结果可保留读取。该目录选择不增加人工核对步骤或改变模型、字段及96000请求预算。实现和真实来源验证见[#234目录预算修复](../../specs/234-image-feedback-repair/catalog-budget-fix.md)。


### 盘点几何错误与定位观察

前置盘点遇到真实重复/无效区域时，错误页可由原模型结合新渲染的原图/图注纠正；合法页保持，重复无新依据停止，原重复/完整性保护继续执行。图片工具提供无标签像素框/轴线/刻度/色块及坐标分辨率，原模型仍判读科学标签、条件与关系，原标定程序计算值。分析副本不改变发送给模型的原图。Flash本篇实际科学验收与边界见[#234记录](../../specs/234-image-feedback-repair/flash-fig4-scientific-validation.md)，不等于整篇业务通过。


### 柱图局部修订与可复用范围

当前图读从原PDF像素核验零基线、柱边分辨率、朝内/朝外刻度与印刷数字行。跨框端点文字须有实际图框边线支持；程序只处理几何，不识别数值或从正文结果反推坐标。无法从图框分辨的独立柱高保留未读，不能写成零值；明确的人工作出科学裁定沿既有表单处理。

图读v10到v11按原来源复核，只重读失败面板和共享轴修正的真实依赖，成功原块及历史保持。精读图携带返回原目标的坐标映射，不替换原图2。实际工具取图后，科学未读保留原因并继续后续校对；错误坐标、轴、身份、范围和严格格式不按未读吞掉。真实Flash正文38条及SI16条专项与复用范围见[#227验证](../../specs/227-scientific-chart-reading/validation.md#2026-11-11-双模型黑盒排障专项)，两模型完整五阶段业务验收仍未完成。


官方DeepSeek的严格工具请求使用其/beta入口和$def传输表示，本地仍校验原规范Schema。传输适配可将已完整绑定的文件/块标识可逆编码为短ID，原始科学文本不改变；模型回执恢复原身份后再走原枚举、来源与保存检查。预算按实际工具Schema计算，成功规范请求缓存仍可复用。新AI结构报告与旧几何解码统一执行已有全文范围排除，被排除原候选和理由留后台事件；最终表单范围保护保持。详见[#205验证](../../specs/205-ai-fixed-field-output/validation.md#2026-11-11-官方deepseek严格工具传输补齐)，完整业务黑盒仍未完成。


状态规划的成功检查点还需通过既有候选完整性、材料条件与来源校验。业务校验失败的原响应完整留证，正常继续只请求未完成步骤；JSON格式合法不代表可复用有效科学结果。范围外且没有候选/结果归属的空状态按已有全文决定排除并留档；任何原候选指向错误材料/条件仍拒绝，不根据自然语言理由猜改序号。


同一目标图的数值化／核验工具已经实际像素验证成功的柱观察，也纳入局部修订的有效结果清单；模型后续只修失败点和真实依赖，最后仍明确提交目标图完成报告。不同精读图的坐标系不直接合并，失败邻点不享有旧通过资格。坐标越界反馈显示原边界及越界刻度，保持原拒绝条件和动作预算；真实验证边界见[#234验收](../../specs/234-image-feedback-repair/validation.md)。
