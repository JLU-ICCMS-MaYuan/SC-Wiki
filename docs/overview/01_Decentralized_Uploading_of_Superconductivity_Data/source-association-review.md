# 来源关联与重新核对

来源核对的表单、侧栏、按钮与红框规则沿用原页面。红框表示当前核对问题尚未解决；“旧关联已失效”是系统状态，不表示科学值必然错误。

## 字段依赖

新生成的共用参数关联按参数值、字段语义、阶段、材料状态及相关计算条件绑定。修改 Tc 或 μ* 不使无关的计算软件和网格关联一起失效；参数自身、相关软件／理论／泛函、压力、物相、近似或来源变化仍需重新核对。扩展参数按稳定字段键定位，不能随数组重排错绑。

旧版整条记录指纹继续保守读取，不能在未查原文时直接换成新指纹。Tc 范围拆分后只有当前字段及必要上下文仍相同的共用绑定可以保持有效，端点和配对仍按各自字段核对。

## 重新核对

现有核对流程同时检查参数值与适用范围。新的关联结论必须有可定位的事实及范围证据，并绑定服务端计算的当前字段内容和来源版本，保存在现有核对结果中；payload 中的原关联保留。读取时重新验证新结论的版本和证据，通过后向原前端输出有效关联，不再由历史关联反复降级。

模型按本次核对段落编号引用时，服务端直接展开原始段落；手写引句继续经过原有逐字定位。旧解析编号不与当前窗口编号混用；顶层返回的关联仅在服务端身份唯一对应一个字段时接收，不能按数组顺序猜测归属。

论文推断继续保持推断身份，不升级为作者直接报告。第一批计算条件可按已确认规则自动核对通过：要求全部有效正文／SI 文件可读、每个来源窗口核查成功，并同时确认当前值、软件、阶段、用途及材料／物相。上传者和管理员都可免逐字段确认，但不设置人工确认标记、不自动批准整篇论文。当前源中出现明确冲突、缺少依据、版本过期或并发修改时，仍不生成有效通过资格。

规则编号、版本、当前内容／来源绑定和各项证据保存在既有核对结果的 `rule_review`。原有前端继续使用 supported 状态和 AI 理由，无新增页面。SSCHA 条件事实与 Tc 结果归属分别核对：条件策略不以 Tc／μ* 数值作为持续有效性依赖；软件、阶段、材料／物相及非谐流程仍需原文依据。结果是否对应原表非谐分组在 Tc 结果项检查，缺口不连带撤销共用条件。DFPT 可以依据方法定义说明电子结构基础 DFT，但不能推导具体泛函。

同一版本的并发核对按服务端请求时间判定先后，较早请求的迟到结果不能覆盖较新核对；较新的冲突仍正常保留。后台进度和取消使用小型状态投影，不在每个流式片段读取整份科学快照。现有侧栏的推断关联固定提示尚未改动；无需逐项确认的资格以 supported 状态及规则理由为准。

泛函按软件单独核对，旧 VASP-PBE→QE 推断已撤销；新提取的已知计算条件若缺少其原文依据，不作为直接事实填写，完整 Methods 关联阶段再补有明确依据的空值。未报告的可选条件留空免审；未读完或解析失败不会被记录为已查无。重新核对本身不自动修改已有科学值。

## 定向核查工具

`scripts/recheck-upload-associations.py` 默认仅盘点指定任务，显式使用 `--apply` 才会调用现有模型并保存核对结果。执行前保存 Redis 草稿／任务、MySQL 草稿／核对记录及校验清单；分批保留模型原始响应、核对结果和失败信息。工具不自动采纳替代值或生成用户人工确认；写回前校验版本，失败或并发变化保留已完成结果并说明边界。

本工具不创建新页面，不重新解析 PDF，不批量改写其他论文。真实处理数量与剩余疑问见对应任务的本地核查报告，不能把模型运行完成等同科学审核完成。

需求和验证见 [#139 后台修复增量](../../specs/139-table-parameters-shared-methods/association-recheck.md)。

## 保存与历史规则重验

合法空单位、未启用的物性值槽可以原样保存；启用值槽和类型仍严格校验。规则已通过的论文推断可正常保存接受，保留paper_inference，不设置human_confirmed，论文最终批准保持独立。

已知旧版完整规则记录可在当前字段事实、必要依赖和来源等价时重新定位原文并验证，产生当前版本投影，旧行保留。新核对漏引证据的尝试单独记录；有效冲突、来源或相关条件变化仍撤回支持。不同组不能借用凭证。

前端共用字段按稳定组身份定位，删除首结果或重排时更新承载记录及路径；结果字段仍保留各自身份。父级变更通知以实际字段变化决定失效，未变化的共用条件不会因整条记录通知而一起标红。页面布局、样式和按钮保持原样。实施与验证见[#144](../../specs/144-review-save-lifecycle/validation.md)。
