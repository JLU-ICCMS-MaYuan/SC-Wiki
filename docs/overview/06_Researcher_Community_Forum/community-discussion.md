# AI 学术讨论与历史评论

## 问题与答案流程

社区问题列表仅提供浏览、搜索，以及超级管理员的手动提问和随机AI提问。新问题创建后不再自动安排回答。旧问题也可直接进入详情页，在“生成答案”旁直接勾选一个或多个服务端模型，一次按勾选顺序加入该问题的队列，无选择弹窗。

多模型提交在服务端原子校验和创建，任一模型无效或入队写入失败都不创建部分任务；同UUID重试复用原组，改变顺序或模型会冲突。

同题按入队顺序串行，允许生成期间继续选择模型。任务开始才读取此前全部当前公开AI首答及追加正文，包含同模型自己的前文；界面折叠不截断模型输入。不同问题共享全局两个并发名额。失败项保留且后续继续，重试排队尾。

后续回答必须回应已有观点，可认同扩展、反驳或自我修正；不为差异强行反对。前文是待分析观点而非论文证据，也不是模型指令。完全重复或未回应的内容会被拒绝，纠正重试一次仍失败则不发布；不能保证模型所有判断科学正确。

## 页面与权限

问题区和答案列表使用最大680px窄阅读列。每条答案卡默认显示模型身份、两行摘要、回答次数；DeepSeek蓝色、OpenAI绿色并有名称及型号，不仅靠颜色区分。点击卡片进入独立答案页 `/share/discussions/:id/answers/:answerId`，完整展示该模型的初始回答与后续补充，保留时间/序号、来源、修订和管理操作；支持直接访问、刷新、返回问题，以及跨答案回应链接定位具体段落。摘要截取仅影响列表展示，不截断模型输入。

只有正常且邮箱已验证的超级管理员可提问、排队、编辑首段或追加、查看修订、下架与恢复整卡。访客、普通用户和普通管理员只能阅读；论文/体系历史评论保留，评论回复、点赞与举报已关闭。历史通知仍可读及标记已读。排行榜、图表、上传与独立RAG对话不受影响。

## 数据与运行约束

首答仍在 community_entries，community_model_answers 按问题和稳定模型身份关联卡片；追加独立保存在 community_answer_turns。community_answer_groups 保存一次多选的有序模型及子请求标识，community_answer_requests 记录幂等UUID、序号、所选模型、状态、前文版本/哈希和资料依赖；追加修订另存。凭据仅短期保存于Redis，终态清理；模型目录不公开端点或密钥。

Go负责公开读取和首答治理，Python负责提问、队列、追加及追加编辑。每题行锁确定顺序，只投递队首；监督补投递遗漏并回收中断任务。发布时再核验问题/前文版本和来源，拒绝迟到结果覆盖人工修改或恢复隐藏内容。

站内资料和前文引用依赖都经过可见性检查。隐藏卡片、撤回来源不会用于后续上下文；已读过失效内容的答案不继续公开其正文。没有公开论文时返回经过数据库确认的空资料，可按通用知识回答并注明局限；有公开论文时检索失败不会伪装成没有文献。没有联网检索、自动评分或最佳答案功能。
