# 表单更新与回归检查

## 适用范围

全站表单遵守局部更新、稳定身份、输入与业务动作分离，以及性能不能破坏正确性的共同约束。当前完整宿主回归首先覆盖上传校对、返修、管理员和超级管理员科学表单。其他页面的入口、适用规则和实际覆盖见 [表单清单](../specs/174-form-processing-contract/form-inventory.md)，未验证项不能称为已经通过。

## 当前科学表单行为

- 材料卡片的错误和待处理路径按当前卡片比较内容。相同内容的新数组不清空所有卡片缓存；真正变化的当前值、临时提示和来源计数仍更新。
- 缓存中的事件读取最新宿主回调；先修改论文标题再编辑材料，不会通过旧闭包恢复旧标题。删除前卡时临时输入、提示和折叠状态随原材料前移。
- 来源标记的定位与结果分开：字段身份或实际节点变化时重新定位；颜色、理由或当前值变化复用既有节点，只更新实际变化的标记。没有核对摘要的占位入口打开时读取当前控件值。
- 科学字段编辑通知只读取明确受影响字段的值；集合增删等拓扑变化仍按稳定身份重新定位。保留未变化记录对象，避免无关标记一起更新。
- 谱图共享状态在业务内容未变化时复用，导航保存仍读取最新宿主回调；真实谱列表、权限和状态身份变化正常更新。
- 自动保存、手动保存、人工决定及模型核对沿用原契约，不增加后台检测，不改变科学标准。

## 可执行检查

在仓库根运行：

```sh
npm run test:form-contract --prefix frontend
npm run test:form-contract:mutation --prefix frontend
npm run build --prefix frontend
```

第一条检查完整宿主、字段设置、保存及审核边界；第二条在临时编译器中注入已知缓存回退，要求四宿主八项测试失败，否则检查自身失败。回退注入不修改工作树。

`.github/workflows/form-contract.yml` 在 PR 或手动触发时运行相同检查和生产构建。当前只验证本地命令与工作流配置，未推送运行，未设置远端强制合并保护。

## 验收边界

固定大草稿副本的实际浏览器输入测试中，整表字段扫描由 22 次降为 0 次，平均按键到画面更新由约 301ms 降为约 41ms；数值属于本机同夹具单次对照，不是所有机器的固定承诺。输入期间两版均无后台请求，停顿后保留原自动保存。验证使用隔离 API，没有修改用户真实草稿或调用模型。

详细场景、既有测试失败基线及证据见 [#174 验证记录](../specs/174-form-processing-contract/validation.md)。本次没有新增材料状态主动排序；稳定身份仍保护增删操作。
