# 去中心化维护与验证

## 功能边界

该功能负责平台数据的结构化维护与验证治理：主业务数据的模型定义、初始化、迁移、导入导出与部署运行时，论文与记录的审核决策，管理员资格审批，以及晶体结构文本的格式校验与存储。它不负责检索算法、问答质量或社区互动。

## 功能组成

```text
去中心化维护与验证
├── 数据模型与 Schema 维护（模型、迁移、导入导出、部署）
├── 论文与记录审核（验证决策）
├── 角色与管理员审批（资格治理）
└── 结构格式校验与存储（数据验证）
```

## 关联关系

领域模型是所有主业务 API 的共同数据契约。01 上传提交的论文在此完成审核决策；审核通过的论文经发布后进入 03 检索与 05 问答。Go 服务通过 GORM 读取 MySQL 并提供主要公开 API；Python 服务通过 SQLAlchemy 承担 RAG、结构、Tc 估算和部分工具接口。

科学数据核对与 01 上传共用 Python/MySQL/Redis/RQ 能力；Go 保有最终审核事务，原文支持程度有疑点时由审核员逐条填写理由，证据与裁决一并留痕。

审核入口提供独立 AI 核对、字段说明文字定位和可编辑建议草稿；保存编辑、AI 核对、人工确认与正式批准分别生效，提交检查当前结果，批准失败保留待审修改。各操作的保存结果与失败处理见[审核工作流程](literature-and-record-review.md#工作流程)。

编辑页允许直接修改或整组清空压强，原始条件可展开编辑；当前值确认先保存再绑定版本，旧结果仅供参考，完成不自动批准。

人工确认保存成功后自动关闭侧栏，手动关闭同样保持原字段的阅读位置；保存失败保留理由供重试。

材料名与化学式至少填写一项，只填材料名也能保存和人工确认。单独修改名称或条件不会被误判为同值；重建状态保留结构家族。改名使本状态相关核对失效，删除字段后移除该核对项。

来源核对区分未核对与无出处；连续输入合并保存、失败暂停重试。管理员可逐条说明推理或专业判断理由完成确认，永久记录独立人工来源；上传者不具备管理员裁决权限。
