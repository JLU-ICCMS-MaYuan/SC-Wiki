# 格式校验与存储

## 功能说明

解析用户提交的 CIF 或 POSCAR 文本，提取晶胞和空间群等元数据，并保存可去重的原始结构记录。

## 当前行为

- 只接受 CIF/POSCAR 类型的结构载荷。
- 使用 ASE 解析结构并提取晶胞参数、元素列表、原子数和体积等元数据。
- 对原始文本计算 SHA-256 摘要，作为内容标识的一部分。
- 新结构记录保存来源、提交者和审核状态。

## 工作流程

API 接收结构格式和文本；服务层验证非空与格式；解析结构并提取元数据；计算摘要；创建待审核的 `SuperconductorStructure`。论文详情的结构预览来源是 `structure_models`（挂在材料状态下），普通物性表不再保存结构文本与结构格式。（[Issue #57](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/57)）

## 约束

- 无法由 ASE 解析的文本会被拒绝。
- 结构内容当前存储于数据库记录，不是独立对象存储。
- 结构科学正确性与文本可解析性不是同一保证。

## 共享上下文与已发布产物

字段采用的片段继续使用不可变来源目录；大块旧背景及冻结稿中的结构来源也可按内容共享，业务读取完整还原，缺失引用不能从当前稿补齐。正式值、字段理由、范围、审核资格与历史快照身份不因存储表示变化而改变。活动结构及工作稿不通过本功能自动批量迁移。

对象模式下，已提交审核产物在稳定对象键、大小/SHA、正常读取入口的完整回读和JSON身份均验证后，才移除本机相同副本；失败或本机文件变化则保留。正式交接同事务冻结成功后清空已关闭上传正文，仍保留周期/归属，失败回滚不丢输入。存量只通过显式定向工具备份、演练和执行，不在打开页面时迁移。

本机Ca–H定向精简及统计边界见 [#223验收](../../specs/223-evidence-storage-compaction/validation.md)。内容减少不等于MySQL表空间文件立即缩小，私有恢复备份另计；不包含历史快照或谱运行删除功能。
