# Feature 规格：编号 LLM 配置与服务端模型目录

**GitHub Issue**：[#116](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/116)；父 Epic：[#21](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/21)。
**创建日期**：2026-09-29。协作状态以 Issue 为准。

## 背景与目标

部署者在 `.env` 填写多组模型，系统自动发现并让已登录用户选择；无需把服务端密钥交给浏览器。复用 #73 的个人配置和统一调用链，增加独立的服务端模型目录，不把 #73 FR-004 的个人供应商预置项改成共享密钥。

## 用户场景与验收

### US1：配置多个模型（P1）

部署者增加或删除编号配置并重新加载服务，即可调整目录。

**独立验收**：配置编号 1、3、10，目录恰好返回三项并按数字排序；不需要数量字段。同供应商的不同型号作为独立项目。

### US2：选择服务端模型（P1）

已登录用户在原模型配置入口选择目录项，不输入部署者密钥；问答、流式、论文解析和核对任务沿用该选择。

**独立验收**：选择两个测试模型，验证真实 HTTP 调用的模型和凭据归属正确；匿名和无效登录不能使用服务端模型，省略 ID 也不能绕过。

### US3：保留原使用方式（P1）

用户仍可自带密钥，超级管理员仍能管理原服务端默认配置。Embedding 和 SMTP 配置不随 LLM 选择改变。

**独立验收**：不配置编号项时 #73 原流程仍通过；配置目录后个人选择优先，目录选择失效明确报错。

## 功能需求

- **FR-001**：自动识别正整数编号的 `LLM<n>_NAME/BASE_URL/MODEL/API_KEY`，允许编号间隔，按数值排序。
- **FR-002**：全空组忽略；非空组要求四字段完整，未知字段、非法编号、无效默认项给出不含凭据的错误。
- **FR-003**：目录只提供 ID、显示名称、型号，不返回 URL、密钥及掩码；浏览器服务端选择只保存安全元数据。
- **FR-004**：编号模型仅允许有效且账户状态正常的已登录用户使用。启用目录后使用服务端默认凭据也要求登录；只读健康状态和公开元数据不额外消耗 LLM。
- **FR-005**：保留个人自带密钥；任一个人配置字段与服务端编号同时提交视为歧义并拒绝，不静默选一个。
- **FR-006**：明确选择的编号不存在时失败，不回退默认；未显式选择时保留超级管理员运行时默认优先，其后为编号默认，再后为原单模型环境配置。
- **FR-007**：`LLM_DEFAULT` 可指定目录默认 ID；未填时使用最小编号。没有编号配置时完全保留原单模型规则。
- **FR-008**：API、上传和核对 Worker 使用同一次任务的模型快照；编号模型快照缺失或损坏不得改用别的模型，终态仍清理短期凭据。
- **FR-009**：保留已有 URL 校验和统一客户端，不扩展供应商协议；生成、重排和灵感探索沿用当前选择。
- **FR-010**：本机和 Docker 均能加载任意编号项，配置变更后重新加载 API/Worker，不记录密钥，不把 `.env` 放进提交或业务数据包。
- **FR-011**：Embedding、SMTP、数据库结构和 PDF 解析器选择不受本功能改变。

## 成功标准

- **SC-001**：US1 的排序、缺项、空组、间隔、非法默认和未知选择场景全部通过。
- **SC-002**：匿名、伪造或失效登录在调用上游前被拒绝；目录与前端存储中无服务端凭据。
- **SC-003**：两个隔离上游的请求路由、流式及 Worker 快照归属正确，且失效选择不回退。
- **SC-004**：#73 定向回归、前端选择和生产构建通过；配置示例与实际部署传递一致。

## 范围外与依赖

依赖 #73 已有实现，不要求其所有第三方实测先结束；关联 #112 的部署配置和 #114 的模型消费路径。范围外包括配额计费、自动轮询/故障切换、Embedding 多模型、个人凭据云端长期保存和 Makefile 机器模板。
