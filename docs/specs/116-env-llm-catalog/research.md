# 设计决策

关联 [Spec](spec.md) 与 [#116](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/116)。

- **D-001**：编号组采用四个独立字段，保持 `.env` 常见格式；不使用 JSON 字符串或数量变量。解析器集中处理编号、排序及缺项，配置错误只输出编号/字段名。
- **D-002**：目录属于部署者；#73 原预置项属于个人。服务端选择仅传 `X-LLM-Config-ID`，个人配置继续使用原请求头。两种选择互斥，客户端不获取服务端 URL 或密钥。
- **D-003**：重用真实 JWT、账号状态与 session_version 校验，不能只检查 Authorization 存在。目录模式下默认服务端调用同样受保护；普通元数据、健康状态和纯数据列表保持只读访问。
- **D-004**：默认优先级保持管理员运行时配置 → 目录默认（`LLM_DEFAULT` 或最小编号）→ 旧 `.env`；显式个人配置或目录选择覆盖默认。管理员旧文件仍按原权限写入，避免改变 #73 FR-025 的职责。
- **D-005**：复用 RQ 的短 TTL 凭据快照，增加来源 ID/显示名并正确保留 user_supplied。任务公开状态只记录安全来源；编号任务缺失快照时失败，不用当前默认冒充原选择。
- **D-006**：使用统一客户端与当前 OpenAI 兼容协议，不追加 Anthropic 等 SDK，不承诺未测试供应商的兼容性。
- **D-007**：API 与 Worker 在环境加载时读取编号组，Docker 通过可选 env_file 接收任意编号项；已有显式数据库环境映射保持优先。真实密钥始终留在私有 `.env`。
- **D-008**：测试用隔离账号、Redis 和上游模拟服务，不向真实供应商发送业务论文。记录隔离集成与真实供应商验证的区别。

#73 FR-004、FR-005 继续约束个人预置输入；本 Feature 的动态目录是新增来源。#73 的密钥保护、URL 验证和失败不回退原则继续有效。


## 收尾决策（2026-09-29）

实际供应商验证发现原连接测试只允许 1 token，推理模型可能消耗额度却未生成正文；DeepSeek 在 256 token 上限下已返回正文。连接测试仍保持单次请求、无重试、无模型切换，使用固定简短提示与 256 token 上限、30 秒读取超时；无正文时区分 length 截断与非预期响应，不把 HTTP 200 网关首页视为成功。上游明确 model_not_found 时优先报告模型不存在，不因网关使用 HTTP 503 而误报服务地址不可达。

模型 ID 来自用户配置；上游目录仅用于诊断，不自动选择替代模型。用户已授权完成真实调用验收与根 README 收尾，覆盖 README 内不允许 AI 编辑的局部提示；只新增本功能使用说明，不改其他内容。
