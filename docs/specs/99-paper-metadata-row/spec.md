# 论文书目信息单行编辑

**GitHub Issue**：[ #99](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/99)

**创建日期**：2026-09-09

## 背景与目标

管理员编辑论文与用户上传解析的书目信息目前顺序不同、分散多行，且缺少独立期号。统一编辑顺序，支持完整保存期号。

## 用户场景与验收

### US1：上传校对书目信息（P1）

用户校对解析结果时，需要按论文书目信息顺序连续填写。独立验收：打开上传解析、填写六项、保存并重载，提交后核对论文详情。

1. 假如已有解析草稿，当打开校对页面，那么六项按期刊名、年份、期号、卷号、起始页码、DOI 排在一行。
2. 假如期号为 `S1` 或 `3-4`，当保存、重载并提交，那么期号原样保留。

### US2：管理员维护书目信息（P1）

管理员需要与上传页面一致的编辑体验。独立验收：打开旧论文、填写期号并保存，重载后六项仍正确。

1. 假如旧论文没有期号，当打开编辑页面，那么期号显示为空，其他书目信息不变。
2. 假如管理员修改或清空期号，当保存并重载，那么显示最新值。

## 需求

- **FR-001**：两个表单按期刊名、年份、期号、卷号、起始页码、DOI 顺序保持一行。
- **FR-002**：期刊名和 DOI 各占可分配宽度的 1/3，其他四项均分剩余 1/3；窄屏允许在行内横向滚动。
- **FR-003**：期号独立于年份和卷号，可空，支持最长 100 字符文本；未报告时不得猜测。
- **FR-004**：解析、草稿保存重载、提交入库、管理员修改和详情读取保留期号。
- **FR-005**：旧论文无需填写期号即可继续编辑；页码范围、文章编号、年份语义及 DOI 校验不因布局改变而变化。

## 成功标准

- **SC-001**：两个表单在桌面与窄屏下六字段均同一行、顺序正确，宽度比例为 4:1:1:1:1:4。
- **SC-002**：文本期号经过上传提交和管理员保存后读取一致，旧数据可空，既有页码文本不损失。
- **SC-003**：相关前端回归与构建通过，并在当前 scwiki MySQL 验证新增字段的持久化链路。

## 边界、依赖与非目标

沿用现有身份权限、保存与提交审核流程。空期号允许 null 或空文本。长字段通过输入框滚动编辑，窄屏只滚动书目行。不修改论文详情的整体布局、不改变物性记录、不对历史页码范围提取或回填起始页。不新增临时测试数据库。
