## 问题与目标

本机历史有 1121 条资讯，本周三栏为空，成功水位停在九月。macOS fork 子进程反复触发 Objective-C initializeAfterFork 崩溃，以 signal 6 退出，留下互斥锁，后续作业 collection_busy。同期线上有本周 24 条预印本和 2 条期刊栏内容，本机空页不代表无文献。

## US1：恢复本地正常采集

恢复资讯进程，让页面展示实际采集到的本周内容。保留历史数据、发表日期和增量水位规则；来源失败据实记录。

## 功能需求

- FR-001：macOS 使用新的解释器进程，避免 fork 后系统网络库崩溃，Linux 保持原模式。
- FR-002：保留独立队列、互斥锁、900 秒作业上限及生命周期恢复，仅重启本地资讯 Worker/Scheduler。
- FR-003：确认进程停止且无活跃资讯作业后，仅比较并释放死亡进程的遗留锁，不清空队列或 Redis。
- FR-004：通过正常来源采集、本周 API 和实际页面验证恢复。

## 成功标准

- SC-001：平台与采集回归通过，实际运行 SpawnWorker，正常采集不重现本次 signal 6。
- SC-002：来源水位推进、本地本周内容可读，仍失败的来源明确说明。

## 范围外

线上部署、推送、正式科研论文写入、来源规则放宽、人工修改日期、从生产复制条目代替采集，以及其他任务的 UI 修改。
