## 背景与目标
让用户在准备和模型核对期间都能看见流程完成比例及当前步骤。
### 需求结论与变更取舍
采用真实完成事件驱动的流程百分比，不代表耗时比例或科学审核通过率。
| 完成事件 | 百分比 |
|---|---:|
| 开始准备 | 0% |
| 必要字段检查完成 | 5% |
| 来源准备完成 | 10% |
| 任务准备完成 | 20% |
| 模型完成批次 | 20%至95%，按实际完成组数 |
| 结果整理及最终版本校验完成 | 100% |
无需模型时直接按实际路径完成；没有完成事件时保持百分比。

## 用户场景与验收
### US1：等待核对时看见实际流程进展（P1）
优先级理由：直接解决截图中的等待不确定感。
独立验收：运行含准备和多批次核对的流程，观察进度与后台事件一致。
1. 假如开始核对，当准备尚未完成，那么显示0%与准备说明，步骤完成才推进。
2. 假如需要5组核对，当完成2组，那么显示50%与2/5组。
3. 假如正在排队或处理一组，当尚无完成事件，那么百分比不变，等待时间更新。
4. 假如核对结果完成且版本校验通过，当整理结束，那么显示100%；有科学疑点仍按原流程处理，不伪称审核通过。

### 边界与异常场景
取消、超时、请求失败、版本冲突不得显示成功完成；保留原输入和已保存结果。重试新运行重置进度，迟到响应不影响新运行。无模型任务可直接完成。复用已有后台任务时使用该任务真实计数。窄屏文字可换行。
