# 调查与设计理由

## 根因及旧要求

旧 #147 明确编辑不新增红框；#191 的 a871fbbd 改了待核对颜色与相关断言，却没有完整替换旧规则。#200 只移除状态文字，不是触发时机改变的授权。当前编辑只更新 pending_review，颜色先命中 required=false 且 human_modified=false，造成原免审字段人工输入仍显示通过。#145 red-marking.md 是历史调查，不能直接复制为现行规则。

## 方案取舍

采用独立本地修改标记；不把浏览器推测写成后端 human_modified，以保留科学版本和人工归因。保留原免审规则，不把全部 pending_review 提前为红，避免未改空项误报。保留现有编辑事件和实际值比较，只处理当前字段，不引入全表轮询。

人工理由草稿与已保存科学值不同：原 guard 会整体拦提交，但缺少字段提醒。待保存身份快照只随成员变化，理由逐字变化仍由原组件处理。处理进度不作为消红资格。

## 文档迁移边界

原图、测试结果与失效规则均留出处；迁出片段集中归档并明确为历史。其他业务正文不迁移。旧 Issue 未完成任务及类型、关系、状态不变。静态图中与科学字段无关的红色线条、按钮和设计标注不属于本规则。
