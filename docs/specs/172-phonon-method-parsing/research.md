# 调查与决策

- 错误类别：#139 新增主路径检查与既有宽松 JSON 输入之间的设计缺口，不是部署版本差异。
- 日志在 condition_rules.remove_unreported_generated_conditions 的 item.get 崩溃；失败响应含 extensions={electron_phonon:{phonon_method:DFPT}}。原有 Extraction 的 payload 只校验 JSON 值，不能确保内部数组。
- 旧函数少了条件过滤，允许此数据经过该阶段；不能证明旧版本全篇正确。
- 决策：在新提取入口先做有界规范化及明确 ValueError 校验，再跑原方法语义与原文检查；复用已有失败机制，不扩大重试。
- 只接受已证实的单一声子方法分组。陌生分组、混合键、非文本方法、数组非对象项拒绝，避免擅自解释新格式。列表元数据保持，输入不原位改写。
- 显示名与后台身份分离；phonon_method 显示为声子方法，electron_phonon 仍保留科学归属。人工 name_raw 不覆盖。
- 拒绝仅修改提示词：模型仍可能输出错误格式，固定失败响应必须通过真实处理链。
- 字段重跑重新调用模型读取必要原文；未改动文字提取可复用，后续标准化/条件检查/组装/草稿保存重读必须真实运行。重放不是重新提取，两类证据分别报告。

## 真实字段重跑发现的同边界缺口

第一次真实模型将软件和泛函放入没有阶段前缀的扩展（calculation_code、exchange_correlation_functional）。这会绕过既有仅处理带阶段扩展的原文过滤；首次验证脚本也因只检查固定软件字段而漏检，不能计为科学验收通过。原响应及初始报告原样保留，后续报告明确否决此结果。

在同一个新提取格式边界拒绝缺少阶段的已知条件扩展，提示使用固定字段或完整 stage.parameter 键；不推断其软件归属、不增大重试。验证入口要求软件归属存在，检查固定字段和对应扩展两处的 QE 泛函。该收敛落实 FR-002～005，并未放宽科学规则或扩大重试范围。

第二次真实重跑返回标准数组，但把原文 density functional (linear-response) theory 改写成 DFPT，被既有直接原文检查剔除；这次明确失败，未放宽检查或篡改输出。共享提示进一步要求 value_raw 保留原文的方法名称，避免用原文没有的缩写替换；新增长名称保留和无直接依据缩写不授信的反例。
