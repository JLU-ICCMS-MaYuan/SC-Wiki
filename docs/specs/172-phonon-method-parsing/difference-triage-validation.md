## 实现和取舍

- 后端在正式解析保存前附加诊断；纯分类不改原文或科学值。等价转换保留正负号、上下标、数值、单位及空间群横线。表格比较单元位置、文字和跨度，空表、重复位置、非法跨度不能核实通过。
- PDF检查绑定上传摘要；文字层支持某个版本只是提示，不是视觉或科学裁决。原文不可读或身份改变保留系统待查。
- 当前影响关系仅列解析时明确的块引用，不能据此保证当前编辑值；谱图和只有页码/引句的关联尚未完整建立，页面明确提示未建立关联不代表没有影响。
- 出版年必须同DOI、同标题且出版日期年份一致；下载/打印日期不是发表日期。GROBID没有DOI时，只有同源PDF首页明确含草稿DOI才能补足身份。查询失败、身份不符或年份歧义不伪造验证成功。
- 前端来源快照与可编辑草稿分开，外部加载/安全刷新才比较诊断。题录当前值变化及时显示；改论文标题或DOI也会使旧年份核验失效。这些是真实依赖，无关输入不重新分类。
- 复用`EvidenceRegion`按需定位原PDF。直接块定位没有RAG片段号，不编造编号；图注仍传原始引句帮助可靠定位，显示时不重复长引句。
- 未新增持续后台核查队列，没有自动完成47项的承诺。本次交付解决分类、责任和已确认年份错误；余下原图/表格/科学关联问题仍清楚保留，供后续按类讨论。

职责按分类、出版年查证、面板展示拆开，复用正式保存与原图入口；不新增第二份科学数据或数据库结构，避免为首批分类引入大型工作流。

## 回归和故障发现

- 旧上传宿主的新增分类测试先失败：不存在分类面板，仍渲染90条原始记录。旧题录组装重放可把AI的2012覆盖成GROBID的2021。缺模块导致的导入失败不算行为反例。
- 后端组合62项通过：新分类/出版年、CaH6全流程既有回归、互补PDF、#139工作流。覆盖μ*/μ、电荷、空间群、235/220、meV/eV、相名混淆、表格错位、空/重复单元、原文不可读、DOI/标题/文件身份错误与同源DOI补足。
- `npm run test:form-contract --prefix frontend`：64项通过，包含新增完整上传宿主及上传/返修/管理员/超级管理员既有回归。
- `npm run test:form-contract:mutation --prefix frontend`：注入整体缓存失效后四宿主8项均检出失败，验证门有效，未修改工作树。
- `npm run build --prefix frontend`通过；现有大分包告警保留，不宣称没有警告。
- 初次构建发现直接PDF块缺少`chunk_index`，改为局部来源类型允许无分段号；原图检查发现图注仅block_id不能定位，补原文quote后真实后端返回located及裁图。
- 浏览器测试先因按钮中文名不符失败，按真实文案修正；再捕获到两次DOM变化，记录确认为刚点击的MUI涟漪动画，等待该动画实际结束后才开始输入测量。没有增加超时或放宽“输入无关重绘为0”的断言。
