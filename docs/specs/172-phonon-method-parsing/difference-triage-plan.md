# 差异分类实施方案

依据已确认的[difference-triage-spec.md](difference-triage-spec.md)，沿用#172，不改变原始解析来源所有权。

## 实现与数据

1. 新增backend/ingest/parsing_diagnostics.py，纯分类函数保持原区域与备选文字不变，为既有parsing_conflicts和bibliography_conflicts条目附加triage元数据。稳定ID绑定文件/页/块，不使用数组序号；版本指纹绑定该身份、候选文本及规则，来源摘要和解析时证据关联另行保存，前端比较整个诊断快照更新实际变化。
2. 明确几何页脚/水印、可证明的表示等价、同引擎分块拼接，其他字符、符号、表格差异保持待系统核查。公式规范化保留上下标、负号、数值、单位；表格必须核对单元格位置/表头/跨度，不能只比较数值集合。读取原PDF文字层时保留匹配结果和不确定性，不按多数票自动改科学值。
3. 来源关联只表述为解析时证据关联，提供稳定状态/记录身份；缺少关联不写成无影响，结构/谱等未建立链接的范围如实标记。
4. 新增backend/ingest/publication_year.py：仅在DOI与标题身份一致且出版日期年份一致时采纳Crossref年份；下载/打印日期不得覆盖出版年份。原候选和外部依据保留；查询失败或年份歧义保留系统待查，不编造年份。
5. 在原解析流水线生成诊断；旧任务通过受控脚本重建诊断。本次仅对指定CaH6任务执行备份、哈希/来源核对及锁内写回，并保留2021→2012记录；其他科学值不改。
6. 新增ParsingDiagnosticsPanel替换上传/返修原始长警告。只读来源快照与可编辑表单值分离：仅在服务器草稿加载/刷新时更新诊断快照，输入不重建分类。默认分类摘要和代表例，详情按需挂载，原PDF通过现有EvidenceRegion按点击读取；不新建自动模型请求。
7. 现有parsing_conflicts/bibliography_conflicts受保护存取继续有效，不增加第二份科学值或数据库迁移。分类不改变来源核对和人工决定，状态system_checked只说明该差异已按所列规则核实，不表示论文批准。

## 质量门与映射

| 需求 | 组件职责 | 验证 |
|---|---|---|
| FR-001～004、SC-001/002 | 纯分类、稳定身份、只读来源账本 | 90区域对照、符号/单位/行列反例、重复/缺失检查 |
| FR-005/006、SC-003 | PDF核验依据、影响与责任、分组详情 | 代表例与原图、未知状态不伪装通过、无批量科学审批 |
| FR-007、SC-004 | 出版年身份校验与受控修复 | 真实Crossref、PDF下载日期、原任务保存重读与并发拒写 |
| FR-008、SC-005 | 独立诊断快照与按需渲染 | 四宿主form-contract和mutation、含90差异完整宿主交互、相关回归/构建 |

管理员/超级管理员的既有科学表单必须回归；本轮不在原本没有解析差异数据的入口虚构诊断，也不宣称全站非科学表单验收。

## 边界

只核对现有解析产物及原PDF，不重跑全文OCR。首次实现不提供“全部通过”按钮。能否修改科学值继续走既有字段流程；读取能力不足是系统技术问题。代码/文档只提交本任务增量，其他并行改动保留。
