## 实际问题和修复

| 问题 | 真实原因 | 修复和边界 |
|---|---|---|
| 截图中的“科学提取不符合契约” | AI对补充材料（SI）提出了11条“这些内容不用提取”的建议，但只指出是哪张表，没说清楚是表里的哪几行。比如（仅作示意），只说“表S1不用提取”，而不是“表S1的第2、3行不用提取”。旧检查规则要求写明行号，因此把这次返回的整份提取结果都拒绝了，不只是这11条建议 | 不完整提议不取得排除资格，保留诊断，交给逐行覆盖分类；不整表放行、不删除科学候选 |
| 分段成功后仍称无法定位 | 模型给对块编号却改写了引句的公式排版，提取层未检查直接quote，直到整篇Claim才发现 | 在分段阶段校验直接引句，允许既有一次纠错改用显式原块引用；缓存13→14，旧漏检结果不复用 |
| 跨页续句被当成遗漏 | 覆盖分类器只收到最多300字符的孤立文本，看不到前页的201 K／187 K及已提取结果 | 提供目标全文、相邻页原始块和已提取记录；仍只对目标作分类，真正新结果保持needs_extraction |
| 汇总丢失Tc配对 | 旧组装按范围端点相等删除单值记录，235/.1和220/.13被220–235范围吞掉 | 移除端点相等去重；上游完整记录身份去重保留，不把范围和单值当同一记录；原防遗漏门不关闭 |
| 总结长度检查依据错误 | 读取论文PDF的工具GROBID没分清摘要在哪里结束，把后面的关键词和一部分引言也算进了摘要。实际摘要只有168个英文单词，却被算成403个，导致系统用错了检查总结长度的依据 | 只有同源IR首页的独立关键词块与前段首尾共同确认时，截取GROBID原文前缀；本篇168词。原始403词与选择依据保留 |
| 动因／类型／总结核对引句错误 | 模型重新抄写LaTeX和上下标，引用不再是原文 | 生成和相关字段核对明确用本次来源编号，由服务器取回原文；旧逐字引句兼容仍经过校验，不把编号当科学判断 |
| 结构优化证据不完整 | 模型把结构搜索或仅有VASP名称的段落当静态DFT优化依据；旧检查还漏认“optimized their structures”句式 | 给出同时满足优化步骤和理论说明的候选原段，模型选择适用材料；服务器取原段、保留来源。增加倒装句式识别；没有DFT/static依据仍不通过 |
| 总结重算后警告未消失 | 原单字段恢复只改正文，未同步旧generation_issues | 成功恢复时只清除对应字段的生成错误，同步AI快照；其他警告不抹除。理论二级类型恢复同样处理 |

受控重跑另增加草稿内容哈希及锁内校验：期间若发生编辑，在写新结果/草稿之前拒绝覆盖。已完成真实正向路径与模拟并发修改的Worker反例。
