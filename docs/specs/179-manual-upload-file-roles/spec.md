## 附件与推断来源

无用户上传附件或图片；`images: []`。批注对象为此前说明文字，不作为独立需求来源。

代码与历史依据：#26 建立多文件上传；#49 支持结构文件；#135 要求自动识别、覆盖角色和歧义暂停，本次需求明确替代这部分规则。#135 的统一来源读取和文件一致性检查继续保留。正文、补充材料沿用 PDF/TXT/MD；源数据文件沿用 CIF/POSCAR 及已有兼容命名，依据当前上传校验代码，不扩展解析能力。以上为现状核对及本次已确认 Issue 的范围解释。

## 背景与目标

上传者已经知道哪个文件是正文、哪个是补充材料或结构数据，应能在指定位置直接上传。取消上传后再次猜测文件角色、覆盖用户选择和要求二次确认的过程，避免同一份补充材料因分类变化而遗漏科学信息。

### 需求结论与变更取舍

采用用户后续批注：三类名称为“论文正文、补充材料、源数据文件”，正文恰好一份，另外两类可为空或多份，不保留普通附件兜底入口。发表后的补充说明和纠正文稿属于补充材料，保留独立文件来源；本次不增加纠正值自动覆盖正文值的规则。用户指定角色成为新任务的有效角色，文件内容不能重新决定角色。

## 用户场景与验收

### US1：在指定区域上传一篇论文的文件（P1）

上传者分别选择或拖入正文、补充材料和源数据文件，提交为一个任务。优先级理由：这是新的主要操作入口。

**独立验收**：在完整上传页选择一个正文、两份补充材料（含一份纠正文稿）和两个结构文件，清单归属正确，任务仅创建一次。

**验收场景**：
1. 假如尚未选择正文，当开始上传，那么界面提示必须有一个正文，后端同样拒绝不合法清单。
2. 假如已有正文，当再次选择或拖入正文，那么明确提示数量限制，不能静默覆盖已选文件或改分到其他区域。
3. 假如向补充材料或源数据区加入多份合法文件，当上传，那么全部关联同一任务和同一篇论文。
4. 假如文件格式放错区域，当选择或调用创建接口，那么明确拒绝，不根据格式自动搬到另一区域。

### US2：按照用户指定身份直接解析（P1）

用户只在上传前确定文件身份，后台依该清单处理。优先级理由：消除此次需求中的重复确认和角色覆盖。

**独立验收**：正文文件名包含 SI、补充材料含摘要与论文章节、纠正文稿具有不同标题时，指定角色均保持原样，不因角色识别暂停；独立文件一致性检查仍遵守原有规则。

**验收场景**：
1. 假如正文文件名含 SI 或论文式标题信号不足，当解析，那么仍按用户指定正文处理。
2. 假如多份补充材料看起来都像论文，当解析，那么都按补充材料处理，不产生角色确认请求。
3. 假如内容无法读取，当解析，那么报告真实解析错误，不改成普通附件来掩盖失败。
4. 假如文件存在真实可比较的身份差异，当检查，那么沿用已有具体差异提示和提交确认，不更改角色。

### US3：保持提取、结构和来源的原有能力（P1）

正文和补充材料参与科学信息提取，源数据文件参与结构处理，所有数据可定位原文件。优先级理由：入口简化不能丢失已有能力或来源。

**独立验收**：补充材料和纠正文稿中的已报告科学值进入提取候选并保留来源；结构文件经过解析、查看、确认、保存和重新读取；引文使用用户指定正文，其他下游读取相同有效角色清单。

**验收场景**：
1. 假如科学事实仅在第二份补充材料中出现，当提取，那么该文件参与处理，证据可定位该文件与原文位置。
2. 假如纠正文稿与正文报告冲突数值，当提取，那么保留来源并沿用既有冲突待审规则，不自行确定纠正优先级。
3. 假如有多个合法或非法结构文件，当解析，那么保留逐文件结果及已有错误、确认和保存规则。
4. 假如打开历史任务或正式论文，那么仍可读取原文件分类、来源与草稿，不触发批量修改。

### 边界与异常

保留每文件 50 MiB、最多三个文件并行上传、重复内容拒绝、权限与任务版本保护、失败与取消恢复。全部声明文件上传完成后才锁定清单并入队，锁定后不能增删、换角色或覆盖文件；需要调整时取消并新建任务。切换正在查看的任务不清空尚未上传的本地选择。新流程适用于新任务，不静默转换历史待角色确认任务，也不批量重算草稿。

## 功能需求

- **FR-001**：提供“论文正文、补充材料、源数据文件”三个独立的选择和拖拽区域；归属由上传位置决定，不要求逐文件再选角色。
- **FR-002**：正文必须恰好一个；补充材料和源数据文件分别允许零个或多个。正文超额时明确拒绝，不静默替换、丢弃或重新分组。
- **FR-003**：正文和补充材料接受 PDF/TXT/MD；源数据文件仅接受已有 CIF/POSCAR 结构格式及兼容命名（.cif、.poscar、.vasp、无扩展名 POSCAR/CONTCAR），前后端按区域校验并明确报告错误。
- **FR-004**：补充材料包含发表后补充说明和纠正文稿，与正文一起参与科学信息提取；每个文件保持独立来源，冲突沿用现有待审规则。
- **FR-005**：源数据文件沿用已有结构解析、校验、候选确认、预览、导出、保存和重读能力，不提供仅存档用途的普通附件入口。
- **FR-006**：新任务直接以用户指定角色处理，后台不再推断角色、不覆盖分类，也不产生因角色不明确而暂停和二次确认的步骤。
- **FR-007**：引文读取用户指定正文；分段、字段生成和来源核对统一读取同一有效角色清单，不能因旧评估或缓存改读其他文件。
- **FR-008**：保持稳定文件身份、原始文件、内容哈希及科学来源位置，草稿提交后仍能定位相应原件；分类展示名称变化不丢失既有来源关系。
- **FR-009**：保留已确认的文件大小、重复文件、并发上传、完成后锁定入队、单论文事务提交、权限、版本及失败恢复规则。
- **FR-010**：文件一致性检查与角色确定分开；保留 #135 的真实差异提示、未知不制造冲突及既有提交确认，不借取消角色判断删除该检查或增加模型调用。
- **FR-011**：历史任务和正式论文可读取，不自动更改其分类或草稿，不批量重算，不将历史兼容入口变成新任务的常规角色确认流程。
- **FR-012**：受影响表单遵守 #174，保留局部更新、稳定身份和无关请求隔离；同步入口清单及实际验证范围，科学表单或共享组件受影响时执行规定的完整宿主和变异回归。

### 关键实体

- 论文上传任务：对应一篇论文和一张表单，包含恰好一个正文及可选多份补充材料、结构源数据文件。
- 文件身份与角色：上传者指定用途；文件名、排序或文本样式不拥有角色决定权。
- 文本证据与结构候选：分别来自参与提取的文本文件或结构处理，关联原文件及来源位置，沿用原有人工确认和审核规则。

## 成功标准

- **SC-001**：完整上传页面支持一个正文、至少两份补充材料和两个源数据文件共同创建一个任务，数量或区域格式错误在前后端均被明确拒绝。（FR-001—003）
- **SC-002**：正文名含 SI、正文信号不足、多份论文式补充材料及纠正文稿四类场景中，角色被覆盖次数和因角色判断暂停次数均为零，无二次角色确认请求。（FR-006）
- **SC-003**：只有补充材料或纠正文稿包含的固定科学事实进入正式提取路径，来源能定位到对应文件；冲突没有未经确认的自动覆盖。（FR-004、007、008）
- **SC-004**：多结构文件的合法、非法输入保留已有逐文件处理能力；有效候选经确认、保存、重读后来源一致。（FR-005、008）
- **SC-005**：主文引文、文本提取与字段核对读取同一指定清单；真实文件差异仍按既有规则提示，未知不误报，文件一致性检查不增加模型调用。（FR-007、010）
- **SC-006**：上传队列、锁定、事务提交与失败恢复回归通过，历史记录可读，历史分类或草稿批量写入数为零。（FR-009、011）
- **SC-007**：更新 #174 表单清单并通过受影响回归；科学表单或共享组件受影响时，规定的两项表单契约命令及完整宿主回归通过。区分固定材料重放、真实来源验证和未验证范围，不以静态字符串断言代替交互验证。（FR-012）
