# 实施计划

依据 [规格](spec.md)，按权限关闭、持久化、后台生成、界面及验收顺序实施。

## 职责

Go 保留公开读取与超级管理员治理；Python 专用 API 负责创建问题、任务与模型生成，独立 RQ 队列不消费上传任务。Python 只写 AI 生命周期，Go 编辑和治理与其共用行锁顺序（问题→答案）及递增版本；问题内容发布后冻结。

## 数据及接口

见 [数据模型](data-model.md) 和 [接口契约](contracts/api.md)。模型配置通过短期 Redis 快照传入 Worker，数据库仅存安全元数据及身份摘要。重试必须匹配原型号和端点，不回退默认。每问题一次站内检索，检索失败进入失败状态，空检索允许无证据回答。公开读取时再核验引用论文可见性，来源失效的 AI 答案隐藏正文。

## 执行与恢复

独立队列 scwiki-community-ai，默认两个 Worker；Redis 全局两槽租约防止多实例超并发。每任务 600 秒，凭据快照 24 小时，终态删除。模型任务独立，唯一任务和行版本禁止重复发布。MySQL 为状态权威，RQ 分发失败与死亡 Worker 在状态读取及 Worker 启动时恢复为失败，可显式重试。客户端请求 UUID 幂等，同 UUID 不创建第二问题。重生成保留当前答案并记录基线版本，提交时发现人工修改或治理版本变化即冲突失败。

## 交付

此前不自动部署；本轮用户明确授权本地 `127.0.0.1:3307/scwiki` 的迁移与服务启用，未授权其他环境。迁移在隔离 MySQL 验证，默认 Worker 启动项加入本地和 Docker。共享 README 仅暂存本任务增量。通过必要验证后按仓库格式自动提交，不推送；远程链接未验证则不关闭 Issue。

## 本地部署补充

先核验公开论文存在性，公开库为空时直接返回经过数据库确认的空资料；不把检索异常降级为空。模型调用复用既有 complete_json 流式入口，限定 retries=0，并要求 finish_reason=stop 才可发布。
