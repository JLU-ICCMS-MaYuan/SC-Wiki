# 默认开启与红框接入契约

## 单一服务端能力

UPLOAD_HUMAN_QUESTIONS_ENABLED默认true；仅修改浏览器构建变量或隐藏组件不是关闭。服务端读取已有任务策略和队列状态，公开can_create_questions、can_answer_existing等最小能力，前端据此展示。具体能力键为技术草案，必须由后端决定，不由前端自造权限。

| 情形 | 新问题 | 已有问题/答案 | 执行 |
| --- | --- | --- | --- |
| 默认/开启的新任务 | 可生成 | 可查看和回答 | 按局部暂挂与恢复 |
| 关闭后创建的新任务 | 不生成 | 无新增队列 | 原有失败/待核对及保护 |
| 已启用且有待答队列，后来关闭全局开关 | 保留原任务策略 | 继续可看可答，不删已接受方向 | 安全点完成局部恢复 |
| 无该元数据的旧任务 | 不自动回填 | 既有草稿/证据保持 | 沿旧流程，不启动重解析 |

## 页面接线

UploadPage持有现有任务身份，UploadModelActivity红框挂载UploadHumanQuestions；新问题不重置正在填写的其他题，不改变页面滚动/焦点，不卸载整个科学表单。UploadParsingDetail只展示真实阶段、局部已完成及待答计数。问题对应字段未形成时仍显示候选/来源定位，不虚构字段下标。

纯查看不调用模型；普通输入和保存零额外模型及全表扫描。活动执行沿已有进度轮询；只剩待答停止整稿轮询，保留问题按需读取和显式继续；刷新后可恢复。后端进入waiting状态前保存恢复上下文，旧Worker不能把它写回ready。终态移除计时器，待答不按失败24小时规则清理。

## 开启与关闭的工程验证

必要回归覆盖默认true、显式false和已有题的关闭恢复，不要求同一真实文献两次解析比较。配置按现有进程加载方式同步API/Worker，不能以热改一个前端开关宣称后端切换完成。实现后README说明具体加载方式；本次不修改.env、不重启服务。

## 端到端验证边界

默认新文献正常上传后，遇到真实科学问题则核实：问题真实依据、另一无依赖字段继续保存、用户选择/填写、人工依据可读、局部恢复与保存重读及正常后续审核。若本篇没有真实问题，记录无题链路；以故障夹具覆盖交互，不能将其冒充真实科学问答。实际业务流程做到哪一步就报告哪一步，不用局部通过代替整篇送审/批准/搜索。
