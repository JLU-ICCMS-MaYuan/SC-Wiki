# 调研与设计取舍：默认启用人工问题窗口并以最小改动接入新文献解析

参见[规格](spec.md)与[计划](plan.md)。以下均为AI查证/工程理解，用户原话保存在规格中。

## 真实接点

- `backend/rag/config.py`已有RagSettings，但没有本功能开关。拟增加upload_human_questions_enabled=true，并由任务创建记录启用策略；API与Worker需读取同一来源，不用前端构建变量另设一套值。
- `UploadPage`挂载`UploadModelActivity`和`UploadParsingDetail`，红框已有请求动态和继续/手动填写入口。新组件由红框挂载，不重做科学表单和右侧栏。
- `upload_contracts.PUBLIC_TASK_FIELDS`为明确白名单，public_parsing_detail另有DTO；只有增加公开能力/摘要并处理轮询及暂停时的展示，前端才看得到真实问题。
- 任务计时、清理与runtime均只认识现有状态；人工作答等待复用paused并说明原因，检查计时不将等待算成模型处理，恢复要保留模型引用，不能因终态清理删掉待答上下文。

## 默认与关闭

用户明确替代了默认关闭和相同文献重复解析对照。后续落地默认开，新任务创建读取当前开关；已有问题以任务当前队列为准继续可答，关闭不是删除队列或隐藏唯一入口。空队列关闭任务沿现有流程；已接受答案和人工依据不因开关切换失效。切换配置需按现有进程加载规则同步API和Worker，不在本轮擅改.env或重启。

## 验证范围

必要回归可以覆盖开关false/true逻辑和故障夹具，这不等于要求用户重复上传同一论文进行产品对照。完成回归后直接用新文献；没有真实冲突时如实记录无题，不能人为改坏科学值制造题。真实新文献/模型/运行目标在执行前按实际用户输入确定，不把Y-H等历史稿视为本轮可删改授权。实现后才更新Overview和README。
