# 实施计划

依据[规格](spec.md)、[研究](research.md)、[数据边界](data-model.md)、[契约](contracts/behavior.md)、[任务](tasks.md)。

## 技术上下文与数据所有权

复用Python/FastAPI/SQLAlchemy、MySQL、Redis/RQ、React/Vite。科学值仍为权威工作稿及正式图；来源为现有文件、来源目录和字段使用关系。无迁移、无标准键变化，无新模型入口。

## 实施路径

1. 全仓索引检索并对照原始需求、Spec、Overview及相关完整链；保留旧数据失败重放。
2. 用共享工作稿快照构建处理完整来源清单和既有归纳来源，将交接／退回、管理员暂存／批准等重建入口接通；真实变化保留失效。
3. 取消前端legacy_evidences兜底及信息提示；原文区不显示重复状态／理由。字段直接／共同依据由既有独立核对结果提供，不添加关键词猜测。
4. 补四宿主交互和来源版本反例，运行必需回归；生产构建写入临时目录。
5. 核对本地目标后删除用户已授权CaH6关联对象及现有解析任务；从给定PDF正式上传和解析，保存真实证据；隔离验证提交、退回与重开。
6. 验证后更新Overview、#174清单和Issue，再自动仅提交本任务文件。远程Spec未推送保持待验证。

## 复杂度与失败处理

来源版本集中构建，避免各入口漏步骤。保留历史兼容的后台资料但去掉展示兜底。不新增数据库表或第二份科学数据。出现新错误先回查原要求；未查明或未验证不提交、不宣布完成。

真实整篇事务验收复用scripts/verify-upload-submit.py，新增--return-cycle覆盖两管理员原样退回、返修重开和轻量摘要；所有写入在MySQL外层回滚，文件及任务状态副本隔离，不代用户正式送审。

## 整篇真实验收补齐的原职责

首次交接采用内部submission上下文保留待确认分类和作者角色；正式历史形成后恢复既有读取来源。model_review沿原source_ids协议明确仅返回当前字段显示依据，全文其他资料保留只读背景，不增加科学审核轮次或提交重判。Source映射仍由原模型核对承担，不以关键词、是否supported或同软件猜测引用归属。
