## 背景与目标

用户希望数值、证据和理由分别按真实修改保存。页面携带某些旧数据，不意味着用户本次修改了这些数据；不能因为它们处于同一字段资料包或同一稿件而一并覆盖。

同一合法经手人的两个标签页共享一份持久工作稿。修改不同项时两边都保留；真正修改同一项时，后一次保存成功的内容生效。这里的覆盖许可不扩展为修改已交出稿件、冻结快照或其他无权限对象。

### 当前实现核对

- `frontend/src/lib/fieldDrafts.ts::createFieldDraftSaver` 已生成变化列表并发送 PATCH，不是所有保存都直接用整稿替换。生成列表前仍会复制整稿，本 Feature 不优化这部分成本。
- `backend/ingest/field_drafts.py::save_fields` 及变更应用逻辑仍包含整稿版本／旧值冲突检查。不能把当前已有局部 PATCH 视为已经满足所有旧页面覆盖要求。
- 当前来源核对说明要求输入、普通保存与审核分离；#177 只保存当前字段及人工依据。本 Feature 保留这些边界，不把数据覆盖许可扩展为接受过期审核结论。

### 需求结论与变更取舍

- 保存数值、证据或理由中的哪一项，就只更新实际变化的那一项；不能按“配套资料”扩大覆盖范围。
- “保存整份工作稿”表示保存该页所有实际变化项，不表示把该页没改过的旧数据重新写回。
- 相同身份且仍有权编辑的工作稿项目允许后保存覆盖；未修改项、无权限目标及已交出内容不在许可范围。
- 只定义保存行为和正确性，不在本 Feature 改写整稿复制／比较策略、保存频率或切页同步机制。

## 用户场景与验收

### US1：数值、证据与理由分别保存（P1）

编辑者只修改自己需要修改的内容，保存后其他资料保持原样。

**优先级理由**：防止一次局部编辑覆盖未修改的资料。

**独立验收**：分别只改 Tc、只改证据、只改理由，再保存重读并逐项比较未修改内容。

**验收场景**：

1. **假如** Tc、证据和理由都已保存，**当** 用户只修改 Tc 数值，**那么** 只更新该数值，不替换原证据、理由及其他科学字段。
2. **假如** A 页已保存新的 Tc 数值，B 页仍显示旧数值，**当** B 只修改理由后保存，**那么** 新理由被保存，A 的新数值保留。
3. **假如** 用户只替换证据，**当** 保存重读，**那么** 证据变化，原数值与未修改理由不被 B 页的旧内容覆盖。

### US2：两个标签页按实际修改范围覆盖（P1）

同一经手人的两页分别编辑同一工作稿，不要求用户处理本来允许的覆盖冲突。

**优先级理由**：用户已明确选择同项后保存覆盖、不同项各自保留。

**独立验收**：两页使用同一初始稿件，分别验证不同字段、同字段不同资料项、同一资料项的先后保存结果。

**验收场景**：

1. **假如** A 修改 λ、B 修改 Tc，**当** 两页先后保存，**那么** λ 和 Tc 都采用各自保存的新值。
2. **假如** A、B 都确实修改了同一个 Tc，**当** A 先保存成功、B 后保存成功，**那么** B 的数值生效；不因 B 页面较旧而拒绝允许的覆盖。
3. **假如** B 携带未修改的旧证据，**当** B 保存修改过的数值，**那么** 不把旧证据重新写回覆盖 A 已保存的新证据。

### US3：保存失败、迟到响应与交出失权时仍正确（P1）

编辑者能保留失败输入，保存响应不会清掉之后的新输入；无权编辑后旧页面不能继续写入。

**优先级理由**：覆盖规则不能以输入丢失或越权为代价。

**独立验收**：注入保存失败和响应延迟，模拟删除前序结果与正式交出，检查输入、身份及写入权限。

**验收场景**：

1. **假如** 保存请求失败，**当** 返回错误，**那么** 当前输入保留，不假称保存成功。
2. **假如** 保存发出后用户继续输入，**当** 旧响应返回，**那么** 不清空新输入或把它错误标为已经保存。
3. **假如** 工作稿已成功交出，**当** 旧标签页或迟到自动保存试图写入，**那么** 服务端拒绝；不能以“允许覆盖”绕过编辑归属。
4. **假如** 前一个结果点被删除导致数组位置前移，**当** 保存原后一个结果点，**那么** 仍更新原稳定身份对应的项目，不写到其他结果点上。

### 边界与异常场景

- 同页点击保存、自动保存及侧栏保存共享实际变化项边界；不因入口名称不同就改成整稿替换。
- 用户清空值、删除证据或清空理由属于真实变化，不能把清空误判为没有修改。
- 本次没有变化时零写请求；仅理由或附件变化不等于整份资料没有变化。
- 目标已经删除或不再可写时，不按数组当前位置猜测，也不悄悄重新创建被删除的项目。
- 当前字段与依据的真实变化仍影响旧科学结论是否有效；保存成功不等于模型核对通过。
- 允许相同经手人同项覆盖，不表示全面移除权限、对象存在性或正式交出后的状态检查。

## 需求

### 功能需求

- **FR-001**：工作稿保存必须以实际变化项为更新范围，未修改的其他数值、证据、理由及科学字段保持服务端现状。
- **FR-002**：同一字段的数值、证据和理由须分别识别真实变化，不能因属于同一资料包而无条件一并覆盖；清空及删除操作须准确保存。
- **FR-003**：整稿保存仅提交本页所有实际变化项，不得将未修改旧数据写回覆盖其他标签页已保存的新内容。
- **FR-004**：同一合法经手人两页修改不同项时，各项均保留；不把另一页未修改的旧项合入本次写入。
- **FR-005**：两页确实修改同一稳定身份下的同一项时，以后保存成功的内容为准；不以页面旧版本或该项旧值为由拒绝本来允许的覆盖。
- **FR-006**：保存目标使用稳定字段、状态及结果点身份；删除造成位置前移时不能串位，已删除目标不能按位置猜测替换。
- **FR-007**：覆盖许可仅用于当前有权编辑的工作稿。正式交出成功后，旧标签页、直接请求及迟到自动保存均不得继续写入冻结内容或越过归属检查。
- **FR-008**：保存失败保留本地输入及待保存状态；旧保存响应不能覆盖后续新输入或错误清除其待保存标记。
- **FR-009**：无变化的数据保存不发写请求；普通保存和自动保存不调用模型，不因本 Feature 新增全量核对、持续刷新或整表扫描。
- **FR-010**：修改后的当前审核状态继续按真实字段内容和依据判断，不能因允许覆盖而把旧结果附给新内容；保留 #177 主动单字段核对边界。
- **FR-011**：上传、返修、管理员及超级管理员四类入口采用相同覆盖边界；保留中文组合输入、中间数值、光标、只读及真实提示。
- **FR-012**：保持已有表单、侧栏、按钮布局、自动保存间隔及保存触发方式；本 Feature 不实施跨标签页自动载入。
- **FR-013**：实施后完成受影响保存回归及仓库规定的科学表单契约与变异检查；既有失败须用独立基线证明，不以文档或代码存在代替验证。

### 关键实体

- **当前工作稿**：当前合法经手人可编辑的持久稿件；多个页面共享同一保存结果。
- **实际变化项**：用户本次真正改变的某个值、证据、理由、附件或明确删除动作，不是页面持有的全部旧资料。
- **稳定保存目标**：科学字段及其所属对象的身份，不随数组位置改变。
- **本地未保存输入**：尚未成功持久化或在请求发出后继续编辑的内容，不能被旧响应清掉。
- **当前核对结果**：与当前字段及依据相匹配的审核状态，不能因数据保存成功而自动通过。

## 成功标准

- **SC-001**：只改数值、只改证据、只改理由、清空或删除资料五类场景保存重读后，实际变化准确落库，所有未修改项保持原样。（FR-001～003）
- **SC-002**：双页不同字段、同字段不同资料项、同一资料项三类交错保存均符合要求：不同项都保留，同项后保存成功者生效；旧页面未修改内容没有写回。（FR-003～005）
- **SC-003**：删除前一个结果点及目标已经删除两类场景中，保存目标不串位，不把请求应用到其他对象或重新创建已删除对象。（FR-006）
- **SC-004**：保存失败、保存后继续编辑、旧响应迟到三类场景均保留最新本地输入，保存状态与实际结果一致。（FR-008）
- **SC-005**：正式交出后的旧标签页、直接保存及迟到自动保存都无法继续写；合法工作稿的允许覆盖不受旧页面版本阻挡。（FR-005、007）
- **SC-006**：无变化保存写请求为 0，普通与自动保存模型请求为 0；当前字段真实变化不借用失效旧结论。（FR-009、010）
- **SC-007**：四类完整宿主及受影响既有回归验证通过，既有布局、触发方式、中文输入、中间数值及只读不退化；执行两项表单契约检查，既有失败单列基线。（FR-011～013）
