# 草稿未归属谱与提取记录删除

关联 [Issue #137](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/137)，FR-017／SC-014／T027。完整用户原话保存在 [Spec](spec.md#原始需求记录2026-10-28-补充)。

## 原行为与提交边界

`bind_to_paper` 会把上传/返修目标下仍存在的谱集合绑定正式论文，包括未归属谱与无曲线提取记录；无有效材料状态时 `material_state_id` 为空。审核者可见这些记录，但公共读取另受论文批准版本和逐谱采纳状态过滤。提交不等于采纳。

## 实施计划与设计理由

用户明确要求删除表示“不保留”，因此采用事务内删除集合及全部运行，不用隐藏卡片或科学审核排除代替。FR-017 → 共用未归属卡片的两类删除按钮和确认弹窗 → 正式 DELETE 接口复用权限与双版本 → 删除两表中的该集合数据 → 提交只绑定仍存在的集合。沿用当前数据所有权，无新增表、迁移、后台清理任务或永久来源黑名单。

删除前保存主表并重新取得目标版本；集合使用用户看到的版本，变化时拒绝。服务只允许 upload/revision 的可编辑未归属集合（包括原状态已删除的孤立集合），拒绝已归属、发现任务、历史归档及本目标仍排队/运行的谱任务。完成后更新共享列表，失败留在确认框显示原因。只读和正式论文页不显示入口。

原 PDF 与哈希共享图像不删除；删除后用户显式重新启动自动提取，仍可能生成新的候选。未删除集合继续随提交绑定，公开仍须独立采纳。本次不自动删除当前上传任务的七条记录。

## HTTP 契约

`DELETE /api/rag/spectra/{collection_id}?target=upload|revision&target_id=...&expected_version=...&expected_collection_version=...`：鉴权后验证目标版本、锁定集合并验证集合版本；返回最新谱列表。集合及全部运行在一个事务中删除。

无权操作返回 403，目标/集合不存在返回 404，版本不符、已经归属、同目标谱任务排队或运行返回 409；不接受 paper 目标。已提交上传由现有 context 阻断。错误不移除前端卡片。删除后详情、历史、图片入口和导出均不可再通过该集合访问。
