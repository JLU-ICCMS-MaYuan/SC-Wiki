## 背景与目标

“先分清问题、提高处理效率”被扩展成独立解析差异分类产品，再用面板是否存在、分类是否正确等检查证明实现完成，漏掉了既有正文简洁要求。此前把面板移到侧栏只改变了位置，未撤销该专用功能链。

目标是精确撤回这项误增功能：现行要求、专用实现、专用验收和当前功能说明一起收敛；原始证据、真正有效的解析修复、科学字段审核与用户数据保持完整。

### 需求结论与变更取舍

1. 沿用用户已认可的行动方案，但按最新明确答复去掉原第4步中对47项旧清单的核查。无需恢复任务、重建列表或寻找替代样本来证明那47项已解决。
2. 撤销的不只是正文面板，还包括仅为独立分类功能存在的侧栏、入口、计算、状态展示和对应工具；不能隐藏后继续执行，或换一个新面板再交付。
3. 保留科学字段原有来源侧栏。解析器之间的差异诊断与字段科学核对不同，但这不构成忽略 #109 页面简化要求的理由。
4. 不整包撤回 #172；只移除已确认偏离的功能分支。保留原始解析账本、声子方法、Tc 配对、出版年份及其他仍有依据的有效修复。
5. 建档阶段只创建 Issue 和 Spec；本次依据用户“开始落实 #180”进入实施，并回写撤销关系。

## 用户场景与验收

### US1：科学表单恢复原有工作方式（P1）

上传者和审核员处理具体科学字段，无需再面对独立的解析差异分类产品。

**优先级理由**：直接消除误增的界面负担。

**独立验收**：上传、返修、管理员及超级管理员完整宿主不再提供撤销的分类面板或入口；原字段标记、问题定位和来源侧栏仍可操作。

1. **假如** 页面存在真实科学待处理字段，**当** 用户进入表单，**那么** 保留真实标记和计数，不铺开独立解析分类清单。
2. **假如** 用户打开字段侧栏，**当** 查看来源、理由或人工记录，**那么** 既有查看、保存、核对与失败恢复保持，不因移除分类功能被删除。

### US2：专用实现退出，原始证据和有效修复保留（P1）

撤销界面时同步退出专用计算和工具，不将隐藏界面误作完整撤回。

**优先级理由**：避免后端继续产生没有实际用户价值的分类结果，以及误删仍需要的能力。

**独立验收**：用隔离输入走实际解析保存路径，不再新增撤销功能的责任分类；原文件、采用文本、备选文本及有效题录处理保持可追溯。

1. **假如** 新任务正常解析，**当** 保存草稿，**那么** 不执行已撤销的专用附加分类，也不重新产生分类待办。
2. **假如** 某脚本同时承担出版年份核验与独立分类，**当** 清理分类依赖，**那么** 年份核验的有效测试和能力保留。

### US3：历史草稿和并行工作安全（P1）

旧数据可能仍含历史诊断，用户人工值和其他任务改动不能成为撤回功能的代价。

**优先级理由**：共享工作区和已有草稿均有独立所有权。

**独立验收**：独立历史夹具含旧 `triage` 时可读取、编辑并保存；不需要原 CaH6 任务，不改真实草稿，不影响 #177 已确认的单字段合同。

1. **假如** 旧草稿携带历史分类字段，**当** 打开或保存，**那么** 不因该字段崩溃、自动重建分类或恢复已撤销入口。
2. **假如** 共享文件同时含 #177 或用户改动，**当** 提交本次清理，**那么** 不整文件回滚，不混入其他任务内容。

### US4：文档与验收不再要求恢复旧功能（P1）

后续维护者能够分清当前要求与历史事实，不再凭旧勾选或旧截图重建面板。

**优先级理由**：消除本次偏离再次出现的文档依据。

**独立验收**：旧设计在现行说明中撤销，历史原话与实施记录仍保留；HTML、规则库及验收入口与实际删除范围一致。

1. **假如** 后续 AI 阅读 #172，**当** 判断是否需要分类面板，**那么** 能明确看到该分支已撤销，不能将过去完成记录当作当前授权。
2. **假如** 运行验收，**当** 评估本次结果，**那么** 检查用户负担及必要能力是否保持，而非要求一个新组件必须出现。

### 边界与异常

- 旧诊断可作为历史保留；不新增数据库迁移、批量清洗或重新分类，也不静默擦除原始来源。
- 真正科学错误、未完成来源核对、权限与版本冲突继续真实显示，不靠清零状态宣称完成。
- 空草稿、无诊断草稿和含历史字段的草稿都须正常工作；只读页面仍可查看原字段来源。
- 当前用户已删除的 CaH6 任务及47项旧清单不作为任何验收前提；不恢复、不重建、不重跑旧 OCR。
- 发现共用能力无法安全分离时，先报告具体依赖与影响，不擅自扩大删除范围。

## 功能需求

- **FR-001**：撤销 #172 当前有效 Spec、Plan、Tasks 中独立分类面板、默认分类展示及缺面板即故障等要求；保留原话和历史实施事实，清楚标记撤销关系。

- **FR-003**：追踪调用关系后移除仅服务该分支的专用分组、快照、责任状态、解析附加分类和重建工具；共用能力先区分用途，不能只隐藏 UI 后继续生成同类待办。
- **FR-004**：保留原 PDF、原始解析、采用及备选文本、真实字段来源、人工值和审核历史；不以删除功能为由清空旧草稿或批量清洗数据。
- **FR-005**：保留声子方法、Tc 配对、出版年份等有效修复，以及科学值、来源、输入错误、权限与版本的原有保护；不整包回滚 #172。
- **FR-006**：旧数据含历史 `triage` 时仍可安全存取，不因此恢复展示或计算；仅作有界历史兼容，不新建永久分类状态系统。
- **FR-007**：不恢复被删除 CaH6 任务，不重建或核查原47项清单，不新建替代分类面板、核查队列或用户排查任务。
- **FR-008**：替换仅证明面板存在的专用验收，采用完整宿主行为证明误增负担已去除、必要功能仍可用；不得通过删除既有有效回归掩盖故障。
- **FR-009**：修改科学表单时执行 #174 两个表单入口及受影响回归，覆盖四类宿主；如实际影响 PDF 字段提取，按 AGENTS.md 重跑受影响字段来源流程，不将撤销展示冒充全篇解析通过。
- **FR-010**：同步受影响 Issue/Spec、Overview、HTML 程序图、字段规则库和测试入口；不删除用户另行要求且仍有效的其他流程图、规则或功能。
- **FR-011**：交付精确删除清单和保留清单；实施中实际发现的遗留或阻塞据实单列，不能重建47项清单充作交付物。
- **FR-012**：与 #177 等并行工作分离，只提交本任务；不修改其他 Issue 的类型、父子关系或无关状态，不推送、部署或代为批准论文。

### 关键实体

- **原始来源账本**：文件、正文、备选文本及定位信息；继续作为可追溯事实保存。
- **撤销的派生诊断**：为了该独立分类产品附加的类别、责任状态及展示；正常流程不再新建，不作为科学审核结果。
- **科学字段与审核记录**：实际值、来源、人工决定及版本；本次撤回不能删除或改造它们的所有权。
