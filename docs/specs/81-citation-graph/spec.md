# 功能规格：基于引用关系的超导论文发展知识图谱

**GitHub Issue**：[ #81](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/81)

**创建日期**：2026-09-02

**状态**：已确认

## 后续规则变更

[#225](../225-citation-matching-and-static-graph/spec.md)替代本规格中禁止模型辅助书目匹配及旧默认布局的条款：程序先确定，LLM2仅核对已有引文与受限候选并持久留据；固定坐标与直线停止模拟。原始引文、论文身份、当前审核版本和公开边边界保持。以下保留历史规格原文。

## 背景与目标

当前“脉络”页面使用 Neo4j 中的人工关系和 `builds_on` 自由文本，无法回答一篇论文实际引用了谁、谁又在后续引用它。该关系既不能稳定计算库内被引次数，也无法在新论文进入 SC-Wiki 后自动补全历史引用。

本 Feature 建立以已审核 SC-Wiki 论文为边界的引用图。读者可以按 Material family 与 Superconductor type 查看发展脉络，识别重要论文，沿上游来源和下游重要分支渐进浏览；管理员可人工标记真正的“源头”和“突破”。

## 用户场景与验收

### 用户故事 1：上传论文后形成可靠的引用候选（P1）

上传者提交 PDF 后，在既有后台解析任务中获得结构化参考文献。解析出的 DOI、题名、作者、年份和原始引文会随论文版本保存，而不是由 LLM 猜测。

**优先级理由**：没有可追溯的引用事实，图谱的上下游和重要性均无可靠来源。

**独立验收**：上传含 DOI 的参考文献 PDF；目标论文已在 SC-Wiki 时形成可查询引用，目标尚未入库时保留未匹配原始引用。

**验收场景**：

1. **假如** PDF 的参考文献可被 GROBID 解析，**当**上传任务完成，**那么**每条参考文献包含原始引文和可用的结构化字段，且可在校对数据中查看。
2. **假如**一条参考文献 DOI 与已审核 SC-Wiki 论文一致，**当**引用论文审核通过，**那么**系统将该记录匹配到该论文 ID。
3. **假如**目标论文尚未收录、GROBID 不可用或某条引文信息不足，**当**任务继续，**那么**不产生伪造边，并记录明确状态供以后重试。

### 用户故事 2：按分类查看发展脉络和重要论文（P1）

读者可选择一个 Material family、一个 Superconductor type 或两者组合，查看对应论文的引用图。圆点大小反映 SC-Wiki 库内去重被引次数，短标题沿用 `knowledge_graph_title`；每篇 SC-Wiki 论文的 `papers.year` 必须有值。

**优先级理由**：这是理解一个超导体系发展历程和识别核心论文的直接界面。

**独立验收**：在含已匹配引用的测试数据中，组合筛选只返回同时匹配当前论文分类的公开论文；节点大小顺序与库内被引次数一致。

**验收场景**：

1. **假如**论文有多个 Material family，**当**选择任一对应家族，**那么**该论文均能进入图谱结果，且不重复为多个节点。
2. **假如**论文的 `superconductor_kind` 为 `unknown`，**当**选择常规或非常规视图，**那么**该论文不出现；标题搜索仍能找到并固定它。
3. **假如**A 被 B、C 两篇已审核论文引用，**当**图谱返回 A，**那么**A 的库内被引次数为 2，且节点大于被引次数更低的节点。

### 用户故事 3：渐进查看来源和分支（P1）

读者点击节点后可分别展开上游被引论文或下游引用论文。默认只显示最重要的五篇，并按需继续加载，避免一篇高被引论文一次撑满浏览器。

**优先级理由**：引用网络会快速分叉，渐进展开同时保留深度探索能力和日常可读性。

**独立验收**：对拥有超过五个下游的论文，首次展开返回五篇和精确剩余数；继续加载不会重复节点或边。

**验收场景**：

1. **假如**C 引用 A 和 B，B 引用 A，**当**读者展开 C 的上游，**那么**图中只有一个 A 节点，并绘制 `C -> A`、`C -> B`、`B -> A` 三条边。
2. **假如**某方向还有未展示关系，**当**读者选择继续加载，**那么**仅请求下一页，界面明确显示剩余数量。
3. **假如**数据存在时间异常或循环，**当**遍历图，**那么**系统按 `paper_id` 去重并停止已访问节点的重复展开，不删除原始引用记录。

### 用户故事 4：人工维护领域里程碑（P2）

管理员和超级管理员可将已审核论文标记为“源头”或“突破”。普通用户只能查看这些标记。

**优先级理由**：引用次数不能替代科研判断；源头与突破必须由人工确认。

**独立验收**：管理员可为同一论文保留两个标记；普通用户的写请求被拒绝，概览和节点详情显示标记。

### 边界与异常场景

- 图只展示双方均为当前已审核版本的 SC-Wiki 论文；未审核、拒绝、升版待审论文不成为公开节点或边端点。
- 引用边固定为 `citing -> cited`。上游查询沿出边， 下游查询沿入边。
- `unknown` 仅表示未归入常规/非常规，不是第三种超导类型；它不影响 Material family 多选和标题搜索。
- GROBID 解析有误或不可用时，上传主任务仍可产生可编辑草稿；引用提取状态必须说明失败，审核不会据此虚构数据。
- 重复参考文献可保留多条原始记录，但图和计数按 `(citing_paper_id, cited_paper_id)` 去重。
- 论文升版时旧版本参考文献不参与公开图；当前版本重新解析、匹配和计数。
- 数据库迁移在把 `papers.year` 设为非空前检查已有记录；存在空年份时不得静默填充猜测值。

## 需求

### 功能需求

- **FR-001**：系统必须以独立本地 GROBID 服务解析 PDF 参考文献，保存每个论文版本的解析状态和结构化参考文献；LLM 不得创建或补全引用边。
- **FR-002**：系统必须保留每条参考文献的原始引文、规范 DOI、题名、规范化题名、作者、年份及匹配状态。
- **FR-003**：系统必须以 DOI 精确匹配优先，并只在题名规范化完全一致且年份不冲突时作保守元数据匹配；多目标候选保持未匹配。
- **FR-004**：当论文审核通过或新论文进入数据库时，系统必须重试关联与该论文匹配的未匹配参考文献。
- **FR-005**：公开图 API 必须只读取当前已审核论文及其当前版本参考文献，并以 `paper_id` 去重节点和以引用论文 ID 去重库内被引次数。
- **FR-005a**：`papers.year` 是论文主表必填出版信息；参考文献记录的 `paper_references.year` 允许为空，因为外部引文可能解析不到年份。
- **FR-006**：图概览必须支持 Material family 多选关系和论文级 `superconductor_kind` 的组合筛选；`unknown` 不匹配 `conventional` 或 `unconventional`。
- **FR-007**：图节点必须返回完整标题、优先短标题、年份、Material family、Superconductor type、库内被引次数和人工里程碑标记。
- **FR-008**：上游与下游展开 API 必须分页；默认页大小为 5，按库内被引次数降序并返回精确剩余数量。
- **FR-009**：标题搜索必须从全部当前已审核论文检索，并允许把当前未展示节点固定到图中。
- **FR-010**：数据库不得用“无环图”约束删除引用；查询层必须按 `paper_id` 去重，并将时间异常和环标记为待管理员核验。
- **FR-011**：管理员和超级管理员可维护 `origin`、`breakthrough` 两类人工里程碑；普通用户没有写权限。
- **FR-012**：旧 Neo4j `builds_on`、`RELATES_TO` 等自由文本和人工关系不得作为本 Feature 的引用事实来源。
- **FR-013**：`papers.year` 必须非空且为有效整数年份；论文提交和管理员批准不得接受缺失年份，数据库迁移必须在已有空值时明确中止并提示补全。

### 关键实体

- **PaperReferenceExtraction**：一篇论文当前版本的 GROBID 引用解析运行和状态。
- **PaperReference**：一条保留原文的参考文献记录；可选地匹配到 SC-Wiki 中被引 Paper。
- **Citation edge**：由 `PaperReference` 在当前公开版本中投影出的去重 `citing -> cited` 关系，不单独接受人工造边。
- **PaperGraphMark**：管理员维护的 `origin` 或 `breakthrough` 标记，归属于 Paper 身份而不是某次内容版本。

## 成功标准

- **SC-001**：含可解析参考文献的上传样本可保存结构化参考文献；GROBID 失败时不产生任何伪引用边且状态可观察。
- **SC-002**：已入库 DOI 引用和后续新入库目标各有自动化测试证明可形成匹配关系；重复原始引文只计一个下游论文。
- **SC-003**：图 API 在分类、公开状态、`unknown`、分页、节点去重和剩余数量场景均返回确定结果。
- **SC-004**：客户端默认展开任一方向至多显示 5 个节点，继续加载保留既有图内容且不重复节点。
- **SC-005**：管理员里程碑维护和普通用户拒绝写入均有权限测试。
- **SC-006**：前端生产构建、Python 关键测试和可用环境中的 Go 测试通过；GROBID 服务可通过 healthcheck。
- **SC-007**：数据库、论文提交和审核接口共同拒绝空年份；引用记录仍可保存没有年份的外部引文。

## 假设与依赖

- 依赖 [GROBID](https://github.com/grobidOrg/grobid) Apache-2.0 服务的 `processFulltextDocument` 输出；服务可用性不是对所有 PDF 解析成功的保证。
- 复用 #70 的 `knowledge_graph_title`，并复用 #79/#80 的论文级分类契约。
- MySQL 是引用事实权威；Neo4j 若继续存在，仅可重建为查询投影。

## 范围外事项

- 外部论文节点、外部引文总数、Crossref/scite 等第三方引文数据。
- 将 LLM 的 `builds_on` 文本、共引或语义相似度自动转换为引用边。
- 自动推断“源头”“突破”。
- 无限自动展开整个图或强制数据库为有向无环图。
- 改变 Material family 必填多选或 Superconductor type 单选 `unknown` 语义。

## 澄清记录

### 2026-09-02

- 问：图谱是否覆盖外部论文？→ 答：否，只显示 SC-Wiki 已审核论文；未入库被引工作保存为未匹配参考文献。
- 问：被引次数来源是什么？→ 答：当前库内、已审核下游论文的去重数量。
- 问：常规/非常规如何分类？→ 答：使用 #80 的论文级单选 `superconductor_kind`；`unknown` 不进入两类视图。
- 问：Material family 如何分类？→ 答：使用 #79 的论文级多选关联，一篇论文可出现在多个材料家族图中。
- 问：是否默认展开所有上下游？→ 答：否，双向默认各 5 篇并显示剩余数，用户按需继续加载。
