# 工具与来源契约：统一固定视觉主模型的看图工具回执与实际图片传递

依据：[Spec](../spec.md)与[数据模型](../data-model.md)；本契约已接入本轮代码，具体注册名与回执版本见下文和validation.md。

## 六类动作的业务契约

| 动作类别 | 输入重点 | 输出重点 | 实际用途 |
| --- | --- | --- | --- |
| 读取上下文 | 授权来源与页/块、原词查询 | 原句、表注、公式定义及位置 | 核对材料、条件、单位和含义 |
| 取得完整对象 | 图/表/公式身份 | 完整区域、图注/表注、实际图片与限制 | 首次读取及回到整体 |
| 调整精读区域 | 父区域、具体问题、目标范围/清晰度 | 新区域、变换、图片和前后关联 | 漏图例、小刻度、邻图混入 |
| 识别文字 | 当前区域、目标刻度/标签 | 文字、位置和真实识别质量 | 刻度或标签存疑 |
| 提取图形数据 | 图型、实际区域和轴/颜色/系列观察 | 柱边、曲线点、标定计算及缺口 | 标量与谱线数字化 |
| 验证结果 | 回执/元素和核验条件 | 几何、刻度、计算、覆盖的通过/失败事实 | 判断原问题是否解决 |

这些是业务动作类别，最终注册名和参数由实现中的封闭目录维护，不能把此表直接变成允许任意动作的自由字符串。未安装/不适用的OCR或像素方法不虚假暴露，提供可用能力和具体错误，由原模型选择其他合法动作。

## 模型/接口交接

结构化结果与实际图片在同一模型上下文中对应。Responses使用其原生工具结果/图片输入部件；Chat Completions使用其支持的user图片块并保持assistant工具调用与tool返回编号配对，不能向不支持的消息位置塞图。官方GPT-6.1 sol工具调用要求Responses；第三方网关逐项实测，不能仅因相同模型名字宣称兼容。

## 失败与用量

来源、权限、页、区域和参数在调用前验证。图片失败/截断保留原始失败，不标已读；暂时上游错误交#224，固定协议错误明确停止。普通保存/输入不调用模型；本轮上传与核对请求使用量沿既有统一统计，不因工具旁路漏计或重复计数。

## 既有字段契约

回执是内部观察协议，其键不是科学表单扩展。字段名/类型/身份由#203/#205程序契约掌管；工具输出不携带批准或人工决定。

## 当前实现接口

定位使用pdf-region-v2，逻辑region_id与物理image_cache_key分开；记录source_sha256、pdf_page、bbox_page、page_size、CropBox、rotation、dpi、renderer及父/跨页关联。image-reading-v1回执不含图片字节，实际PNG独立进入模型images参数。无新科学字段或数据库结构。

六类注册名：read_image_context、read_complete_object、adjust_image_region、recognize_image_text、digitize_image_elements、verify_image_reading。标量提取/验证接受封闭panel协议；谱线用独立report_spectrum_calibration及原谱engine，结构仍用report_structures。文字识别当前只声明原PDF文字层/已登记OCR，不冒称新部署OCR服务。

公开来源接口为GET /api/rag/visual-sources/{paper_id}及/{source_id}/image；历史来源按既有交接权限读取，不能用公开路径访问私有快照。模型图像、来源和实际用量分别留证。
