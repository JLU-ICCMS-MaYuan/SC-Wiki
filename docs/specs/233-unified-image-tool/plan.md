# 实施计划：统一固定视觉主模型的看图工具回执与实际图片传递

Issue：[#233](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/233)；日期：2026-11-10；依据：[spec.md](spec.md)。

## 摘要

沿用SC-Wiki左侧起初选定且支持图片的同一主模型，看图工具统一返回结构化事实、依据和实际图片，接口适配正确传递；不增加第二个视觉模型，不部署Qwen3-VL。 本文件现记录本次实施设计与实际职责；验证结果见validation.md。

## 技术上下文

- 语言：既有Python后端与React/TypeScript前端；精确依赖版本在未来验收运行中记录，不凭旧日志冒充当前运行版本。
- 主要依赖：复用PyMuPDF、Pillow、NumPy及现有解析器/领域算法，FastAPI/SQLAlchemy、Redis/RQ任务及已有存储；不在本轮安装或升级。
- 数据：原件、DocumentIR、共享来源、模型请求检查点和正式交接快照；数据库结构/标准科学契约保持，具体关系见data-model.md。
- 目标：先本机隔离验证，不涉及服务部署或业务数据迁移。
- 规模：正文和SI，完整图/面板与必要原文；无主观图表数量上限，不承诺全版式自动准确。
- 性能：按实际输入记录图片尺寸/传输、缓存/渲染/模型用量；不设未讨论的准确率百分比或以放宽断言换通过。

## 设计决策

### 角色

采用：只有任务起始选定的视觉主模型，读取工具返回和原图后补充观察；工具负责取源、裁剪、OCR/像素和计算。

取舍：撤回文本主模型分支、第二视觉后端和Qwen3-VL前置部署。

### 传输

采用：业务层统一回执和图片清单，适配层按实际Chat Completions/Responses协议装配；工具历史保留编号配对。

取舍：模型名字支持图片不等于网关/协议已实测，不用未知字段猜接口兼容。

### 六类动作

采用：复用read_document/read_page/read_region/extract_table/inspect_figure等并补足图像动作；参数由程序限定，工具只暴露实际能力。

取舍：自然语言说“换方法”却没有实际操作不算反馈成功，也不允许任意shell脚本。

## 阶段与依赖

T001核对原话/现状；US1、US2、US3依次补测试、实现、集成；最后执行共享回归、真实原PDF新模型请求、存储/历史/RAG与权限层验证。不同模型按独立隔离任务测试，各任务内部不换模型。共享文件和数据库边界串行，不并行覆盖别人的修改。

全局依赖见[#232交付框架](../232-complete-pdf-regions/delivery-framework.md)：先定义区域/来源契约，再实现统一图像协议，随后接自动反馈及快照/RAG复用。依赖验收未完成时不只凭复选框进入下游。

## 兼容与回滚

旧来源缺少新定位时保持可用旧文字/原件及明确的未定位状态，不伪造新协议；历史不在普通读取时自动迁移。图像回执/提示/定位版本参与有效性判定，采用结果变化走既有核对失效；缓存可以重建，业务原件/证据/冻结快照不可随回滚删除。

## 必要复杂度

保留来源版本、API适配和动作检查点是为防止历史串位、模型未收到图或重试丢上下文。拒绝另建第二模型选择、第二重试器、永久图片副本和全表重核。内部观察协议不复制科学字段模型。
