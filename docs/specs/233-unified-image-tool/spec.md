## 用户场景与验收

### US1：一个主模型完成看图与反馈（P1）

研究者在左侧选择支持图片的模型后，整个任务不再选择或切换模型。

优先级理由：直接支撑本需求主路径、错误边界或既有生命周期。独立验收：首次图像请求和至少一次反馈均能核对相同模型身份和实际图片。

1. 假如当前任务选择DeepSeek Flash，当查看原图并反馈重读，那么所有请求仍用该任务起始配置，无第二生成模型。
2. 假如选定接口明确不支持图片，当开始图像阶段，那么准确报告不满足要求，不伪造图片已读或改用另一个模型。

### US2：可检查回执与实际图片（P1）

主模型既能读程序事实，也能回到像素核查。

优先级理由：直接支撑本需求主路径、错误边界或既有生命周期。独立验收：回执的元素和坐标能对应本轮实际图片，模型观察可进入程序验证。

1. 假如看图工具返回局部裁图，当下一请求发出，那么结构化事实与实际图片同时进入API，而不是只有文件路径。
2. 假如工具尚不能确定柱对应材料，当主模型看图补充观察，那么观察仍绑定同一来源并经程序验证后使用。

### US3：专用工具和接口兼容（P1）

各业务入口按来源类型使用同一工具协议，保持原有计算和权限。

优先级理由：直接支撑本需求主路径、错误边界或既有生命周期。独立验收：六类动作、API配对和四入口行为各有集成验证。

1. 假如字段仅需正文证据，当核对，那么只读取文字；需要图例时才调用图像工具，不重跑整表。
2. 假如模型服务使用不同API协议，当传递工具结果与图片，那么适配对应字段和调用编号，失败不静默改模型。

### 边界与异常场景

原件/权限/页/区域错误明确拒绝；模型503、固定API错误和科学内容缺失分别处理。保留中文组合输入、并发、只读及失败恢复等#174原契约；普通输入/无变化保存不新增模型或全量扫描。自动读图修复不取消既有人工最终决定/批准权限。

## 需求

### 功能需求

- **FR-001**：任务开始时使用左侧已选的主模型并固定其模型/提供者/端点身份快照；图像理解、反馈、核对和续跑不更换主模型，不新增每步模型选择或多模型投票。
- **FR-002**：本轮只实现支持图片的视觉主模型主路径；不保留纯文本主模型检查分支。不支持图片时明确告知当前选择不满足图像任务，不静默切换模型或假装工具文字等于主模型已看图。
- **FR-003**：使用现有GPT-6.1 sol或DeepSeek Flash接口能力，不要求新增独立视觉后端或Qwen3-VL部署。OCR/像素程序提供辅助事实，图意仍由原主模型读取实际图片后判断。
- **FR-004**：工具返回结构化回执、说明和实际图片；回执包含来源摘要、区域/图像身份、页及坐标变换、对象/元素身份、已取得的刻度/位置/观察、程序读数、读图精度、未读原因及工具/算法/提示版本。尚未取得的信息明确缺失，不要求工具预先“全部看懂”。
- **FR-005**：主模型接到图片后可补充或修订结构化观察，交程序校验、标定和后续填写；解释文字可保留，不能用无位置的自然语言总结替代可复现事实，也不能把工具回执当唯一科学真值。
- **FR-006**：实际图片须以所用API支持的图片内容/有效上传文件引用进入模型请求；本地路径、图片编号或只有文字的工具结果不计作像素输入。重读图片必须与本轮回执来源一致。
- **FR-007**：按接口真实能力适配图片和工具调用协议，保留工具调用编号/结果配对；GPT官方Responses要求和现有第三方网关能力需分别验证，不能把Chat Completions与Responses字段混用或默默绕过严格工具协议。
- **FR-008**：能力检查针对实际模型、端点和协议，记录图片已生成、已发送、模型成功完成读取三个事实；503/超时属技术未知，不能推断模型不支持。基础数字图探针通过不等于科学图表准确率通过。
- **FR-009**：保留首次整图含完整图注及后续局部精读；记录发送宽高和可知的服务端缩放限制，细节不足可通过#234请求更局部图片；不把600 DPI文件等同于模型按原像素查看。
- **FR-010**：共享六类明确动作：读取上下文、取得完整对象、调整精读区域、识别文字、提取图形数据、验证结果。仅暴露当前来源与运行环境实际可用的动作，参数接受封闭定义并核验。
- **FR-011**：图、表、文字、公式保留专用路径；表格先处理表头/行列/单位，公式先处理表达式/定义，必要时调用图像动作。字段核对只按需查图，不重新执行整套提取或全表扫描。
- **FR-012**：标量标定、曲线像素追踪/积分、几何校验与结构展开由程序完成；主模型理解材料、系列、条件和归属。数字标签可转录后校验，程序不强行从坐标重算作者明确标签。
- **FR-013**：工具动作只返回观察与计算候选，不直接改科学字段、原件、历史证据或批准状态；既有正文/表格等合法证据继续有效，主模型不能凭无来源印象补值。
- **FR-014**：复用来源白名单、严格工具参数、目标权限、用量统计和#224检查点；不执行模型任意代码/命令，不允许任意文件路径或公网URL作为文档来源，不暴露密钥。
- **FR-015**：分别以独立隔离任务验证已配置GPT和Flash；各任务始终固定自己的起始主模型，不把分开兼容性测试当运行时多模型互审。

### 关键实体

原PDF及其固定来源、不可变区域、图片传输、工具观察/反馈和科学采用结果职责分开，关系见[data-model.md](data-model.md)。权限由程序保证，主模型不创建业务ID/审批决定。

## 成功标准

- **SC-001**：支持图片的单一主模型在首次、反馈和恢复中身份一致；无新增模型选择步骤、纯文本分支或第二视觉后端。
- **SC-002**：实际接口请求包含图片，模型能回答未在提示和旧结果提供、仅图中可见的信息；图片/回执/原PDF身份一致。
- **SC-003**：六类工具动作可执行且有封闭参数和具体结果，非法/跨来源/不可用动作拒绝且不产生副作用。
- **SC-004**：图、表、文字、公式和四个宿主入口继续使用各自读取及科学契约，字段核对仅在实际需要时查图。
- **SC-005**：生成/发送/成功读取记录和用量准确；失败、截断、仅有路径或工具文字不冒充已读成功。
- **SC-006**：实际GPT与Flash协议兼容分别留证，第三方网关差异明确；尚未实测的接口不声明通过。
