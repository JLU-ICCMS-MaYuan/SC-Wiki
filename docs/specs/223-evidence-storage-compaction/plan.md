# 实施方案

## 所有权与主路径

复用ScientificSourceItem，不建第二来源表。补充shared_context_ref标识整个重复上下文，与已有source_ref片段引用共存。后台expand批量读取并递归还原，不扫描全表；缺失/循环失败。正常compact只对大于等于4096字节的指定旧背景容器共享，不替换字段值、理由或已判定范围。

ScientificEvidenceCheck当前写入已剔除legacy_evidences，不恢复旧字段；仍保留的legacy_source_history按内容共享。正式field_review_commit写来源前共享旧背景；冻结交接在计算原逻辑内容摘要后共享旧背景及嵌套sources。public_snapshot先还原完整冻结内容，不能从当前稿补资料。正式结构模型及活跃返修正文保留其原表示。

已提交产物发布完成后，沿正常read_artifact_path读取仓库稳定身份，验证实际字节和JSON任务/论文版本，再清理本机相同文件；返回原产物清单。清理失败不影响已有成功发布，保留文件并记录原因。上传交接结束时只清空已冻结上传正文并保留周期身份。

## 定向执行与恢复

工具默认只审计，显式给paper_id、预期题名/正文SHA；本轮仅1208。对相关正式来源、上传/返修/正式核对结果、冻结事件及关闭上传正文建立私有JSON备份并校验逻辑展开摘要。迁移在单事务内按固定锁序锁论文/活动稿及待处理行；新引用使用数据库原生JSON_EXTRACT复制，JSON_SET替换为引用，避免科学DOUBLE经文本再解析产生一ULP变化。记录前后精确展开结果，任一差异回滚。

隔离MySQL副本先恢复备份、验证字节/浮点和引用、演练精简及重复执行；再用同一工具及计划指纹在本机运行。共享资料仅新增，不删除旧独有证据/历史/谱数据；备份保留到用户决定处理。当前文献原页、字段核对、快照、文件下载、正式详情和返修API前后逻辑响应对比。
