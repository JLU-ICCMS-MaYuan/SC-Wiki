# 实施计划：以可定位证据驱动同一主模型自动重读和修复

Issue：[#234](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/234)；日期：2026-11-10；依据：[spec.md](spec.md)。

## 摘要

同一视觉主模型按具体问题选择工具动作，以原图、新证据和程序检查验证修复；自动补读和重算，完整保留成功步骤、反馈历史和来源，不以人工接管作为读图疑点默认出口。 本文件现记录本次实施设计与实际职责；验证结果见validation.md。

## 技术上下文

结构首次report_structures完整发现后，宿主以稳定reading_id保留每项原始报告和正式校验结果。后续仅暴露repair_structures，允许修改失败项；成功项不在修订枚举中，不重发、不重校验。未更新的失败项仍保留原疑点，不因遗漏消失。同条件不同来源仍有独立身份。记录updated_reading_ids与reused_reading_ids，复用不计为新提取。局部回执不能修改成功项、创建未知身份或重复覆盖同项；新内容继续走原来源和科学校验。文件级未读范围单独保留。13次动作预算、无进展保护和传输失败规则保持。该方案按2026-11-11用户澄清替代此前要求反复提交完整报告的实现选择。

- 语言：既有Python后端与React/TypeScript前端；精确依赖版本在未来验收运行中记录，不凭旧日志冒充当前运行版本。
- 主要依赖：复用PyMuPDF、Pillow、NumPy及现有解析器/领域算法，FastAPI/SQLAlchemy、Redis/RQ任务及已有存储；不在本轮安装或升级。
- 数据：原件、DocumentIR、共享来源、模型请求检查点和正式交接快照；数据库结构/标准科学契约保持，具体关系见data-model.md。
- 目标：先本机隔离验证，不涉及服务部署或业务数据迁移。
- 规模：正文和SI，完整图/面板与必要原文；无主观图表数量上限，不承诺全版式自动准确。
- 性能：按实际输入记录图片尺寸/传输、缓存/渲染/模型用量；不设未讨论的准确率百分比或以放宽断言换通过。

## 设计决策

### 反馈对象

采用：以来源/回执/元素和原问题绑定动作及核验条件，记录新事实与修订版本。

取舍：“你算错了”不足以执行；覆盖旧回执会破坏来源恢复。

### 进展

采用：复用已有总动作预算；相同动作身份和观察摘要判断无新证据，服务故障交运行器。

取舍：不新增无限循环、不规定统一两轮、不把五次技术失败预算当图像科学重读轮数。

### 验证

采用：程序的几何/数值/覆盖与原模型实际像素/上下文检查共同判断；正文本身仍是来源。

取舍：不采用必须换检查模型、自检接近零、置信度准确率或回执唯一真值等绝对说法。

全局依赖见[#232交付框架](../232-complete-pdf-regions/delivery-framework.md)：先定义区域/来源契约，再实现统一图像协议，随后接自动反馈及快照/RAG复用。依赖验收未完成时不只凭复选框进入下游。

## 兼容与回滚

旧来源缺少新定位时保持可用旧文字/原件及明确的未定位状态，不伪造新协议；历史不在普通读取时自动迁移。图像回执/提示/定位版本参与有效性判定，采用结果变化走既有核对失效；缓存可以重建，业务原件/证据/冻结快照不可随回滚删除。

## 必要复杂度

保留来源版本、API适配和动作检查点是为防止历史串位、模型未收到图或重试丢上下文。拒绝另建第二模型选择、第二重试器、永久图片副本和全表重核。内部观察协议不复制科学字段模型。
