# 退役材料关系字段与旧材料图谱边

**GitHub Issue**：[ #127](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/127)

## 背景与目标

论文级 `material_relations` 把同一材料的不同角色显示为重复条目，也没有进入当前 MySQL 论文引用图。退役独立材料关系数据、界面和旧 Neo4j `STUDIES` 边；保留材料状态、研究材料汇总、其他旧论文关系、Mentor 工具及公开引用图。

## 用户故事与验收

### US1：校对论文无需维护材料关系（P1）

上传者、审核员和读者在校对、审核及详情中只看研究材料和材料状态，不再看到材料关系表单、来源核对项或第二套侧栏控件。旧草稿与返修草稿也不会使字段重现。

### US2：运行数据不再保留旧关系（P1）

维护者在隔离环境验证清理后，从当前运行库、有效草稿、解析产物、证据/审核快照和已发布检索内容中移除材料关系。只移除相关字段或记录，保留其他科学内容与历史。

### US3：旧图谱不再表达材料研究边（P1）

Neo4j 不再生成或暴露 `STUDIES`，已有边和论文节点的 `material_relations` 属性被清除。其他旧论文关系及 Mentor 工具仍可用；公开引用图继续使用 MySQL `paper_references`。

## 功能需求

- **FR-001**：新解析、草稿、提交、返修、审核与详情不得生成、接收、保存或显示 `material_relations`；旧客户端显式提交该字段时返回可识别的客户端错误。
- **FR-002**：移除该字段的语言校验、AI 建议、来源核对、审核历史新写入及前端文案；研究材料和材料状态行为保持。
- **FR-003**：对当前运行数据定向清理 `papers` 专列、上传/返修草稿、Redis 草稿、解析文件、科学核对与正式来源及审核快照；不删除同条记录中的其他内容。旧缓存不得重新引入该字段。
- **FR-004**：移除旧 Neo4j 两处 `STUDIES` 生成和材料边查询，清除现存 `STUDIES` 边与论文节点旧属性；保留其他节点、边及 Mentor 论文工具。
- **FR-005**：保留 MySQL 引用图的接口、筛选、节点和边，不把材料关系转换为引用事实。
- **FR-006**：#23 中保存材料关系及 #103 中关系编辑的现行要求废止；#109/#120 的待验收要求不再依赖该字段。历史验收记录保持可追溯。

## 成功标准

- **SC-001**：三种页面入口、旧草稿和返修均无材料关系；旧请求不能重新写入。
- **SC-002**：隔离迁移与实际运行数据清理后，目标字段、JSON 路径、缓存产物及独立证据记录的残留数均为零；其他字段和历史事件仍可读。
- **SC-003**：Neo4j `STUDIES` 边和论文旧属性均为零；其他论文关系和 Mentor 工具正常。
- **SC-004**：MySQL 公开引用图及相关上传、审核、返修、检索回归通过。

## 边界与澄清

- 用户确认全部清除**当前运行数据**中的该字段，含审核与核对历史中的专属内容；既有整库备份和冻结包沿原保留周期处理。
- 用户确认仅退役材料路径，保留 Neo4j 的无关论文关系和 Mentor 图谱工具。
- 不删除论文 PDF、材料状态、研究材料汇总或引用记录；降级迁移只能恢复空字段结构，不能恢复已删除的关系值。
- 不自动切换分支、推送或修改生产外部实例；执行前须先验证目标实例和隔离清理结果。
