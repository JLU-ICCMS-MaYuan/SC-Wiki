# 技术决策

## R1：保留独立的引用图与旧论文关系

**决策**：仅移除材料 `STUDIES`；保留 Neo4j 其他论文关系及 Mentor，公开 `/knowledge` 继续读 MySQL 引用记录。

**理由**：`material_relations` 只为旧 `STUDIES` 提供角色值，公开引用图不读取它；Mentor 仍有其他 Neo4j 论文工具。

## R2：拒绝旧字段并使旧缓存失效

**决策**：新请求显式传入 `material_relations` 时拒绝，而内部读取历史草稿时定向剔除；分段缓存版本升级。

**理由**：旧客户端、持久草稿或已缓存分段不得重新写入退役数据。

## R3：不可恢复的定向清理

**决策**：只清当前运行数据，清理前在隔离环境核对影响行数；正式列删除后降级只能创建空列。既有整库备份保留。

**理由**：用户明确不要业务历史关系，但其他科学与审核事实必须留存。
