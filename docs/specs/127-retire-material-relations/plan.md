# 实施计划

**输入**：[规格](spec.md)、[技术决策](research.md)、[数据清理](data-model.md)、[任务](tasks.md)。

## 顺序

1. 收敛 Python、Go、前端及提取契约，旧客户端显式字段请求拒绝；升级分段缓存契约，避免旧结果复用。
2. 在隔离数据库及模拟 Redis/解析产物中演练定向清理；核对清理前后非目标字段与记录数。
3. 对确认的当前运行实例暂停相关写入，先更新应用与 Worker，再执行 MySQL 清理/删列、Redis/文件清理、Neo4j 边清理及检索重新发布；最后恢复写入。
4. 验证上传、审核、返修、详情、Mentor 其他论文关系及公开引用图；更新 Overview 和 Issue 状态。

## 关键约束

- 不修改旧的 Alembic 迁移；新增迁移清理旧 JSON 路径并删除专列。降级只重建空列。
- 对证据/审核 JSON 只移除对应字段或独立记录，不删除包含其他字段的历史事件。
- 运行清理程序必须先输出目标实例和待清理数量；无法确认目标或完整覆盖时停止写入。
- 既有备份不追删；本次运行数据清理后生成的新备份不含旧字段。
