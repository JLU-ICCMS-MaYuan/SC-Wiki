# 二维拖动与补点回折验收

## 诊断依据

只读核对来源 http://127.0.0.1:5187 的指定 Demo 草稿，399点、43次操作；副本为 [已保存草稿](assets/user-saved-alpha-xy.json)，哈希、来源及前后不变验证见 [诊断记录](assets/free-drag-diagnosis.json)。浏览器测试使用独立上下文，不写用户原浏览器。

旧默认 amplitude 模式锁住频率轴；旧 free 模式也用相邻频率间距限制整个位移。密集点可能因此几乎无法纵移。

用户日志中先点击 (685.13,302.24)，后点击 (687.80,302.30)。旧频率排序把右侧新点排到旧端点前，造成折回。该局部坐标真实点击回归通过。最终399点快照含后续删改，未把历史截图冒充当前完整快照。

## 当前实现与通过项

- 默认 X/Y 自由拖动，图框限位保留，不再用相邻频率夹住点；幅值锁定仍可选。
- 描线顺序与频率表排序分开。点击时一次线性扫描现有边、相邻断口和开放端点；新点保留点击坐标，在局部插入或外延，修改目标边而不重排全谱。
- 旧草稿保持坐标及现有连线，不自动修改存储。“重新连接人工补点”固定两遍局部相邻交换，只处理人工点参与、频率像素间隔不超过0.5且局部线长减少的点对；不进行全局重建，不移动点，不跨断口，可撤销。未发现可修正回折时有明确提示。
- 28项 Vitest逻辑测试通过；34个真实Chrome场景通过；TypeScript与Vite构建通过。包含源日志坐标、二维越过邻点、重复频率描线、原稿恢复、局部修正、撤销重做、保存刷新、窄屏与原有边界。
- 实际源浏览器保存键在测试前后 SHA-256 相同，399点保留；测试副本中各点坐标映射在重新连接和保存恢复后逐点相等。

## 性能及边界

10000点复用准备结果移动120次；仅35点受联动位移影响。准备 0.800 ms，移动加路径生成中位 0.400 ms、95分位 0.500 ms（不含React渲染）。点击邻接搜索及显式局部修正均为 O(n)，不使用全点对搜索、拟合或逐帧重新排序。

描线草稿允许重复或回退频率，尚不能作为已采纳单值谱积分。界面仍不开放 λ/ωlog 或3N科学验收，不做数据库写入或生产部署。
