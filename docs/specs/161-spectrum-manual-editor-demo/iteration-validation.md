# 补点连线与局部微调验收

本轮对应 FR-014 至 FR-016 / SC-008 至 SC-010，替代旧频率半径与孤立补点规则。

- 23 项 Vitest 逻辑测试、TypeScript/Vite 构建通过。
- 30 个真实 Chrome 浏览器场景通过，证据见 [本轮记录](assets/iteration-browser-validation.json)。原 25 场景回归通过，新增邻点衰减、补点连线、旧草稿恢复、连线持久化与核心计算测试。
- 人工补点内部插入/端点延长会连接相邻点，不增加额外数值点；删除重新断开，补点/删除可撤销。其他曲线不变。
- 旧草稿用稳定 ID 识别人工补点，包括 status 已成为“人工调整”的点；坐标及读取时的 localStorage 字节不变。保存后重开仍连接。
- 两侧各5点核心区，第6点起指数衰减，第18点起不动。浏览器实拖验证两侧第1、5、6、10、17、18点；单元测试覆盖不均匀采样与不跨断口。
- 无业务 API 请求、无下载、无页面脚本错误。保存仍只在本机 Demo；不涉及数据库和部署。

## 性能证据

10000 个点，准备一次后复用 120 次，实际受影响点为35个。准备 0.500 毫秒，移动加 SVG 路径生成中位数 0.300 毫秒、95分位 0.600 毫秒。本机 Chrome 测量，**不含 React 绘制与整体帧率**，不作为跨设备性能承诺。

排序按点数组/标定缓存，移动限位保证次序后复用有序数组；拖动中复用权重，路径每条只生成一次、白底线和彩线共用。无全点对搜索、拟合或逐帧指数计算。
