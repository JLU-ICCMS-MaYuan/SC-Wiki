## 背景与目标

当前表单保留了 Tc，但未完整填写同一结果的耦合参数和计算条件。目标是让系统联合读取表格、表题／脚注、正文和 Methods，完整提取科学数值，并依据原文语义把共用条件关联到适用结果。

代码调查发现：旧分段提示词限制 Tc 对应的 μ*、方法来自“同一句或同一表格”；领域提取提示词允许多页证据，但同时禁止从一条记录复制条件到另一条。它们可能阻碍共用条件的正确关联，不能仅据此断言已定位本次所有遗漏的根因。领域提示词还同时出现 `omega_log_k` 与 `parameters.omega_log` 写法，后续须核对实际契约和转换，避免字段丢失。

### 需求结论与变更取舍

- 合并为一个 Feature，分别验收表格／表注提取和 Methods 共用条件关联，并贯通核对、填写和保存。
- “原文有依据的共用”允许跨记录关联；仅凭材料相同、压力相近或领域惯例不能推断共用。
- 科学数值必须来自材料；模型负责解释其归属和范围，关联依据不冒充作者逐条声明。
- 同一材料、相和压力下的谐／非谐结果保持可区分，不要求强行拆成不同材料状态。
- 用户确认 Spec／规划后，又明确要求“开始落地实施”。本轮按既定范围实施，未获得推送、部署或业务库迁移授权。

## 用户场景与验收

### 用户故事 1（US1）：完整填写表格中的超导参数（优先级：P1）

上传论文后，用户能看到每一条 Tc 对应的 λ、ωlog 和 μ*，无需手动把表格及表注重新抄入表单。

**优先级理由**：直接解决用户截图中数值缺失的问题。

**独立验收**：对照原 PDF 的 Table 1，逐行核对全部 8 行结果及其参数，记录每项来源。

**验收场景**：

1. **假如**参数位于表格、μ* 和方法位于表题或脚注，**当**完成解析，**那么**这些信息能联合进入同一条结果，并保留各自出处。
2. **假如**150 GPa 非谐行报告 λ=3.94、ωlog=745 K、Tc=281–311 K，表注给出 μ*=0.16→0.1，**当**填写表单，**那么**正确显示全部参数及 281 K↔0.16、311 K↔0.1 的对应关系。
3. **假如**300 GPa 同时存在谐与非谐结果，**当**组装记录，**那么**两组数值分别保留，不相互覆盖或拼接。

### 用户故事 2（US2）：理解和填写 Methods 的共用计算条件（优先级：P1）

用户能获得论文中适用于多条结果的共用计算条件，即使作者没有在每个压力结果旁重复说明。

**优先级理由**：解决计算条件成片空缺，并防止按论文级软件名误填。

**独立验收**：检查同方法的多个压力结果使用正确共用条件，并通过计算阶段不同和局部例外的反例核验。

**验收场景**：

1. **假如**Methods 明确给出本文相应计算的共同参数，**当**模型结合材料、方法、阶段和上下文判断适用范围，**那么**适用结果都能填写该参数，并给出共同来源及简短关联说明。
2. **假如**结构优化使用 VASP，电声耦合使用 QE/DFPT，非谐修正使用 SSCHA，**当**填写计算条件，**那么**参数保留各自阶段，不能把 VASP 的截断能与 QE 的网格拼成一个未经说明的计算设置。
3. **假如**某压力、物相或计算步骤另有明确参数，**当**与共用条件合并，**那么**相应局部明确条件优先；不能消解的冲突保留待核对原因。

### 用户故事 3（US3）：核对并保存关联结果（优先级：P1）

用户能查看数值和条件的证据及关联说明，保存重开后仍得到相同内容。

**优先级理由**：保证前述提取结果实际进入现有表单与持久化流程。

**独立验收**：从真实解析结果完成核对、填写、保存与重开，逐项比较值、归属、单位和证据。

**验收场景**：

1. **假如**一项参数由表行和 Methods 联合支持，**当**来源核对，**那么**系统联合判断这些证据，不因结果行未重复条件而直接判缺失。
2. **假如**已填写含共用条件的记录，**当**保存并重新打开草稿，**那么**参数、单位、对应关系和证据保持一致。

### 边界与异常场景

- 表题／表注与表行跨页、跨段时仍能联合读取；文本受损或不可读时保留原因，不伪造数值或来源。
- 只给 μ* 范围但未明确 Tc 对应关系时，保留范围及不确定性，不依据大小排序或物理常识擅配端点。
- 不同压力、近似、方法、物相及本文／引用工作的结果不能串用；压力未报告时不假设常压。
- 单位写法、千位分隔及符号需正确识别；转换保留原始值、单位和依据，单位无法确定时不作无依据换算。
- 多阶段各自存在 k/q 网格或截断能时保留阶段归属；无法明确写入现有字段的内容不能静默丢弃或写入错误字段。
- 仅有共同材料身份不足以支持共用条件。无依据、冲突或失败时显示待核对原因；未报告的展宽保持空值。
- 失败、重试和保存重开不得静默覆盖已有人工更正或生成重复科学结果；沿用现有权限、任务与草稿约束。

## 需求

### 功能需求

- **FR-001**：系统必须联合阅读表头、单位、分组、全部结果行、表题和脚注，提取 λ、ωlog、Tc、μ* 及对应方法。
- **FR-002**：系统必须按材料、相、压力、近似和方法关联这些参数，保留同压力下不同近似的独立结果，不能只保留最高 Tc。
- **FR-003**：系统必须保留 Tc 与 μ* 的明确对应关系；无法确认对应关系时保留原始范围和待核对原因，不擅配端点。
- **FR-004**：系统必须使参数在提取、归一化、组装及表单之间保持语义与单位一致，保留原文写法和有依据的单位转换。
- **FR-005**：系统必须结合全文理解 Methods 中共用条件的适用材料、阶段、方法和压力范围，允许原文支持的条件关联到多个结果。
- **FR-006**：系统必须区分结构优化、电子结构、声子／电声耦合及非谐修正等计算阶段，避免跨阶段混用软件、方法、泛函、截断能和网格。
- **FR-007**：系统必须优先采用范围明确的局部条件；共用关系不明、存在例外或冲突时保留待核对原因，不能无条件向所有状态广播参数。
- **FR-008**：系统必须保存数值及适用范围的可定位原文，区分作者直接报告的参数和模型基于原文判断的关联，并提供简短依据说明。
- **FR-009**：来源核对必须允许联合表格、表注、正文及 Methods 证据判断，不因单条结果附近未重复条件而直接否定有依据的关联。
- **FR-010**：系统必须覆盖现有实际提取入口、代码和提示词流程，保证填写及保存重开后参数、条件、归属与证据不丢失。
- **FR-011**：系统必须将未报告或无法可靠读取的参数保持为空，并说明缺失或待核对原因；不得引入领域惯例值或编造展宽。

### 关键实体

- **结果记录**：特定材料、物相、压力、近似及方法下的 Tc 结果，以及关联的 λ、ωlog 和 μ*；范围及端点对应属于记录语义。
- **计算条件及适用范围**：原文报告的计算设置，包含其所属计算阶段、明确范围、局部例外及可关联结果；一个共同条件可关联多个结果。
- **证据与关联说明**：支持数值和适用范围的原文定位，以及模型对结果归属所作的简短解释；解释本身不是作者原文。
