## 需求与成功标准

### 讨论中的原始选择记录

以下为逐项讨论时的原始选择文字；泛函的早期选择由后续明确撤销要求替代，不作为当前许可。

- 计算软件共用：`允许按此规则通过 (Recommended)`。
- 生效角色：`上传者和管理员都免逐项确认 (Recommended)`。
- k 网格：`认可按阶段共用 (Recommended)`。
- q 网格：`区分用途后自动通过 (Recommended)`。
- DFPT 到 DFT 方法定义：`允许有依据的方法推导 (Recommended)`。
- 截断能：`允许分用途共用 (Recommended)`。
- 早期 QE-PBE 选择（已撤销）：`满足条件就自动通过 (Recommended)`。
- 清空问题的澄清原话：`仍找不到这两处 QE=PBE 的明确依据？这是什么意思？？？`。
- 未报告的计算条件：`未报告的计算条件统一免审 (Recommended)`。
- SSCHA：`按明确的 SSCHA 范围通过 (Recommended)`。

- FR-023：仅对白名单计算条件按材料、物相、软件、阶段和参数用途核对；共用关系允许压力不同，但不越过局部例外。
- FR-024：核对结果和来源类别分开。规则通过可使用 supported，仍可为 paper_inference；不能生成 human_confirmed 或省略最终批准。
- FR-025：泛函必须有对应软件的报告依据，关闭专用和通用 QE 泛函推测；允许有 DFPT 依据的 DFT 方法推导。
- FR-026：未报告的可选条件保持空白免审，来源缺失、失败和未读窗口不产生“已查无”的结论。
- FR-027：仅清空指定草稿两处 QE=PBE，保留所有历史和 VASP 设置，再核查 145 项；保留图谱标题问题。
- SC-012：正反例覆盖跨软件／阶段／相、例外、网格用途、数值单位和不完整来源。
- SC-013：四种入口使用相同规则，保存重读、规则升级和并发修改不继承无效通过。
- SC-014：真实草稿两处清空及其余值不变，核查结果逐项留证，前端本次零修改。

## 技术方案和契约

新增后台共享规则模块，使用现有字段断言、完整来源分窗和核对持久化；不增加表、公共路由或前端组件。白名单以参数语义区分采样／插值 q 网格、波函数／电荷截断能、能量／力阈值等，未知参数不自动通过。

模型返回逐字段的语义判断，包括值的来源方式、材料／相／软件／阶段、参数用途、适用范围及可定位证据。服务端检查这些身份与当前字段一致，检查数值及方法定义依据，并由服务端记录实际完成的来源窗口。只有所有有效正文／SI 文件可读、全部窗口成功核查且无冲突或不确定范围时，聚合成 rule_review。模型自报“已读全文”不构成完成资格。

rule_review 保存规则版本、字段内容／来源 hash、软件和阶段、原文证据及解释，沿用现有核对 JSON。读取时重新验证规则版本、字段和来源，不信任旧缓存中的 supported。前端已有 supported 和空值 required=false 语义继续使用；AI 理由明确按规则通过，不把推断冒充作者直接记载。泛函额外检查引用中的软件归属，VASP-PBE 与 QE 软件分别出现在原文不能组合成 QE-PBE。

新提取和补空继续保护已有值；通用建议不能为计算条件引入无证据推测。关闭旧专用 PBE 推断生产入口，历史元数据可读但不再作为有效规则。提取及规则缓存版本升级，防止旧结果回填。新上传在最终条件补空后，对受影响字段运行同一规则核对；已完成字段不重复处理。

### 真实核查中收敛的执行边界

- 服务端可补入当前原文同句／同表行中明确的材料和物相身份锚点，排除否定、对比和 respectively 等容易错配的句子。不能从全文两个孤立词拼接归属；原始文本保留并重新定位。
- 缺少近似身份的历史 SSCHA 记录，须用当前压力、Tc、λ、ωlog 在明确非谐分组内匹配；谐波分组中的数值不能借来授信。补入的是已有原始块，不改科学值或编造表行。
- 分窗编号只在当前窗口解析；确定性身份锚点和原表匹配可以使用完整目录，但仍须等所有来源窗口成功核查且无冲突后才能生成通过结果。
- 模型明确声称支持却遗漏必要引句或结构字段时，只给一次带具体校验反馈的补证机会；真实冲突／不确定结论不反复重试。保留原始响应和补证响应，取消即时传播。
- 同版本的并发 AI 核对按服务端请求时间排序；迟到的较早请求不能覆盖较新结果。较新的真实冲突仍可撤回旧通过，不采用“支持永远优先”。旧记录没有开始时间时使用已有完成事件作保守边界，不伪造历史开始时间。
- 实际后台任务约 59 MiB，旧流式回调每个片段读取完整快照造成超时。现有任务另保存极小的 Redis 状态投影，完整任务和投影原子更新；轮询及流式取消只读投影，流式检查最多每秒一次，权限和取消终态不变。含计算条件的批次最多 12 项，其他批次沿用原设置。
- 前端代码仍不修改。原“推断关联待人工核对”的固定提示文字是旧前端文案，实际是否需要确认由当前核对状态决定；新 AI 理由说明规则通过，不伪造人工确认。

## 边界

规则通过不表示人工批准。来源无法证明适用范围、存在真实冲突或解析缺口时保留问题；不改其他科学值，不自动清理其他历史论文。实现验收后再回写 Overview；旧 US5 的历史不删除。完整论文、备份和模型原始响应只留在本地数据目录。

实际实现、200 项回归、7 项 MySQL 验证、正式队列和指定草稿处理结果见[验收记录](condition-auto-review-validation.md)。


## 后续规则修订：条件事实与结果归属分离

用户在[#144](../144-review-save-lifecycle/spec.md)明确认可：Tc／μ*数值变化不连带撤销未变共用条件。当前condition-rules-v2将原表非谐结果匹配放在结果归属核对，SSCHA条件仍要求原文声明软件、阶段、材料／物相与非谐流程。本文此前以当前Tc数值作为SSCHA条件通过前置的描述保留为历史，当前行为以#144及上传Overview为准；不是无条件恢复旧关联。
