## 技术方案与数据所有权

现有字段断言已按字段版本核对，但 payload 来源关联仍使用整条科学记录指纹，是此次原设计缺陷。科学值继续唯一存于原草稿／PropertyRecord；不新增表、公共接口或页面。

1. 新生成关联增加可选字段绑定，复用字段上下文并保存稳定扩展身份；保留旧整条指纹用于历史及旧格式保守读取。字段绑定必须检查状态与阶段，未知版本不授信。
2. 旧关联失效后不直接迁移。现有 AI 核对输入显式提供关联、计算阶段及适用范围，要求返回逐关联事实证据、范围证据和判断。模型只给语义候选，当前内容及来源绑定由服务端计算。
3. 新关联核对结果保存于现有 ScientificEvidenceCheck.result，作为与当前字段内容／来源绑定的复核版本；payload 原始关联继续保留。读取时先验证复核版本，再输出既有 source_associations 展示结构。新版本不匹配时回到原始关联的保守判定，历史不能为新值背书。
4. 分批核对聚合不能丢失新关联，存在明确范围冲突时不能采用其他窗口的通过结论。沿用既有全文分窗、证据定位、PDF 来源、保存锁及审计事件；不新增独立来源库。
5. 上传写回前比较当前版本，过期即拒绝，不保存迟到的核对结果。正式来源转存应保留新核对的证据映射；无法验证时明确失效。

## 核对结果契约

- `field_binding`：可选 JSON，包含 `version=1`、稳定扩展 `field_key` 和字段依赖 `fingerprint`；缺少稳定扩展键时不猜位置继承。整条旧指纹仍保留。
- `association_reviews`：模型返回的逐关联候选，位于每个 `results[i]` 内；包含服务端 `association_id`、适用／冲突／不确定判断、依据类别、简短解释和事实／范围证据。模型不生成内容版本或人工通过标志。
- `association_review`：服务端验证后的当前核对 JSON，含规则版本、当前内容／来源 hash、输入关联身份、新关联及原关联历史。只存于既有核对结果，不创造第二份科学数值。
- `review-source-N`：本次完整来源窗口中的段落编号，服务端展开原始文本；模型附带的转述不作为引句保存。旧解析器编号不进入此命名空间。仅提供引句的候选继续严格定位，不接受编造或改写。
- 分批输出的明确冲突阻止采用其他窗口的有效关联；模型遗漏关联、引用不完整或无法定位时，保留旧关联失效状态。论文推断即使重核合理仍待人工判断。
