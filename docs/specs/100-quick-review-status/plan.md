## 职责与事实来源

沿用 React/TypeScript 编辑器、Go 审核 API 和 Python 科学保存事务，不增加表或独立分类写接口。共享 `paperReview.ts` 负责三状态、读取、分类解析和批准载荷。

- 超导体类别、材料维度始终来自当前正式详情。
- 仅 `pending` 且正式论文级家族为空时，使用同版本提交快照回填家族候选；结构家族回填合并未落库候选，保留已有正式关联，按稳定 `state_key` 匹配；历史缺少 key 时只允许唯一化学式匹配，不按数组位置拼接。
- 管理员保存必须包含非空材料家族；解析或创建材料/结构目录项，然后在科学保存同一事务内保存关联。保存成功后正式论文级家族非空，即退出首次回填。结构家族清空后不再读回快照。无需以空数组猜测“尚未保存”与“已清空”两个合法成功状态，因为论文级空列表不是合法保存结果。
- 普通上传、上传者返修继续只解析既有目录，不创建新项。
- 快速批准遇首次回填时，复用现有科学保存和编辑转换，仅保存科学段，重新读取正式详情，再执行现有核对及批准。拒绝/退回不依赖分类读取和保存。无快照 404 使用正式数据，其他读取错误直接中止。
- 同值判断纳入论文级类型、材料家族与结构家族。创建目录使用既有名称规范化、别名解析、唯一约束和创建者字段；并发相同名称复用目录项，失败不留半份关联。

## 实施顺序与边界

用户已确认新家族创建时机，先更新设计，再补失败回归，完成持久化及共享读取，执行前后端与跨层回归、构建，最后回写 Overview、提交和关闭检查。不修改既有论文、不批量修复历史数据、不放宽 Evidence 或自审校验、不发布测试论文到真实索引。

已有共享工作树包含 #110 科学图保留改动；本 Issue 只新增分类相关逻辑，提交时按实际补丁隔离，独立提交副本验证。
