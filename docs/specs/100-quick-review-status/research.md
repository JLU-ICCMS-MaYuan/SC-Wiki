# 研究与决策

## 根因

#79 移除快速审核批准选项，原请求也缺少批准分类。初次修复恢复三状态，但后续 #103 要求批准分类与已保存数据一致，旧上传快照仍会覆盖同版本新值并触发 `evidence_stale`。

真实保存回归还发现：科学保存的同值比较遗漏论文级类型/家族，且没有写入 `PaperMaterialFamily`；新结构家族没有目录 ID 时也不落库。因此仅删除快照回填会丢掉首次送审的家族。

## 2026-09-18 已确认决策

用户明确允许管理员保存时创建新材料/结构家族，普通上传者不变。用同一科学保存事务完成目录解析/创建、论文关联、结构关联和版本更新；目录唯一冲突以嵌套事务处理并重新读取，整个保存失败时创建项一起回滚。

沿用 #79 家族非空保存规则：首次待审正式论文家族为空时可回填提交快照；保存后正式家族必定非空，不再读取旧分类。结构家族可清空，重开依然为空；论文家族全清空保存失败，旧落库值不变。这比新增持久状态标记更简单，也没有在读取请求里写库。

类型/维度始终以当前详情为准；结构首次回填按状态 key（历史仅唯一化学式）匹配，避免状态重排造成串值。快速批准先完成首次分类的科学保存，重读正式 ID，再执行严格证据核对。既有论文只通过用户触发的保存进入新路径，不进行批量迁移。

## 备选方案

继续仅批准时创建目录会要求额外的持久候选和证据契约；用户选择前移至保存，本次不引入该额外模型。无条件使用旧快照无法保留新值；无条件禁用快照会丢失首次送审候选，两者均不采用。现有权限、来源核对、自审限制、版本和历史规则继续有效。
