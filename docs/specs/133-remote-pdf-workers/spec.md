# Feature 规格：跨机器 PDF 解析与故障恢复

**GitHub Issue**：[ #133](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/133)

**父 Epic**：[ #130](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/130)

**日期**：2026-10-12

**状态**：规划已确认；未实施、未完成跨机器验收

## 背景与目标

现有 Redis/RQ 已将解析与网站请求分开，但 Worker 读取应用本地路径，结果与草稿写入也缺少跨节点执行身份。本功能使计算组可以从网站机器迁到第三台机器，并在重试、节点中断和外部存储故障下保持数据一致。

## 用户场景与验收

### US1：用户照常上传、核对与审核（P1）

上传入口保留在网站，后台解析与证据核对运行在独立计算机器。用户继续使用现有任务列表、校对、提交与审核页面。

**独立验收**：计算节点不挂载应用业务目录，真实 PDF 主文/附件经过解析、证据核对、提交、审核后可读取全部必要文件。

1. 假如 API 已保存原文件，当远程 Worker 消费任务时，那么从稳定引用获取相同内容并处理。
2. 假如必需产物未全部持久化，当计算函数返回时，那么不得把任务公开为成功或可校对。
3. 假如网站需要按需展示证据区域，那么可取得原 PDF 并渲染，不依赖计算节点临时目录。

### US2：失败与重试不破坏已确认结果（P1）

用户能看到明确失败原因并重新发起任务；管理员能诊断节点退出和存储故障，不出现重复正式记录或旧结果覆盖新结果。

**独立验收**：重复消费、计算进程终止、过期执行回写、对象上传失败、MySQL/Redis 断连和清理重跑。

1. 假如同一执行被重复投递，那么只有持有当前执行权的一方可提交结果。
2. 假如用户取消或重新发起任务，那么旧执行不能覆盖新状态、证据或正式记录。
3. 假如持久提交已经成功但公开状态更新失败，那么恢复时仅同步已提交结果，不重新调用模型或创建业务记录。

### US3：从两机扩展到三机（P2）

管理员暂停新解析、排空任务，将计算环境迁到 C，A 保留网站与 API，B 保留数据服务。

**独立验收**：同一业务版本完成单机、两机、三机全链路矩阵及两机到三机的切换前回退。

## 需求

- **FR-001**：计算组只通过数据服务和稳定文件引用取得输入，不依赖网站机器本地目录。
- **FR-002**：每次执行必须拥有独立身份、输入版本和临时目录，输入内容须校验；执行结束可清理临时文件。
- **FR-003**：必需产物完整持久化、校验并提交业务结果后，才能发布成功状态；部分结果不冒充完整结果。
- **FR-004**：重复消费、重试与旧执行迟到回写不得覆盖当前结果或重复创建正式论文、证据和索引。
- **FR-005**：节点退出、连接中断、认证错误与存储失败必须收敛到可诊断状态，并提供有界恢复路径。
- **FR-006**：保留既有用户权限、校对/提交/审核规则、任务列表与状态契约；取消及版本改变可阻止旧执行提交。
- **FR-007**：清理必须可重试并保护当前执行、正式论文、返修和审核引用；删除计算缓存不破坏业务数据。
- **FR-008**：GROBID、上传解析和证据核对依赖可随计算组迁移；网站保留交互 API，既有按需文件读取和区域渲染可用。
- **FR-009**：任务模型配置保持请求归属和短期凭据边界，不因跨机器丢失选择，也不将凭据写入产物或备份。
- **FR-010**：支持暂停新任务、排空运行任务及迁移计算组；迁移不要求再次搬运持久业务文件。
- **FR-011**：同一业务版本在单机、两机、三机完成真实业务回归，模型/SMTP 等外部能力未验收时明确记录。
- **FR-012**：执行日志关联任务、尝试、输入版本和制品版本，错误可追踪且不泄露文件内容、密钥或模型内部思维链。

## 成功标准

- **SC-001**：远程计算环境没有应用业务目录，仍完成主文/附件上传、解析、证据核对、提交、审核与授权读取。
- **SC-002**：每次公开成功都可追溯到完整产物清单与持久提交；模拟任一必需对象写入失败时成功数为零。
- **SC-003**：重复投递、取消、显式重试与旧执行回写场景不产生重复正式记录或错误覆盖。
- **SC-004**：故障矩阵逐项通过，已持久提交的任务恢复不再次执行解析；缓存清除与清理重试不丢业务数据。
- **SC-005**：单机、两机、三机真实业务矩阵以及计算组迁移/切换前回退通过；仅容器网络模拟不满足三机验收。

## 假设、依赖与范围外

依赖 [#131](../131-unified-file-storage/spec.md) 和 [#132](../132-three-tier-deployment/spec.md)。复用 #114 解析契约、#109 证据权限、#35 清理语义。解析器本身只产生 IR/Claim，现有业务编排层负责持久化，不把权限和正式提交移动到解析器。

本 Feature 不提升模型准确率、不改变解析方案选择、不新增 GPU 调度或自动扩容。网站可保留按需证据渲染和 Tc 等既有同步接口，本次分离的是上传解析与证据核对后台计算，不以删除网站所有 PDF 库作为验收标准。
