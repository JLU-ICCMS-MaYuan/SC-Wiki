# 研究与决策：跨机器解析执行

**Issue**：[ #133](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/133)，2026-10-12。以下来自只读代码检查。

## 现状与缺口

| 证据 | 当前行为 | 缺口 |
| --- | --- | --- |
| `backend/scripts/run_upload_workers.py` | RQ 多进程消费上传队列并处理核对任务 | 可独立进程运行不等于可跨机器读文件 |
| `backend/rq_runtime.py` | Redis 错误后重建 Worker | 进程重连不保证执行幂等或结果已提交 |
| `backend/ingest/upload_tasks.py` | enqueue 保存短期模型配置，任务执行超时目前为 -1 | 新执行身份、失联判断与投递恢复需要明确 |
| `backend/ingest/upload_jobs.py` | 直接使用原始路径及产物目录，finally 写运行元数据 | 产物尚未持久化可能已更新状态 |
| `backend/ingest/property_evidence.py` | 核对任务读快照，限时运行并写证据 | 旧快照任务须受版本与执行身份保护 |
| `backend/ingest/document_regions.py` | 网站按需打开原 PDF 渲染证据 | 网站仍需文件读取能力，不应把所有 PDF 操作都改成后台任务 |
| `backend/ingest/prop_names.py` | 有运行时追加源码 CSV 的路径 | 计算节点上的学习缓存不能成为唯一共享配置 |

## D1：保留 RQ，新增最小持久提交记录

Redis 保留队列、运行状态和公开任务 DTO 的职责；MySQL 新增 `task_execution_heads`，记录当前执行代次、执行权和已提交结果指针。它不是第二套任务管理产品，不替代 Redis 列表，不改变正式论文数据所有权。

理由：仅 Redis 锁或 RQ job id 无法阻止锁过期后的旧执行向 MySQL 回写，也无法证明“对象已保存、数据库已提交、Redis 更新失败”的恢复状态。拒绝宣称消息队列提供 exactly-once；通过代次检查、原有提交幂等键和事务约束实现业务幂等。

## D2：对象先持久化，数据库事务再发布结果

产物写入本次 attempt 的不可变命名空间，回读/摘要核验后形成 manifest。业务草稿/证据结果和执行提交标记在同一个 MySQL 事务提交；Redis 成功状态随后投影。提交事务失败时产物只是未引用对象，不可见为成功。

必须先审计当前解析编排中写 MySQL、Qdrant 和共享文件的每个位置。中间业务写入受当前代次检查，候选产物按尝试隔离；正式论文仍由用户提交接口与既有唯一性规则创建。Qdrant 临时索引使用带尝试身份的点 id/payload，只有提交指针指向的尝试可读；正式索引继续在既有批准路径生成。

## D3：同一任务至多一个有效执行，不自动重做模型任务

用数据库时间维护 60 秒执行租约，活跃 Worker 每 10 秒续约。提交和所有影响当前业务的写入必须锁定执行记录并核对 generation、attempt_id、输入版本与取消状态。不能取得执行权的重复消息无副作用结束。

租约过期或运行进程退出时，由恢复检查收敛为明确失败；用户显式重新发起才增加 generation。默认上传最大执行时间 2 小时，可配置有限上限；核对保持既有 1800 秒上限。超时不自动换模型或重跑。长模型调用期间续约线程仍须运行；续约失败就不再提交副作用。

## D4：投递失败和结果投影失败分别恢复

创建新代次先写持久执行记录（dispatch_pending），再以确定性 RQ job id 投递。命令/Worker 启动恢复检查只补投仍有效且尚未执行的当前代次；不重新消费已提交或已失败的代次。MySQL 事务成功而 Redis 状态未同步时，仅按提交指针修复公开状态。

这比在每个读取请求里查库兜底更可控：正常任务列表仍读 Redis；恢复由显式 reconcile 或 Worker 启动/监督循环处理。代次递增、取消、结果投影共享版本比较规则，旧代次不能降低公开状态版本。

## D5：计算侧无唯一业务文件

使用 #131 的 materialize 与 FileRef，原始 PDF 和必需产物归对象存储。模型下载缓存本地可重建；源码中的物性名基础映射保持只读，学习映射通过既有规范化逻辑接入 Redis 命名空间缓存，不写源码 CSV。数据库中的正式规范化结果保持事实来源。

首版继续复用 Python 镜像与已验证解析依赖，不另做 API/Worker 镜像瘦身。网站区域渲染使用对象存储取回的短期文件；GROBID 通过可配置私网地址访问。
