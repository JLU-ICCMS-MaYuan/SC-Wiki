# 上传解析记录表单性能修复

**GitHub Issue**：[Issue #96](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/96)

**创建日期**：2026-09-09

**状态**：已完成

## 背景与目标

上传解析任务进入 `ready` 后，用户在审核表单中修改晶系、空间群、分类或模块化物性记录的选项时，页面会同步刷新大量未修改的材料状态和记录。材料状态较多或记录 Schema 较复杂时，输入反馈会明显延迟，影响校对效率。

目标是在不改变草稿数据、自动保存、校验和提交语义的前提下，缩小编辑更新的渲染范围，避免每个字符都触发整张表单的重复计算。

## 用户场景与验收

### 用户故事 1：材料状态选项即时编辑（优先级：P1）

用户在包含多个材料状态的上传解析记录中修改晶系、空间群、材料维度或结构家族，输入和选择结果应立即显示。

**优先级理由**：这是用户直接报告的卡顿路径，阻塞基本校对流程。

**独立验收**：渲染计数测试证明修改一个状态时其他状态不重新渲染；空间群自由输入的草稿值在选择或失焦后保持正确。

**验收场景**：

1. **假如**表单包含至少 5 个材料状态，**当**用户修改第 1 个状态的晶系，**那么**第 2–5 个状态的字段不重新渲染，且第 1 个状态显示新值。
2. **假如**用户在空间群符号框中连续输入文本，**当**输入尚未提交，**那么**输入框保持本地响应；选择候选或失焦后，草稿保存最终文本。

### 用户故事 2：物性记录选项稳定编辑（优先级：P1）

用户在包含多个物性模块和动态 Schema 记录的材料状态中修改记录定义、枚举字段或条件字段，不应触发其他记录的校验、Schema 构造和定义绑定更新。

**优先级理由**：模块化记录字段数量和 Schema 复杂度会放大整树重渲染成本。

**独立验收**：记录渲染计数测试证明未修改记录保持稳定；定义缓存和校验结果不因无关字段编辑重复生成。

### 用户故事 3：草稿保存与提交兼容（优先级：P1）

用户完成选项编辑后，自动保存、手动保存和提交仍使用现有草稿结构和接口，数据值与优化前一致。

**独立验收**：现有上传编辑器交互测试、自动保存测试和 TypeScript 构建通过。

## 边界与异常场景

- 分类目录或空间群目录尚未加载时，现有加载态和降级输入行为保持不变。
- 只读解析中的临时表单仍不可编辑，不触发父级草稿更新。
- 空材料状态、空物性模块和定义加载失败时，现有错误提示和提交校验保持不变。
- 卡片折叠状态是界面状态，不写入草稿；优化不得因重新渲染重置用户已经选择的折叠状态。
- 自动保存仍在最后一次编辑后 5 秒触发；编辑期间不为每个字符发起保存请求。

## 需求

### 功能需求

- **FR-001**：编辑单个材料状态字段时，系统必须限制渲染更新在该材料状态及其必要的父级状态范围内，未修改的材料状态不得因引用未变化而重新渲染。
- **FR-002**：空间群符号的自由输入必须使用本地输入状态；只有候选选择、清空或失焦提交时才更新草稿中的 `reported_space_group_symbol`。
- **FR-003**：空间群选项、分类选项、动态 Schema 和客户端校验结果必须在输入值未变化时复用，不能在每次父级渲染时重复构造。
- **FR-004**：物性定义绑定不得在每次无关记录编辑时重复写入相同的定义对象或错误状态。
- **FR-005**：自动保存、手动保存、提交载荷、校验错误定位、只读模式和折叠行为必须保持现有语义。

### 关键实体

- **上传草稿**：`UploadDraft`，仍由 `UploadTaskEditor` 持有并通过现有 PUT 接口保存。
- **材料状态**：`DraftMaterialState`，是渲染隔离和状态更新的基本单元。
- **物性记录**：`PropertyRecordDraft`，继续由动态 Schema 表单编辑，定义版本和 payload 结构不变。

## 成功标准

- **SC-001**：包含 5 个材料状态的回归测试中，修改一个状态的选项时，其余状态渲染计数保持不变。
- **SC-002**：包含多个动态物性记录的回归测试中，修改一个记录时，其余记录渲染计数保持不变，且定义请求调用次数不增加。
- **SC-003**：空间群自由输入测试证明连续输入不会逐字符调用父级草稿更新，提交或失焦后最终值准确写入。
- **SC-004**：上传相关 Vitest 定向测试、TypeScript 构建通过；现有保存与提交契约测试无回归。

## 假设与依赖

- 继续使用 React 19、MUI、现有分类目录和表单定义缓存；不引入新的状态管理库或虚拟化依赖。
- #90 的模块化物性数据结构和 #94 的记录编辑行为已经落地，本 Feature 只优化渲染和输入更新路径。
- 性能验收以渲染范围、请求次数和可重复的定向测试为主，不把单机绝对毫秒数作为唯一门槛。

## 范围外事项

- 不修改后端 API、Redis 草稿结构、MySQL Schema、解析提示词、权限和业务校验规则。
- 不重写整个表单为第三方表单库，不改变字段布局和用户可见文案。
- 不处理上传解析 Worker、PDF 提取或 LLM 推理性能。
