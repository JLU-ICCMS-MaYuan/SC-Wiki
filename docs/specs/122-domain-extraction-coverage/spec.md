# Feature 规格：领域提取覆盖全部表格行/结果块/图

**GitHub Issue**：[#122](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/122)（父 Issue：[#114](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/114)）

**创建日期**：2026-10-09

**状态**：已确认

## 背景与目标

#114 新 PDF 链路（Docling/MinerU → Document IR → 领域提取 → Claim 定位 → 覆盖检查）的覆盖
检查要求：疑似结果块、每个表格行、每个图/公式块要么被已验证 Claim 覆盖，要么计入未覆盖并
使任务失败（`document_review_required`）。2026-10-08 用 2014 H3S（主文 + 补充材料）实测：
Docling 解析成功、8 个科学候选全部定位通过，但覆盖检查发现 89 个未覆盖项（主文 29 个结果块 +
14 图；补充材料 2 张表 45 行 + 3 图）——提取模型没有为每个表格行/结果块/图生成候选，也没有
"已审阅并排除"的表达，任务确定性失败。

目标：领域提取契约支持显式排除；覆盖检查承认带理由的排除；使真实论文能走完新链路产出
ready 草稿，或把确实需要人工的项目明确列出，而不是整任务失败。不放宽证据定位规则，不伪造 ready。

## 用户场景与验收

### 用户故事 1：新链路论文解析产出可校对草稿（P1）

作为上传者，我选择 Docling 解析真实论文后，希望得到 ready 草稿供校对；无法覆盖的内容
在草稿/检查产物中明确列出排除理由，而不是整任务失败。

**优先级理由**：这是新链路可用前的关键缺口；当前对任何含表格/图的论文必然失败。

**独立验收**：2014 H3S 主文 + 补充材料用 Docling 完整管线达到 ready，或仅剩明确列出的需人工项。

**验收场景**：

1. **假如**表格的某行是表头或单位说明（不是结果数据），**当**提取模型输出该行的排除项
   （类别"非结果内容"），**那么**覆盖检查不再把该行计入未覆盖，任务可以继续。
2. **假如**某图是结构示意图（不含科学数据），**当**模型输出排除项（类别"图无数据"），
   **那么**该图不再阻断任务。
3. **假如**模型想排除一个实际包含 Tc 数值的结果块，**当**排除类别是"无法读取"，
   **那么**任务仍标记需人工，不得静默放行。
4. **假如**模型把全文绝大部分结果块都排除掉，**当**排除比例超过阈值，**那么**任务保持
   需人工，不产出 ready。

### 用户故事 2：排除理由可审计（P2）

作为审核员，我希望每个排除项带受控类别理由，能追溯到具体文件、页和块，供抽查。

**独立验收**：覆盖检查产物（coverage.json）记录全部排除项、类别与引用位置。

**验收场景**：

1. **假如**某表格行被排除，**当**查看 coverage.json，**那么**能看到 `table:{id}:row:{n}`、
   类别和理由。

## 边界与异常场景

- 排除引用不存在的块/行 → 服务端拒绝该排除项（保留未覆盖状态），不静默丢弃。
- 排除类别不在受控清单内 → 契约校验失败，与现有领域提取失败路径一致。
- 排除与 Claim 覆盖同时指向同一项 → 以 Claim 覆盖为准，排除项冗余无害。
- 网络/模型失败 → 沿用现有重试与 failed 终态，不因排除机制改变。

## 需求

### 功能需求

- **FR-001**：领域提取契约（`Extraction`）新增 `coverage_exclusions` 列表，每项包含
  `file_id`、定位（`block_id` 或 `table_id`+`row_index` 或 `pdf_page`，页号可作辅助信息）、
  受控类别 `category`（`non_result_content` / `reference_or_background` / `figure_without_data` /
  `header_or_unit_row` / `out_of_model_scope` / `unreadable`）和简短理由 `reason`。
- **FR-002**：`DOMAIN_SYSTEM_PROMPT` 要求模型审阅全部疑似结果块、表格行、图/公式块：
  生成候选记录，或输出对应排除项；两者必居其一。
- **FR-003**：服务端校验排除项引用真实存在的块/表行/页，类别合法；无效排除项被丢弃并
  保留该项未覆盖状态。
- **FR-004**：`audit_coverage` 接收排除项：被排除项不再计入 `uncovered_candidates`；
  `unreadable` 类别与"疑似结果段落的 `non_result_content` 排除比例超过阈值（默认 50%，疑似
  块不足 4 个的小样本不触发）"两种情况保持 `requires_human=True`，其余情况允许 complete。
  提取或分类后仍有未覆盖项时，执行一次定向"未覆盖项分类"调用（每文件一次）：明确非结果的
  项转为带理由排除，确实需要提取的超导数据保持未覆盖。
- **FR-005**：覆盖检查产物记录全部排除项、类别、理由与引用位置（coverage.json），供审计。
- **FR-006**：`repair_claims` 有限补证循环不变（仍只给同值候选补出处）；排除机制不参与
  伪造证据。

### 关键实体

- `CoverageExclusion`：file_id + 定位（block/table row/page）+ category + reason。
- `CoverageReport`：新增 `exclusions` 字段；`uncovered_candidates` 只含未覆盖且未排除项。

## 成功标准

- **SC-001**：2014 H3S 主文 + 补充材料 Docling 完整管线达到 ready，或 requires_human 项
  全部来自 `unreadable`/阈值保护且在 coverage.json 中明确列出。
- **SC-002**：覆盖检查未覆盖且未排除项为 0；排除项全部带类别与理由。
- **SC-003**：#114 定向测试通过；新增排除契约、校验、聚合的单元测试；与 HEAD 相比无新增失败。

## 假设与依赖

- Docling IR 的 block_id/table_id/row_index 稳定（#114 已保证）。
- 提取模型能在一次调用中完成"候选 + 排除"双输出（上下文预算内；H3S 主文 IR 分组后可行）。
- 阈值 50% 为初始保守值，后续按 50 篇质量门数据调整。

## 范围外事项

- 不改变默认链路（legacy 保持默认直到 #114 的 50 篇质量门满足）。
- 不放宽证据定位逐字规则；排除不等于证据。
- 不做图像内容识别（图是否含数据由模型判断并自负其责，审核员可抽查）。
- 不迁移历史任务的 coverage.json 格式。

## 澄清记录

### 2026-10-09（用户确认）

用户确认以 #114 的 Spec 与 Issue 为基础继续完善该需求，并确认了 Issue #122 的目标、范围与
验收标准；"不伪造 ready"边界通过 unreadable 类别与排除比例阈值保留。

### 2026-10-09（实施澄清）

- 新增类别 `out_of_model_scope`：2014 H3S 实测发现大量真实科学内容（能带隙、晶格参数、原子
  分数坐标、Eliashberg 谱函数）在当前领域契约中没有注册模块可表达；将其诚实标注为"模型范围外"
  并记录审计，而不是伪装成 non_result_content，也不永久阻断 ready。审核员可在 coverage.json
  按类别抽查。后续若注册电子/结构模块，这些项自然转为候选。
- 阈值口径修正：只对疑似结果段落按 `non_result_content` 类别计比例（背景引用与 out_of_model_scope
  是正当归类，不计入）；疑似块不足 4 个的小样本不触发比例判断。
- 文本层为空的图/公式块不计入未覆盖：实测中被分类器诚实标注 unreadable 的 8 项全部是空文本
  figure 块，其本质是"当前解析方案不读取图像内容"的管线能力边界（#114 视觉/原生 PDF 方案的
  范围），不是提取覆盖缺陷。改为记录 `figures_without_text_layer` 计数供审计；有 caption 文本
  的图块仍按原规则要求覆盖。任务因需人工项失败时，错误信息按文件列出未覆盖计数。
- 提取模型不会主动为全部块/表行申报处置（实测主文 25 块、补充 45 行遗漏）；按 FR-004 增加
  一次定向"未覆盖项分类"调用（每文件一次，失败不改变原覆盖结果），把明确非结果的项转为
  带理由排除，确实需要提取的超导数据保持未覆盖并进入需人工清单。
