# 分段及模型运行的所有权

每段保持原文件、原页、块及原编号；完整段落、表行和科学结构不为拼接改写。辅助前文与主要读取页分开，必要表头、表注及邻页说明保留。

`ordered_extract`先收集本次输入，以最多两段并发处理，主线程按完成事件更新对应编号和进度，最终按原编号返回结果。清单写入受进程锁保护，不由结束顺序改变科学归属。

线程复制ContextVar，继承选定模型、用量记录和执行身份。ModelRuntime派生实例独立持有连接及接收事件，共享任务代次、检查点和受锁保护的请求出现计数。失败停止未开始任务，并使在途派生执行拒绝迟到响应。

所有上传模型请求通过Redis租约共享当前`upload_llm_concurrency`额度；保持现有十Worker配置。租约续期、停止释放及丢失后的响应拒收不生成科学通过结果。没有新业务表、标准科学字段或提高模型输入预算。

并发接收事件显式携带本次phase、attempt、filename和pages，不能继承其他分段刚写入的动态。主清单按稳定分段编号保存，前台动态表示实际最新事件，不作为科学结果归属依据。
