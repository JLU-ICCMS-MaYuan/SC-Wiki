# 实施计划

## 职责与接口

正文保留句段边界，表格保留完整行及表头表注；有限前文替代固定整页重叠。预先准备输入，受限并发，原编号归位。保留模型配置、运行上下文、统计、取消和恢复。

## 默认选择

来源标记可开关，按需读取上下文和原件。前文目标2000字符，必要完整块/表头表注仍保留。分段并发默认2，受进程共享额度限制。论文核对结果保存成功后交接，后阶段只处理材料字段并保留论文所有权。

## 后处理请求按职责投影

结构优化判断保留状态身份、优化类型和相关原文，不重复发送完整物性模块；宿主完整候选不变。状态归属请求只投影状态身份、标量结果及来源引用，参数与软件仍由宿主保留。全文来源不裁剪；同摘要、当前读图版本、已完成且无该页未解决项、存在实际标定事实时，才复用已读页并明确登记。必要原图仍随组发送。

超过现有96k预算时按真实请求大小分候选组，每组保留完整文字及本组必要原图；规划后仅合并物理身份完全相同的状态，重映射目标，所有原记录恰归位一次，然后执行一次原有应用。科学整理优先读当前记录及档案引用原文，其余来源留在可查目录；重复引句可投影为唯一来源块内的Unicode区间，不能唯一匹配则保留原证据。

材料填写由下文小组流程主动分组；组内真实预算不足时仍按不能跨状态合并的边界缩小；全局候选身份、结果键及审计索引不变，每候选父子请求总交互仍最多4轮。任何子组失败均保留原始全稿，并向上报告实际子错误，不能以部分成功替换。宿主DOS来源档案在模型字段检查前暂存、检查后原样恢复；模型仍不能写入该键，不修改标准契约、锁摘要或科学接受规则。

## 材料组执行方案（替代原先整稿填写后统一核对）

在全局材料状态规划和结构归属之后，以稳定状态顺序每2个为一组；不跨组改变材料状态身份。组内沿既有填写函数与四轮上限，传入全局state_offset；预算不足可按原独立状态边界再缩小，绝不扩回整稿。全局候选去向聚合仅供程序防丢检查，不再送模型重新填写。

每组先完成填写及原有Claim来源检查，再调用现有字段核对，只选择本组state_key的字段；快照仍基于全稿全局身份。核对保留论文和未选状态，不对后组做补填或改写。材料核对首批原文只取本组引用，其他原文由既有目录、搜索及读页工具获取；一般论文级与主动字段操作维持原策略。

核对技术失败或填写不完整立即停止，不进入后组；不确定/缺依据是已完成的核对结论，继续沿既有人工处理。当前组值与成功核对结论先保存到正式ScientificUploadDraft，保存成功才将material-stage.json对应组标记完成。检查点绑定完整原输入、原文、论文值、流程及执行模型身份和处理版本；保存完整前组草稿及候选去向，不复用失败组。续跑相同身份时恢复完成前缀，来源/模型/输入变化不复用。

结构归属在开始组循环前完成；原防丢门按各组填写后、字段核对前的只读副本核验，避免用之后合法纠正值倒查旧候选。各组在核对前执行原来源门，最终完整性是程序验证，不加全表模型合稿。保存所有模型请求/响应到组制品，正式草稿报告递归去除请求全文，避免嵌套attempts把整包上下文带回后续阶段。

运行元数据material_batch保存index/total/state_count/completed_states/action；详情复用现有轮询显示，不增加科学键、数据库表或请求。
