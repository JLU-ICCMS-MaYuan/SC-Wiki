# 目标 1：为什么已填写的字段仍有大量未核对项

本文只讨论系统与人的核对分工。建议尚待讨论，不改变现有 Spec、审核资格或业务数据；材料状态预览和计算条件整批失败分别留给目标 3、目标 2。

## 先回答你的问题

**已经填写，不代表已经核实；但系统已经核实并成功保存的内容，不应再让你逐项确认。**

例如，原文同时出现 235 K、220 K、μ*=0.1、μ*=0.13。找到这些数字只是第一步，还要确认材料、压力、计算方法及配对：150 GPa 的 235 K 对应 0.1，220 K 对应 0.13。把 235 K 填在 0.13 下面，即使数字都有出处，关系仍然错误。

这些检查应由系统先完成。只有查完当前正文、补充材料和必要上下文后仍有真实歧义，才需要你判断。

**这次 CaH6 大量未核对，主要暴露了结果保存和失败展示的问题，不能据此认定需要你处理同样数量的科学疑问。**

| 检查对象 | 实际结果 | 应怎样理解 |
| --- | --- | --- |
| 共享快照中的字段 | 413 项 | 包括空值、可选项和程序派生项，不是问题总数 |
| 当前需要核对的字段 | 150 项：131 项普通字段、19 项派生字段 | 表示尚无有效结论，不代表 150 个科学错误 |
| 空值或可选等无需核对项 | 263 项 | 按前端现有规则可免核对，不应要求人工补满 |
| 可复用的当前字段结果 | 0 项 | 当前任务没有读到任何有效字段结论 |
| 数据库中该任务的核对表行 | 1 行，仅来源元数据 | 不是某个科学字段已经核对通过 |
| 字段生成／核对阶段 | `suggestions_status=failed` | 整体处理失败，却仍保留了可校对草稿 |

这里的数量来自共享快照和前端状态规则的投影，没有通过截图逐个统计控件；一个控件也可能汇集多个字段的提示。

### 已定位的保存故障

本机 MySQL 缺少新版的 `scientific_source_items`、`scientific_work_drafts` 表。对应迁移为 `20261030_0192`；当前数据库版本记录仍为 `20261020_0049`、`20261022_0153`。

程序生成快照时，即使没有新工作稿表，也会给出 `cycle:upload:…` 形式的周期标记。保存来源的代码却只判断这个标记是否非空，在缺表时抛出：

> ValueError：字段采用来源目录尚未完成迁移

本轮已在真实本机缺表条件下重放这个拒绝分支，确认未产生 ORM 待写入对象。结合原任务的 `ValueError` 日志、没有字段结果的数据库记录和代码调用链，可定位保存失败路径；原任务日志没有完整堆栈，不能还原每批模型的全部中间判断。

失败被上传任务捕获后，初始提取值仍保存，任务进入 `ready`。读取字段结果时，找不到结论就生成“待提交时核对”；前端未收到对应字段的失败信息，又将其显示成“待核对”。19 项派生字段则因依赖的输入尚无有效核对结果而等待。

**结果是：系统没有成功保存检查结果，却让用户看起来像还有一大批内容需要亲自判断。删除旧草稿、重新上传，不能补齐数据库结构。** 本轮没有执行迁移或重跑真实核对。

## 建议怎样分工

先沿用现有字段身份、来源和核对机制，把处理责任分清；以下是待讨论方向。

| 情况 | 系统应该做什么 | 你需要做什么 |
| --- | --- | --- |
| 原文和适用关系明确，最终值已核实且结果保存成功 | 自动记录有效通过；值、依据和必要条件未变时复用 | 无须逐字段再次确认 |
| 系统自己填错，但原文能唯一纠正，且没有人工处理保护 | 查证、纠正、核实最终值及保存 | 无须替系统确认它自己的纠错 |
| 来源冲突，或查完仍无法确定材料／压力／方法／配对 | 展示具体疑问、已查资料和可比较的候选 | 判断这个真实分歧 |
| 模型超时、读取失败、数据库缺表或保存失败 | 标明失败步骤，保留输入；满足恢复条件后继续未完成步骤 | 无须作科学判断；确需维护时只处理明确的维护动作 |
| 当前规则允许留空，且已确认原文未报告 | 如实留空，不制造人工任务 | 无须补造内容 |
| 程序可推导的元素数、晶系等 | 核实输入及计算关系，复用有效输入结论 | 无须再次调用模型或逐项确认派生值 |

“未报告”必须与“没有读完／处理失败”分开。系统不能因为没有找到或调用失败，就认定原文没有。

也不把自动通过等同于整篇论文批准：现有最终审核决定独立保留，本目标解决的是不必要的逐字段人工劳动。

### 流程需要衔接的地方

1. **生成和自检衔接。** 初始解析若已经完成与正式核对等价的检查，就保存当前字段值、采用依据、适用关系和结论，后续直接复用。仅有原文定位成功，不能直接升级为科学通过。
2. **成功和保存衔接。** 同一次来源阅读可以形成多个明确字段的结论；按现有稳定身份分别保存。研究如何保留已完成部分，避免后续故障让整批结果消失，不在本讨论中预先决定事务拆分方案。
3. **失败和提示衔接。** “系统还在处理”“系统处理失败”“确需人工判断”必须能够区分。每个交给人的科学问题都应说清具体分歧，不能只给一个“未核对”。

共享原文可以减少重复阅读，但不能把整段来源无差别地当作所有字段的通过依据。主动核对单字段时，继续只处理当前字段及其采用依据，不借此扩大到其他字段。

## 本轮先讨论的一个原则

**系统负责把自己生成的内容查证、核实并保存成可复用结果；用户只处理系统查证后仍存在的真实科学分歧，以及明确需要人执行的维护动作。系统技术失败不能伪装成科学疑问。**

这个原则是否符合你的预期？本轮先讨论它，不同时决定具体页面改版、数据库迁移或真实草稿修复。
