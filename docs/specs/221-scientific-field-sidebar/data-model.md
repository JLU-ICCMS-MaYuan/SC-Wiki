# 状态与数据所有权

本轮进入产品实施；复用持久模型，不新增业务库列。侧栏沿用原宿主当前值、稳定字段身份、字段内容／来源／人工资料版本、核对结果与候选，不产生另一份正式科学值。

设计区分四类状态：未保存／保存中／已保存／部分失败；尚未核对／处理中／科学结论已返回／技术未完成；当前值与尚未应用候选；当前工作稿与冻结历史。保存按钮、结论显示和标红资格分别由对应事实驱动。颜色条件只见 #220。

过程投影应绑定当前 target/item_key 与任务身份，只报告真实阶段及可公开简短摘要，终态停止更新；不得用模型内部推理、候选文字或本地颜色授予后台通过资格。jobs 的可选 activity/activity_log 仅为公开小型投影，不进入科学字段契约。具体白名单与终态保护见 contracts/sidebar.md。


补充PDF沿已有人工证据条目及SHA绑定，100,000字符限制仅作用于PDF正文读取。review_pdfs_read属于后台调用回执，worker据此更新原条目的ai_read_status；该状态不授予科学通过，不改变字段内容和来源令牌，同状态重复回执不增加修订。


人工留空复用field-review-v2 action=approve，增加mode=empty与人工资料摘要作为内部审核元数据。不是新增科学表单键/状态表。字段能力empty_allowed由程序计算；实际空值与是否已人工确认分开，后端每次按当前资料和权限校验，不相信客户端授予资格。
