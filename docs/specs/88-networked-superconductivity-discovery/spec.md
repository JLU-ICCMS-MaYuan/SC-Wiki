# Feature 规格：全网超导文献、科研新闻与产业资讯定时发现

**GitHub Issue**：[＃88](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/88)

**创建日期**：2026-09-03

**状态**：需求已确认

> 2026-10-23 后续修订：[#160](../160-news-source-semantics/spec.md) 按用户新要求取消 Phys.org 位于期刊栏的例外，统一按内容类型分栏，并更新单原文入口和期刊发现策略。下文原有 FR-006、SC-004 及对应澄清保留为历史，不作为当前实现规则。

## 背景与目标

已完成的 [#63](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/63) 每日资讯功能只定时采集 arXiv、Crossref 和 Phys.org 三个固定端点，再展示已保存的结果。它不能保证发现 APS、ACS、Nature、Science 等出版商的最新超导论文，也没有覆盖超导产业、政策或股票资讯。

本 Feature 是 #63 的进阶版本。系统必须以 `superconduct` 和 `超导` 为固定主题定时联网发现外部内容；发现能力不得依赖用户输入题名、DOI 或本地历史记录是否已经存在。发现结果仍是资讯，不进入正式论文、材料、审核或知识图谱数据。

## 用户场景与验收

### US1：发现最新超导文献（优先级：P1）

研究者打开资讯页时，可以阅读由系统自主发现的最新超导预印本与期刊论文，并跳转至出版商原文页。

**优先级理由**：这是本 Feature 的核心价值，解决固定三源漏收最新论文的问题。

**独立验收**：使用可重复的来源响应样本，证明各类文献来源可发现、去重、保留出版商链接并显示在资讯页。

**验收场景**：

1. **假如** arXiv、Crossref、OpenAlex 或指定出版商来源出现相关新论文，**当** 定时发现任务运行，**那么** 资讯页展示论文题名、发表时间、DOI（存在时）、发现来源和原文来源。
2. **假如** APS、ACS、Nature Portfolio、Science/AAAS、NSR、CPL、CPB 或 Materials Today 的论文只能由 Crossref/OpenAlex 发现，**当** 该条目被展示，**那么** 页面同时显示聚合发现来源和原始出版商链接。
3. **假如** 同一论文从预印本、聚合索引和出版商入口重复出现，**当** 任务再次运行，**那么** 页面不产生重复条目，并保留可用的多来源链接。

### US2：阅读超导科研与社会资讯（优先级：P1）

研究者可以同时看到与超导有关的科研报道，以及产业、企业、政策和股票等社会资讯，且不会把新闻报道误认为同行评审论文。

**优先级理由**：用户需要从论文之外了解超导技术的社会与产业动态。

**独立验收**：使用科研报道和社会资讯样本，证明相关性筛选、来源类型和页面分栏均正确。

**验收场景**：

1. **假如** 出版商新闻稿、科研机构新闻、科学媒体或合规网页搜索服务返回超导相关报道，**当** 任务运行，**那么** 系统将其展示为科研报道或社会/产业资讯，并显示原文来源。
2. **假如** Phys.org 返回超导相关条目，**当** 页面展示它，**那么** 它位于期刊论文栏，同时明确显示 `Phys.org 科研报道`，不显示为同行评审论文。
3. **假如** 出版集团或网页搜索返回题名、摘要、关键词和分类都无法证明与超导相关的内容，**当** 系统处理该内容，**那么** 不向资讯页发布。

### US3：持续可靠地运行（优先级：P1）

维护者不需要人工重启资讯服务；单次来源或 Redis 连接故障后，后续定时发现可以自动恢复。

**优先级理由**：一次 Redis 连接超时曾导致 `news-worker` 永久退出，直接中断资讯更新。

**独立验收**：模拟 Redis 短暂连接故障和单来源失败，确认 Worker 自动恢复，其他来源不受影响。

**验收场景**：

1. **假如** Worker 的 Redis 长连接发生短暂超时，**当** Redis 恢复可用，**那么** Worker 自动重连或由运行环境自动重启，并继续消费资讯队列。
2. **假如** 一个外部来源限流、超时或返回损坏数据，**当** 本次任务结束，**那么** 该来源记录可诊断的失败状态，其他来源继续执行，下一次调度可重试。
3. **假如** 外部来源没有公开关键词接口或暂时不可用，**当** 该来源存在 Crossref/OpenAlex 补充元数据，**那么** 系统允许该补充来源发现条目，并保留实际发现来源。

### US4：追溯发现依据（优先级：P2）

研究者可以判断一条内容为何出现、来自哪里以及它是论文还是新闻。

**优先级理由**：多来源联网发现会扩大覆盖范围，必须保持结论可追溯和类型透明。

**独立验收**：打开任一详情，核对来源、相关性依据、内容类型、发表时间和外链均可见且一致。

**验收场景**：

1. **假如** 用户打开任一自动发现条目，**当** 查看详情，**那么** 可以看到内容类型、展示栏位、发现来源、原文来源、命中依据、发布时间与原文链接。
2. **假如** 内容缺少 DOI，**当** 系统去重和展示它，**那么** 使用稳定的原文 URL 或来源标识，且不猜测 DOI。

### 边界与异常场景

- 不抓取付费墙、登录后内容或受访问控制全文；只读取公开元数据、公开 RSS、公开检索结果或允许展示的摘要片段。
- 出版商未提供稳定公开入口时，不能伪造“官方直连”；必须标记补充发现来源。
- 网页新闻来源可能无法覆盖未被搜索服务收录的微信公众号文章；系统不得承诺穷尽互联网内容。
- 期刊出版日期只有年或月时，保留日期精度，不能伪造具体日。

## 需求

### 功能需求

- **FR-001**：系统必须按可配置的定时计划，以 `superconduct` 与 `超导` 为固定主题联网发现最新外部内容；发现请求不得依赖用户输入或本地已存条目。
- **FR-002**：系统必须至少覆盖 arXiv、Crossref、OpenAlex、APS、ACS、Nature Portfolio、Science/AAAS、NSR、CPL、CPB、Materials Today 及相关物理/材料期刊的超导文献发现。
- **FR-003**：系统必须优先使用出版商官方 API、RSS 或公开检索入口；当其没有关键词接口、不可用或限流时，可使用 Crossref/OpenAlex 补充发现，并分别保存发现来源和原文出版商来源。
- **FR-004**：系统只发布题名、摘要、关键词或出版商分类能够证明与超导相关的内容；不相关内容不得因来源属于指定出版集团而发布。
- **FR-005**：系统必须发现和展示超导相关的科研报道、产业、企业、政策与股票社会资讯；网页新闻仅使用合规搜索服务已公开提供的结果。
- **FR-006**：系统必须将同行评审论文、预印本、科研报道和社会/产业资讯作为不同内容语义保存并在页面中明确区分；Phys.org 条目必须展示在期刊论文栏并标记为 `Phys.org 科研报道`。
- **FR-007**：系统必须以 DOI、arXiv ID 或规范化原文 URL 去重，合并同一内容的可用来源链接；不得依据相似题名猜测同一内容。
- **FR-008**：每个自动发现条目必须保留内容类型、展示栏位、题名、发表时间及精度、发现来源、原文来源、相关性命中依据和安全外链；不得向正式论文、材料、审核或知识图谱数据写入。
- **FR-009**：资讯 Worker 遇到 Redis 短暂连接超时后必须自动恢复消费能力；单来源失败不得阻断其他来源，失败状态必须可诊断且可重试。
- **FR-010**：系统必须限制外部请求频率、超时、重试次数与响应大小，并且不通过公开接口泄露凭证、完整上游响应或内部队列标识。
- **FR-011**：自动化测试必须覆盖来源发现与补充、相关性筛选、去重、内容语义和展示栏位、Worker 恢复、来源失败隔离、公开接口及页面展示。

### 关键实体

- **发现条目**：一次定时联网发现后对外展示的内容，可为预印本、同行评审论文、科研报道或社会/产业资讯。
- **发现来源**：系统实际获得该条目的外部服务或出版商入口。
- **原文来源**：用户可访问的原始出版商、机构或新闻页面；可与发现来源不同。
- **展示栏位**：资讯页面承载条目的位置。它可与内容语义不同；Phys.org 的内容语义是科研报道，展示栏位为期刊论文。
- **相关性命中依据**：题名、摘要、关键词或出版商分类中证明条目与超导相关的公开字段。

## 成功标准

- **SC-001**：定时任务在不接收用户输入的情况下，可从文献和新闻来源发现并展示新的超导相关条目。
- **SC-002**：每个指定出版集团至少有一条可重复的官方入口或 Crossref/OpenAlex 补充发现验证样本；每条样本均能显示原文来源。
- **SC-003**：同一 DOI、arXiv ID 或规范化原文 URL 的重复发现不会新增第二个资讯条目，并保留至少一个有效原文链接。
- **SC-004**：论文、预印本、科研报道和社会/产业资讯的内容语义在详情中可见；Phys.org 样本在期刊论文栏中显示 `Phys.org 科研报道`。
- **SC-005**：模拟一次 Redis 连接中断后，无人工干预的资讯 Worker 恢复消费；后续定时任务可完成且不影响其他来源。
- **SC-006**：来源限流、超时、损坏响应和无关内容均有自动化测试，且不泄露凭证或内部任务信息。

## 假设与依赖

- “最新”按来源可获得的发表、上线或更新时间排序；不同来源的日期精度可能不同。
- 出版商与网页搜索服务的公开接口、覆盖范围、速率限制和服务可用性由其自身控制。
- 对没有公开官方检索接口的出版商，Crossref/OpenAlex 是允许的补充发现来源，不等同于出版商直连。
- 网页社会资讯依赖合规搜索服务；该服务的凭证、成本和可用范围将在技术方案阶段确认。

## 范围外事项

- 绕过访问控制、反爬措施、登录要求或付费墙抓取全文。
- 将新闻报道自动转换为同行评审论文，或把自动发现条目写入正式科研数据。
- 对所有互联网内容作完整性或即时性保证。
- AI 摘要、翻译、热度评分、推送通知和投资建议。

## 澄清记录

### 2026-09-03

- 问：对于全学科出版集团，是否只保留可明确证明与超导相关的内容？→ 答：采用；依据题名、摘要、关键词或出版商分类判定。
- 问：出版商无公开关键词接口、不可用或限流时，是否允许聚合索引补充发现？→ 答：允许；必须区分 Crossref/OpenAlex 发现来源与出版商原文来源。
- 问：新闻是否包含科研报道之外的社会内容？→ 答：包含超导相关的产业、企业、政策和股票资讯。
- 问：Phys.org 应如何归类？→ 答：展示在期刊论文栏，同时明确标注为 `Phys.org 科研报道`，不冒充同行评审论文。
- 决定：本 Feature 新建 #88 作为 #63 的进阶版本；#63 及其 Spec 保留为已完成实现的历史记录。

### 2026-09-04

- 决定：OpenAlex 是聚合学术索引，只有 `article` 且主来源为 `journal` 的记录可作为期刊论文发布；仓储、会议和预印本记录不以该路径发布为同行评审论文。
- 决定：聚合索引的题名、关键词或分类直接命中超导词时可以收录；仅摘要命中时，必须同时存在临界参量、涡旋、配对、能隙、磁通钉扎等超导学术上下文，避免仅引用或提及超导的无关内容混入资讯。
- 决定：OpenAlex 免费接口不能按 `updated_date` 增量过滤，系统每次至少滚动检查最近 30 天的期刊文章并依靠身份键去重，避免延迟收录的论文永久漏失；明确未发表、未接收及 Zenodo 仓储 DOI 不作为期刊论文发布。

### 2026-09-08

- 决定：#88 只负责阻止新记录违反 OpenAlex 期刊与相关性契约；规则收紧前已经写入的 Zenodo 历史存量由 [Issue #92](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/92) 以可审计、可回滚的数据维护流程处理，不在本 Feature 中直接删除。
