# 科学图表读数实施计划（草稿）

Issue：[#227](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/227)。依据：[spec.md](spec.md)。2026-11-09。

## 实施边界

用户已要求完成本Feature。Python解析、React四宿主表单、MySQL科学图及对象存储沿现有架构；本机原生测试，10个上传Worker上限不变。标定使用既有PyMuPDF/Pillow/NumPy；读图精度保存在现有DocumentIR来源metadata及来源文字中，不新增科学字段。连续线仅在图中标记、原文明确条件或既有字段需要的明确横坐标处取数，不创建任意采样状态。

## 模块与数据职责

1. 原图和上下文：复用DocumentIR、真实PDF页/裁剪、稳定文件/块定位及既有查图工具，图内指令只作数据。
2. 图表解释：模型返回受程序字段约束的图型、物理量、面板、轴/色标、类别/系列及候选图中位置；不得创建权限、人工决定或新科学字段。
3. 标定与读数：数字标签按原图读取；坐标/色标估读需可重放的标定事实与精度。评估现有谱标定能力和必要开源组件，先验证许可证、图型覆盖及真实图片效果，不预先承诺接入某个库。
   轴端点由`axis_bounds`统一验证为有限的0..1000非零区间并排序，仅规范化图像位置。刻度对齐、柱边追踪、主轴/横轴/色标的坐标换算复用该入口；刻度值及物理方向不变。来源保留原`axis`和实际`calibrated_axis`，区分边界格式、刻度越界与数据越界。读图v4使旧完成缓存重新读取，旧块按既有版本失效规则保留；不直接改写业务草稿。
4. 科学整理：在前置Tc收录、材料状态规划及固定表单填写之间共享图文判断，不能把图中具体点在前置阶段排除。保留每点/柱/格与原候选的去向。
5. 来源和版本：读数事实进入现有来源链；读图精度与论文误差条分开。先检查`value_raw`及来源元数据是否足够；若需变更标准键/含义，先登记并由用户审查，再升级契约，禁止自动重录快照。
6. 核对与交接：复用当前科学核对和字段决定；实际值或真实依赖变化才失效，同版本复用。保存、返修、批准、公开读取都核验该来源事实。

## 质量门与顺序

独立面板只能使用请求区域内的原图，整幅内嵌图完全包含在裁剪区域时才直接取原位图。读图版本升级后保留旧派生块与引用，将其标记为不参与新提取；新读取仅用原始文字和真实图片，不拿旧读数作为新原文。未读说明按来源及内容保持稳定身份，每次原回执仍在覆盖报告和请求记录中保留。写盘前完整验证IR。

v2曾生成完全相同、仅阅读顺序不同的机器派生未读重复块。正常读取入口对这一类缓存先验证来源、内容、稳定ID及全部语义字段一致，完整IR验证通过后保留原字节备份和逐项恢复记录再原子写回；其他重复、冲突或新版本不兼容均保持拒绝。此兼容不写业务草稿、审核决定或数据库，不放宽通用IR唯一性。

- 规格的未决高影响项未确认前，禁止依赖它们实现契约或取样行为。
- 实现前保留真实失败响应，先证明回归能检出，之后覆盖正式提取、整理、后处理、校验和保存链。
- 不允许以放宽阈值、删除校验、扩大模型轮次或硬编码Peng2017补值取得通过。
- 修改科学表单/共享路径运行`test:field-contract`、`test:form-contract`、`test:form-contract:mutation`及受影响既有回归；旧失败独立基线单列。
- 最后通过原文件真实重跑和五阶段黑盒，回写Overview、原Spec替代关系及Issue验证；本轮不推送/远端部署。


## FR-014 高清图片传输

`backend/rag/image_inputs.py`在`complete_json`归档/预算/缓存前处理本次直接图片，按32像素块核验本机上游已报告的单图30000上限。超限时沿长边二分，保留64像素边缘重叠；对原图直接无损裁片，不缩放或覆盖原图。可信系统说明登记原图序号/大小/摘要、附件序号、像素框与片摘要，要求返回坐标仍按完整原图；原Image 2的精读标定契约不改。图片URL不主动抓取，历史工具消息不改写。分片产生新的请求身份，旧失败证据保留。该容量为实际边界，不以模型名称推断更多能力。
