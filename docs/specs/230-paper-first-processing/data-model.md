# 两阶段草稿与执行检查点

## 论文阶段

论文级值、依据和核对结论由该阶段掌管，使用既有ScientificUploadDraft和字段核对结果存储。`paper-stage.json`是执行检查点，保存来源/模型/端点身份摘要、完成标志及论文草稿；技术失败保留部分值和成功结论，但完成标志为false。

论文阶段不携带材料状态，内部只读核对明确限定`paper.*`；不向普通调用提供未绑定流程的科学编辑或提交绕过。相同来源和模型的完整检查点可复用，文件/文本、模型身份变化时不能沿用。

## 材料阶段

材料阶段引用已完成的论文草稿，只填写和核对材料字段；原research_materials不再从状态无条件重写。差异附到既有对应字段问题中，保留状态来源和论文原值，进入现有人工处理，不新增全表汇总或合稿。

## 进度

兼容既有任务大状态，附加`processing_phase`显示论文提取/填写/核对、读图、流程选择、材料提取/识别/填写/核对。失败及暂停显示实际子阶段。它是运行元数据，不是科学字段；未匹配仍保留已完成的论文结果，完整人工批准边界不变。

所有权在正式保存中同样生效：显式字段保留，漏传沿已有稿值，无绑定旧请求才兼容派生；管理员科学数据入口不更新论文级材料清单。没有新增标记键或数据库迁移。

## 材料组检查点

material-stage.json是服务端执行制品，不属于科学字段。source_identity绑定原状态候选、论文结果、原文、执行模型与版本；completed_groups仅保存正式草稿保存成功的前缀。每项保留原offset/state_keys、填写审计、核对结果、该组核对前状态和来源Claim；draft保留已完成组与尚未处理候选。遇到失败只更新预览和已成功保存结论，不将该组记为完成；恢复时验证前缀及身份。

state_keys限制核对选择范围，field路径仍是全稿全局索引；其他状态不归本组所有。material_batch是任务元数据，只表达真实运行情况。form_filling_report只存去向与科学审计摘要，所有层级attempts/输入全文留组制品，不进入草稿。
