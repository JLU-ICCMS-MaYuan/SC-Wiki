# 技术决策：PDF 解析详情紧凑布局

## 常驻栏定位

- **决策**：保留 `position: sticky` 和原有层级，顶部偏移从 8px 改为 0；竖向内边距从 12px 减少到 4px，保留不透明 `background.paper`。
- **理由**：现有顶部 8px 空隙会在滚动时暴露背后表单；按钮本身已有至少 44px 高，减少栏的额外内边距即可让总高度不超过 56px。
- **备选方案**：使用全局固定栏；会脱离当前解析卡片的生命周期和宽度，增加同步负担。
- **证据**：`frontend/src/pages/UploadPage.tsx` 当前使用 `top: '8px'`、`py: 1.5`、`bgcolor: 'background.paper'`。

## 横向边距

- **决策**：解析详情展开时，由上传页根容器抵消 `AppShell` 桌面 32px、窄屏 16px 内边距中的多余部分，使两侧各保留 8px。
- **理由**：空带来自 `AppShell` 的通用内边距；局部抵消可避免改动所有页面，收起后自然恢复。
- **备选方案**：让 `AppShell` 根据路由全程减小上传页边距；会影响未展开时的上传入口和任务列表。
- **证据**：`frontend/src/components/AppShell.tsx` 的 `main` 使用 `{ xs: 2, md: 4 }` 内边距。

### 后续修订：#126 全站统一布局

- **决策**：用户已确认所有应用页面左右各保留 8px，上传解析展开与收起均采用 `AppShell` 的统一边距；原局部抵消方案由 #126 移除。
- **理由**：统一全站后保留上传页负边距会使解析展开态超出视口，且收起态不应再返回 32px。

## 数据与接口

本次只调整已有 DOM 的样式，不新增持久数据、HTTP API 或组件间数据契约。
