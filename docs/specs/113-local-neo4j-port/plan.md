## 摘要与技术上下文

本计划补录 `7a614bb3` 的最小修改方案。目标环境为 Linux/WSL2，已有 Neo4j 5.26.29 和
OpenJDK 21；Bash 负责服务编排，Python 负责环境文件生成。认证和业务数据库沿用既有配置，
本次不新增实体、数据模型或接口协议。

## 配置与职责

| 位置 | 职责与最终值 |
| --- | --- |
| `scripts/lib-local.sh` | 本地启动端口 `NEO4J_BOLT_PORT=17687` |
| `scripts/setup-local.sh` | 新安装写入监听与公布地址，复用上述端口变量 |
| `scripts/gen-env.py` | 改写或补齐 `NEO4J_URI=bolt://127.0.0.1:17687` |
| `.env` | 已有本机应用连接地址；私有配置不入库 |
| `.local/neo4j/conf/neo4j.conf` | 已有本机 `server.bolt.listen_address` 和 `server.bolt.advertised_address` 同步为 `127.0.0.1:17687` |
| `scripts/local_deploy/config.py`、`scripts/local_deploy/environment.py` | #112 未提交代码中的配置默认值与端口检查清单同步；不纳入本 Bug 的代码提交 |

在 `7a614bb3` 中，`setup_neo4j` 发现已安装时会提前返回，所以此次同步修改了本机配置，不能只改安装脚本。
HTTP 端口仍为 7474；启动后公布的新地址还需通过 HTTP 根入口验证。

补录期间 #112 正在工作区改写安装入口，其新增 `scripts/local_deploy/runtime.py` 也使用相同的
监听和公布地址；这部分尚未提交，不替换本计划的实现基线，也不纳入本 Bug 的运行验收。
