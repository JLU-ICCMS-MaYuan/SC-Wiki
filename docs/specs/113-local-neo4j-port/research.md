# 调查与决策：Neo4j 本地端口冲突

关联 [Spec](spec.md) 与 [Issue #113](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/113)。

## 故障证据

2026-09-21 的 `.local/log/neo4j.log` 在 05:34:23 UTC 记录：

```text
PortBindException: An error occurred while trying to bind to the socket /127.0.0.1:7687
bind(..) failed with error(-98): Address already in use
```

当时 Linux `ss` 未显示该端口，但 Python 实际绑定 7687 返回 `Errno 98`。Windows
`Get-NetTCPConnection -LocalPort 7687` 显示 PID 6456 占用 `0.0.0.0:7687`，进程查询为 AweSun。
`wslinfo --networking-mode` 返回 `mirrored`。这些是故障发生时的证据，PID 与占用状态不是长期约束。

故障当时的启动脚本使用 Linux `ss` 预检端口，只轮询 HTTP 就绪状态，未因 Neo4j 进程退出而提前终止。
因此最终的 120 秒超时是退出后的等待结果；直接失败原因是 Bolt 端口绑定冲突。

## 决策一：固定改用 17687

- **决策**：经用户确认，本地默认端口改为 17687，并在修改前实际验证该端口可绑定。
- **理由**：允许保留 Windows 向日葵运行，改动局限于本地配置。
- **备选**：停止向日葵会影响远程连接；自动选择端口需要同步所有客户端，超出当前需求。
- **证据**：提交 `7a614bb3`；[Quickstart](quickstart.md) 记录真实启动与连接验证。

## 决策二：同步监听、公布和客户端地址

- **决策**：同步本机 `.env`、Neo4j 配置、共享启动端口与生成器，安装脚本明确写入公布地址。
- **理由**：只改监听端口会留下旧客户端地址；已有安装会跳过安装步骤，必须单独更新本机配置。
- **备选**：只改 `.env` 无法改变 Neo4j 监听；只改安装脚本无法修复当前安装。
- **证据**：现有凭据认证成功，HTTP 根入口 `bolt_direct` 返回新地址。

## 决策三：限定交付与验证范围

- **决策**：本 Bug 交付已提交的端口修复及文档；#112 两个未提交模块仅同步配置约定，交付由 #112 负责。
- **理由**：共享工作区存在其他开发任务，不能将其整体纳入本次提交或完成声明。
- **备选**：打包提交全部工作区会混入未经本 Bug 验收的部署功能，因此不采用。
- **证据**：`7a614bb3` 仅含 6 个文件；没有数据迁移、数据库内容清理或生产 Compose 修改。

## 验证限制

本机端口切换与认证查询通过不意味着所有服务已经启动，也不证明另一台机器、生产环境或外部 AI 服务可用。
本次没有声称实现通用端口检测修复。新端口仍可能在其他机器被占用。
