# 实施计划：可靠定位PDF区域并生成含完整图注的高清裁剪

Issue：[#232](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/232)；日期：2026-11-10；依据：[spec.md](spec.md)。

## 摘要

按原PDF可靠定位图、表、文字、公式，首次Fig裁剪完整保留整幅图和完整图注，再提供可回溯的独立面板精读；保证实际图像清晰度及坐标可追查。 本文件现记录本次实施设计与实际职责；验证结果见validation.md。

## 技术上下文

- 语言：既有Python后端与React/TypeScript前端；精确依赖版本在未来验收运行中记录，不凭旧日志冒充当前运行版本。
- 主要依赖：复用PyMuPDF、Pillow、NumPy及现有解析器/领域算法，FastAPI/SQLAlchemy、Redis/RQ任务及已有存储；不在本轮安装或升级。
- 数据：原件、DocumentIR、共享来源、模型请求检查点和正式交接快照；数据库结构/标准科学契约保持，具体关系见data-model.md。
- 目标：先本机隔离验证，不涉及服务部署或业务数据迁移。
- 规模：正文和SI，完整图/面板与必要原文；无主观图表数量上限，不承诺全版式自动准确。
- 性能：按实际输入记录图片尺寸/传输、缓存/渲染/模型用量；不设未讨论的准确率百分比或以放宽断言换通过。

## 设计决策

### 候选定位

采用：复用现有IR/PDF文字及绘图信息，结合图注构建多个候选，使用正文约束、切断/重叠检查辅助选择；保持原模型逐页盘点。

取舍：直接引入整个pdffigures2 Scala服务不是已采纳要求；只使用最近图注会误配。

### 规范坐标

采用：以明确的页面坐标空间为共同基准，解析器/归一化/旋转坐标经矩阵映射；输出像素取整后的实际原点和尺寸参与反变换。

取舍：不把0..1000整数框当无损真值，也不把72 DPI坐标参照当输出清晰度。

### 图像生成

采用：原PDF固定区域一次渲染；首次完整图含图注，随后局部直接按原坐标取图；原始位图清晰度单列。

取舍：从派生PNG反复截屏放大或直接取原位图而漏矢量轴均不采用。

## 兼容与回滚

旧来源缺少新定位时保持可用旧文字/原件及明确的未定位状态，不伪造新协议；历史不在普通读取时自动迁移。图像回执/提示/定位版本参与有效性判定，采用结果变化走既有核对失效；缓存可以重建，业务原件/证据/冻结快照不可随回滚删除。

## 必要复杂度

保留来源版本、API适配和动作检查点是为防止历史串位、模型未收到图或重试丢上下文。拒绝另建第二模型选择、第二重试器、永久图片副本和全表重核。内部观察协议不复制科学字段模型。
