# 实施计划

Issue：[＃176](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/176)。依据：[spec.md](spec.md)。

## 技术上下文与职责

Python 3.12、Pydantic、SQLAlchemy／MySQL、Redis；前端 TypeScript 5.6、React 19、MUI 7。沿用现有上传、返修和管理表单、稳定记录键、来源定位与科学记录存储，不迁移数据库。

新增 backend/ingest/scientific_form_filling.py 处理已组装状态的模型整理，不让论文摘要模型再次自由生成整份数据库草稿。复用 scientific_context.build_context 的原文分块和来源编号。模型接收明确字段契约、候选身份、来源目录和首批原文；可定向请求其他来源／搜索相关段落，完成后提交有候选去向的结果组。服务器解析并验证来源、数值结构、单方法、共同参数一致性及候选完整覆盖；失败保留原候选及诊断。每次调用与读源结果留档，取消检查和有限轮数防止空转。

upload_jobs.py 在科学候选组装后、最终 Claim 定位前接入。已有来源覆盖门保留，Tc 防遗漏门只在模型明确整理并经服务器验证的范围端点等价情形接受归并，不能全局关闭。

前端 predictedTcGroups.ts 以 predicted_tc 身份分流，不以 value_kind 更换表单。PredictedTcGroupEditor.tsx 提供固定七项、other 名称、历史错误内容说明与数值恢复，移除多余内部标题。读历史数据不改库；显式编辑转换时保留原始表达。SchemaDrivenRecordForm 继续负责计算条件和来源。

## 必要复杂度

保留候选去向是为防止模型整理时静默丢数据；它不承担科学语义判断。拒绝仅以端点相等删除记录、仅增加正则、删除全部来源门或建立第二套科学数据库。当前支持的其他科学记录为测量 Tc、带隙和费米能级 DOS，按各自定义处理，不把 Tc 规则套给它们；未新增解析支持的模块不在本次扩展。
