# 填写与展示契约

## 模型边界

输入：同一篇上传有效正文／SI 的来源目录、可读原块、材料状态及带稳定 candidate_id 的科学候选、字段说明。

输出：读取请求或最终整理。最终整理为分状态结果、每条结果的输入候选与来源引用、共同组／方法行、明确排除、未解决原因。所有原候选必须被覆盖；新补全结果也必须有原文。服务器不接收模型提供的数据库 ID、权限、审核状态或可执行脚本。

## UI 与保存

预测 Tc 始终使用固定共同参数／方法／配对布局。七个方法选项不被数据扩充；other 显示具体名称输入。方法文本不能当作 Tc；旧错误值以说明展示且不能变成代表结果。已有可选空 μ* 不编造，代表结果继续要求明确组合。

普通编辑和保存不请求模型。原文查缺只在解析或明确核对动作中执行；迟到响应遵循宿主版本保护。保存沿用当前接口，不引入全表刷新。

## 失败

模型输出非法、来源无效或候选遗漏时允许有界纠错；仍失败则保留原候选、响应和诊断，不返回虚假通过。取消原样传播。无来源、未报告、冲突、读取失败及技术失败分别记录。

## 2026-11-03 概述与详细范围的显式归并

FR-006 的模型语义归并补齐：整理响应增加程序定义的 `candidate_relations` 数组；无此关系时为空。每项仅含 `summary_candidate_id`、`canonical_candidate_id`、`relation=summary_of_range`、`source_ids`、`reason`。它是整理控制协议，不是科学表单字段，不进入 `payload` 或新增数据库列。

当前只处理“方法未知或与详细结果相同、无独立参数／条件的数值概述 → 同状态、同模块的已报告 Tc 范围”：模型必须明确判断同一结果并引用概述及详细范围的实际来源。程序检查候选存在且已映射、状态与记录类型相同、概述数值处于原详细范围内、结果仍覆盖详细范围原有端点及已知配对，以及声明来源同时对应双方原候选并已合并到输出。数值包含关系本身不构成归并依据；缺少模型声明继续拒绝。不同已知方法、独立 μ* 或计算条件不使用此归并路径，不能跨物相或压力。

报告保留原概述完整记录、原数值、映射目标、来源及理由。H3S 的真实失败例为概述 200 K 与同一 200 GPa Im-3m 的 191–204 K；未声明、来源错误、跨状态、已知 μ*、原详细端点被丢弃均须拒绝。原失败响应作为固定重放保存，不将添加测试声明的构造用例冒充真实模型通过；真实模型与原来源重新提取另行验证。
