# 实施计划：材料家族全文判断与目录优先

**关联**：[Issue #120](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/120)、[Spec](spec.md)。本文件记录 2026-10-11 增量；此前 FR-001～009 的实现仍以原 Spec 和任务记录为准。

## 技术上下文

- 两条 PDF 解析路径在 `backend/ingest/upload_jobs.py` 的全文汇总后生成同一论文级草稿；现有汇总提示词允许自由家族名称，草稿归一化只按名称去重。
- `material_families` 目录在数据库中，包含 ID、规范中文名、可选英文名及别名；上传表单已能显示目录选项和 `pending` 名称。
- #120 的 `check_mode=synthesis` 按语义核对材料家族，`supported` 仍须可定位的本文引句；#109 保存人工修改和来源版本。

## 数据流与实现

1. 在共用全文汇总后，独立读取当前目录与本次论文的全文来源。分类调用以摘要、本文材料状态、分段候选和原文为上下文，明确排除引用工作；超长来源先逐批提炼本文材料线索，再做一次整篇分类。模型返回每个家族的现有目录 ID 或新名称、理由与原文引句。
2. 服务端逐项定位原文引句，校验目录 ID；规范名/英文名/别名精确命中时改用目录 ID。无法定位依据的候选不填入；仍无现有语义适合项时才接受新名称为 `pending`。结果复用 `paper.material_families[]`；草稿响应增量返回服务端分析和错误字段，不新增路由、数据库表或批准事务。
3. 在草稿中保存服务端生成的分类判断快照，并把匹配当前字段值的理由及引句接入现有字段核对记录；用户改值后旧快照失效。目录或分类失败时保留其余草稿字段，材料家族为空并显示提示；用户仍可人工选择后提交。
4. 对唯一 H3S 草稿读取任务、来源哈希、当前草稿与字段核对，保存私有快照；使用同一分类逻辑重算。持任务锁并比较草稿版本；若已有正确目录 ID，仅刷新过期的该字段核对，不改其他值或人工记录。新旧结果分别重读核验。

## 验证与收尾

- 用真实目录读取与固定模型响应测试校验、去重、失败及两条路径；用实际 H3S 来源和当前模型验证语义匹配与证据定位。
- 仅对一份现有草稿执行定向重算，保留私有备份及前后差异；检查论文级分类、核对状态与其他字段一致。
- 验收后更新上传 Overview 的已实现行为；只提交本任务的文件片段，不纳入并行工作区修改。

## 2026-10-11 材料家族理由修正

复用已持久化的材料家族判断快照和字段核对记录。新结果由分类模型的具体理由与核对模型的结论组成；有效旧结果可在内容、来源版本一致时回用 `reason`，不能把空 `ai_reason` 解释成直接摘录。#109 共用证据层负责来源类别、缺理由和侧栏呈现；本 Feature 用真实 H3S 草稿验证目录 ID 不变且解释可见。数据生命周期见 [数据模型](data-model.md)，草稿和核对读写见 [接口契约](contracts/material-family-reason.md)。
