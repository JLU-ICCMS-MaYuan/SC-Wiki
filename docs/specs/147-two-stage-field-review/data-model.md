# 数据模型

## 2026-10-28 已确认基线与展示状态

不新增表。字段详情返回 approval_state 和 approval_message，区分有效通过/免审与仍待处理；can_approve 保留服务端资格语义。

本次定向修正的 field_decision 附 repair_id 和 authorization_origin；发生时间是本次授权修正时间，不是假定的旧按钮点击。上传状态追加 kind=field_review_baseline 事件，包含字段身份、精确值的规范化表示、内容/来源版本及相同 repair_id。旧 field_change 事件保留；changed_keys 从最近基线比较未来修改。数字采用科学字段已有 canonical 表示存入基线，避免 MySQL JSON 浮点末位变化；不改原草稿科学值。该事件只能由固定目标修正脚本写入，普通字段 API 不接收。

| 实体 | 内容与约束 |
|---|---|
| 字段身份 | 稳定state/module/record/extension身份与现有键；不以数组位置、名称或值作为身份 |
| 字段版本 | 最终值、对应证据版本、必要科学范围；与模型名无关 |
| 字段草稿 | 原始输入、可解析值、说明、预期草稿版本；正式记录不接收未完成数字 |
| 核对结果 | 逐字段状态、原因、证据、方法、版本、时间；通过不能由说明标记代替 |
| 提交版本 | 一次冻结草稿；权限、版本、所有必需字段结论同时成立才提交 |

数据所有权：现有草稿存储保存编辑内容，科学核对表保存历史与结论，后台队列保存进行中任务。字段说明不是科学数据更改；旧结果保留，不能覆盖迟到的新决定。关联上下文可以读取，不意味着共用结果。

管理员暂存使用scientific_review_drafts：paper_id唯一、owner_id、base_revision、base_fingerprint、draft、updated_at；正式论文版本变化时拒绝覆盖。

2026-10-22 已实现修订：人工审核决定与普通人工说明分开。人工通过保存操作者、时间、字段及所认可内容／依据版本，不要求理由，不改写 AI 判断来源；人工不通过保留原内容并进入修改记录。现有核对存储和审计历史用于持久化决定，同版本有效人工通过纳入提交复用。详见 [最新流程](review-flow.md)。
