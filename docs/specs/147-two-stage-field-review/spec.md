# 两阶段逐字段审核与稳定结果复用

**Issue**：[#147](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/147)

**创建日期**：2026-10-21

**状态**：原始方案已有基线实现；2026-10-22 新增的人工认可与三个模型入口规则已按用户要求建档，相关业务实现尚未执行。既有实现验收以 validation.md 为准。

**最新流程入口**：[人工认可与三个模型调用入口](review-flow.md)。包括三个流程图、完整新增原话、截图、替代关系及 FR-011—015 / SC-006—010。该修订优先于下文保留的历史原话。

## 背景与目标

减少重复检查，保证每个可编辑键有独立结果。编辑阶段只保存变化；模型只在上传解析、提交中的必要字段审核、侧栏主动核对三个入口调用。人工认可现有内容时正式保存人工通过决定，不要求理由且不调用模型；仅保存人工修改说明不授予通过。

## 需求结论与变更取舍

本轮最终计划替代 #145、#144、#139、#109 中与编辑自动失效、整条记录共用核对、人工确认绕过相关的旧行为；旧文档与审核历史保留。计算条件按软件、阶段、物相限定的科学规则继续有效，不恢复 QE-PBE 推断。保持页面整体布局，允许必要的前端逻辑和独立入口修改。

上段描述原始方案的替代关系。2026-10-22 修订将“保存”与“人工审核通过／不通过”分开：正式人工通过可在同版本提交复用，历史普通说明或旧接受标记不能冒充新决定。此前讨论的“推翻 AI 时补理由”已被最新要求替代，认可分支没有理由输入区。新增业务行为尚未实施，不能把本轮图示当成当前界面。

## 用户场景与验收

### US1：编辑与保存（P1）

用户修改名称、数值或说明，只有实际变化被保存，原问题字段去掉旧红框。点击“保存”不写入未修改的科学数据，也不授予通过；点击“人工审核通过”只记录对现有内容的认可。独立验收：监测请求、模型计数、字段标记、保存后的原始输入。

### US2：独立字段主动核对（P1）

当前字段读取自己的依据与历史；主动核对只改变该字段结果。独立验收：N(EF)名称改变不影响数值、单位的状态与原因。

### US3：稳定且不可绕过的提交（P1）

提交检查必要字段、复用未变化结论；失败仅归属本次有问题的字段；全部通过自动完成本次送审。独立验收：上传、返修、管理员直调接口同样受门禁约束。

## 功能需求

- FR-001：解析生成独立字段结论，收拢解析后和页面打开自动核对入口。
- FR-002：编辑、保存不科学核对；无变化保存零请求；支持原始中间输入。“完成”拆为保存和明确的人工审核决定；人工通过记录决定但不调用模型，见 FR-011。
- FR-003：按现有键独立身份、说明、结果、历史，名称、重排、父记录无关变化不影响身份。
- FR-004：主动模型核对当前字段；摘要与历史分开读取。
- FR-005：提交先做程序检查，实际人工修改且当前版本尚未核对的字段进入 LLM ②；已有同版本模型通过或失败结果按复用规则处理。合法可选空值不默认失败。
- FR-006：结果按最终值、证据和适用范围复用；恢复原值复用历史通过；同版本失败不语义重试。
- FR-007：压力/Tc等关系错误归修改字段，未修改字段历史保留但不冒充新上下文通过。
- FR-008：技术失败与科学问题分开；任务去重、一次技术重试、迟到结果与同版本模型矛盾保护。
- FR-009：提交冻结编辑并验证版本原子提交；旧接口和人工说明不能绕过。
- FR-010：有界继承旧数据，未证明覆盖的在首次提交检查，不在编辑新增红框；保留真实补充证据来源。

新增 FR-011—015 及 SC-006—010 以 [最新流程](review-flow.md) 的对应条目为准：无理由的人工认可、三个模型触发入口、修改保存分支、准确来源状态、旧候选待选事项处理。FR-010 的旧数据兼容不能另设第四个自动模型入口；无法证明通过的字段不得仅凭无红框视为已通过。

## 成功标准

- SC-001：连续输入及自动保存零模型调用、零全量核对刷新、零新增科学红框。
- SC-002：N(EF)、测量Tc、补充条件、论文信息、结构可编辑键逐项独立验收。
- SC-003：原值恢复、主动通过、部分通过复用；相同失败不通过重复提交重新问模型。
- SC-004：并发、迟到、模型故障不误提交、不丢输入、不覆盖有效通过；三类入口不可绕过。
- SC-005：447项基线局部保存P95目标1秒以内（不含模型及附件）；记录请求数、读取范围和耗时。

## 关键实体

字段：稳定实体身份加现有键。字段版本：值、依据和适用范围。核对结果：状态、理由、出处、方法和版本。草稿：允许中间文本的编辑内容。提交版本：同一次冻结内容及其门禁结果。

## 边界与异常

可选空值免审只适用于未修改且确实未报告；技术错误不变成科学红框。人工清空仍按修改审核。模型冲突保留有效通过并记录系统异常。结构原子不扩成新增人工项目。

## 假设、依赖与范围外

复用现有Redis/RQ、MySQL、FastAPI、React和Go审核入口。无待确认产品决策。不重设计页面、不修改真实科学数值、不推送、不代替管理员批准。

# 两阶段逐字段审核：编辑不重核，提交只检查必要内容

## 1. 确定后的使用流程

当前代码在解析过程中已包含字段核对、共用条件关联及部分再次核对，解析完成后还有自动任务入口。本次将这些入口收拢，形成下面的流程：

| 阶段或操作 | 要做的事情 | 红框与模型调用 |
|---|---|---|
| **PDF解析阶段** | 提取数据及证据；程序完成能确定的检查，无法确定的科学含义再交给模型 | 解析结束给出逐字段结论，只标对应问题字段 |
| **输入、修改、自动保存** | 记录并保存实际变化，不进行科学核对 | 不调用模型、不全量预检查、不新增红框；修改原红框字段后，去掉其旧红框 |
| **侧栏“完成”** | 保存当前字段的说明或实际改动，然后关闭侧栏 | 不代表审核通过，不启动核对 |
| **主动点击“大模型核对”** | 只核对当前字段，读取其证据及必要上下文 | 更新本字段的“AI理由”和红框；通过后，同版本提交时直接复用 |
| **点击提交／管理员批准** | 程序检查后，只对需要核对的字段启动模型任务；全部通过后完成这次提交 | 任一必需项失败就阻止提交，只标对应字段，并说明原因 |

上传、返修、管理员使用同一规则。上传成功仍是送审，不代替管理员批准。

提交审核期间暂时禁止编辑当前表单，避免审核版本与提交版本不同。其他页面发生并发修改时停止提交，保留已完成且仍有效的字段结果。

## 2. 字段独立、检查归属明确

以现有数据键为边界建立独立核对结果、证据说明、AI理由和历史，不新增跨字段的审核“大包”。

依次拆解和验收：

1. **普通物性**：N(EF)、带隙等的名称、数值、单位、值类型分别处理。
2. **测量 Tc**：数值、方法、实验条件分别处理。
3. **补充计算条件**：名称、值、单位、值类型分别处理。
4. **论文信息**：作者、通讯作者、共同第一作者、关键词等各自独立，取消通讯作者等定位到作者审核入口的归并。
5. **旧条件汇总与结构资料**：按现有可独立查看、编辑的键拆解；不把结构文件内部所有原子变成新增人工审核项。

核对一个字段可以读取其他字段作为上下文，**但不能因此合并结果或连带标红**。

按已确认的例子：压力从250 GPa改成300 GPa，而Tc保持331 K，若组合与证据不符，问题归到本次修改的压力，说明“新压力与现有Tc不对应”，阻止提交；Tc原来的历史通过结论保留，不能当成新压力下已经通过。

多个修改字段共同造成问题时，分别说明涉及的修改字段。未修改字段不承担本次改动的问题。

## 3. 模型、程序与结果复用

**程序负责：**

- 类型、必填、数值范围、单位格式和字段间明确约束；
- 可确定的单位换算、元素种类数、空间群映射；
- 证据文件、原文定位及来源版本；
- 权限、并发版本、提交完整性。

**模型负责：**

- 解析阶段程序无法确定的科学含义、分类、归纳和结果归属；
- 提交时所有实际人工修改过的数据字段；
- 用户主动点击“大模型核对”的当前字段。

程序已经发现明确输入错误时直接阻止，不先消耗模型请求。人工补充的图片、文本、PDF可以作为证据，但必须保留真实来源，不能冒充论文报告；一句人工理由不能绕过失败。

**复用规则：**

- 按最终内容比较。改动后又恢复到已通过的原值，证据与适用条件也相同，就复用。
- 已通过且未变化的字段，不再交给模型判断，不重复逐字扫描旧证据。
- 主动核对或前一次提交中已经通过的字段，下次提交未变化就复用。
- 同版本的未通过结果保留；重复点击提交不靠再次询问模型“碰运气”。修改内容、补充证据或主动核对后再判断。
- 同版本的新模型回答若与已有有效通过结论矛盾，记录为系统／模型一致性异常，保留原结论，不能直接新增科学红框交给用户。
- 模型超时、断网、返回格式错误属于技术失败：停止尚未完成的提交，保留输入和已有通过结果，提示重试，不伪造科学错误。
- 未报告且未修改的可选空字段继续免审。人工清空属于实际变更时仍按修改流程判断，但合法空值不能因“没有填写”自动失败。

每个字段版本最多建立一个有效核对任务；技术失败最多重试一次，不做为了得到“通过”而循环询问模型的语义重试。

## 4. 实现范围与接口

- **编辑与核对解耦**：取消输入事件中的科学失效判定和红框刷新。编辑时仅记录“待提交检查”；上次理由可查看，但明确属于上次内容。
- **局部保存**：增加统一字段草稿保存接口，提交稳定字段身份、实际变更和预期版本；未变化不发保存请求。原始编辑文本保存在草稿层，不能因尚未完成数字输入而丢失，也不提前写入正式科学记录。
- **独立字段身份**：身份不依赖数组位置、显示名称或父记录整体摘要。名称改变、组内重排、删除首条结果不使无关字段失效。
- **精简读取**：页面读取当前字段结论摘要；历史在打开对应历史页签时按字段读取。正常保存不构造整篇科学快照、不读取整篇历史、不加载PDF原文。
- **核对任务**：复用现有后台队列，区分解析核对、提交核对、主动单字段核对。模型请求可以批处理多个字段，但响应必须逐字段给出结论、依据和问题归属，禁止返回整条记录的笼统失败代替子项结果。
- **提交门禁**：提交时读取轻量当前状态清单，构造一次本次提交版本；选出修改、未通过或缺少可复用结论的字段。核对成功后，现有提交接口验证同一版本再原子提交。
- **取消旧绕过路径**：人工理由、已接受建议、“不提供证据的原因”和旧人工确认标记，均不能绕过本次必需审核失败。
- **旧数据兼容**：能证明旧通过覆盖当前字段且内容、证据未变的，保留通过；无法证明的放入首次提交核对清单，不在编辑时突然新增红框。历史记录不删除，恢复逻辑不在每次保存中执行。
- **界面**：保持整体布局；“让系统重新查找”改为“大模型核对”。补齐独立字段入口，同一个字段侧栏只展示自己的内容。程序错误也写入现有“AI理由”区域，但注明“程序检查”，不伪称来自模型。

## 5. 验收与建档

**必须通过的场景：**

- 连续输入、修改、自动保存：零模型调用、零全量核对刷新、不新增核对红框。
- 未修改点击完成：零科学数据写入；有新增说明时只保存说明。
- N(EF)只改名称：仅名称进入模型审核，数值和单位的结果、理由、红框保持独立。
- 修改红框字段：先去旧红；提交失败时只恢复该字段的问题红框。
- 改后恢复原值：复用原有效通过，不调用模型。
- 单字段主动模型核对通过：提交时不重复核对。
- 提交中部分字段通过、部分失败：整体不提交；下次只处理发生变化或仍待处理的字段。
- 修改压力导致与原Tc不对应：只标修改的压力并解释关系问题。
- 来源不变、值不变：模型切换或内部代码调整不能无缘无故推翻有效通过。
