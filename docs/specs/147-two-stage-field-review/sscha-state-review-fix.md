# #149 SSCHA 状态查证修复

关联 [Issue #149](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/149)，复用本目录的审核合同和新增状态流程。用户已认可两步方案，并明确“开始落地”。本修复不宣称整表批量入口已经完成。

## 实施与数据保护契约

1. 状态基本字段的模型输入独立携带材料、压力、物相、优化方式等 `state_review_context`；新核对结果及人工决定与该上下文绑定，内容与来源摘要之外同时检查上下文。旧结果不跨状态复制；相同字段、相同内容/来源且没有较晚范围编辑的既有结果保留，发生范围变更则不复用。核对请求版本包含当前范围，不能接受中途换状态的迟到结果。
2. 新增整行事件记录创建操作与值来源，操作者仍保留。初次新增的已填值可直接自动查证，不要求逐项先填人工理由；之后真正修改该字段或补充人工材料仍遵循现有修改规则。不因“新增”就授予人工通过。
3. 普通字段支持模型引用本次 sources 的准确编号，服务端取回原文；未知编号、错文件或不匹配引句拒绝。保留模型原响应。缺证、定位技术失败、科学矛盾分开表达；失败不拼接相互矛盾的肯定理由与“无需修改”。
4. 对历史目标只执行有版本检查的定向维护：先备份 Redis 草稿/状态与数据库检查记录；只选择目标状态仍未通过且非空的字段。模型看完整主文与附件，无自动填值和候选采纳；真实结果写入前重读草稿与字段/来源/范围版本，保留原输入及其他检查记录。
5. 历史新增来源归因只在此前独立备份能够证明新增状态时追加说明，不改写旧事件，不假定所有 null→值都属于系统提取。修复结果为模型核对，不伪造 human_confirmed，不提交或批准论文。

## 2026-10-22 实施与真实查证结果

- 增加 `state_field_review.py`：状态基本字段向模型提供 `state_review_context`，包含静态/SSCHA 及材料、物相、压力等。新核对和人工决定按范围复用；旧记录仅在字段/内容/来源匹配且没有晚于核对的范围编辑时保留，不能跨状态复制。请求版本和详情引用包含范围，来源摘要原算法保持，避免技术修复让其他字段普遍失效。
- 新增整行事件区分 `human_input`、`model_extraction`、`system_assembly` 值来源；创建操作者仍如实保留。初次已填值可以自动查证，已有字段从空白改成值或后续改值不借此跳过原人工修改规则。空字段不填充，不生成新的人工认可。
- 普通字段现在接受本次来源编号并由服务端取回原文；编号、文件和所指原段须一致。定位失败记为 `unchecked` 技术未完成，完整查证缺证仍为 missing；原模型肯定意见单独保留，不与最终错误提示拼接。
- 第一轮真实模型对 7 字段查证，1 项通过、6 项定位未完成。原始响应直接证明：模型重抄引句遗漏 PDF 文本中的 U+00AD 软连字符，肉眼相同而旧严格匹配失败。本轮根因有真实复现，不据此反推此前所有历史失败都只有同一原因。
- 新增仅用于引句定位的排版规范化与字符位置映射，恢复并保存真正的原始引句；数字、化学式和正负号变化仍拒绝，错误来源编号不跨片段兜底。独立保留旧 `normalized_text`，不改变来源身份摘要。
- 第二轮仅重查尚未完成的 6 项，均获得可定位且 PDF 文本层验证的原文并通过。最终 7 项为：材料维度、压力值、空间群符号、材料状态类型、结构家族、原始压力、压力单位。此前已通过的化学式、优化方式及超导数据没有重新核对或覆盖。
- 操作前备份完整草稿、任务元数据、持久记录、核对历史和来源。写入前持任务锁，重读草稿及内容/来源/范围版本；历史失败记录追加保留。只对有独立 7→8 状态备份证明的目标追加来源说明，不重写旧人工事件。
- 第一轮前到第二轮后的科学草稿完全相同，Redis 草稿原值与 MySQL 持久草稿均保持；未选中的 1,694 条检查记录的结果与决定摘要不变，新增人工确认数为 0。第一轮通过的状态类型在第二轮也未重查。
- 实际本地 HTTP 摘要和字段详情均读取到这 7 项 supported、有证据、can_approve=true。真实 Chrome 打开原生产页面路由，材料维度无红框、可显示三维氢笼原句，人工通过按钮可用，无页面异常。浏览器拦截所有业务写请求，未点击审核/提交，也未改变草稿。

## 验证与已知基线失败

- 42 项定向单元/接口回归通过：新状态初次排队、状态范围版本、字面与编号来源、软连字符原句恢复、错数字/化学式/符号拒绝、原审核复用与 PDF 质量检查。
- 48 项原有来源、科学证据和关联核对回归通过。
- 6 项真实 MySQL 外层事务回滚测试通过：人工决定、摘要/详情重开、字段范围持久化、不同优化方式的旧结果失效，不写入真实用户业务结果。
- 扩大测试另有 53 通过、4 失败，以及旧 backend 字段拆分套件 2 通过、6 失败。全部 10 个失败均在未修改 HEAD `a995900` 的隔离源码副本复现；涉及已经退役的条件修正调用次数、旧字段拆分数目及人工 API mock 签名，不宣称全仓回归通过，也未为这些失败放宽科学门禁。
- 最终代码经差异检查和本次保护边界核对后提交；未推送、未部署阿里云，整表“全部核对”入口仍属于 #147 的未实施范围。本次不代用户提交或批准整篇论文。
