# 接口契约

统一前缀 `/api/rag/evidence`，目标沿用 upload / revision / paper。所有写入检查登录、所有权和目标版本。

- 当前摘要：仅字段定位、当前值摘要、结果/理由与版本；不回传整篇历史及PDF正文。
- 字段草稿保存：稳定字段身份、实际变化、预期版本；原始输入保存在草稿；版本冲突409，不覆盖其他编辑。
- 字段说明保存：只保存说明，不进行科学检查、不授予通过。
- 字段历史：按item_key定向读取；不在普通保存/完成时调用。
- 核对任务：purpose区分parse、submit、field；主动field只允许一个字段；相同版本任务去重；返回逐字段结论。
  `/jobs.expected_draft_version` 接收 `/summary.version` 的草稿令牌；后端校验后构造科学快照。`expected_version` 仅用于已有科学快照令牌，两种令牌不得混用。完成响应的 `version` 仍是科学快照令牌，用于提交门禁。
- 提交：程序错误阻止模型调用；同版本失败不重新请求；通过后原子校验版本并调用原送审/批准事务。
- 技术失败：结构化错误，保留数据和已通过结果，不能写unsupported替代网络/格式错误。

旧接口同样检查严格门禁，不接受普通人工理由、accepted、旧 human_confirmed 标记作为新规则下的正式人工审核决定。

## 2026-10-22 人工决定契约修订（已实现）

- 新增单字段正式人工审核决定接口：稳定字段身份、正在查看的内容与来源版本、通过／不通过；操作者由登录身份记录。通过操作不接收或要求新的人工理由，保存真实点击决定，保留原值、AI 理由及依据。
- 新决定绑定同一版本并幂等；摘要、字段详情和提交接口共用有效性判断；同版本人工通过可以提交复用。格式、权限及并发错误仍拒绝，不能只隐藏红框。
- “保存人工记录”仍只保存人工修改及证据；修改分支的待审核内容不得使用认可原内容接口跳过模型审核。
- 模型入口只有 parse、submit、field：submit 在点击提交并完成程序检查后选出尚未核对的人工修改；同版本有效通过不重核，同版本科学失败不自动再问模型。
- 来源详情绑定当前字段及其结果版本，明确加载／错误／无来源／历史来源，避免空摘要被误读为无证据。

实际接口：`POST /field-decision` 请求为 `target`、`target_id`、`item_key`、`action=approve|reject`、`review_token`；无需理由。响应包含当前 `record`、新的 `review_token`、`can_approve` 和 `source_state`。令牌绑定字段内容、依据及用户查看的结论；过期返回 409，目标权限仍由服务端验证。来源详情通过 `GET /field-detail` 返回相同契约，`history=true` 仅返回本字段历史。

2026-10-23 修订：`can_approve` 仅表示当前未解决红框项是否允许人工通过，已通过和免审项返回 false；不能把普通“不通过”入口一并禁用。相同版本的已保存人工决定仍幂等返回，响应中的按钮资格为 false。前端结合可见红框状态控制按钮，只有收到已保存的正式决定才消红并关闭；旧摘要／详情不覆盖新决定。见 [状态回归](../approval-state-regression.md)。
