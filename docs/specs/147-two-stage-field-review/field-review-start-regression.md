# 主动核对反复提示版本失效

关联 [Issue #147](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/147)。本轮为已确认的 FR-004、FR-006、FR-008 及 SC-003、SC-004 修复，不改变整体布局和提交门禁。

## 原始需求记录

μ* 的设置入口已补回归测试，验证侧栏能打开完整设置并保存。确实是能保存。为什么我点击“大模型核对”之后又跳出来这个界面。我希望的是你直接调用大模型核对之后，如果确实按照我给出的 AI 人工记录的理由，核对了证据或者没有证据核对了没有证据的理由，就直接通过保存就行。等到提交的时候，就不需要再核对这个字段了。

现实情况是：我反复点击“让系统重新查找”，就会开始核对证据，然后又要重新核对。

## 根因与测试遗漏

1. `/summary` 为保持轻量返回 `draft_version(draft)`，前端却把它作为 `/jobs.expected_version` 发送；后者需要包含科学内容与来源的快照版本。两个不同定义的摘要被直接比较，首次排队前就报错。重试重复同一请求流程，因此无法解除。
2. 主动核对前仅刷新普通说明队列，没有保存侧栏尚未提交的人工依据。旧代码可能核对到上一次保存的说明。
3. 无附件时，人工判断理由与未提供证据理由未进入字段来源版本。理由修改无法准确撤销旧结果的适用性。
4. 旧核对规则在无论文引句时直接降为 missing，不能表达模型已评价无证据说明且认定当前值成立的结论。
5. 上一轮侧栏保存测试未贯通真实摘要与启动任务的版本契约；前端模拟返回相同版本字符串，掩盖了错误。本轮接口测试用真实摘要与快照生成逻辑，直接验证二者不同及旧请求必然失败。

## 修复与验收

- 摘要保持轻量。任务新增独立的 `expected_draft_version`，启动时在目标锁内校验草稿，再构建科学快照；旧 `expected_version` 语义保留，不能取消版本检查。
- 主动核对先保存当前侧栏人工说明及附件；缺少必需说明或保存失败时留在侧栏，不能忽略输入发起核对。
- 主动单字段不再倒数三秒；只排队当前字段。成功持久化后关闭进度与侧栏；不通过则显示该字段理由。
- 模型读取真实人工理由、无证据说明及附件；无证据路径必须额外给出具体 `manual_reason_review`，确认理由成立且当前值 supported 后才保存为 `model_reasoning`，不冒充论文报告或人工确认。说明本身不能绕过科学失败；计算条件继续受已确认规则约束。
- 理由、无证据说明及附件元数据进入该字段来源版本；内容不变则复用，真实变更后重新判断。核对期间依据变化不能把旧回答当成当前结论。
- 同版本已通过结果从存储恢复后，提交无需新模型任务；前端在等待期间发生新编辑时也拒绝覆盖新状态。
- 错误后的操作文案为“重试核对”，不再暗示用户要不断重新查找证据。
