# 实施计划：浅度论文解析与直接入库

**Issue**：[#241](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/241)；日期：2026-11-12。
**Spec**：[spec.md](spec.md)。用户“开始落地”授权在已确认需求内实施。

## 摘要

复用文件读取、草稿、论文写入与搜索；浅度在读取原文后执行独立的论文级提取，不进入论文核对、适用性判断、科学提取或审核。上传完成后明确选择模式，再原子入队。历史客户端维持深度默认。

## 技术上下文

- 语言：现有 Python、TypeScript/React、Go；依赖 FastAPI、SQLAlchemy、Redis/RQ、Gin/GORM、MySQL。
- 存储：任务状态保存模式；程序注册浅度流程绑定并随草稿及上传历史保存。正式论文用 published 表示直接收录，保留 approved 专用于既有审核链。
- 检索：复用 chemical_systems 保存论文研究材料的可解析元素集合；不创建 superconductor、材料状态或物性。
- 测试：pytest、Vitest、Go；独立数据库和文件目录验证，禁止操作业务数据或应用迁移。
- 性能：浅度科学提取、核对和审核零调用；普通输入及保存零模型调用，无变化保存零写入。论文匹配使用数据库查询、去重后分页。
- 范围：上传及共享编辑器、正式提交、论文详情和搜索；保留四宿主深度回归。

## 文档结构与源代码职责

本目录包含 Spec、Plan、Research、数据模型、接口契约、Tasks、Quickstart 和需求检查表。
代码入口：backend/api/upload_tasks.py、backend/ingest/upload_tasks.py、parsing_workflows.py、
shallow_parsing.py、upload_jobs.py、backend/api/rag.py；Go 搜索及论文详情；
frontend 上传面板、模式选择、共享编辑器和搜索入口。

模式由服务器任务状态持有；浏览器编辑不能改写绑定。浅度提取单一职责，不给旧深度函数增加多组跳过核对开关。
浅度提交复用同一正式事务，按服务器模式跳过科学持久化及审核交接。原文件、题录、作者身份及分类候选仍保存。
published 不伪造审核人、审核时间、approved_revision 或 reviewed 事件；RAG 的 approved 门不随之放宽。
