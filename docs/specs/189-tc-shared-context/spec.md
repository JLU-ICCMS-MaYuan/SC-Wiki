## 背景与目标

一个确定材料状态、一套确定电子结构与声子计算资料和同一个 Tc 方法下，可以有多个 μ* 对应多个 Tc。结果点不同，不要求为每个点再存一整套相同方法、参数、计算条件和来源。

本功能调整共同资料的持久化组织和对应关系，使共同部分只存一份，各点保留自己的身份、配对与独有内容。科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。


### 当前实现核对

- [#94 的正式多点实施决定](../94-property-record-editor/tc-multi-result-implementation.md)规定每个显式 μ*–Tc 组合沿用一条 `predicted_tc` 记录，共同 λ／ωlog／条件逐条保存，分组元数据用于组织表单。因此现有界面已共用不等于共同资料已只持久化一份。
- `backend/ingest/tc_groups.py` 已检查共同参数组、方法和点的身份及一致性。不能仅删除重复字段而丢掉这些科学边界、稳定身份和现有读写能力。
- #181 区分电子结构、声子、振动处理与结构优化语义。本文在明确材料状态和实际计算资料范围内共享，不把不同层次的方法混装。

### 需求结论与变更取舍

- 采用“共同计算资料、方法及其专属设置、多个结果点”的关系；同一份真正共同资料只保存一次，点通过明确归属读取。
- 保留已存在的共同参数组和方法行含义。共同资料有真实适用范围，方法专属设置仍归对应方法；不因软件名、方法名或压强相同就自动合并。
- 点保留 μ*、Tc、稳定身份、代表标记及真正独有的参数或证据；不要求每个点都独立上传相同出处。
- 共享范围内的一次共同资料修改，应由相关点读取同一新资料；只改某点 Tc 或 μ* 不改其他点，也不使无关共同资料反复核对。
- SCDFT 可表达 μ* 不适用，不能用 0 或惯例值伪装缺失；有特殊实现按原文实际报告保存。
- #94 中共同资料逐点持久化的旧决定需要在本功能调整；其现有前端设计、组布局与代表选择入口保持。

## 用户场景与验收

### US1：多个结果点读取一份共同资料（P1）

编辑者在原有表单里查看同一组多个 μ*–Tc 点，所有点共享真实相同的计算资料，无须重复填写或保存。

**优先级理由**：这是减少重复数据且保持科学含义的核心价值。

**独立验收**：以同一明确计算组至少三个结果点为夹具，保存后检查持久化共同资料数量并重新读取全部结果。

**验收场景**：

1. **假如** 三个点使用同一材料状态、计算资料及 Tc 方法，**当** 保存，**那么** 真正共同的资料只持久化一份，三个点均可完整读取。
2. **假如** 用户在原共同参数区修改共同条件，**当** 保存后重开，**那么** 适用组内各点读到同一修改，不产生逐点不一致副本。
3. **假如** 仅修改一个点的 Tc 或 μ*，**当** 保存，**那么** 其他点与未修改的共同资料保持原样。

### US2：配对、独有依据及组归属始终准确（P1）

用户新增或删除结果点后，仍能确定每个 Tc 对应哪个 μ*、哪种方法及哪份来源。

**优先级理由**：去重不能丢科学对应关系或错合不同计算。

**独立验收**：覆盖共同证据、独有证据、删除首点、不同实际条件及多方法的正反例，检查保存重读、送审及导出。

**验收场景**：

1. **假如** 同一表格支持多个结果点，**当** 关联证据，**那么** 表格可共享，各点仍保留必要的行列或配对关系，不重复上传。
2. **假如** 某点有独有证据或参数，**当** 保存、重读或导出，**那么** 独有内容仍属于该点，不扩大为全组共同结论。
3. **假如** 删除第一个点，**当** 重新读取剩余点，**那么** 稳定身份、μ*–Tc、组归属、来源和代表身份不串位。
4. **假如** 两条记录材料名或方法名相同而实际计算资料不同，**当** 整理共同资料，**那么** 不自动合并或用其中一套覆盖另一套。

### US3：现有页面设计保持，适用方法正确表达（P1）

科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。

**优先级理由**：用户明确要求不修改现有前端页面设计。

**独立验收**：在上传、返修、管理员、超级管理员及只读展示中对照原页面，验证现有操作与 SCDFT 存取。

**验收场景**：

1. 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。
2. **假如** 论文使用不适用经验 μ* 的 SCDFT，**当** 保存和送审，**那么** 可保留“不适用”含义，不强填 0 或其他数值。
3. **假如** 特殊实现报告了方法专属参数，**当** 保存，**那么** 按原文及实际归属保留，不以通用方法规则删除已报告资料。

### 边界与异常场景

- 未报告、未知、不适用和真实零值不能互相冒充；本 Feature 不推算缺失科学参数。
- 只有明确科学归属的共同资料才能共享；来源不同或条件相互矛盾时不能按相同名字粗略合并。
- 删除或清空代表点不自动为用户选择另一个点；保留已有代表身份与选择入口，不借重构代选结果。
- 读取冻结快照时使用该版本共同资料，不跟随当前工作稿修改；本 Feature 只定义共同资料的冻结读取约束，不实施全部快照生命周期。
- 历史无明确分组或真实共同资料不一致时保留可读，不通过打开页面自动合并、修复或删资料。
- 部分失败、权限变化或迟到响应不能造成孤立点、错绑资料或覆盖新输入；继续遵守既有保存与审核边界。

## 需求

### 功能需求

- **FR-001**：在确定材料状态、确定电子结构／声子计算资料及对应 Tc 方法的明确适用范围内，真正共同的方法、参数、计算条件及来源必须只持久化一份，各点通过明确归属读取。
- **FR-002**：共同资料、方法及其专属设置、结果点之间的关系必须明确，保持现有共同参数组和方法行的科学含义，不将不同方法或实际条件强行合并。
- **FR-003**：各点保留稳定身份、μ*–Tc 配对、代表身份及确实独有的参数或依据，不因共享而丢失或串位。
- **FR-004**：共有表格／出处可以被多个点使用，不强制重复上传；每个点仍能还原必要的对应位置与适用关系，独有证据不得扩为全组结论。
- **FR-005**：共同资料的真实修改由其适用点读取同一新内容；只改某个点的 Tc 或 μ* 不改变其他点及未修改共同资料。
- **FR-006**：新增、删除、保存、重读、送审、批准读取、快照读取与导出必须保留完整值、组归属、配对和证据；删除前序点不按数组位置换绑。
- **FR-007**：不得仅凭材料名、压强、软件或方法名相同就自动合并实际不同的科学资料；矛盾、不明确或不同范围保持分开。
- **FR-008**：SCDFT 支持 μ* 不适用，不以 0 或惯例值替代；特殊实现按原文报告保留。未知、未报告、不适用及真实零值分别表达。
- **FR-009**：科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。
- **FR-010**：原有代表结果身份与选择由用户控制，不因底层共享代选或自动改选；原始科学值、来源类型及 #181 方法语义保持。
- **FR-011**：上传、返修、管理员、超级管理员四类科学表单和只读展示保持一致；输入及普通保存不得因共享新增模型请求、无关核对或整表扫描。
- **FR-012**：共同资料须支持冻结版本的独立读取，工作稿修改不改变旧快照；本 Feature 不实施交接和公开版本切换流程。
- **FR-013**：旧数据兼容与迁移须在后续设计中明确有界方案；建档或读取不得自动批量改写真实论文、合并历史组或删除科学资料。
- **FR-014**：实施后必须验证实际持久化去重、完整科学往返、共同与独有依据、现有界面保持及受影响回归；执行仓库科学表单契约与变异检查，不能只以页面看似共享证明底层只存一份。

### 关键实体

- **共同计算资料**：明确适用于一组结果的方法背景、已报告的共同参数、条件和来源，不等于同材料下全部记录。
- **Tc 方法及专属设置**：对应实际计算方法和仅属于它的资料，不能与电子／声子／结构优化层次混装。
- **结果点**：一个具有稳定身份的 μ*–Tc 对应结果，保留其真正不同的参数、依据及代表身份；μ* 不适用时如实表达。
- **来源适用关系**：一份资料支持哪些组、方法或点及对应位置，区分共有与独有范围。
- **冻结共同资料**：快照时刻固定的共享内容，不随当前工作稿覆盖。

## 成功标准

- **SC-001**：同组至少三个 μ*–Tc 点，持久化检查确认真正共同资料只保存一份；全部点重读后信息完整，独有内容未丢。（FR-001～004、014）
- **SC-002**：共同条件修改及单点 Tc／μ* 修改两类场景中，前者仅影响实际适用点读取的共同内容，后者不改变其他点或未改资料。（FR-005）

- **SC-005**：SCDFT μ* 不适用、特殊实现明确报告、未知／未报告及真实零值案例保存与送审均保持原义，不使用虚构默认值。（FR-008）

## 2026-11-04：方法身份与逐结果原文写法分离

### 追加原始需求记录

**．先让 AI 把方法与温度对应清楚**

结合原文，明确：

- 使用什么计算方法。
- 哪些 Tc／μ\* 组合属于这个方法。
- 这些结果属于哪个材料状态、哪套计算条件。
