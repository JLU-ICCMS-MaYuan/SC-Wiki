# Rollout 契约

## 阶段

- `legacy`：仅旧链路。
- `shadow`：旧链路结果服务用户，新链路只保存对照结果。
- `gray`：按允许名单/比例启用新链路；新链路失败时任务可以显式回到旧链路，但不会在解析器内部静默切换方案。
- `default`：新链路默认；任务仍可显式选择已支持的解析方案，旧链路保留为任务级回退。

## 门禁

默认切换使用当前已逐篇人工核对论文的详细比较报告，满足 SC-001～SC-003，且失败收敛和旧缓存回归通过；不设固定篇数或类别齐全要求。配置不满足门禁时拒绝进入 `default`。解析方案通过任务策略选择并记录；不要求用户长期绑定某个解析器。

## 观测

每次运行记录主阶段、`reading` 子状态、解析方案、解析器、版本、错误码、耗时、token/资源统计和最终路径；不记录密钥或思维链。

## 默认切换报告

`UPLOAD_PARSER_QUALITY_REPORT` 指向维护者提供的本地 JSON 报告。当前检查字段为：

- `annotated_papers`：当前已逐篇人工核对的论文数，用于校验报告明细与分母一致；至少有一篇，不设批量配额。
- `new_f1`、`legacy_f1`：新链路不低于旧链路。
- `new_complex_recall`、`legacy_complex_recall`：已有复杂样本召回率不得退步；当前没有复杂样本时两者为 0。
- `evidence_location_rate`：至少 0.95。
- `unsupported_writes`：整数 0。
- `failure_recovery_passed`、`legacy_revision_review_passed`：必须为 true。

缺项、非有限数值或不满足门槛时拒绝 default；未知 rollout 配置也报错，不静默换模式。
显式选择 legacy 的任务不受维护者默认方案覆盖。

报告必须具有 `benchmark_version: "1"`、人工核对标记、四个输入摘要、当前出现类别的样本数、
新旧逐论文计数、逐类别指标及独立验收引用。只提供上述汇总字段的早期报告不再接受。
配置检查重算逐论文总计，核对新旧论文集合与分母；只检查当前已出现的类别是否退步，
没有出现的类别保留未验证状态，不用复杂总计掩盖已出现类别的退步。

通过 `python -m backend.ingest.pdf_benchmark` 生成报告；格式和口径见
[评测说明](../../../../tests/fixtures/issue114/README.md)。合成集不计人工论文数，
未实测资源保留 null。上传运行与导出已通过本机 API/RQ 路径接通；用户逐篇确认的
真实模型质量记录仍需积累，T002/T030 按实际验收保持未完成；维护者须审核输入和独立验收真实性。

## Shadow 任务隔离

`UPLOAD_PARSER_STAGE=shadow` 时，旧链路任务保留真实用户草稿，同时为 PDF 创建内部
对照任务，采用 `UPLOAD_PARSER_DEFAULT_PROFILE` 指定方案。显式选择新方案的任务不
再生成第二份对照。两个独立 RQ 作业能由不同 Worker 并行执行；只有一个 Worker 时
顺序执行。文件先复制并核对 SHA-256，任务、缓存、凭据与产物分开保存。

内部任务不进入用户任务列表，不占用户可编辑任务额度，拒绝从上传、校对、补证或
提交 API 访问。它不登记结构来源、不保存科学核对建议、不写正式论文；解析器失败
不换方案，父任务结果不受影响。父任务取消后，对照任务在下一取消检查点停止；
对照作业有 1800 秒任务超时和入口失败回调。

父任务 `shadow-comparison.json` 比较两份 `result.json.ai_values`，不读取人工编辑值。
保存同源摘要、运行状态、错误码和记录差异；相同记录数不是准确率，不替代人工基准。
灰度任务级显式重新选择与全部回滚验收仍待 T029 完成，不因 Shadow 可用宣布全部上线。
