# H3S：500000 字符上限与 Codex 实际抽取对比

日期：2026-09-28  
关联：[#114](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/114)  
来源、原图核对与文件摘要见 [首轮案例](2014-h3s.md)。

## 本轮结论

已实际重跑 PyMuPDF、Docling、MinerU，并按用户选择调用 Codex（gpt-6-astra）抽取两份文件。三种解析器产生的 IR 与 9 月 24 日完全一致；用户保存的 max_chars=500000 已生效，六份输入均能分段，不再触发此前的单页超限。

**就本例的 Tc 和计算条件，MinerU + Codex 给出的科学信息更完整；就表格结构和单元定位，Docling 更好。当前三组都不能直接作为合约通过、已审核的表单。** 共同接口问题与化学式归一化缺陷尚未修复，不能承诺整张表无须人工核对。

本轮没有向模型提供参考答案，没有填写正式论文库。结果是 Codex 的真实首轮候选，不是上一轮助手整理的参考草稿。诊断检查没有绕过门禁生成 ready 任务。

## 调用方式与可复核边界

- 全部使用同一模型 gpt-6-astra、现有高推理配置、相同领域提示和返回契约，每个解析器分别提供正文、补充的完整 IR。
- 原 Codex CLI 0.148.0 被服务端以“模型需要更新客户端”拒绝。临时安装 0.157.1 后实际调用成功，没有升级用户的全局安装，也未复制凭据进 SC-Wiki。
- CLI 临时会话只保留最终结构化输出及必要运行摘要，不保存内部推理文本。模型提示禁止额外工具和联网。
- 早期脚本把 CLI 的弃用配置告警误判成工具使用，导致调度提前结束；修正判定后复用了已有最终响应，并完成剩余调用。正文三个调用的 token 统计没有保留，不据此计算总费用。
- Docling 正文返回的内部 JSON 缺少末尾两个闭合符号。仅为诊断追加了缺失的 ]}，没有改动事实，原始响应和修复记录同时保存。它不能算作未经修复即可通过的输出，也不能靠补闭合符证明没有漏项。
- 没有把三组结果接入真实上传任务或发布流程；均未通过当前 normalize_extraction 契约。下列“定位通过”是在诊断中独立检查来源，不代表整个上传成功。

## 引句与补充材料

| 方案 | 正文 Claim 可定位 | 补充 Claim 可定位 | 补充内容表现 |
| --- | --- | --- | --- |
| PyMuPDF + Codex | 26/26 | 8/8 | 提取 6 个相/压力状态及 2 条动力学稳定性记录；未填出晶格参数值 |
| Docling + Codex | 20/20 | 8/8 | 同样保留 6 个状态及 2 条稳定性记录；表格底层有单元坐标，但未转成结构表单 |
| MinerU + Codex | 29/29 | 4/12 | 额外输出四组晶格参数，数值与原图相符，但对应引句不合格 |

这些分母不同，不能直接用百分比排名。MinerU 多出的 8 个未定位 Claim 对应 4 个结构状态及其晶格参数记录，不是 8 个不同科学数值错误。

MinerU 的结构引用使用了类似“R3m / H(9b) a=4.405 / ... / (130 GPa)”的拼接省略引句。真实原文没有这段连续引句，定位校验正确拒绝。必须重新绑定确切原文片段；表格本身又缺少独立单元 bbox，不能把数值正确等同于证据交付已经完成。

三种解析器的数学符号与表格差异仍与首轮相同：文本层有等号/负号/乘号失真，OCR 也有局部 H3S3、列合并、Wyckoff 字母问题。Codex 在正文中依据其他 H3S 出现位置避开了错误化学式，但这不证明 OCR 错误普遍能自动消除。

## 共同的程序问题

### 领域提示与实际表单契约不一致

- 模型输出 allen_dynes_modified_mcmillan 或 allen_dynes_mcmillan，术语含义正确，但后台只接受 allen_dynes。
- thermodynamic_properties、vibrational_properties、phonon_properties、structural_properties 不是当前注册模块。
- 当前提示本身提到 omega_log_k，前端默认参数控件使用 omega_log；software、q_point_mesh 等键也与 calculation_code、q_grid 不一致。
- μ* 范围返回对象，但现有 μ* 控件是单数值；需要规范范围表达，不能擅自取一个端点。
- 小于 37 GPa、大于 180 GPa 的单侧范围不能完整落入当前“必须同时有上下界”的规则。
- 稳定性、晶格参数和原子坐标应按各自实体承接，不能要求它们都变成 Tc，也不能因为没有输出这些字段就认为人工工作少。

这些问题应优先通过明确枚举、字段映射和契约修复自动解决，不应要求用户反复改代码名。当前六份候选均被契约拒绝；本轮没有为了通过而删除问题记录。

### 化学式归一化会改变材料身份

实际只读调用当前函数得到：

| 模型原值 | 当前草稿归一化结果 | 判断 |
| --- | --- | --- |
| H3S | H3S | 正常 |
| (H2S)2H2 | H2S | 错误，丢失括号与组分 |
| (H₂S)₂H₂ | H | 错误，丢失下标与其他元素 |

原文的 (H2S)2H2 与 H3S 化学计量比例等价。模型保留分组写法本身不是科学错误；现有程序截取其中一段作为化学式才是错误。

本轮 Docling 正文和各组补充输出确实使用了这些表示。虽然当前更早的契约门阻止了提交，仍必须先修复完整化学式解析，不能仅修枚举后就放行。这是程序缺陷，不应算作某个解析器的科学错误。

## 仍需保留的人工判断

- 原文对 Im-3m 报告的 EPC 分量 18.4% 与 82.6% 合计 101%。三组保留了原值；应标明原文不一致，不自动改成“凑够 100%”的数字。
- 相级共有计算条件与逐压力独立报告要分清。
- 空间群号、元素数等程序派生值不能标成论文逐字报告。
- 图像、引用文献、结构表的覆盖处置仍需单独规则；不能用“每个块都有 Claim”代替覆盖语义。
- 原子坐标、完整 CIF 与所有附加物性的穷举正确率没有在本轮得到证明。
