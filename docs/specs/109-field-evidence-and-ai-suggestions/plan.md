# 实施设计

依据 [需求](spec.md)、[数据模型](data-model.md) 和 [接口](contracts/api.md)。React/MUI 共用编辑组件；Python 承担解析、核对与建议；Go 承担批准事务。原 FR-001—014 复用现有 MySQL 结果；US5 的人工文件证据需要独立持久化及私有文件存储。

## 实施路径

1. 扩展共享字段清单，纳入书目与空可选字段。字段浏览覆盖全部项目，提交门禁仍只约束实际存在的断言；派生字段继续用确定性规则。
2. 扩展来源依据类型与说明。上传汇总后使用同一字段快照生成推断、推测和证据；有效结果直接补入主表单，重建快照后保存与新值绑定的类别和 AI 理由。生成失败保留已提取草稿并暴露可重试状态。复用模型配置与可取消执行。
3. 全量管理员复核显式声明任务目的，重新送入所有非派生项目、已有 AI 理由与原判断。自动填写与独立审核不能共享跳过条件；所有结果通过确定性来源定位与字段类型校验。
4. 上传草稿与正式来源保留依据类型及 AI 理由；上传者只获得提交待审资格，管理员批准仍校验逐项人工决定。自动填写来源和 AI 核对状态分别存储，不能相互覆盖。
5. `EvidenceFieldMarkers` 分离可点击与问题样式，复用原标签，补全数据字段锚点；`EvidenceWorkflow` 移除接受列表，空态和成功记录共用侧栏。缺少锚点的结果保持折叠备用入口，避免堆满顶部。
6. 验证上传到审核再到永久来源/RAG 的链路，更新 Overview 和 README 的对应段落。

## 新增实施路径（FR-010—014，验收中）

1. 在共享核对结果读取路径统一判定当前 `supported` 是否具备可定位原文、有效人工来源或带已核验输入的确定性推导。概括字段保留语义判断，但不能以定位失败的 AI 文字替代相关原文；更新规则版本，旧结果只作历史查看。
2. 将系统原文、人工修改记录与 AI 理由分开组织。系统原文置顶并默认展开，文本直接显示引句；确由图像支撑时显示可靠的原 PDF 区域。旧 `legacy` PDF 未保存区域坐标时，仅在文件哈希匹配且引句于原 PDF 文本层唯一出现后，按需渲染实际页与逐段高亮；否则说明缺口，不猜测位置。长来源可折叠，图片不可用时仍保留已有引句和定位信息；侧栏不输出 JSON，也不重复主表单的字段值。
3. 复用现有字段身份、来源定位、持久核对结果和上传转论文映射，不新增第二套证据存储。针对无来源、概括多论断、派生输入失效与跨文件同名引句分别验证状态和门禁。
4. 用真实上传/审核数据路径和浏览器验证三入口及转接后的依据可见性，完成后才更新 Overview、README 和 Issue 验收状态。

## 人工修改与证据实施路径（FR-015—021，验收中）

1. 服务端按稳定字段身份和规范化值对比解析基线或当前论文版本，识别实际人工修改。沿用自动保存允许半成品；显式提交、重新提交和批准时逐字段检查理由，缺少人工证据时同时检查缺证原因。完整的人工说明允许无论文出处的修改进入待审，但不授予 `supported` 或管理员批准资格；更改值使旧说明变为历史。
2. 增加独立的 `scientific_manual_evidence` 持久记录与迁移。每条记录绑定目标、字段、修改前后摘要、提交者、理由、缺证原因和证据条目；图片及文本文件存私有 `manual_evidence/` 目录，按服务端生成 ID 与 SHA-256 管理。该目录不随临时上传任务清理，只有未提交且无引用的文件可回收。
3. Python 提供按目标与字段保存说明、上传/预览/移除待提交证据的接口，沿用上传、返修和管理员现有鉴权。对直接文字、PNG/JPEG/WebP、TXT/MD 分别校验内容，初始限制单文件 10 MiB、单字段最多 5 项、直接文字最多 2 万字；文件名仅供展示，绝不作为磁盘路径。
4. `EvidenceWorkflow` 首区显示系统论文依据，其下以可读差异和独立来源标记展示人工修改；末区为“AI 理由”，只显示来源类别、精炼理由及必要引句。上传的截图不进入论文原文片段；按需加载安全预览，避免打开侧栏时批量读取全部图片。

## 2026-10-10 调整：自动填写与 AI 理由

1. 生成阶段仅对通过服务端类型、字段约束及来源定位校验的 `paper_inference`、`general_knowledge` 结果执行自动填写。默认只补空值或 `unknown`；已有非空提取值保留，防止推测覆盖原文。
2. 对写入后的草稿重新构建字段快照，在新内容版本保存来源类别、简短 AI 理由和论文引句。发生依赖变化的其他字段重查，旧版本核对不得直接复用。
3. 上传提交允许带有效版本标记的自动填写值进入待审；正式批准沿用人工逐项理由门禁。字段编辑后标记失效并重新核对。
4. 侧栏移除 `editable_fields` 渲染的第二套表单。点击“返回编辑当前值”进入主表单；任何隐藏的旧候选均不得由侧栏确认按钮意外写入。
5. 将当前有效人工证据以独立 `human_provided` 上下文传给审核 AI。文字和文本文件提供实际内容；先用服务端随机图片验证模型图像能力，再按批次发送人工图片，校验通过且审核请求成功才标记“AI 已读取”。无法读取时保留给人工审核，结果显式标为未读；人工证据不能提升为 `paper_quote` 或绕过管理员裁决。
6. 上传/返修提交在同一数据库事务中把说明绑定到论文 revision；Go 批准事务保留来源、理由和历史，校验失败不丢失草稿或文件。使用真实存储、回滚、越权和浏览器流程验收，再更新 Overview 与 README。

## 2026-10-10 PDF 局部证据实施路径（FR-022—024）

1. 从已鉴权目标的服务端 PDF manifest 校验文件哈希。标题与作者只在主 PDF 首页、字段值与实际文本相符时生成首页来源；其他引句按原 PDF 文本层唯一匹配修正页码，图表沿用可信 IR 块坐标。文本层位置不能单独取代科学语义核对。
2. 区域接口保留旧 `image/region` 响应，新增 `dpi=300` 与有序 `crops`。根据文本行的同栏阅读顺序保留引句上下三行，跨栏或跨页分图；图表合并可信对象与邻近 caption。PyMuPDF 按 `clip` 从原文件直接渲染，超大裁剪保持 300 DPI 分片；扫描件源图低分辨率明确提示。
3. 侧栏局部图按服务端像素尺寸显示于双向滚动容器；点击同一局部图打开更大弹层，再点击或 Escape 缩回。图片失败保留文件、页码和引句，不增加整页查看入口。
4. 待审旧来源通过默认 dry-run 的定向修复命令处理：按任务锁或论文行锁生成差异、保存原 JSON 备份、事务内替换标题来源并清理错误的待审历史；已批准论文跳过。验证生产读取、提交与批准均不会恢复旧末页依据。

## 质量门与复杂度

先写并运行行为失败用例，再实现。共享字段身份和核对组件避免第二套表单；人工文件的权限、持久路径和独立来源需要一张新表及迁移，不能塞进原论文文件或只存在 Redis。模型不能决定权限、原文真实性或直接修改科学实体。实际图片读取和生成不能凭纯文本测试夹具冒充多模态验收。

## 2026-10-11 人工证据二选一实施路径（US7）

1. `ManualEvidenceSection` 将当前编辑控件收敛为判断理由与互斥路径。已有人工条目在只读列表显示；移除当前编辑区的修改前后值、直接文字输入及人工来源输入。选择提供证据后显示附件选择，选择不提供证据后显示缺证理由。切换时清除未保存的相反路径输入；已有待提交附件须先移除才能选“不提供证据”，避免界面选择与服务端真实条目冲突。

## 2026-10-11 模型归纳理由实施计划（US10）

1. 以服务端 `check_mode=synthesis` 和来源身份作为归纳字段的共同判断入口；作者原列、派生值、人工值和单纯原文事实沿用原有语义。核对模型收到该标志，返回字段专属的依据、判断桥梁与局限，不输出内部逐字思维。
2. 服务端把当前核对的具体 `reason` 写为模型归纳字段的 `ai_reason`，有效旧结果缺少专用字段时按当前内容与来源版本回用 `reason`；空泛理由不得变成支持资格。字段变化后旧理由只进入历史。
3. 共用侧栏按当前版本的来源类型展示原文和 AI 解释；模型归纳字段缺理由时显示重新核对提示，不使用直接记载兜底。以 H3S 的材料家族、旧结果重读和其他归纳字段回归验证上传与审核路径。

数据字段与生命周期见 [数据模型](data-model.md)，预检返回和界面契约见 [接口](contracts/api.md)。#120、#128、#129、#66 保留各自字段的生成规则，本计划只收敛共享来源语义。
