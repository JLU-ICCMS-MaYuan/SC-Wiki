# 实施设计

依据 [需求](spec.md)、[数据模型](data-model.md) 和 [接口](contracts/api.md)。React/MUI 共用编辑组件；Python 承担解析、核对与建议；Go 承担批准事务；现有 MySQL JSON 保存结果，不新增表。

## 实施路径

1. 扩展共享字段清单，纳入书目与空可选字段。字段浏览覆盖全部项目，提交门禁仍只约束实际存在的断言；派生字段继续用确定性规则。
2. 扩展建议依据类型与说明。上传汇总后使用同一字段快照生成建议和证据，保存完成结果及原草稿；建议失败保留已提取草稿并暴露可重试状态。复用模型配置与可取消执行。
3. 全量管理员复核显式声明任务目的，重新送入所有非派生项目、已有建议与原判断。生成建议与独立审核不能共享跳过条件；所有结果通过确定性来源定位与字段类型校验。
4. 建议草稿与正式来源保留依据类型；上传者只获得提交待审资格，管理员批准仍校验逐项人工决定。采用来源和 AI 核对状态分别存储，不能相互覆盖。
5. `EvidenceFieldMarkers` 分离可点击与问题样式，复用原标签，补全数据字段锚点；`EvidenceWorkflow` 移除接受列表，空态和成功记录共用侧栏。缺少锚点的结果保持折叠备用入口，避免堆满顶部。
6. 验证上传到审核再到永久来源/RAG 的链路，更新 Overview 和 README 的对应段落。

## 质量门与复杂度

先写并运行行为失败用例，再实现。共享字段身份和 JSON 记录避免第二套表单及数据库迁移；模型不能决定权限、原文真实性或直接修改科学实体。增加的依据分类用于区分推测与论文事实。实际生成不能凭测试夹具冒充真实模型验收。
