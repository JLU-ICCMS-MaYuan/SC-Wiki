### 需求结论与设计

沿用本 Issue 的 `type:feature`，关联 #94 紧凑字段表单与 #103 字段定位，不新增 Issue 或父子关系。本次用户明确授权设计、完善 Issue/Spec 并实施。

此前实现将来源核对理由与表单校验错误合并，再在 Tc 组逐条渲染红色 Alert。按子项拆分审核后放大为整片重复提示。这种长篇铺排没有已确认设计依据；“保留待核对状态”不等于“主表单重复展开全部理由”。本增量明确替代相关旧展示行为，保留历史原话。

1. 主表单只展示字段名称、当前值与紧凑核对状态标记；材料和模块保留待处理数量。来源引句、核对理由和旧关联解释不出现在组级警告列表、模块长摘要或字段 helperText 中。
2. 真正输入错误独立处理，在对应字段旁保留简短说明；定义不可用、保存失败、权限或版本冲突仍有明确反馈。来源待核对不得伪装成数值格式错误。
3. 核对标记默认进入来源页，来源页以短状态文字配普通段落展示当前字段的完整理由，不用大块红色感叹号包装来源说明。 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。
4. 独立“待处理项”导航保留完整数量、所属材料及字段定位；未定位项仍有紧凑入口。保持实际状态、来源、真实依赖失效、人工理由、提交及批准门禁，不通过改变状态制造通过。
5. 原 PDF 区域仍可查看和放大；切页签及折叠不丢内容。上传、返修、管理员／超级管理员共享同一展示规则，只读保留查看。

范围外：不更改科学数据、重跑提取或核对模型，不调整原任务来源关联范围、数据库、公共 API 或批准规则；不推送、不关闭本 Issue 其他未验收项。
