# 实施方案：正式交接与冻结内容

依据[规格](spec.md)、[调查](research.md)、[数据模型](data-model.md)及[接口合同](contracts/workflow.md)。

## 数据所有权与实现

工作稿、内容快照、交接记录、公开批准引用分开。按用户新答复保留审核队列，首位开始处理的合法审核员在事务锁内接手；上传者不能自审，不增加指定审核员控件。其他审核员只能读正式收到的内容，不能看到当前经手人未交出的私稿。
正式交接在数据库事务中冻结规范内容、写幂等交接记录、结束旧工作稿并转移归属；写租约绑定工作稿周期，所有数值／证据／说明／候选／模型写回都检查，不能仅禁按钮。内容判等包括值、当前采用证据、理由和有效核对结果，排除操作人／时间／交接意见等流程元数据；同内容复用已有快照而每次交接保留记录。
当前字段状态和人工说明覆盖更新；停止新增逐字段事件、旧结果版本和中间回答历史。旧真实历史只读保留，不删除、不打开页面自动迁移。快照保持不可变来源引用和文件租约，删除工作稿附件不能损坏旧版本。
公开修订只改独立工作稿，正式已批准科学图在新版批准前不变。其他合法审核者正式交还后原上传者才能修订，不能自行撤回。批准提交科学图和公开引用在同一事务完成。保留已确认demo的标题入口、新标签交接列表和新标签只读整稿； 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。
快照字段读取冻结资料，不能请求当前工作稿替代。

## 跨功能依赖

183与185提供字段资料、局部写入基础；189在其上提供共同资料目录；192消费这些规范合同并冻结／交接；187消费相同工作稿修订号且不替换快照。186独立评估，不混入尚未确认的性能重构。

## 需求／设计／任务／证据映射

FR-001～014/020→归属、冻结、幂等、公开与旧历史；FR-015～019→已确认页面；FR-021～023→联合回归和既有审核权限。任务按下方Tasks执行，证明信号为真实读写／权限／完整宿主／持久化结果，不以文件存在或字符串检查替代。

## 执行质量门

先加入实际故障和边界测试，再实施；有PDF字段或证据处理变化时定向真实重提。最终执行科学表单双门、受影响回归、独立既有失败基线与候选构建。未推送的远程链接仍待验证，不据此关闭Issue。

## 管理员恢复接线补修

统一使用 paperEditorFromWorkdraft 组合当前工作稿内容与服务端身份／版本元信息，覆盖首次接收、旧格式恢复、建议应用与工作稿刷新四条路径。显式 null 不由正式旧科学值填补；路由 paperId 始终保留。不新增持久化请求或模型调用。

## 已提交后响应超时的恢复

管理员两审核入口在502/504时重发相同review_request_id及原payload一次，直接复用既有后端幂等交接分支，不再执行gate或模型核对；第二次失败继续报错，业务错误及无操作身份不重试。详情只读提示使用真实状态，避免已批准仍提示待审。此为FR-009/SC-004失败恢复补齐，不改权限／门禁／超时上限。
