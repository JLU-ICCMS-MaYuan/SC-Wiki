## 摘要与技术上下文

在 `scripts/complementary_pdf_demo/` 实现独立 Python 命令，输出到 `demo/complementary-pdf/`。Python 3.12，复用项目 DocumentIR、Docling 2.130.0、MinerU 4.0.6、领域提取和物性记录校验；Marker 2.0.0 安装到仓库 `.local/` 隔离环境，不修改运行中的项目依赖。目标为 macOS arm64，当前机器 48 GiB 内存。重型解析顺序执行，原始输出和 stderr 单独保存；进程有超时，失败不切换引擎冒充成功。

文件系统是本 demo 唯一写入存储，不写 Redis/MySQL，不调用上传或发布 API。下游使用项目既有默认模型配置，四路固定同一模型、温度、提示和预算；凭据仅在内存读取，报告不保存密钥。真实运行记录实际版本、配置、源码摘要与文件摘要。性能不预设优劣，记录真实时间和调用用量。

## 数据与组件职责

1. `run.py`：校验输入清单和 SHA-256，创建唯一运行目录，保存代码/依赖基线，编排子进程与结果汇总；重跑创建新运行，不覆盖旧输出。
2. `parsers.py`：Docling/MinerU 复用现有 worker 转换配置并保存转换前原始响应；Marker 使用独立 Python 进程，输出原始 JSON、Markdown、图片及配置，再转换为现有 IR。PDF 页码统一为 1 起始，坐标统一为 PDF 点、左上原点；原页/引擎坐标保留在原始结果。
3. `complement.py`：按文件、页和几何重叠对齐内容，不跨文件/页面。Docling 提供结构化骨架；表格/公式/图像及文本异常触发补充候选，MinerU 提供数学/OCR 候选，Marker 提供独立布局与读序/文本候选。只是基于能力的内容取用规则，不把任何引擎当科学真值。对齐只表示空间候选关系；一对多、缺坐标保留为不确定。
4. `extraction.py`：把 IR 压缩成无信息截断的字段输入（只省重复元数据、表格父块重复文本），保留所有来源身份；共用领域契约提取，复用规范化/记录验证。论文信息、结构候选与科学记录分别保留；未支持的内容单列，不新增物性定义。原始模型响应、规范化结果和验证错误同时保存。
5. `report.py`、`template.html`：生成离线 HTML、JSON 汇总；四路表单按论文/状态/结构/物性/条件展示，并提供全字段表、来源查看、冲突、覆盖和核对记录导入导出。页面不调用生产接口。原文及模型输出作为文本渲染，不执行其中 HTML/脚本。

## 互补策略与公平边界

三路全量解析是实验采样步骤；互补规则只读取候选内容类型、区域及质量信号，不读取 H3S 参考值。普通正文保留结构骨架，表格保留单元与跨度；公式/OCR 疑点、图像/图注和缺失结构触发补充。候选差异保留，不按多数票覆盖科学数值。互补输入包含被取用的来源和需要解释的冲突，完整三路原始结果仍在审计产物中。

该首版评估“使用哪些内容可改善提取”，不宣称已实现生产按需调度或节约三路执行成本。独立基线与互补运行使用相同下游提示和预算策略；输入长度、块数和耗时分别记录。Marker 可使用自带本地识别模型，但不单独打开额外云端 `use_llm` 修订。

评测清单与生成管线隔离。历史 H3S 参考值仅用于结果产生后的核对；没有依据的字段标记未核对。程序匹配、来源定位和科学语义核对是三种证据，不互相冒充。真实数值统计的分母为明确列出的核对项，不能宣称全字段准确率。
