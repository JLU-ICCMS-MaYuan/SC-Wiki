# DeepSeek 推理模式对照

日期：2026-10-13。用户本轮明确要求比较开启与关闭额外推理的效率和效果；该实验独立于尚待评审的四工具新架构，不修改旧 demo 结果或生产默认。

## 执行前固定的比较方法

- 输入固定为上一轮 H3S 正文及补充的 MinerU IR，以 MinerU 为核心的提取场景先做对照。
- 模型使用当前既有配置 deepseek-v4-pro，提示与输入内容在两种模式间逐字相同；参考清单不进入模型。
- thinking=enabled 且 reasoning_effort=high，对比 thinking=disabled；各两次，同一轮两组并发，第二轮反转提交顺序。
- 两组 max_tokens 均为 65536，输入预算相同。官方说明推理模式忽略 temperature；记录请求温度 0.1 与实际生效差异，不谎称推理时温度可控。
- 记录完整响应、JSON/契约校验、引用定位、34 项指定科学检查、总耗时、首段最终答案时间及供应商 token 用量。不保存模型内部推理文本。
- 失败与截断如实计入；不补括号、不删除错误字段。缓存命中、服务端负载、非确定性和每组仅两次都是效率结论的限制。

## 来源

- [官方推理模式参数](https://api-docs.deepseek.com/guides/thinking_mode)：默认开启且 high；thinking 开关；推理时 temperature 不生效。
- [官方模型说明](https://api-docs.deepseek.com/quick_start/pricing)：本轮查询 deepseek-v4-pro 对应 DeepSeek-V4-Pro-0813；服务实际返回的模型名另记，不能仅凭别名推断每次版本。

## 实施与验证

入口为 `scripts/complementary_pdf_demo/reasoning_benchmark.py`，复用同一提取、来源校验及生成后评测逻辑。实验放入旧运行的独立 `reasoning-benchmarks/<timestamp>/`，不覆盖旧 `extractions/*/latest.json`。

实际目录：`demo/complementary-pdf/runs/20261013T072756Z-c15a7ebd/reasoning-benchmarks/20261013T091133Z/`。四次实际调用已完成，均为 finish_reason=stop，没有截断；旧 demo 的候选及 latest 指针保持原样。

关闭平均 148.7945 秒、31/34 项匹配；开启平均 361.2215 秒、31.5/34 项匹配。开启平均耗时约 2.43 倍、输出 token 约 1.77 倍，只多匹配 0.5 项；不能据此声称同时提高质量和效率。34 项是指定字段样本，不是全文正确率；重复同一论文不是新增两篇独立样本。

四次共享相同输入与提示摘要；提示仍为旧 demo 的 `322e6c0431241e0ed13ade00e4e12ae299d379cf81528ff6a2e7c7c030bf649e`。模式带来的内部包装不同，供应商报告关闭输入 54364 token、开启 54443 token，不以此否认原始输入字节相同。请求模型与返回模型名分别保存于 request/call。

四次输入 SHA-256 均为 `cff7e536ff0b39587fdadadc06c99bfc93212487ec2d46f995cee8f780ed8737`，响应模型名均为 deepseek-v4-pro。实际端点主机核实为 api.deepseek.com，不是本机模型；只有非敏感主机/模型信息用于说明，密钥未输出。

科学结果的具体差异：

- 关闭第 1 次出现多余的 184/179 K 记录挂在 200 GPa 状态下，同时也生成了正确的 250/300 GPa 状态；这污染 Q002/Q010 的候选组。开启两次没有这类额外错挂，但关闭第 2 次也没有，说明输出存在波动。
- 四次均把原表的 `S(8l)` 保留为 OCR 候选中的 `S(8I)`，推理并没有稳定修复这个来源错误。
- 开启第 2 次漏掉 Cccm 的一条独立原子行，只有 6 行，Q030 不通过。额外检查还看到该结构一个未列入 34 项的 H 行坐标发生变化，所以不能把 31/34 写成其全部结构参数正确率。
- 四次均通过科学记录结构校验，但论文枚举/范围参数等完整表单适配仍失败；开启并未自动解决契约问题，部分输出还把数值写成带单位文本。没有删除这些候选或取 μ* 范围端点换取通过。
- 引句数不同，不能直接按上述比例宣称某模式证据更好；零条定位失败也不保证对应值、条件和语义正确。

## 效率结论的限制与建议

第 1 次开启时缓存未命中 53675 个输入 token，其他三次多为缓存命中；服务端负载和缓存会影响时间。本实验给出了真实端到端表现，不是严格排除所有服务端变量的性能基准。推理模式忽略 temperature，虽请求值一致，也不能称采样分布完全一致。

现有证据支持“不能因第一次截断而淘汰 thinking”，也不支持“开启后整体更划算”。建议保留可配置能力，后续在更小的材料/条件归属或冲突核对任务上比较，而不是把开或关永久固定为唯一内部实现。产品仍可只有一个用户可见流程；内部预算/模式选择与产品提供多个解析方案是两件事。
