# 研究驱动力缺陷修复计划

Issue：[#231](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/231)。日期：2026-11-10。依据：[spec.md](spec.md)。状态：实施草稿，尚未修改运行代码。

## 触点与职责

- `backend/ingest/paper_first.py`：首次填表传递当前有效主文，避免已有notes就清空原文；保留论文级值、核对及检查点顺序。
- `backend/ingest/research_motivation.py`：保留分批阅读和原次数；聚合时按候选引用从原目录取回完整必要来源，编号稳定且去重，不用摘要替代证据。来源缺失或非法编号明确返回处理错误。
- 生成控制协议：空结果的缺失判定必须显式区分原文确无支持与上下文不足；程序依据实际已发送来源及窗口覆盖验证，不使用关键词猜科学结论。
- `paper_first`检查点及相关调用者：区分技术错误与科学留空。旧版无证明的source_absent不得作为新有效缺失判定；定向恢复须读取当前权威稿及人工归属，限定research_motivation及真实依赖，不重新填写其他已审字段。
- 现有字段核对、持久化和界面原因：复用当前机制，错误名称准确，不增加产品操作步骤或新科学键。

## 数据与兼容边界

科学字段与#203摘要不变，无数据库迁移。来源包含现有file_id、role、chunk_index/page及完整content；候选source_id必须来自本次对应窗口。控制协议变化进入组件请求版本，不无故失效有效结果。旧失败仅保留历史，不能把旧AI答案当新提取；当前人工值和所选引用保持。不得直接修主线程草稿或将缺失原因一律转换为成功。

## 顺序与质量门

先保存失败证据并建立能失败的回归，再实施源交接、错误语义和论文级/恢复集成。运行相关motivation/paper_first回归及字段、表单和变异检查，现有失败需独立HEAD证明。真实调用不可用时保留未完成项。实施后按overview-maintainer更新当前功能，原Spec只加本Issue修复关联；远程链接未推送不宣称可访问，不关闭Issue。

## 假设及复杂度

首次请求只携带必要原始主文及已有窗口信息，归纳携带候选所需完整原文，避免全SI坐标表无意义重传。真正必要内容超既有预算时明确停止，不提高预算或丢原文。候选数超过显示上限交模型归纳，不由程序裁前几条。旧检查点恢复与并发保护在实施前检查真实调用链；此计划不授权绕过人工/版本保护。
