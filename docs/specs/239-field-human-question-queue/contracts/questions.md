# 人工问题读答与恢复契约

本文件定义拟新增接口和UI语义，当前尚不可据此调用业务API。颜色/侧栏/人工通过只引用#220/#221，不在此增加审核门槛。

## 拟新增HTTP接口

### GET /api/upload-tasks/{task_id}/human-questions

沿_owned_state鉴权，返回queue_revision、capability、待答计数、按创建顺序排列的问题和当前处理状态。问题含question_id、prompt_revision、简述、目标标签、真实原文/图来源引用和选项说明；不返回服务器路径、密钥、系统提示或内部完整思维链。

前端可以使用现有任务轮询获取revision/计数，队列变化时读取详情；不每次进度更新扫描全部表单或重复下载大原文。paused等待不需无限刷新整篇草稿；刷新/重开主动取回队列，其他标签页答案通过既有轮询恢复后可见。

### POST /api/upload-tasks/{task_id}/human-questions/{question_id}/answers

输入为answer_id、expected_queue_revision、prompt_revision、当前目标版本令牌、choice_id或manual_text/reason。来源内容只能引用服务端已有资料或沿现有人工证据入口保存，不能信任客户端随传的“已审核”标志。至少三类入口：recommended、investigate、manual，实际推荐说明由相关事实生成；不能把“推荐”当成用户已经选择。

响应返回answer_id、accepted状态、更新后的queue_revision/问题状态及当前处理状态。accepted仅表示持久接受，不等于已应用或科学通过。运行中的任务等待安全点；idle待答任务幂等排队；排队失败保留已接受答案并显示可恢复错误，重复请求查询同答案结果。

- 权限错误返回403；无对象返回404；队列/字段/来源/题目版本变化返回409并保留可恢复回答；非法格式/动作返回422。
- 已接受answer_id的相同重试优先返回既有结果；同ID不同内容明确冲突，不重复写入或重跑。
- 无关题目的追加允许旧expected_queue_revision；同题prompt_revision、target_token、输入和目标/来源版本仍须一致，超前revision拒绝。独立题目不因队列增长失去可回答资格。
- 已resolved问题的旧操作不能推翻新决定；需要改变方向时按当前字段操作和版本重新确认。
- 对问题的答复不是普通字段输入/自动保存；只有明确答复才触发所需局部继续，不重跑整稿。

## UI与字段应用

红框显示简述、双方原文/图依据、受影响字段、推荐及其他选择；第三入口可填写方向/值与理由。进一步查证保留问题，暂不处理和不点击均不变更科学字段。输入框保留中文组合输入、失败输入、焦点和逐题草稿。点击已清楚说明结果的推荐项可以提交，不再额外增加一轮通用确认。

答案进入对应字段human_context；尚未形成字段时绑定提取/结构候选，待正式身份确定后由宿主验证映射。模型能结合人工方向完成后续处理，程序只接受现有契约允许的局部补丁。值修改、人工理由/资料、候选采纳或人工通过沿各自接口和资格；回答本身不生成approve。

## 模型与宿主内部连接

#238提供需人工路由事实，#239只接收合法科学问题；提取、结构读取、规划或核对均经同一窄接口报告问题，不将所有异常捕获后改成人工待答。问题文本不执行代码或数据库指令。

局部计划返回待答targets、真实依赖及已完成项，宿主校验身份和内容。仅有当前模型称“无依赖”不足以随意放行未知关系；未能判断是否依赖的分支保持暂挂，已知无关材料可继续。一个问题可能影响同一状态多个记录，但不能把该状态全部字段默认标为依赖。

## 权限与生命周期

上传问题仅上传者按当前任务可写资格作答；正式送审后的内容沿返修/审核入口，不能继续让旧上传问题修改已交稿。共享字段证据及当前人工方向在上传、返修、管理员、超级管理员四宿主重读保持；不据此给全部管理员增加操作别人上传任务的新权限。冻结快照只读。
