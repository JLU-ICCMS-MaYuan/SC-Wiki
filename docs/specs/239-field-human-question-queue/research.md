# 调研与设计取舍：支持解析人工问题追加排队、字段暂挂与回答后局部恢复

参见[规格](spec.md)与[计划](plan.md)。以下均为AI查证/工程理解，用户原话保存在规格中。

## 当前链路与必要变更

`material_batches.process_material_groups`按每组2状态执行填写、来源prepare、review、save，只记连续completed_groups；技术review_error保存后抛错。需要记录组内完成/待答和精确依赖，不能只增加前端弹窗，也不能跳过全组重写结果来补单字段。

`model_review.review_fields`已有human_context及human_provided_evidence，但自动上传核对调用者不能当然认为已将新答案传入；必须明确把当前答案投影到受影响字段的调用点，并按字段版本绑定。当前方向不是模型可以覆盖的原文，也不自动生成field_decision=approve。

## 持久化审计

`ScientificUploadDraft`已有state/draft JSON；`persist_upload_state`只更新已存在行，首题发生在论文草稿生成前时并不会凭空创建持久行。因此首次接受问题前须在现有上传行建立任务状态与可恢复部分稿；仅创建内部上传草稿，不提前创建正式papers记录。SQL提交后再发布缓存；SQL失败不返回问题已保存。检查点文件保存运行制品，当前问题的写入权威为现有上传持久state，不把Redis和文件做成独立可互相覆盖的账本。

## 简单恢复设计

继续使用单任务单Worker和原锁顺序。只剩人工待答时复用paused并增加明确pause_reason=human_questions/processing_phase，不把科学待答写成failed或ready。保存源、模型引用、工具回执与局部进度后释放；配置引用安全保存，不保存密钥。有人回答时，有运行中执行则安全点领取，否则正常入队，实际领取沿execution_generation。人工长等待不占Worker；503原地有限重试不改。

问题逻辑版本、来源/字段版本与Worker代次分开：正常暂停续跑增加代次不能无条件废弃尚未回答的问题；仍由当前执行验证输入及字段是否改变。旧Worker写回必须被代次拒绝。所有更新按稳定身份，不凭数组位置；删除、归并或拆分后无法唯一定位就标过期而不猜目标。

## 避免额外审核轮次

回答是明确的继续触发，不等于普通输入/自动保存启动模型。按既有必要核对范围和预算补做；合法人工审核决定与科学方向分开，已有明确人工裁定不要求模型再次替人作同一裁定。文字理由属于人工依据，可与原文一起留存，但“我确认”不伪装成作者原句。格式、必填、权限与当前版本保护不豁免。
