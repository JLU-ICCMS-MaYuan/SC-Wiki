> ## 总体方案
>
> 取消研究驱动力的固定三次模型调用。上传流程保留分段提取，再用**一次主汇总调用**生成论文级表单内容；程序随后检查缺漏、格式、数值归属和原文依据。只有检查发现具体问题时，才对受影响字段调用模型重试。第三步始终报告检查结果，但不固定调用第三次模型。
>
> 现有 [#120](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/120)讨论的是分段、汇总、核对三个流程阶段；[#66](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/66)增加了研究驱动力的专门生成与一次重试。没有查到要求每个字段固定调用三次模型的 Issue 条款。合并提示词可以减少调用，但不能保证一次回答完整；原文和程序校验仍然必需。

> ## 处理流程与接口
>
> - **识别文件**：所有文本文件先完成提取，再根据文件名、正文标题与作者、摘要、DOI、章节结构，以及 SI 标题和 `Fig. S`／`Table S` 等信号判断角色，不使用上传顺序。恰有一篇明确主文时自动纠正角色，包括与手动选择冲突的情况；证据不足或出现两篇主文候选时，在昂贵的分段 LLM 前暂停并展示依据。
> - **角色状态**：任务保存原声明角色、最终有效角色及判断依据。歧义任务进入 `needs_role_review`；新增带任务版本校验的角色确认接口，确认后复用已提取文本继续处理。引文解析、分段提取、专门生成器及证据核对统一读取最终角色，避免再次出现汇总看到主文、研究驱动力只看到 SI 的情况。
> - **生成和比较**：一次主汇总生成论文级字段；Tc 等科学记录在 `legacy` 与 #114 路径都从带出处的分段候选由程序校验、去重和组装，汇总模型不再改写数值行。程序先检查候选覆盖、材料／压力／方法配对、单位范围、引句和字段格式；只对缺失或存疑字段重试。第二个结果只有补齐有依据的缺漏、且不改变已验证事实时才替换第一个；无法判优或两者冲突时保留首值并标记待审。
> - **可诊断结果**：草稿按字段返回“未读取主文、原文确无依据、模型未生成、引句未定位、格式不合格、两次结果冲突”等具体问题。私有任务产物保存每次候选、来源版本、校验失败项和调用耗时；不在普通日志记录完整 PDF、密钥或模型内部思维。
>
> ## 验证与既有草稿
>
> - 用 SI 先上传的 La-Sc-H、H3S、CaH6，以及至少一篇实验论文做同模型对照。逐项检查研究动因、分类和数值记录；特别验证 167 GPa／316 K、250 GPa／331 K 等 Tc 不漏行、不串压力或方法。对语义等价的提示词比较**事实与依据**，不要求字面措辞相同。
> - 记录每篇的模型调用数、tokens、分阶段耗时和字段正确率。首轮已合格的字段不再发生专门生成调用；与现有流程比较成本，同时要求有依据的字段和科学记录不退步。当前 La-Sc-H 的约 47.8 分钟仅作总耗时基线，不能直接归因于研究驱动力调用。
> - 自动盘点并重算全部受影响的**未提交上传草稿**（当前持久化盘点为 3 份）。每份先保存私有快照，核对文件哈希、任务版本、模型配置和人工修改；仅替换仍由 AI 拥有且版本未变化的值。人工改值保留，新的模型结果作为待审建议；缺失原模型凭据或并发冲突的任务明确列入未完成报告。已提交论文不批量改写。
>
> ## 已确定的边界
>
> 低置信度角色判断由用户确认；高置信度判断自动纠正。#114 解析器本身暂不自动升为默认方案，但两种解析方案采用相同的科学记录组装规则。研究驱动力等字段保留人工校对和正式审核门槛；“一次主生成”是默认调用策略，不是“一次模型回答必然正确”的保证。

## 背景与目标

#26 的旧契约默认首文件为正文，角色锁定后只做身份冲突警告。La-Sc-H 先上传 SI 时，正文被标为附件；部分专门生成器排除附件，虽然全文汇总仍处理了两份文本。目标是在昂贵 LLM 调用前识别一篇论文的正文和 SI，使所有下游读取同一有效角色，并保留可审计的原声明与判断依据。

### 需求结论与变更取舍

用户已确认：高置信时自动纠正包括手动选择在内的错误角色；证据不足、多篇主文候选时暂停让上传者确认。新约束替代 #26 的首文件默认正文和仅警告不纠正规则。解析器本身不自动切换，已提交论文不批量改写。

## 用户场景与验收

### US1：SI 先上传仍识别论文正文（P1）

1. **假如** La-Sc-H 的 SI 在正文前上传，**当**两份文本提取完成，**那么**正文为有效 `main`、SI 为 `supplementary`，上传顺序和原手动角色均不决定最终结果。
2. **假如** H3S 正文先上传且识别明确，**当**角色评估完成，**那么**角色保持正确并记录判断依据。

### US2：歧义在模型阅读前由上传者解决（P1）

1. **假如**两份文件都像独立主文或文本证据不足，**当**角色评估完成，**那么**任务进入 `needs_role_review`，展示每份信号，不开始分段 LLM。
2. **假如**上传者用当前任务版本提交完整角色选择，**那么**系统复用已提取文本恢复处理；旧版本、非所有者或非法角色被拒绝。

### US3：下游来源与文件角色一致（P1）

1. **假如**有效正文与原声明不同，**当**提取引文、分段候选、论文级字段或来源核对，**那么**它们使用相同有效角色和文件身份；原声明保留用于追溯。
2. **假如**文件为 CIF/POSCAR 等结构附件，**那么**不作为正文候选或叙述来源。

## 功能需求

- **FR-001**：解析所有受支持文本文件后、分段 LLM 前，使用文件名、首页标题和作者、摘要、DOI、章节结构、SI 标题与 S 编号图表识别正文、SI 和附件；不得使用上传顺序作结论。
- **FR-002**：只有恰有一个主文候选且正负信号均明确时才自动纠正角色；高置信结论优先于原手动选择，保存原声明、最终角色与逐文件依据。
- **FR-003**：无唯一可靠主文时暂停在 `needs_role_review`；任务在待确认期间保留文件和解析文本，不运行分段 LLM，允许所有者带版本提交完整角色表并恢复。
- **FR-004**：引文解析、候选提取、论文级生成器、字段核对和正式来源均使用统一有效角色；角色变更后旧来源版本失效，不能继续支持当前值。
- **FR-005**：高置信重分组、用户确认和恢复具备幂等及并发保护；单文件任务保持现有行为，不自动拆分多篇论文或切换 PDF 解析器。

## 关键实体

- **角色判断**：任务内每个文件的原声明、有效角色、识别信号、结论与来源哈希。
- **待确认任务**：已提取但未进入分段 LLM 的任务，保留任务版本和可复用文本。

## 成功标准

- **SC-001**：SI 先上传的 La-Sc-H 自动得到正确有效主文，全部下游来源包含其正文；H3S 正文先上传不误改。
- **SC-002**：两篇主文、扫描文本不足及矛盾信号均暂停；用户确认后不重复提取文件或丢失任务。
- **SC-003**：未经确认的任务没有昂贵分段 LLM 调用；角色版本冲突、权限错误及非法角色有明确反馈。
- **SC-004**：API、前端、缓存、单文件兼容及来源重核通过有生产边界的测试。

## 假设与依赖

- 角色判断只使用本次上传文件，复用 #26 的文件清单和 #24 的任务中心；#120 的全字段统一来源依赖本 Feature。
- 解析文本不足时保留歧义并请用户选择，不能用文件顺序猜测。

## 范围外事项

- 不自动把 #114 Docling/MinerU 切为默认解析器；不修改已提交论文或自动拆分多个 Paper。

## 澄清记录

- 用户在计划讨论中选择高置信自动判、歧义暂停；明确手动角色与高置信判断冲突时由系统直接纠正。
- 用户要求所有受影响未提交草稿自动重算，该数据回写由 #120 的版本保护流程实施。

## 最终草案确认

- 用户明确要求实施已展示的《多文件主文识别与按需生成的自动填表流程》总体方案；本 Spec 将该方案落实为角色识别与统一来源契约。
