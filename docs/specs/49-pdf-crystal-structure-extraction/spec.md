# Feature 规格：论文附件晶体结构提取

**GitHub Issue**：[#49](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/49)

**创建日期**：2026-08-24

**状态**：原有规格与历史澄清保留；2026-10-20 结构资料增补已获“开始”实施授权，当前按本轮实施基线验证。

## 背景与目标

2026-10-20 用户要求保留和建模伴随材料 LaSc₂，完整保存无原子坐标的晶格资料，排除仅正文描述产生的假结构，并明确元素检索 La–Sc 时能发现无 Tc 的结构及其来源论文。完整原话见本文末尾；两张原图、逐表核查、搜索缺口与拟议方案见 [结构资料完整保留需求分析草案](structural-information-review-20261020.md)。用户随后回复“开始”，授权按上述目标实施；内部存储方案由实现负责，不再要求用户选择表结构。本轮实现与验证见 [实施记录](implementation-20261020.md)，尚未完成的真实业务库应用和独立论文验收继续由 Issue 跟踪。

2026-10-19 对现有结构解析与候选核对行为的缺陷修复、完整本次用户原话和附图登记，见 [结构与谱异常核查](../137-phonon-spectra-digitization/assignment-audit-20261019.md)。按既有 FR-004～010／FR-013～019 处理，不表示整个 Feature 已完成。

当前论文上传链路可以从 PDF、TXT 和 Markdown 提取文本并生成可编辑草稿，结构管理也已经支持
用 ASE 校验现成的 CIF/POSCAR，并用 3Dmol.js 展示结构。然而，两条能力尚未连通：上传任务
不能接收 CIF/POSCAR 附件，也不能从可搜索 PDF 的正文或表格恢复晶体结构。

本 Feature 要从一篇论文的全部来源文件中发现全部可证实结构，保留结构条件和原文证据，生成
CIF 与 POSCAR 候选，并在用户核对证据和三维预览后随论文当前 revision 一并提交。系统不得
根据常识、材料名或缺失参数猜测结构。

## 用户场景与验收

### 用户故事 1：直接上传结构附件（优先级：P1）

研究者希望把论文正文与作者提供的 CIF/POSCAR 一起上传，由系统校验附件并加入论文草稿。

**优先级理由**：原生结构附件包含最直接、最完整的几何证据，是风险最低的首要交付路径。

**独立验收**：上传一个可搜索正文 PDF 和合法 CIF 或 POSCAR 后，草稿出现结构候选、来源附件、
校验结果和两种可下载格式；非法结构只影响对应附件并显示具体错误。

**验收场景**：

1. **假如**任务包含合法 `.cif` 附件，**当**后台完成解析，**那么**草稿显示通过校验的结构候选及其原始附件。
2. **假如**任务包含 `.poscar` 或无扩展名 `POSCAR`，**当**后台完成解析，**那么**系统识别其格式并生成 CIF 与 POSCAR。
3. **假如**附件声明为 CIF 但内容不可解析，**当**后台校验，**那么**该附件显示失败原因且不得产生可提交结构。

### 用户故事 2：从 PDF 正文与表格恢复全部结构（优先级：P1）

研究者希望系统从可搜索 PDF 中提取论文明确报告的晶格、空间群和原子位点，并按材料、压力、
物相和计算条件分别形成结构候选。

**优先级理由**：大量论文没有独立结构附件，PDF 表格是结构数据的主要来源。

**独立验收**：在包含完整坐标的 PDF、包含空间群与独立 Wyckoff 位点的 PDF、以及同篇多压力
结构 PDF 上，系统分别恢复全部可证实结构；不完整表格只产生待人工补充项。

**验收场景**：

1. **假如**PDF 明确列出晶格和全部原子分数坐标，**当**解析完成，**那么**系统生成与原文一致的结构候选。
2. **假如**PDF 明确列出晶格、空间群和独立 Wyckoff 位点，**当**参数内部一致，**那么**系统按空间群确定性展开等价原子并标记为推导结果。
3. **假如**同一论文报告多个材料、压力、物相或计算条件，**当**解析完成，**那么**每个结构分别出现且保留各自条件。
4. **假如**晶格、坐标、空间群或占位信息不完整或冲突，**当**解析完成，**那么**系统列出缺失或冲突字段，不自动生成完整结构。

### 用户故事 3：核对并提交结构候选（优先级：P1）

研究者希望在正式入库前核对每个结构的条件、证据、推导说明和三维模型，修正或排除错误候选。

**优先级理由**：PDF 表格和符号存在提取误差，人工确认是防止科学数据污染的必要门槛。

**独立验收**：用户可以逐个查看来源定位和 3Dmol.js 预览，只有明确确认且通过校验的结构会随
论文提交；任一事务失败时不留下半套正式记录。

**验收场景**：

1. **假如**候选已通过结构校验，**当**用户打开草稿，**那么**页面显示材料状态、晶胞、原子、来源证据、推导类型和 3Dmol.js 预览。
2. **假如**用户尚未确认候选，**当**提交论文，**那么**该候选不得写入正式结构实体。
3. **假如**用户确认多个候选，**当**论文提交成功，**那么**结构、来源 Evidence 与论文当前 revision 在同一事务中保存。
4. **假如**正式提交中的任一结构违反数据约束，**当**事务失败，**那么**论文、文件、Evidence 和科学实体整体回滚并返回真实错误。

### 用户故事 4：选择晶胞表示与导出格式（优先级：P2）

研究者希望默认查看惯用胞，并在导出时按用途选择原胞或惯用胞以及 CIF 或 POSCAR。

**优先级理由**：双格式导出提升互操作性，但依赖前三个故事先建立可信结构。

**独立验收**：同一候选默认以惯用胞显示；用户可导出原胞 CIF、原胞 POSCAR、惯用胞 CIF
和惯用胞 POSCAR，四份文件均可重新读取并与同一结构等价。

**验收场景**：

1. **假如**候选通过校验，**当**用户首次打开三维预览，**那么**系统默认展示该结构的惯用胞。
2. **假如**候选可转换为原胞和惯用胞，**当**用户选择晶胞表示与 CIF/POSCAR 格式，**那么**系统导出对应组合且文件可被结构工具重新读取。
3. **假如**结构来自原生附件，**当**用户导出派生结构，**那么**原附件仍可单独取得，派生文件不会覆盖原文件。

### 用户故事 5：查看已审核的公开结构（优先级：P2）

研究者希望在论文审核通过后，在论文详情中查看结构并按需要下载不同晶胞和格式的文件。

**优先级理由**：公开展示使结构提取结果能够被整个研究协作方复用，但必须服从论文 revision
和权限边界。

**独立验收**：已批准论文的当前 revision 对允许访问的普通用户显示默认惯用胞预览和四种导出
选择；pending、rejected 或旧 revision 不因本 Feature 绕过现有权限而公开。

**验收场景**：

1. **假如**论文当前 revision 已批准，**当**普通用户打开论文详情，**那么**用户可以查看默认惯用胞并选择导出表示和格式。
2. **假如**论文处于 pending、rejected 或请求的是旧 revision，**当**普通用户请求结构，**那么**系统按现有权限矩阵拒绝或隐藏，不泄露结构内容。
3. **假如**上传者或管理员查看自己的 pending 草稿，**当**用户具有相应权限，**那么**仍可按草稿规则核对候选，但内容不进入公开查询。

### 边界与异常场景

- 扫描 PDF、图片中的表格和不可搜索文字不进入自动结构识别。
- 只有空间群而没有足够几何信息时，只保留论文报告空间群，不创建结构模型。
- 对称展开只能使用论文明确报告且内部一致的晶格、空间群和独立位点；展开结果必须与直接报告区分。
- 部分占位、无序占位、互斥位点或参数冲突不得自动转成单一有序结构，必须转人工处理。
- 笛卡尔坐标和分数坐标必须明确区分；坐标类型无法确定时不得自动生成结构。
- 一个来源文件解析失败不得抹掉其他已成功候选；正式提交仍受用户确认和完整性校验约束。
- 原始附件保持不可变；任何规范化或格式转换都形成派生内容。
- 同一材料状态下，PDF 与结构附件的规范化几何在明确容差内等价时合并为一个多证据候选；
  原始文件和各自 Evidence 仍分别保留。条件不同或几何不一致时不得合并，并显示结构冲突。
- 原始结构作为不可变证据保留；用户三维预览默认使用惯用胞。导出时必须允许独立选择原胞或
  惯用胞，以及 CIF 或 POSCAR。任何标准化结果都是派生表示，不得覆盖原始结构。
- 公开展示与导出复用论文当前 revision 的既有权限矩阵：未登录用户只看 approved，普通登录
  用户按现有规则查看 approved/pending，上传者可查看自己的 rejected，管理员可查看全部。

## 需求

### 功能需求

- **FR-001**：上传任务必须接受现有 PDF、TXT、MD 以及 `.cif`、`.poscar` 和无扩展名 `POSCAR` 附件，并保持恰好一个正文文件的任务约束。
- **FR-002**：系统必须保留每个原始结构附件的文件身份、角色、内容哈希和不可变原文，不得用派生文件覆盖原件。
- **FR-003**：系统必须对原生 CIF/POSCAR 执行结构解析和完整性校验，并为失败附件返回可定位到文件的错误。
- **FR-004**：系统必须从可搜索 PDF 的正文和表格提取晶格参数、空间群、元素、原子位点、坐标值、坐标类型、占位信息及结构条件。
- **FR-005**：系统必须按材料、压力、物相和计算条件保留论文中全部可证实结构，不得只选取单一代表结构。
- **FR-006**：每个结构候选必须关联来源文件、文件角色、页码以及可用的章节、表格或证据文本定位。
- **FR-007**：当论文明确提供晶格、空间群和独立 Wyckoff 位点时，系统必须能够使用确定性空间群操作展开等价原子。
- **FR-008**：对称展开候选必须记录直接报告的独立位点、所用空间群、展开方式和“推导”标识，不能标记为论文直接报告的完整坐标。
- **FR-009**：只有输入字段完整且内部一致、生成结构通过确定性校验时，候选才能进入可确认状态。
- **FR-010**：参数缺失、冲突、坐标类型不明、部分占位或无序占位时，系统必须列出问题并阻止自动生成完整结构，不得猜测缺失值。
- **FR-011**：每个有效候选必须能够派生原胞和惯用胞，并分别导出 CIF 与 POSCAR；四种导出组合重新读取后必须与同一结构等价。
- **FR-012**：候选必须区分原始附件、论文直接报告结构和确定性推导结构，并保留各自来源链。
- **FR-013**：草稿必须展示每个候选的材料状态、结构摘要、来源证据、校验状态、推导说明和 3Dmol.js 交互预览，预览默认使用惯用胞。
- **FR-014**：用户必须能够逐个确认、排除或修正结构候选；未经明确确认的候选不得进入正式结构实体。
- **FR-015**：确认后的结构必须与对应材料状态、论文当前 revision 和同 revision Evidence 一并提交，不得写入旧结构路径。
- **FR-016**：论文、来源文件、Chunk、Evidence、结构及其他科学实体必须在同一事务中提交，任一失败时整体回滚。
- **FR-017**：系统必须保留同一论文中的多个结构，不得按材料、压力或结构哈希跨条件静默合并。
- **FR-018**：结构处理失败必须使用明确的文件级或候选级错误语义；不得把结构错误误报为 DOI 重复或整篇 PDF 不可解析。
- **FR-019**：系统必须为原生附件、PDF 完整坐标、Wyckoff 对称展开、多结构、不完整参数、人工确认、双格式一致性和提交回滚提供自动化验证。
- **FR-020**：同一材料状态内的多来源结构在规范化元素、晶胞和原子位置于明确容差内等价时，系统必须合并为一个候选并关联全部来源 Evidence；条件不同或几何不等价时必须保持独立并标记冲突。
- **FR-021**：用户必须能够在导出时分别选择原胞或惯用胞以及 CIF 或 POSCAR；原始结构、标准化原胞和标准化惯用胞必须具有明确标签且不得互相覆盖。
- **FR-022**：已批准论文的当前 revision 必须向具有查看权限的用户提供默认惯用胞 3Dmol.js 预览和四种导出组合；pending、rejected 和旧 revision 必须继续遵守现有权限控制。
- **FR-023**：结构公开查询和导出不得绕过论文级审核、revision 一致性或用户权限检查，也不得返回无权限候选的原始证据或文件内容。

### 关键实体

- **结构来源文件**：论文上传任务中的原始 CIF、POSCAR 或承载结构证据的 PDF，始终保留原始身份和内容。
- **结构候选**：提交前可编辑的结构数据集合，包含结构条件、直接报告字段、推导字段、格式内容、校验状态和确认状态。
- **结构候选来源集合**：同一候选关联的一项或多项原始附件、PDF 证据与推导记录；候选合并不得删除任何来源。
- **结构证据定位**：候选与来源文件、页码、章节、表格和证据文本之间的可追溯关系。
- **结构推导记录**：确定性对称展开所用的空间群、独立位点、操作类型和结果摘要。
- **正式结构模型**：用户确认后属于明确材料状态和论文 revision 的完整几何。
- **派生结构表示**：从同一有效候选确定性生成的原胞或惯用胞，具有标准化方法和结果摘要，不替代原始结构。
- **派生结构文件**：按“原胞/惯用胞 × CIF/POSCAR”组合导出的内容，不替代原始附件。

## 成功标准

- **SC-001**：验收夹具中的合法 CIF、合法 POSCAR 和无扩展名 POSCAR 识别成功率为 100%，非法附件均返回文件级错误且不产生可提交结构。
- **SC-002**：验收夹具中直接报告完整坐标和可确定性展开的 PDF 结构恢复率为 100%，元素、原子数和晶胞与期望结果一致。
- **SC-003**：包含至少两个压力或物相结构的验收论文中，全部结构均独立出现且条件关联正确，遗漏和静默覆盖数量为 0。
- **SC-004**：参数缺失、坐标类型不明、部分占位和空间群冲突夹具的自动完整结构生成数量为 0，且每项都显示可操作原因。
- **SC-005**：每个可确认候选均具有来源文件和页码定位；对称展开候选还具有独立位点和推导标识，追溯完整率为 100%。
- **SC-006**：同一候选的原胞 CIF、原胞 POSCAR、惯用胞 CIF 和惯用胞 POSCAR 均可重新读取，并通过结构等价校验，验收夹具通过率为 100%。
- **SC-007**：未确认候选正式入库数量为 0；确认候选的材料状态、论文 revision 和 Evidence 关联完整率为 100%。
- **SC-008**：故意制造提交晚期失败时，Paper、来源文件、Evidence、结构和其他科学子实体残留新增记录数为 0。
- **SC-009**：桌面和窄屏验收视口中，用户均可查看候选证据、操作确认状态并使用 3Dmol.js 旋转和缩放默认惯用胞，同时能选择四种导出组合。
- **SC-010**：同状态等价几何夹具只形成一个候选且关联全部来源；不同压力、物相、计算条件或不等价几何的错误合并数量为 0。
- **SC-011**：已批准论文的授权用户可以查看和导出当前 revision 结构；未授权或未批准 revision 的结构读取和导出成功率为 0，且无敏感内容泄露。

## 假设与依赖

- 依赖 #46 完成上传草稿、材料状态和新科学实体提交主链路；#49 只扩展结构候选，不建立第二套提交模型。
- 依赖 #32 的 `StructureModel`、`StructureModelEvidence`、论文 revision 和材料状态约束。
- 结构科学处理使用项目已有 ASE 依赖；用户展示继续使用已有 3Dmol.js。
- PDF 自动提取只处理可搜索文本和可恢复表格，不包含 OCR 或图片识别。
- 人工修正后的结构仍必须通过与自动候选相同的确定性校验。

## 范围外事项

- 扫描 PDF、OCR、论文图片或光谱图中的结构识别。
- 根据材料常识、外部数据库或生成式模型补全缺失晶格、空间群或坐标。
- 对部分占位或无序结构自动选择有序构型。
- 外部材料数据库检索与自动补全。
- ASE GUI、服务端桌面窗口或以 ASE 替代网页结构查看器。
- 结构弛豫、能量计算、声子计算或其他材料科学计算。
- 历史论文和旧结构表的迁移、回填或删除。
- 跨论文结构合并、相似度治理或 GNN 导出去重。

## 澄清记录

### 2026-08-24

- 问：自动结构来源包含哪些文件？→ 答：支持可搜索 PDF 的正文/表格，以及直接上传的 CIF/POSCAR；不包含扫描件和图片识别。
- 问：同一论文报告多个结构时如何处理？→ 答：全部提取，并按材料、压力、物相和计算条件分别保存。
- 问：每个有效结构输出哪些格式？→ 答：同时生成 CIF 和 POSCAR，并保留原始附件。
- 问：用户端采用哪种结构展示？→ 答：使用 3Dmol.js；ASE 只负责结构解析、校验和转换。
- 问：结构何时写入正式数据库？→ 答：先进入候选草稿，用户核对证据和三维预览并明确确认后再随论文提交。
- 问：PDF 只给空间群与独立 Wyckoff 位点时是否允许展开？→ 答：允许使用论文明确参数做确定性对称展开；结果必须标记为推导并保留输入证据，冲突、部分占位或无序情况转人工处理。
- 问：同一论文的 PDF 与结构附件描述同一几何时如何处理？→ 答：同一材料状态且规范化几何在明确容差内等价时合并为一个多证据候选；原始文件和 Evidence 全部保留，条件不同或几何不一致时保持独立并标记冲突。
- 问：预览和导出使用哪种晶胞表示？→ 答：3Dmol.js 默认展示惯用胞；导出时允许选择原胞或惯用胞，以及 CIF 或 POSCAR。原始结构保持不可变，所有标准化结果均作为明确标注的派生表示。
- 问：审核通过后的结构是否对普通用户公开？→ 答：纳入本 Feature。approved 当前 revision 的授权用户可以使用 3Dmol.js 查看并导出；pending、rejected 和旧 revision 继续遵守现有权限矩阵，不新增旁路。
