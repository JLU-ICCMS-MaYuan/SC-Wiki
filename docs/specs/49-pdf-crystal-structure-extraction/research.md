# 技术研究：论文附件晶体结构提取

**GitHub Issue**：[#49](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/49)

## 研究结论

### 2026-10-19：打印精度内恢复对称约束

LaSc₂H₂₄ 的 Sc(2c) 为 `(0.333, 0.667, 0.000)`，H(6m) 为 `(0.759, 0.519, 0.500)`。直接浮点展开会产生额外轨道；统一放大去重容差会掩盖错误。采用报告空间群操作 `R,t` 的固定点约束 `(R-I)x=n-t`：仅保留可在每项打印舍入半宽内成立的操作。兼容操作数必须恰好等于群阶除以报告多重性；再以各坐标舍入半宽归一，求最小改变量投影，逐坐标校验界限、约束残差及严格轨道多重性。操作数不符、约束冲突或调整越界则保持失败。

这得到 Sc 的 `(1/3, 2/3, 0)` 与 H 的 `(0.7594, 0.5188, 0.5)`，均位于原文三位小数的舍入区间。它们是可核对的对称派生坐标，不声称恢复作者未打印的精确计算值。原始字符串、坐标及引句不变；候选保存派生值、半宽和改变量，仍为 `confirmation=unreviewed`。完整 CIF 独立读取后具有 27 个原子、LaSc₂H₂₄ 化学计量及空间群 191；以此交叉检验局部位点处理。科学边界在结构服务，前端只展示派生依据。

### 决策 1：结构候选接入 #46 的 `material_states[]`

**决策**：结构候选作为材料状态内的结构集合进入 #46 草稿，不扩展旧的 `key_properties`，正式
提交只调用 #46 的新科学实体事务写入路径。

**理由**：结构的压力、物相、数据主体和计算条件与材料状态绑定；#32 已规定每个
`StructureModel` 属于论文当前 revision，并通过 `StructureModelEvidence` 关联 Evidence。

**备选方案**：继续把 `structure_text` 放进旧 `KeyProperty`。该方案无法表达多结构、来源集合、
原胞/惯用胞派生，也会继续扩大已被 #46 取代的旧契约，拒绝。

### 决策 2：原生附件先经过 ASE，PDF 候选再经过同一校验器

**决策**：CIF/POSCAR 附件使用 ASE 读取；PDF 解析出的直接坐标或空间群展开结果先构造成 ASE
`Atoms`，再由同一服务执行完整性校验、哈希、导出和等价比较。

**理由**：将科学有效性判断集中在确定性服务中，避免前端和 LLM 各自实现一套结构规则。

**备选方案**：让 LLM 直接输出 CIF 文本并以语法解析成功作为通过条件。语法有效不代表晶胞、
坐标、占位和空间群科学一致，拒绝。

### 决策 3：空间群展开使用 `pymatgen`，ASE 负责最终读写

**决策**：使用项目已有 `pymatgen` 的空间群工具从独立 Wyckoff 位点生成等价原子；生成后的
结构转换为 ASE `Atoms`，由 ASE 读写 CIF/POSCAR。若空间群、位点或占位无法确定，则不展开。

**理由**：空间群操作和标准化是晶体学库职责，不能手写 230 个空间群操作；ASE 已是当前项目
的结构校验依赖，保留其作为读写和最终一致性边界。

**备选方案**：仅支持 PDF 明列全部原子坐标。实现较简单，但会漏掉以独立 Wyckoff 位点报告
结构的论文，不符合本 Feature 已确认的范围。

### 决策 4：原始结构、原胞和惯用胞分开保存

**决策**：原始附件或论文直接报告的规范输入不可变保存；原胞和惯用胞是带转换方法与父候选
标识的派生表示。3Dmol.js 默认读取惯用胞，导出接口显式接收 `cell=primitive|conventional`
和 `format=cif|poscar`。

**理由**：默认惯用胞更适合用户识别晶体对称性，原胞适合计算；分开保存可追溯且不会用标准化
结果覆盖论文原始表示。

**备选方案**：只保存一种标准化结构。会损失论文原始晶胞语义，拒绝。

### 决策 5：同状态等价几何合并为多证据候选

**决策**：候选合并键先使用材料状态条件（材料、压力、物相、计算主体/条件），再比较规范化
元素、晶胞和周期性原子位置；在固定长度和角度容差内等价才合并。所有原始来源和 Evidence
均保留。条件不同或几何不等价时保持独立并标记冲突。

**理由**：避免 PDF 与附件重复生成结构，同时不跨论文或跨条件静默合并。

### 决策 6：候选草稿与正式结构分离

**决策**：结构候选、错误、来源集合和用户确认状态只保存在 Redis 草稿/审核快照中；用户
确认后才在 #46 的单事务中创建 `StructureModel` 和 Evidence 连接。未确认候选不创建正式实体。

**理由**：上传解析是可失败、可编辑阶段；正式数据库只能接收用户确认且通过校验的结构。

### 决策 7：权限复用论文 revision，不新增结构级公开状态

**决策**：公开结构查询先检查论文状态和 `approved_revision == content_revision`，再检查现有
论文查看权限；结构实体不新增独立审核状态。pending 草稿只对有权限的上传者/管理员返回。

**理由**：#32 已确定论文级审核是唯一公开边界；新增结构级权限会造成状态分裂。

## 风险与缓解

- PDF 表格跨栏、上下标、负号和分数坐标可能在文本层丢失：保留来源页码/表格文本，低置信度
  或字段冲突转人工，不自动生成。
- Wyckoff 位点和空间群符号可能使用非标准写法：要求符号—群号一致或由用户补齐，不能只按
  材料名推断。
- CIF 与 POSCAR 的周期边界、原子顺序和对称等价表示不同：使用元素、晶胞和周期性位置的
  明确容差比较，不比较原始文本。
- 同一论文可能有弛豫前后、不同方法和多个压力结构：候选键必须包含结构条件，禁止只按材料名
  合并。
- 公开导出可能泄露 pending/rejected 论文内容：导出和预览共用论文权限门，不接受结构 ID
  作为绕过权限的凭据。
