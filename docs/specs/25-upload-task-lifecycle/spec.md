# Feature 规格：多任务上传中心与安全清理生命周期

**GitHub Issue**：[#25](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/25)
**父 Epic**：[#24](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/24)
**状态**：已确认，待实施

## 目标

用户可在重新登录后恢复最多 100 个活动上传任务，查看真实阶段、取消运行任务并安全清理终态任务。清理不得把 Redis 状态缺失误判为未提交，也不得删除已被 MySQL 正式论文认领的文件。

## 用户故事与验收

### US1：恢复任务中心（P1）

登录用户可按最近活动时间查看自己的上传解析记录。列表由服务端用户索引恢复，不依赖浏览器本地任务编号；响应不得包含服务器路径、RQ job id 或内部缓存键。

### US2：准确保留时间（P1）

- `ready`：从用户主动打开详情、编辑或保存草稿起滑动保留 24 小时。
- `failed`、`duplicate`、`cancelled`：从进入状态起固定保留 24 小时，查看不续期。
- 后台轮询不算用户操作，不续期。
- API 返回服务器时间 `cleanup_at`；列表每秒本地更新倒计时，刷新时重新同步。
- 少于 1 小时显示分和秒；到期但尚未执行清理时显示“等待清理”。
- `uploading` 连续 1 小时无进度转为 `failed`，再开始 24 小时保留。
- `queued/extracting/reading/summarizing/submitting/cancelling` 依赖心跳，不在正常运行中自动过期，也不显示删除倒计时。

### US3：取消与清理（P1）

原取消入口状态为 `cancelling → cancelled`；Worker 在文件、分段和汇总边界协作停止，当前阻塞 LLM 请求允许自然结束或超时。可恢复的停止／继续与暂停保留采用后来用户确认的 [#224](../224-resumable-model-requests/spec.md)，不把暂停当取消终态。单个和批量清理只能删除可清理终态或用户主动选择的暂停任务，跳过运行任务。

## 功能需求

- **FR-001**：为每个用户维护可枚举的活动任务索引，禁止以 Redis `SCAN` 作为列表实现。
- **FR-002**：创建任务时原子清理失效成员、检查活动任务数并执行 100 个上限。
- **FR-003**：活动任务指所有尚未提交、未删除且仍有状态的任务，包括失败、重复和取消；提交、删除或过期后释放名额。
- **FR-004**：状态更新必须原子化，避免并行上传、Worker 与草稿保存互相覆盖。
- **FR-005**：提供创建、列表、详情、取消、单项清理和批量清理 API。
- **FR-006**：任务查询使用公开 DTO 白名单。
- **FR-007**：所有清理在删除文件前查询 MySQL 永久认领记录；数据库或 Redis 不可用时延后清理。
- **FR-008**：提交与清理依赖数据库唯一 `upload_task_id` 实现最终一致性和幂等。
- **FR-009**：任务取消后，迟到的 Worker 不得重建状态或覆盖为成功。
- **FR-010**：前端在记录旁显示服务端截止时间驱动的动态倒计时。

## 成功标准

- 100 个并发创建请求不会突破上限。
- 重新登录能恢复全部活动任务。
- Redis 状态过期但 MySQL 已有对应论文时，PDF/Markdown/附件零误删。
- 批量清理不会删除运行中或正在提交的任务。
- 倒计时误差在刷新同步后不超过 2 秒，轮询不续期。

## 范围外

- 不保证中断一个已经发出的第三方 LLM HTTP 请求。
- 不为已提交论文显示临时任务倒计时。
- 不建设永久任务审计日志；正式论文审计由 MySQL 承担。
