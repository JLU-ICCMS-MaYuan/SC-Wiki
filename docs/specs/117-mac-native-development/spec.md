# Feature 规格：Mac 原生本地开发

**GitHub Issue**：[#117](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/117)

**创建日期**：2026-09-29

**状态**：本机实现与验收完成；协作状态见 Issue。

## 背景与目标

Mac 当前使用 Lima 中的容器和固定源码副本，无法直接开发工作区。用户要求移除该方式，使用与 Linux 相同的 make 命令控制原生服务。

## 用户场景与验收

### 用户故事 1：直接开发当前源码（US1，P1）

优先级理由：日常开发主路径。独立验收：原生启动并修改源码，Python 和前端重新加载，Go 重新编译。

1. 假如依赖已就绪，当运行 make start，那么基础服务和应用在 macOS 进程中运行，网站可访问。
2. 假如服务正在运行，当运行 make stop，那么只停止本项目拥有的进程。

### 用户故事 2：部署与数据冻结（US2，P1）

优先级理由：保留现有数据和可恢复性。独立验收：部署检查无写入，冻结包校验通过，隔离恢复验证数据。

1. 假如配置和数据包有效，当运行 make deploy，那么恢复或初始化本地实例，失败明确报告。
2. 假如源码已提交且服务归属明确，当运行 make frozen，那么导出业务数据并恢复源服务。

### 用户故事 3：退出 Lima 环境（US3，P2）

独立验收：原业务数据保存，Lima 实例及本任务专用文件不存在，原生服务继续工作。

## 边界与异常场景

未知端口、PID、已有目录归属冲突必须拒绝接管；下载必须校验；失败保留数据。未提交源码保持现有 frozen 拒绝行为。旧 dist 包不得无条件覆盖当前数据库。外部 LLM、SMTP 和 OCR 模型验收不属于启动成功。

## 功能需求

- **FR-001**：相同 make 命令按宿主选择原生开发入口，Mac 配置独立，Linux 行为保持兼容。
- **FR-002**：Mac 启停、状态、日志及源码重载覆盖全部现有服务，不依赖 Docker/Lima。
- **FR-003**：依赖安装使用独立环境或项目目录，校验版本，不改 shell 配置或接管系统服务。
- **FR-004**：deploy 支持只读预检、初始化/恢复与失败保护；frozen 保留业务数据一致性、归属和凭据门槛。
- **FR-005**：迁移前保留可校验备份，恢复核对后删除本任务专用 Lima 配置、虚拟机、镜像和临时副本。
- **FR-006**：操作方式、兼容边界和实际验证证据写入文档，其他任务改动不纳入提交。

## 关键实体

原生实例、运行进程、数据包、历史容器备份；数据所有权以项目目录与既有部署状态为准。

## 成功标准

- **SC-001**：11 个原生服务运行，主页及核心健康接口成功，停止后项目服务端口释放。
- **SC-002**：部署预检无文件改动，冻结和恢复覆盖真实存储；异常输入不覆盖数据。
- **SC-003**：旧 Lima 实例和专用目录清理完成，业务数据数量及附件摘要符合迁移清单。
- **SC-004**：Linux 命令路由及已有部署回归通过，文档和提交仅包含本任务内容。

## 假设与依赖

用户已准备 Conda；首先验收当前 arm64 Mac。不自动扩大到未验收平台。原始业务数据和备份不属于可丢弃临时文件。

## 范围外事项

生产镜像测试发布、业务接口改造、任意历史源码的数据自动升级。
