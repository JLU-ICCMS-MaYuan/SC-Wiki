# 技术决策

## 稳定体系身份

决策：新增 community_systems，使用按字母排序、去重的合法元素符号组成 system_key。理由：现有 chemical_systems 按论文和版本保存，同一 Hg 有多个记录，不能作为共享讨论身份。备选：直接外键关联旧体系；因版本变化和跨论文不共享而拒绝。依据：goserver/models/models.go 的 ChemicalSystem。

## 内容与权限集中

决策：统一 community_entries 存放问题、答案和评论三种内容，明确 question_id、answer_id、paper_id、system_key 和 parent_id；用类型校验限定组合。理由：共用作者、正文、状态和治理；各类目标通过外键保持关联。备选：任意字符串多态目标，因缺少删除约束而拒绝。

论文阅读复用 canViewPaper，其他公开问答直接阅读；被删除/隐藏的问题和答案阻断后代访问。评论占位不返回正文、作者或可操作入口；只保留已有回复。通知每次读取重新校验，不保存可泄漏的正文快照。

## 取消弹幕与保留通知同步

决策：取消弹幕全部能力，只保留每 30 秒获取站内未读通知的普通 HTTP 轮询，页面不可见时停止。用户反馈弹幕与评论重叠，且独立输入区占用空间；评论已有根线程、回复对象和连续交流能力，直接使用现有评论组件。

删除弹幕组件、播放队列、轮询与专用文案；新内容类型只接受 question、answer、comment。历史 danmaku 行和关联审计留在数据库，公开读取、按 ID 操作、通知和管理员举报列表均排除，不转换为评论、不执行清库或改写已应用迁移。仅隐藏前端会留下可调用接口，因此不采用；直接删除历史记录超出本次功能移除所需范围，也不采用。

## 评论定位与并发写入

评论按根线程归组，分页附带缺失根评论上下文；通知焦点自动计算所在页，避免长线程中的回复无法定位。相同目标的刷新保留前端数据和编辑器，点赞不会清空未提交答案或评论。

写事务按账号、论文或问题、答案、根评论、具体回复的顺序锁定。权限判定使用当前锁定读，避免 MySQL 默认事务隔离级别读到隐藏前的快照；问题和答案使用排他锁，防止更新活跃时间时共享锁升级死锁。真实 MySQL 测试以屏障让回复先读取旧快照、再提交隐藏，验证回复不会继续写入。

管理操作也遵循相同祖先锁顺序，并在锁定身份后重查管理员资格。已有体系空间只读取，不做无条件 upsert；否则体系写锁与隐藏评论时的外键检查可能形成死锁。隔离 MySQL 同时覆盖隐藏根评论与回复、隐藏答案与新增评论两组并发场景。

## 编辑与清理

决策：复用 Markdown 依赖，但新增不带 RAG 引用重写的安全展示组件；不解释 HTML，不渲染图片。删除内容软标记；论文物理删除通过外键级联清理其互动、举报和通知，体系讨论独立保留。

## 迁移与工作区

决策：新迁移追加在当前主业务 revision 20260916_0106，保留 20260914_0052 并行 head，不执行不带版本的 upgrade head。理由：工作区包含未提交的迁移和业务变更，不能合并或提交他人工作。实现验证覆盖当前工作区，交付明确记录前置迁移未提交的边界。
