# 设计调查：任务新标签页

## 新标签页入口

- 决策：采用原生链接和 `target="_blank"`、`rel="noopener"`；链接覆盖卡片普通区域，独立控件位于其上方。
- 理由：用户点击即可打开新标签页，同时保留键盘、复制地址与浏览器链接语义；不会因上传回调或异步请求导致窗口拦截。
- 备选：`window.open` 配合卡片事件需要额外处理键盘、右键和冒泡；本功能不采用。
- 证据：已认可方向的 Demo 及用户 2026-10-16 明确的新标签页要求、实施指令。

## 地址恢复与复用

- 决策：`/upload/tasks/:taskId` 为独立入口，以当前账号和地址任务 ID 挂载任务工作区，复用 `UploadPage` 已有任务部分、`UploadParsingDetail` 和 `UploadTaskEditor`。
- 理由：现有组件已覆盖五阶段、重试、手填、校对、核对及提交；任务地址不能被 `localStorage` 中旧活动任务覆盖。
- 备选：复制整个表单会形成双份行为；仅切换上传页底部状态不满足新页面要求。
- 证据：当前 `UploadPage.tsx`、`UploadParsingDetail.tsx`、`UploadTaskEditor.tsx` 与任务状态 API。

## 保存与原列表恢复

- 决策：详情页保留自动保存，未保存／保存中输入注册浏览器离页保护；返回上传记录使用原生地址链接。原列表重新获得焦点时刷新任务索引。
- 理由：关闭新标签页是用户自然动作，不能在保存前静默丢失输入；详情提交后原列表需要能更新任务移出情况。
- 边界：浏览器可能合并或限制原生提示；页面不能保证在被强制结束进程时保存尚未完成的编辑。不新增跨标签页同时编辑的锁或版本协议。
- 证据：编辑器已有 5 秒自动保存、获焦读取草稿与人工证据草稿保护；任务提交返回正式论文 ID。

## 数据与接口影响

只调整现有界面访问方式。任务、草稿和正式论文仍使用既有 API 与权限，不新增表、字段、迁移或后端写入接口。
