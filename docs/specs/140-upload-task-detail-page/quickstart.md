# 验收步骤：新标签页解析

## 前提与边界

启动现有前端与 API，登录有上传任务权限的账号，准备等待校对、处理中及失败任务。浏览器交互使用隔离样例或只读任务，正式提交只在明确的测试目标执行；不能用 Demo 验收替代正式组件验收。

## 自动化

运行相关上传界面测试与 `npm --prefix frontend run build`。具体已执行命令、通过数及限制记录在 [validation.md](validation.md)，没有执行的步骤不得标记通过。

## 操作验收

1. 在 `/upload` 保留待上传文件，选择一条任务，再点击另一条任务普通区域。应在新标签页打开 `/upload/tasks/<任务ID>`，原标签页地址、文件和选择状态保留；列表没有查看／收起按钮或内联结果。
2. 检查新页标题、任务阶段、分段结果和校对内容均属于地址指定任务。刷新、直接打开同一地址、打开另一个任务均不读取错误的活动任务缓存。
3. 修改并保存草稿，刷新查看保存值；存在未保存输入时点击返回或关闭页，浏览器提供离页保护。人工证据草稿仍走既有保护，不自动提交。
4. 在原列表分别用鼠标和键盘操作复选框、取消、清理和批量删除，均不误开详情标签页；任务链接可用键盘激活。
5. 任务失效或无权限时显示可读反馈和返回入口，不显示旧任务表单；任务已提交则沿用正式论文查看跳转。
6. 在桌面及 390px 窄屏检查链接、返回入口和表单，无新增页面横向溢出。关闭详情或切回原页后，原页可继续上传，重新获焦可更新服务端任务列表。

## 回写与远程边界

验收后记录实际证据和未验证场景。更新当前功能说明和 Issue；尚未推送时远程 Spec 链接保持待验证，不关闭 Issue。
