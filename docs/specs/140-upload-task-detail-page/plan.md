## 摘要与技术上下文

使用 React 19、TypeScript 5.6、React Router 6 与 MUI 7。上传任务继续读取现有 Python API，保存、证据核对及提交接口不变；没有数据结构或迁移变更。采用原生链接新开标签页，复用上传页已有工作区，不复制科学表单。

测试使用 Vitest、Testing Library 和真实浏览器。主要命令为 `npm --prefix frontend run test:upload-ui -- <文件>`、`npm --prefix frontend run build`。目标为现有桌面及窄屏浏览器。

## 文档与源代码结构

本目录包含 Spec、Plan、Research、Tasks、Quickstart、需求检查表及既有 Demo。没有新业务实体或新后端接口，数据模型与接口契约独立文件不适用。

- `frontend/src/components/UploadTaskCenter.tsx`：整条任务原生链接与独立控件；重新获焦时刷新列表。
- `frontend/src/pages/UploadTaskPage.tsx`：读取地址任务 ID，以账号和任务为键挂载既有上传工作区。
- `frontend/src/pages/UploadPage.tsx`：列表模式只管理上传；传入任务 ID 时只显示已有解析校对区域，移除活动任务本地存储依赖。
- `frontend/src/LazyRoutes.tsx`：注册 `/upload/tasks/:taskId`。
- `frontend/src/components/UploadTaskEditor.tsx`：补足未保存表单的浏览器离页保护；原有自动保存、人工草稿保护继续生效。
- `frontend/src/i18n/{zh,en}/upload.ts`：新增标签页、返回入口与错误提示。
- `tests/01_decentralized_uploading/`：覆盖原生链接、任务地址恢复、权限与失效、独立操作和草稿保护。

## 阶段与依赖

1. 同步用户原话和新标签页结论，明确替代旧 Spec 中不强制新标签页的描述。
2. 修改任务入口和地址页面，复用原工作区；不在异步上传成功回调中自动打开窗口，以免弹窗拦截。用户点击任务后才新开页。
3. 保留任务状态恢复、失败动作、核对、保存和提交；为关闭详情页和返回入口补足未保存保护。
4. 更新已有回归、新增路由测试、构建和浏览器检查；根据实际证据更新 Overview、README、Issue 与任务记录。

## 复杂度与工作区边界

复用既有上传工作区的任务模式是本次最小改动，避免复制编辑器和解析状态逻辑。独立页面壳只负责地址及挂载隔离。工作区已有主文角色确认等未提交代码，本次保留其位置与行为；提交时从本次变更中排除这些原有差异，避免混入其他 Feature。
