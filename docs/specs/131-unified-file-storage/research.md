# 研究与决策：统一业务文件存储

**Issue**：[ #131](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/131)

**日期**：2026-10-12。以下为代码只读核查与设计选择，不是实现或环境验收结果。

## 已核查现状

| 证据位置 | 当前事实 | 设计影响 |
| --- | --- | --- |
| `backend/api/upload_tasks.py` | 上传写入任务目录，状态含绝对 `stored_path` 和相对 `source_file_path` | 不能只改挂载目录，须改变引用生产者和消费者 |
| `backend/ingest/upload_jobs.py`、`document_regions.py` | 解析与证据渲染直接打开路径 | 统一取得受控本地临时文件 |
| `backend/models.py`、`backend/manual_evidence_models.py` | `PaperFile.stored_path`、头像键、草稿和证据 JSON 分散保存引用 | 建立字段级迁移清单，不做全库字符串替换 |
| `scripts/local_deploy/paths.py` | 已登记部分路径字段及两类草稿 JSON | 复用安全边界与扫描思路，但现有清单不等于生产迁移全覆盖 |
| `goserver/handlers/account.go`、`public_profile.go`、`governance.go` | 头像由 Go 读写和删除本地文件 | Go 必须接入同一配置与键约束 |
| `backend/services/structure_storage.py` | 部分结构正文已存 MySQL | 不将这些数据库事实重复迁移为对象 |

## D1：一个文件接口，两种实现

决策：Python 提供 `backend/storage/`，Go 提供职责对等的 `goserver/storage/`；支持 `local` 与 `s3`。两种语言共用配置和行为契约，不共享权限业务逻辑实现。Python S3 SDK 选 boto3，Go 选 AWS SDK for Go v2 的 S3 客户端；新增依赖仅在实现阶段以项目方式锁定和验证。

理由：保持本地无 Docker，生产直接访问标准 S3 接口。拒绝新增独立文件 HTTP 微服务，避免再增加服务跳数及认证体系。拒绝跨机器共享本地路径作为正式契约。

## D2：复用既有引用字段，不新增文件业务数据库

决策：数据库既有文件键列仍保存字符串，但生产新写入只保存规范对象键；包含大小/哈希的引用使用 `FileRef`。引用归属仍由现有论文、草稿、证据、用户字段决定。切换时一次性迁移历史字段，不在正常查询路径对本地/S3 双读。

理由：无需重建一套文件权限数据库。现有 `stored_path` 列名可暂留，必须在模型注释和契约中明确它在新路径中表示键。数据库内已有 `document_json` 和结构正文继续在原事务中保存，外置文件不是其另一个事实来源。

## D3：不可变对象与受控临时目录

决策：对象键由服务端生成，包含用途、归属及随机身份；覆盖文件产生新键，业务引用成功更新后再清理旧键。每次执行使用独立临时目录，下载校验大小与 SHA-256，退出清理。分片上传失败需终止，遗留分片由运维生命周期策略清理，不能替代业务引用清理。

理由：不依赖各 S3 产品不同的跨对象事务或重命名行为。对象上传与 MySQL/Redis 不是一个事务；未引用对象可稍后清理，禁止先发布引用再上传内容。

## D4：停写窗口内复制、核验、改引用

决策：默认 dry-run；复制阶段不改源，验证后更新登记引用，记录旧值便于切换前回退。跨 MySQL/Redis 无事务，使用逐项日志与幂等条件更新；任一阶段失败继续维护模式，禁止半迁移开放。

理由：用户允许维护停机，无需双写和实时同步。不能直接用 #112 的包恢复流程替代生产迁移，尤其其路径登记不覆盖全部人工证据和新增快照。

## D5：权限仍留在调用入口

决策：API 先做现有用户/角色/版本检查，再请求存储。桶不公开；不把真实 S3 URL 返回浏览器；对象不存在与权限不足遵循现有 API 区分规则，存储服务错误输出稳定脱敏错误。

备选方案：浏览器预签名直传可减少应用带宽，但会扩大本次客户端契约与权限范围，首版不采用。
