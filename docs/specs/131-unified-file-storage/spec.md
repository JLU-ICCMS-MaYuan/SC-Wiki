# Feature 规格：统一业务文件存储

**GitHub Issue**：[ #131](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/131)

**父 Epic**：[ #130](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/130)

**创建日期**：2026-10-12

**状态**：规划已确认；未实施、未执行迁移

## 背景与目标

API、上传 Worker 和证据核对当前通过本机目录共享文件。将计算节点移到其他机器后，数据库仍可连接，但文件路径不再可达。本功能让业务文件不依赖应用或计算机器的位置，同时保持本地原生开发体验。

## 用户场景与验收

### US1：在统一存储中使用业务文件（P1）

用户照常上传论文、结构附件、人工证据和头像，查看解析结果与审核证据，无需知道文件存放在哪台机器。

**独立验收**：使用真实对象存储运行上传、读取、替换和清理流程；拒绝直接访问应用持久目录后仍可用。

1. 假如用户上传合法文件，当上传成功并进入后续任务时，那么文件已完整保存且内容可核验。
2. 假如其他用户无权读取草稿或证据，当其请求文件时，那么沿用现有权限拒绝访问，不泄露存储位置或凭据。
3. 假如文件仍被正式论文或返修引用，当清理上传任务时，那么仍可从授权入口读取文件。

### US2：迁移已有文件且可恢复（P1）

管理员在维护窗口将历史文件与引用迁至统一存储，不丢失已有论文、草稿、证据和头像。

**独立验收**：对包含正式记录、持久草稿、返修及临时任务的样本迁移，中断重跑后逐项校验。

1. 假如扫描发现文件缺失、越界或引用不支持，当管理员预检时，那么阻断应用切换并输出定位信息。
2. 假如对象复制完成但引用更新中断，当继续同一迁移时，那么按清单续跑，不重复覆盖冲突内容。
3. 假如目标尚未开放新写入，当需要回退时，那么能恢复旧引用和原文件访问。

### US3：保留本地开发与运维边界（P2）

开发者仍可无 Docker 启动本地服务，使用文件系统实现；生产对象存储故障则报告不可用，不读取意外的旧本地副本。

**独立验收**：原生启动、文件操作与冻结恢复回归；对象存储停机时确认无本地兜底成功。

## 需求

- **FR-001**：所有持久业务文件必须通过统一访问边界读写，包括原始附件、解析与审核产物、人工证据、头像；数据库内结构正文仍以数据库为事实来源。
- **FR-002**：跨进程引用必须是稳定文件标识及完整性信息，不包含节点绝对路径、存储凭据或可变临时位置。
- **FR-003**：保留现有 API、权限、文件格式及大小限制；先鉴权再读取，上传成功前完成内容校验与持久化。
- **FR-004**：文件写入失败、部分写入或内容冲突不得发布有效引用或伪报成功。
- **FR-005**：计算所需本地文件必须由持久引用按需取得；本地缓存丢失不得造成持久数据丢失。
- **FR-006**：删除必须遵循文件所有权、论文版本和引用关系；清理可重试，不能删除仍被引用的对象。
- **FR-007**：迁移必须先建立文件与引用清单，覆盖附件表、头像、持久草稿、返修、审核/证据快照和 Redis 临时任务中的已登记字段。
- **FR-008**：迁移必须支持预检、校验、续跑和切换前回退；保留源文件，不自动清除旧数据。
- **FR-009**：生产存储模式不静默读取旧目录；本地开发保留文件系统实现及现有原生命令行为。
- **FR-010**：错误、日志、备份和迁移报告不得泄露访问密钥、临时模型凭据；未知引用和不一致必须明确阻断。

## 成功标准

- **SC-001**：US1 中每类文件的上传、读取、替换、清理及越权场景均在真实 S3 后端通过。
- **SC-002**：迁移清单中全部有效引用可解析，文件大小与 SHA-256 全部一致；存在未解释缺失时不得切换。
- **SC-003**：同一迁移中断后重复执行不产生内容冲突、重复业务记录或丢失源文件；切换前回退通过。
- **SC-004**：移除应用/Worker 历史目录和缓存后，已迁移业务文件仍可读取；对象存储故障不会伪报成功。
- **SC-005**：本地文件后端、原生启动和冻结恢复回归通过，正常本地工作不新增 Docker/S3 前置条件。

## 假设、依赖与范围外

对象存储初期自托管并与其他服务同机，之后归数据组。首版 API 代理上传下载，桶保持私有。本地与生产使用相同文件业务接口、不同存储实现。

三组编排由 [#132](../132-three-tier-deployment/spec.md) 负责；跨机执行提交由 [#133](../133-remote-pdf-workers/spec.md) 负责。保留 #35 的清理语义、#109 的证据权限和 #114 的解析契约。对象存储集群、CDN、浏览器直传、自动删除旧文件不在范围内。
