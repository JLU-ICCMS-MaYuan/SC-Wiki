# 数据与引用模型

**Issue**：[ #131](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/131)。本文件描述拟实现契约，不声明数据库已变更。

## FileRef

| 字段 | 约束 |
| --- | --- |
| `key` | 非空、UTF-8、最多 500 字符的相对对象键；无开头斜杠、反斜杠、空段、`.`、`..`；服务端生成 |
| `size` | 非负字节数；新写入必须有值 |
| `sha256` | 内容的 64 位小写十六进制摘要；不使用 S3 ETag 代替 |
| `media_type` | 按既有内容校验得出的类型，不信任客户端声明 |

对象键推荐布局为 `files/<kind>/<owner-id>/<uuid>/<安全文件名>`；执行产物使用 `runs/<task-id>/<attempt-id>/<相对产物名>`，由 #133 约束尝试身份。键不包含机器地址、bucket、用户名或凭据。部署命名空间由配置选择，不能通过请求任意指定。

## 既有实体的适配

| 实体或载体 | 文件引用变化 | 权威事实 |
| --- | --- | --- |
| `PaperFile.stored_path` 与文件大小/哈希 | 字符串改为规范对象键，字段名暂留 | 论文 id、revision、所有者、来源内容摘要 |
| 用户 `avatar_key` | 保存完整规范键，Go 不再直接拼接本地目录 | 用户及原有头像访问规则 |
| `scientific_upload_drafts`、`paper_revision_drafts` | 仅登记路径字段改为键；新增内部引用包含 FileRef | 原草稿版本与归属 |
| Redis 上传状态、核对任务快照 | 文件 manifest 使用 FileRef；公开 DTO 不暴露内部键和凭据 | 当前任务状态与所有权 |
| 人工证据 `items`、审核与历史快照 | 明确登记到 JSON 指针，逐字段迁移 | 现有证据身份、版本和权限 |
| Document IR、结构正文 | 保留数据库 JSON/正文；外部附件单独使用引用 | 现有事务内数据 |

本 Feature 不增加数据库业务实体或为对象存储另建权限表。若现有列长度不足，先在实现前报告并修正规划，不能截断键。内部任务引用升级与 #133 的状态契约版本一起发布；迁移命令负责旧格式，普通业务路径不永久兼容两种生产格式。

文件契约具有独立 `file_contract_version=1`，首次引入对象键时 API/Worker 必须同时支持，部署检查拒绝混用旧制品；#133 再增加执行代次时升级任务契约。#131 的单项验收不允许让未适配文件键的旧 Worker 消费新任务。

## 生命周期

文件产生 → 内容完整写入与校验 → 业务事务/任务状态引用 → 被正式论文或返修引用 → 引用解除 → 安全清理。

清理必须检查现有正式记录、持久草稿、任务和审核引用；任一必要事实来源不可用则保留对象并报告重试。正式提交或返修与清理沿用同一任务/论文并发控制，不能仅凭某个临时任务过期就删除对象。不得为上传后缺少引用的对象立即执行全桶清扫。

## 迁移清单

每项保存 `source_root_id`、相对路径、大小、SHA-256、目标键、引用位置（表/主键/列/JSON 指针或 Redis 键/指针）、旧值、目标值、阶段与错误。清单不包含业务全文或密钥；权限 0600，并与备份存放在受控目录。

阶段为 `discovered → copied → verified → referenced`，冲突为 `blocked`。清单必须穷尽文件字段的生产者/消费者；不得递归替换所有包含斜杠的科学文本。已有文件系统模式的绝对路径仅通过显式源根校验解析，生产 S3 模式不接受绝对路径。
