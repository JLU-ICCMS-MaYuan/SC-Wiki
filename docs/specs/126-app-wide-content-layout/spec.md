# Feature 规格：全站页面主体窄边距布局

**GitHub Issue**：[#126](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/126)

**创建日期**：2026-10-09

**状态**：已确认

## 背景与目标

全站页面共用的主内容左右留白为桌面 32px、窄屏 16px；部分页面还有整页最大宽度，留下明显空带。用户要求把 #124 的左右窄缝规则推广至所有应用页面，同时保持普通页面上下节奏，并维持已有常驻操作栏的紧凑、不透明效果。

## 用户场景与验收

### 用户故事 1：跨页面使用一致的宽工作区（优先级：P1）

用户在导航、论文、社区、账户和管理页面之间切换时，页面主体始终充分使用侧栏右侧的窗口宽度。

**优先级理由**：直接解决全站明显的左右空带。

**独立验收**：查看各类路由在宽屏及窄屏的页面主体，确认左右约 8px 间隙；页面切换和侧栏收起后仍保持一致。

**验收场景**：

1. **假如** 用户进入任意应用页面，**当** 页面显示主体内容，**那么** 主体距导航右缘和视口右缘各约 8px，上下留白保持该页原有节奏。
2. **假如** 页面曾因整页最大宽度居中，**当** 宽桌面显示账户、社区或管理工作区，**那么** 根内容和主要卡片填充可用宽度。
3. **假如** 上传页的解析详情从展开切换为收起，**当** 工作区重排，**那么** 两种状态都保持约 8px 左右间隙，待上传文件不丢失。

### 用户故事 2：窄窗口中继续操作（优先级：P1）

用户在较窄窗口中使用聊天、Tc 估算及管理员编辑时，主要控件仍可见、可用，页面不被全屏负边距或固定多列布局撑宽。

**优先级理由**：统一边距不能以新增水平溢出为代价。

**独立验收**：在 375px 与 768px 视口检查主要布局，文档宽度不超过视口；必要的大表格、图表只在各自内容容器内横向滚动。

**验收场景**：

1. **假如** 视口较窄，**当** 打开对话、Tc 估算或管理员论文编辑页面，**那么** 多列工作区按可用宽度重排，按钮和表单仍可操作。
2. **假如** 页面包含宽表格或图表，**当** 内容超过容器宽度，**那么** 只在该内容容器内部滚动，不扩大整个页面。

### 边界与异常场景

- 侧栏可展开为 216px 或收起为 64px；两种状态下均以侧栏右缘作为左间隙起点。
- 仅调整页面主体。对话框、抽屉、菜单、段落阅读行宽和空态提示可保留现有尺寸。
- 现有页面级顶部常驻栏只有上传解析栏；维持其顶部偏移 0、不透明背景和至少 44px 高的收起按钮，不给其他页面新增栏。

## 需求

### 功能需求

- **FR-001**：所有由 `AppShell` 承载的页面主体左右各保留约 8px，普通上下边距维持现状。
- **FR-002**：账户、公开主页、社区讨论、系统页、管理工作台和管理员论文编辑页不得用整页最大宽度限制主要内容。
- **FR-003**：上传页解析详情展开与收起时均采用统一左右边距，不再以解析状态改变外层边距。
- **FR-004**：对话页不得用旧的全屏负边距抵消新边距；Tc 估算和管理员论文编辑中的固定多列布局必须在窄窗口重排，页面主体不得因本次修改新增水平溢出。
- **FR-005**：已有上传解析常驻栏、侧栏展开收起、上传草稿以及各页主要交互必须保持可用。
- **FR-006**：对话框、抽屉、菜单及内部阅读行宽的既有尺寸规则保持不变。

## 成功标准

- **SC-001**：375px、768px、1366px 和宽桌面视口下，受影响路由的主体左右间隙均为 8px，允许浏览器亚像素取整误差 1px。
- **SC-002**：上述视口的页面级 `scrollWidth` 不超过视口宽度；宽内容可在自身容器内滚动。
- **SC-003**：上传页展开、收起解析后的左右间隙一致，原有常驻栏和草稿行为通过回归验证。
- **SC-004**：相关前端回归测试和生产构建通过；路由、API 和数据契约不变。

## 假设与依赖

- 与 [#124](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/124) 关联；本 Feature 覆盖其“收起后恢复 32px”边距约定，不改变其常驻栏要求。
- `RagPage.tsx` 当前存在其他任务的未提交重写；本 Feature 在公共壳层限定 `/rag` 根容器的横向边距，不修改或提交该文件的业务改动。

## 范围外事项

- 不新增顶部常驻栏；侧边 sticky 卡片不按顶部栏规则改造。
- 不改变弹层尺寸、业务流程、API、权限、持久化或导航信息架构。
