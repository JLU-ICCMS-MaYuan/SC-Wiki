# 技术决策：全站页面主体窄边距布局

## 边距事实来源

- **决策**：`AppShell` 的 `main` 统一 `px: 1`，原 `p: { xs: 2, md: 4 }` 拆为水平与竖向规则。
- **理由**：现有宽边距来自壳层，统一处理可避免每页复制负边距；上传页目前的负边距需要同步移除。
- **备选方案**：逐页面抵消壳层内边距，会积累互相冲突的例外。
- **证据**：`AppShell` 当前使用响应式 `p`；`UploadPage` 展开态使用 `mx: { xs: -1, md: -3 }`。

## 整页限宽与局部阅读宽度

- **决策**：只删除限制整个页面主体的 `maxWidth` 或 `Container maxWidth`；保留新闻标题文案、聊天消息、空态与弹层的局部宽度。
- **理由**：让主要卡片占满窗口，同时保持长文本可读性。
- **证据**：账户、公开主页、讨论、系统页、管理工作台等根容器有 820px 至 1280px 上限；管理员编辑使用 `Container maxWidth="lg"`。

## 窄屏网格

- **决策**：Tc 估算的左右列在窄屏叠为单列，文件选择区也在最窄宽度叠为单列；管理员编辑中固定 3 至 5 列的字段组按可用宽度降列。RAG 页保留竖向全屏补偿；公共壳层仅在 `/rag` 路由覆盖页面根容器的横向负边距。
- **理由**：放宽主体不能让固定列宽挤压控件或扩大文档宽度。
- **证据**：`TcPredictPage` 使用最小 320px 的结果列，管理员编辑存在固定 4/5 列字段组；RAG 新工作区根容器使用 `m: { xs: -2, md: -4 }`，实测 375px 视口下从期望的 72–367px 伸展至 56–383px，当前重写仍未提交。
- **提交隔离**：RAG 文件的同期重写覆盖几乎整页，无法从 Git HEAD 安全暂存单行布局改动；壳层的路由限定覆盖可独立提交，并通过真实视口几何核验。

## 常驻栏与接口

唯一页面级顶部常驻栏是上传解析操作栏；其 `top: 0`、不透明背景与最小 44px 按钮维持现状。Tc 估算和论文详情的 sticky 卡片属于侧边内容，不新增顶部栏。本次不改变 API、数据、持久化或权限。
