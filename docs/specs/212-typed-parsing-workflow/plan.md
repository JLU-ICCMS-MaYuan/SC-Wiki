# 实施计划：文献类型流程选择

**Issue**：[#212](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/212)；**日期**：2026-11-03；**规格**：[spec.md](spec.md)。

## 技术上下文与摘要

Python/FastAPI、RQ/Redis、SQLAlchemy/MySQL、React/TypeScript/Vite。复用文献读取、模型适配和来源分批。pytest、Vitest及三类表单契约负责验证，不引入插件框架或数据库迁移。

## 数据所有权与组件职责

1. `backend/ingest/parsing_workflows.py` 登记流程身份、表单版本/摘要和专用执行入口，管理适用性判断及绑定校验。模型只能返回本文科学类型、理由和来源编号，程序决定流程及表单。
2. `upload_jobs._process_upload_task` 先通用读取正文/SI文本及IR，全文分批判断。匹配后派发常规计算入口，复用本次读取文件，再处理结构、候选、材料状态、填写与谱。未匹配停在 `needs_workflow`，不创建可编辑科学稿。
3. 新任务的 `workflow_policy` 和根级 `_parsing_workflow` 为程序元数据；不进入 #203 标准科学字段。当前登记固定表单版本及摘要，本次不改标准键。
4. 绑定随草稿、正式提交历史和整稿交接快照保存；`paper_revisions.current_draft` 从提交元数据恢复。整体保存继承服务端绑定，局部根白名单不开放绑定写入。操作校验身份，不因输入或保存重新判断或调用模型。
5. 前端暂停时只显示通用结果、原因与文件，停止轮询；四宿主通过共享标识显示流程与表单版本。

## 历史和失败

无策略/绑定的既有稿件沿原有授权路径读取，不把身份缺失当常规类型；重新解析重新选择。存在但非法的绑定必须报错。暂停保留文件和通用产物，沿现有24小时活动清理机制，不伪造完整解析结束时间。

## 文档与源代码结构

本目录包含 Spec、Plan、Research、数据模型、流程契约、Tasks、Quickstart、检查表及验证记录。主要触点为上传 Worker/状态、`field_drafts`、提交/返修/整稿交接服务、共享前端流程展示与暂停详情。

## 阶段与依赖

文档→失败回归→流程模块→上传前置门→持久化与界面→回归及真实来源→Overview与独立提交。共享文件串行，不使用子代理。绑定仅用于保持同一文献全流程一致，未引入未来类型枚举或工作流引擎。
