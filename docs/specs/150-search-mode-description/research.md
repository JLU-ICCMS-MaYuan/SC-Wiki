# 技术研究：检索方案说明

## 决策一：根据既有匹配规则解释方案

- 决策：组合是材料元素集合属于所选集合的子集；精确是集合相同；包含是材料集合包含全部所选元素。
- 理由：文案必须解释当前行为；不能凭按钮名称猜测。
- 证据：goserver/handlers/papers.go 的 superconductor 查询中三个分支；backend/api/structural_records.py 的集合匹配；本地材料检索 Overview。
- 备选方案：仅解释按钮名称无法区分“部分所选”和“全部所选”，不采用。

## 决策二：同一选项列表派生说明

- 决策：每个选项保留值、名称翻译键及说明翻译键；展示时从 mode 查找选项。
- 理由：复用已有状态，语言切换后自然更新。
- 备选方案：单独保存说明状态会造成额外同步，新增接口或 effect 均无必要。
- 边界：非三种元素模式不显示误导性说明；正常入口仍默认组合模式，不扩展 URL 校验范围。

## 决策三：自适应卡片头部

- 决策：桌面将说明放在标题与操作区之间；宽度不足时换行，文字完整显示，按钮组内部允许换行。
- 理由：满足 IMG-001 指定位置，同时适应英文和移动端。
- 备选方案：固定绝对定位或强制固定高度容易遮挡，悬浮提示不满足直接显示要求。

## 验证边界

构建证明类型与打包有效；已有检索回归保护默认行为；浏览器使用真实页面和布局引擎，隔离 API 以验证点击、文案与出站参数，不声称验证生产数据库结果或上线。
