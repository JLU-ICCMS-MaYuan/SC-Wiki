## 背景与目标

用户在检索前需要理解三个方案的匹配范围；在选中方案旁显示解释，降低仅靠按钮名称判断的成本。

### 需求结论与变更取舍

在截图红框区域显示当前方案说明，随选项立即切换。保留现有检索规则、默认选项及主要操作。后续“开始”确认初版草案。最新反馈明确替换初版头部布局：桌面第一行依次为标题、说明、三个模式、进入页面、清除选择；已选元素移到独立下一行。除说明外统一字号，说明宽度恰好为标题与模式组之间的可用空间。保留历史原话，按最新要求实施；窄屏仍完整换行。

## 用户场景与验收

### US1：选择方案时理解匹配范围（优先级：P1）

用户选择方案后直接阅读说明，并据此选择元素发起检索。

**优先级理由**：这是本次唯一用户目标。

**独立验收**：在检索页逐个切换三个方案，核对以下文案、显示位置和既有操作。

| 选项 | 显示说明 |
| --- | --- |
| 选择元素的组合 | 检索由所选元素中的一种或多种组成的材料，不包含其他元素。例如选择 La、H，可匹配 La、H 和 La–H 体系。 |
| 仅包含选择元素 | 检索恰好由全部所选元素组成的材料，不包含其他元素。例如选择 La、H，仅匹配 La–H 体系，不限制各元素的比例。 |
| 包含所选元素 | 检索同时包含全部所选元素的材料，允许包含其他元素。例如选择 La、H，可匹配 La–H、La–H–S 等体系。 |

**验收场景**：

1. 假如用户初次进入检索页，当页面加载完成，那么显示默认选中方案的说明。
2. 假如尚未选择元素，当用户切换任一方案，那么立即显示对应说明，无需发起检索。
3. 假如已选择元素，当用户清除选择，那么继续显示当前方案说明。
4. 假如正在阅读说明，当切换中英文，那么使用对应语言；窄屏允许换行排列。
5. 假如使用桌面窗口，当显示周期表卡片，那么标题、说明、模式和操作按钮在同一行垂直居中；已选元素位于其下一行。
6. 当检查头部文字时，标题、模式、操作按钮以及已选元素区域字号一致，说明保留较小字号，并占满标题与模式组之间的可用宽度。

### 边界与异常场景

- 未选元素、清除元素均不隐藏说明。
- 说明不依赖请求结果，网络错误不影响阅读。
- 示例仅解释匹配范围，不保证数据库存在对应记录。
- 长文案在窄屏完整换行，不遮挡按钮或截断文字。

## 需求

### 功能需求

- **FR-001**：在截图指定区域展示当前选中方案的说明。
- **FR-002**：说明与选中方案同步，采用上表定义的准确含义。
- **FR-003**：未选择元素时也能阅读说明。
- **FR-004**：支持现有中英文切换，确保窄屏文字完整可读。

- **FR-005**：桌面第一行放标题、说明、三个模式与进入/清除操作，垂直对齐；已选元素放在其独立下一行。
- **FR-006**：除说明外，头部标题、模式、操作和已选元素区域使用相同字号。
- **FR-007**：说明区域宽度为标题与模式组之间扣除必要间距后的全部剩余空间。

本功能无新增业务实体或持久数据。

## 成功标准

- **SC-001**：三个选项逐一切换，说明全部对应正确。
- **SC-002**：桌面说明位于指定区域；窄屏说明与按钮无重叠、无文字截断。
- **SC-003**：元素选择、清除选择及进入结果页操作保持正常。
- **SC-004**：桌面第一行标题、说明和各操作的垂直中心偏差不超过 1 像素；已选元素位于整行下方；除说明外计算字号一致；说明占满中间列而不越界。

## 假设与依赖

- 沿用三个方案和当前默认组合模式；依据 SearchPage 与现有后端匹配逻辑。
- 无新增外部服务和持久化依赖；使用当前语言切换能力。
