## 背景与目标

图谱科学标题是概括论文核心贡献、供知识图谱节点显示的短标题，独立于论文原标题。当前生成、保存和科学核对已有该字段，上传校对表单却缺少入口。用户需要看到被核对的实际内容，并能修改、保存和查看其依据。

### 需求结论与变更取舍

补齐已确认 Issue 的字段入口和核对流程，不通过删除核对项解决可见性问题。保持字段原有的可空性、英文生成约定及标题缺失时图谱回退原标题的行为。首次“确认”批准 Issue；展示完整 Spec 后，用户明确要求继续实现与验证，确认本版实施基线。

## 用户场景与验收

### 用户故事 1：查看、修订并核对图谱科学标题（US1，优先级：P1）

上传者打开解析草稿，在论文原标题附近看到图谱科学标题的实际值及用途，修改并保存后查看来源、继续现有核对流程。

**优先级理由**：当前字段会阻塞用户核对，却没有直接编辑入口。

**独立验收**：同一草稿完成查看当前值、编辑保存、刷新恢复与打开对应字段侧栏；原标题保持不变。

**验收场景**：

1. 假如草稿已有图谱科学标题，当打开表单，那么显示真实当前值及字段名称、键名和用途。
2. 假如用户修改该值，当保存成功并刷新，那么显示保存的新值，原标题不变。
3. 假如该字段有待处理核对项，当点击字段标签，那么打开对应来源核对与字段设置侧栏，不再因缺少控件出现在待定位区域。
4. 假如当前值已有有效核对结论，当修改值，那么旧结论按现有内容版本规则失效；仅打开页面不使结果失效。

### 边界与异常场景

- 历史草稿缺失字段或值为空时，仍显示空输入框，不强制补写或复制原标题。
- 只读时可查看和按现有权限查阅来源，不允许修改。
- 提交中或已有版本冲突时，遵守现有禁用规则；保存失败不得显示保存成功，冲突不得静默覆盖。
- 没有来源核对记录时，字段仍可见；不伪造来源或人工通过结论。

## 需求

### 功能需求

- **FR-001**：在上传校对表单论文原标题附近显示“图谱科学标题”，提供 `paper.knowledge_graph_title` 键名及“用于知识图谱节点展示的简短标题”的用途说明。
- **FR-002**：显示草稿的真实当前值；字段缺失或为空时显示空输入框，不自动填入原标题。
- **FR-003**：有编辑权限时支持修改和保存，保存后刷新保持该值，且不修改论文原标题。
- **FR-004**：字段标签接入现有来源核对和字段设置侧栏；已有核对项能定位到该控件。
- **FR-005**：修改值使旧核对结论按现有规则失效；未修改时保留有效结果，不自动产生人工确认。
- **FR-006**：遵守现有只读、提交中、保存失败和版本冲突规则。
- **FR-007**：保留可空性、原有标题生成和图谱展示规则，不新增必填要求。

### 关键实体

- 论文草稿：图谱科学标题与论文原标题是两个独立字段，当前草稿值是表单显示与保存的依据。
- 字段核对记录：对应图谱科学标题当前内容及来源的核对结果；旧值的结论不能自动证明新值正确。

## 成功标准

- **SC-001**：有值、空值和历史缺失字段三种草稿均可找到该控件，显示值与草稿一致。（FR-001、FR-002、FR-007）
- **SC-002**：修改、保存并刷新后新值保持，原标题不变；失败和冲突不被报告为成功。（FR-003、FR-006）
- **SC-003**：存在该字段核对项时能从控件打开对应侧栏，且不再因控件缺失进入待定位列表；修改后旧结论失效。（FR-004、FR-005）
- **SC-004**：只读、提交中和版本冲突场景无法通过该控件修改值，已有其他字段编辑与核对行为保持正常。（FR-006）
