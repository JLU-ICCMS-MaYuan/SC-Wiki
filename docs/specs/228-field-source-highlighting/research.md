# 依据与取舍

## 指定讨论材料

以下摘录是用户指定的材料，技术内容不冒称逐字新指令或已实现。

第一项：证据定位、存储与高亮展示

##### 目标与当前基础

让用户在侧栏“系统找到的原文”中，看清当前字段依据的具体文字或区域，同时读到理解它所需的上下文。改进同时涉及来源定位、原件复用及阅读体验，不能只增加一个高亮样式。

当前已有文件、页码、块、区域及原句定位；[EvidenceRegion](../../../frontend/src/components/EvidenceRegion.tsx) 能展示引句及 PDF 区域，[PDF 裁图](../../../backend/ingest/pdf_evidence_crops.py) 已按可信位置即时渲染，不持久保存生成的裁图。尚未确认存在等同 LangExtract 的统一字符区间接口，也不能认定每个单元格、曲线点或公式符号都已有精确坐标。

##### 借鉴机制与已认可方向

LangExtract 让模型返回提取文字、类别和属性，再由程序对齐输入原文，计算 `char_interval`。起点包含、终点不包含；例如 `Tc = 200 K.` 中 `200 K` 的区间是 `[5, 10)`，位置从 0 开始。程序根据区间切分原文并添加高亮，按类别区分、联动属性和上下文，生成独立 HTML。对齐不要求模型数位置，也不为定位再调用模型；精确、近似匹配和未定位需要分别表达。依据见 [resolver.py](https://github.com/google/langextract/blob/main/langextract/resolver.py)、[字符区间定义](https://github.com/google/langextract/blob/main/langextract/core/data.py)与 [visualization.py](https://github.com/google/langextract/blob/main/langextract/visualization.py)。

SC-Wiki 将这种机制用于现有侧栏，展示与当前字段对应的来源，而不要求引入独立 HTML 页面或替换现有模型提取。例如原文 `At 150 GPa, Tc reaches 200 K.`，Tc 字段可突出 `200 K`，压力字段可突出 `150 GPa`；前后文字继续保留，不能把一个数值单独框出后省去限定条件。

非文本内容依靠原 PDF 区域坐标，不能用字符区间直接画框：

| 来源 | 期望的定位与展示 | 必须保留的阅读内容 |
| --- | --- | --- |
| 正文 | 高亮对应文字或证据句 | 前后句、限定条件及相关反证 |
| 表格 | 定位对应单元格或结果行 | 表头、单位、同行条件及表注 |
| 图片或曲线图 | 定位实际已识别的子图、图例、点或曲线区域 | 坐标轴、图例及理解结果所需的其他曲线 |
| 公式 | 定位整式；有可靠细定位时再突出局部符号 | 符号定义、前后假设及适用范围 |

只有整图地址时只能可靠地框出整图；没有局部定位时，不能根据提取值假装知道对应曲线点。定位准确与科学解释正确分开核对，来源无法定位或无法读取时如实显示。

存储采用“共享原件 → 字段引用位置 → 查看时读取或渲染”的方向。每处定位绑定文件身份、版本或摘要、页码、块及区域，必要时关联字符区间；一个字段可引用多处，例如数值、单位和适用条件分别在不同页面。原件保持可访问，更换 PDF 或解析文本变化后不能盲用旧地址；重复数值应在确定的来源范围内定位，不能取全篇第一个匹配。近似文字匹配本身也不能直接授予科学支持。

用户希望同时看到高亮与未高亮的原始内容。完整原页和局部阅读范围可以共享同一份原件，高亮只是其上的标记。减少重复持久存储不等于删除必要文字依据；已有按需裁图也不能再次计为“新增节省”。实际节省空间、渲染耗时和缓存收益尚未测量。

##### 边界与待定细节

整句还是字段文字高亮、默认整页还是局部、放大和滚动方式、文字引句是否保留及保留长度仍待讨论；更细的表格、图像及公式定位是否可得需验证。来源加载、失败、反证、权限和当前值绑定继续遵守 [#221](../../specs/221-scientific-field-sidebar/spec.md)，本节不另立侧栏现行规则，不删除历史证据。


## 工程选择

复用现有依赖和契约，保存起始工作区版本，只提交本次改动。重复文字限定来源范围；无可靠局部坐标不猜点位；文件或文本变化使定位失效；加载失败和权限维持#221。
