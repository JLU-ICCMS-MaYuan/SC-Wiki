# Feature 规格：上传解析记录支持多选批量删除

**GitHub Issue**：[#121](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/121)

**创建日期**：2026-10-08

**状态**：已确认

## 背景与目标

上传页的「上传解析记录」列表当前只支持单条操作：运行中的记录可逐条「取消」，终态记录（failed/duplicate/cancelled）可逐条「清理」。当列表中积累了大量失败、重复或已取消的记录时，用户必须逐条点击，操作繁琐。

本 Feature 为该列表增加**多选批量删除**能力：用户通过复选框勾选任意状态的解析记录，一次性删除全部选中项。已确认的范围决策：**任意状态的记录均可勾选删除**——运行中/排队中的记录由后端先终止解析，再清理状态、文件与索引。

## 用户场景与验收

### 用户故事 1：批量清理失败与过期记录（优先级：P1）

用户在上传解析记录列表中勾选若干失败、重复、已取消的记录，点击「批量删除」并确认后，全部选中记录从列表中消失，对应的临时文件与解析产物被清理。

**优先级理由**：这是用户提出需求的核心场景，覆盖绝大多数日常操作。

**独立验收**：勾选多条终态记录批量删除后刷新列表，记录消失；`upload_PDFs/{task_id}` 目录与 Redis 状态键被清理。

**验收场景**：

1. **假如** 列表存在 3 条 failed 记录，**当** 用户全选并点击「批量删除」且确认，**那么** 3 条记录被删除，列表刷新后不再显示，界面反馈删除成功数量。

### 用户故事 2：删除运行中的记录（优先级：P1）

用户勾选一条正在解析的记录（如 extracting 状态）并批量删除，后端终止该解析任务并删除记录，不需要用户先手动取消再等待终态。

**优先级理由**：用户明确要求"任意状态可删"；若只支持终态，截图场景中大部分记录无法删除。

**独立验收**：勾选运行中记录批量删除后，该任务的 RQ 解析作业被移除，Redis 状态与用户索引被删除，Worker 不会再推进该任务。

**验收场景**：

1. **假如** 一条记录处于 queued 状态，**当** 用户勾选并批量删除，**那么** 记录被直接删除（取消与删除在同一请求内完成），不进入「正在取消」中间态。
2. **假如** 一条记录处于 extracting 状态，**当** 用户勾选并批量删除，**那么** 其 RQ 作业被删除，状态与文件被清理。

### 用户故事 3：删除已提交记录但保留正式论文（优先级：P2）

用户勾选一条 submitted 记录批量删除；系统仅清理该解析记录与临时数据，已入库的正式论文及其待审核快照不受影响。

**优先级理由**：submitted 记录长期占据列表（有 24 小时倒计时），需要能手动清除；但误删论文是数据安全事故，必须隔离。

**独立验收**：批量删除 submitted 记录后，对应 Paper 数据库记录仍存在，`review_artifacts/{task_id}/result.json` 审核快照仍保留。

**验收场景**：

1. **假如** 一条记录状态为 submitted 且已生成正式论文，**当** 用户勾选并批量删除，**那么** 记录从列表消失，论文详情页仍可访问。

### 边界与异常场景

- **批量删除前必须二次确认**：确认对话框显示选中数量，取消则不做任何改动。
- **部分失败不影响整批**（best-effort）：某条记录删除失败（如生命周期锁超时、记录已被并发清理）时，其余记录照常删除；接口返回逐条结果，前端展示成功数与失败原因。
- **越权与不存在**：不属于当前用户（且非管理员）的任务、格式非法或已不存在的 task_id 被拒绝，计入失败明细，不中断整批。
- **并发保护**：正在被提交（submission 持锁）的记录删除失败并提示"任务正被处理"，稍后可重试。
- **空选择**：未选中任何记录时批量删除按钮不可用。
- **数量上限**：单次批量删除不超过 100 条（与列表容量 32/100 一致），超出时整批拒绝并提示。

## 需求

### 功能需求

- **FR-001**：解析记录列表每条记录前必须显示复选框，支持逐条勾选与取消勾选。
- **FR-002**：列表顶部必须提供全选/取消全选控件，作用于当前加载的全部记录。
- **FR-003**：系统必须实时显示已选中数量；未选中任何记录时批量删除按钮必须禁用。
- **FR-004**：点击批量删除时，系统必须弹出包含选中数量的确认对话框；用户确认后才发起删除。
- **FR-005**：系统必须提供批量删除接口，接收 task_id 列表，逐条处理并返回成功与失败明细（含失败原因）。
- **FR-006**：对运行中状态（uploading/queued/extracting/reading/summarizing/submitting/cancelling）的记录，批量删除必须先终止其解析作业再清理。
- **FR-007**：对 submitted 或已持久化正式论文的记录，批量删除必须只清理解析记录与临时数据，保留正式论文与审核快照。
- **FR-008**：批量删除必须沿用现有用户归属校验（本人或管理员），防止越权删除。
- **FR-009**：批量删除完成后，前端必须刷新列表并展示结果（成功数/失败明细）。
- **FR-010**：批量删除相关界面文案必须提供中英文两套。

### 关键实体

- **上传任务（Upload Task）**：一次解析请求的记录，含状态（uploading/queued/extracting/reading/summarizing/ready/submitting/failed/duplicate/cancelling/cancelled/submitted）、归属用户、关联 RQ 作业与临时文件。约束：删除运行中任务必须先终止作业；删除已提交任务不得触碰正式论文。
- **正式论文（Paper）**：submitted 任务入库后的产物，不属于本 Feature 的删除对象。

## 成功标准

- **SC-001**：用户可在一次操作中删除任意数量（≤100）的选中解析记录，无需逐条点击。
- **SC-002**：批量删除后，选中记录的 Redis 状态键、用户索引、临时文件目录全部清除；submitted 记录对应的正式论文 100% 保留。
- **SC-003**：单条失败不影响其余记录；接口对每条记录返回明确结果。
- **SC-004**：越权 task_id 被拒绝且不泄露他人任务信息。

## 假设与依赖

- 现有清理原语 `cleanup_transient_data` / `cleanup_unsubmitted_files` / `cleanup_duplicate_candidate` / `submitted_paper_id`（`backend/ingest/upload_tasks.py`）行为正确，可直接组合复用。
- 现有单条取消/清理接口与 24 小时自动清理（cleanup_at）机制保持不变。
- 前端复用 AdminPage 已验证的多选交互模式。

## 范围外事项

- 不改变单条「取消」「清理」按钮的现有交互与接口。
- 不修改 cleanup_at 自动清理倒计时与 Worker 定期清理逻辑。
- 不删除正式论文及其衍生数据（社区、证据、图表等）。
- 不引入跨用户批量管理能力（管理员与用户走同一归属校验）。
