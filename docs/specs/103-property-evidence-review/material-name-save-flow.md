# 材料名、空化学式与人工确认保存闭环

关联 [Issue #103](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/103)；补充主 [Spec](spec.md) 和 [缺列修复](material-name-migration-fix.md)。本次覆盖新增字段后主路径遗漏，不只处理数据库缺列。

## 需求与验收

- FR-030：材料名、化学式至少填写一个，上传和管理员共用保存规则；化学式为空不解析、不伪造关联。非法化学式、类型或长度错误应定位字段，不返回笼统 500。
- FR-031：单独修改材料名或材料状态的任一实际持久化条件都必须保存；同值才跳过，清空后重读不得回填。
- FR-032：材料名进入状态及物性核对上下文，修改只使对应状态依赖失效，稳定键不变。抽屉显示当前值，旧候选只参考；删除化学式后移除该核对项，不将其理由自动转为材料名已确认。对材料名可另行填写理由并确认。
- SC-019：真实 MySQL 事务覆盖只有材料名、只有化学式、两者都有、两者皆空、单字段修改、重复保存、导出与核对版本；所有测试数据回滚，真实 #29 科学值不变。
- SC-020：共享表单和抽屉验证清空、输入、理由、失败重试及已删除字段，完成零模型/批准调用；前后端回归与构建通过。

## 原因和方案

日志 `ValueError: chemical formula is required` 来自公共 `persist_scientific_draft`：前置规则允许名称，持久层却无条件 normalize_formula。普通保存、上传提交、人工完成、重查前保存都受影响。另一处公共同值比较只覆盖 material、pressure_value_gpa、state_kind、模块，遗漏名称及多数条件；回归已证明单字段更新被丢弃。

采用可空 `material_states.superconductor_id`，沿用复合外键与 state_key，不创建假化学式。迁移 `20260916_0106` 只放宽关联列；旧数据不回填，不修改已有关系。降级遇到无化学式状态时拒绝，避免删数据。GORM、读取、导出和相关 JOIN 同步兼容；化学式/元素专用筛选仍只匹配有化学式的状态。

持久化和同值比较共用状态字段规范化；已解析的正式状态是保存和核对事实来源。材料名不代替 material，不代替 state_key，不自动接受旧核对。界面共用命名和至少一项校验，旧候选显示为修改前参考。合法名称无需公式解析；非法非空公式在重建前返回字段错误。沿用现有两段保存和人工草稿接口，不增加模型调用，不自动批准。

排查还复现了结构家族只校验不重建关联的问题。现已恢复已解析目录 ID 的关联并纳入同值比较，改名保留关联，主动清空才移除。搜索同步返回独立材料名；不存在的化学式筛选返回空集，不能退回无条件搜索。公开详情的物性与结构标题复用“材料名（化学式）”显示规则。
