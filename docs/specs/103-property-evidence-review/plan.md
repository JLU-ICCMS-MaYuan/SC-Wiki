# 实施方案

React/Vite、Go 审核事务、Python FastAPI/SQLAlchemy、Redis/RQ、现有 MySQL。

1. Python 共享证据服务统一草稿/正式记录视图、来源片段、摘要、原文定位和 LLM 核对。
2. RQ 生成候选与结果，不修改科学实体。上传锁内重新检查摘要；证据与核对结果随论文事务保存。
3. Go 保有批准事务，在论文行锁内调用 Python 只读准备接口，验证当前快照，再事务内写入证据、核对记录、分类和人工历史。LLM 不占数据库事务。
4. 共享前端 hook/dialog 承担倒计时、进度、取消、问题展示与人工裁决，原操作参数和幂等标识保持不变。
5. 新增核对记录表；摘要包含材料状态、记录值/定义/条件与来源。仅 revision 相同不足以复用，因为 pending 编辑不升版。
6. 按用户后续确认，移除共享前端的手动候选选择与引句编辑，原文折叠只读展示。重试显式绕过前端疑点缓存，交给后台重新搜索；后台仍复用已支持记录。无出处保持原状态，提示自动重试或修改科学记录。
