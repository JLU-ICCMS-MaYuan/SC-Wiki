# 决策与依据

## 结构区空白与折叠

用户截图中的底部空白来自网格行由右侧参数/原子表决定高度，左侧画布加图例较短；只删除 Sn 文案仍会留白。固定双栏高度并限定数据区滚动，模型工具条放在画布内，原子数量不会再撑高整行。宽度保持响应式而非固定像素，避免手机溢出。

附件折叠只影响本地显示。保留已挂载内容和当前选择，不通过重新创建候选来折叠；当前文件摘要与精确来源锚点始终可见，不在折叠时迁移核对入口。不会触发编辑、保存或 AI 请求。此前字段统一及来源归属规则继续有效。

3Dmol 的尺寸观察忽略零尺寸，重开且有效尺寸不变时只重绘，不调用 `zoomTo` 重置用户缩放；实际容器尺寸改变时才重新适配。浏览器通过模型视角和画布像素验证，不用受页面滚动与截图裁剪取整影响的截图文件字节比较替代视角检查。

## 统一展示与结构同源

用户已确认 Demo。底部散落内容属于字段锚点缺失与兜底呈现问题：研究材料、关系和状态类型没有对应控件，结构面板缺少稳定核对锚点。直接隐藏会丢失待处理项，因此采用明确字段、结构归位和紧凑兜底入口。

矩阵与位点读取已解析的 3Dmol 模型，避免模型使用原胞、旁边却展示候选 validation 中惯用胞参数。复用库矩阵 API，矩阵按行显示晶格向量；非正交晶胞分数坐标使用 u/v/w，不能写成 x/a。后台 ASE 继续负责校验和保存，展示层不增设可编辑事实。

非正交 POSCAR 浏览器验收发现 3Dmol 2.5.5 的 VASP 解析器按行构造矩阵，而原子位置按列变换。
加载后通过 `setCrystMatrix(matrix.clone().transpose())` 统一方向，再生成晶胞线框与数据表。
直接坐标与直角坐标文件均使用真实库解析回归；升级 3Dmol 时必须复查该兼容处理。
手机端保留数值精度，晶格/原子表在自身区域滚动，不压缩数值造成重叠；页面不横向溢出。

## 红框与标签可读性

现有完整 outline 绕过 MUI outlined 输入的 legend 缺口，因此会穿过浮动标签。这属于共享标记
的样式缺陷，不是字体、科学值或核对结果异常。复用原生缺口边框着红色，保持标签前景层和输入
尺寸；不使用固定白底覆盖、额外框层或高全局 z-index，以兼容主题背景及正常浮层顺序。

## 压强编辑故障

本次属于主路径缺失：核对标记的原生 input/change 监听早于 React 受控更新，导致刚输入的字符被恢复成旧值。Chromium 实测逐字输入仍显示 0.000101；仅改成微任务仍失败，因为浏览器会在监听器之间执行微任务，而组件测试未复现这一浏览器边界。改用事件传播结束后的定时通知，并忽略文本失焦的重复 change，真实输入才保持 0、0.、0.0025。stale 原先同时锁住人工理由和重查，普通保存又不刷新核对状态。压强被按原始数值/单位识别为派生项，但原始条件缺少编辑入口。

采用局部临时文本、表单通知与当前版本人工确认；不删除版本检查，不将人工改值写成论文原始值。用户明确选择清空五个压强字段；原值保留在历史。上传规范化只对缺失字段读取旧契约，显式 null 不回填旧条件、不生成原始值。沿用已有接口、存储和两段保存，禁止历史接受候选回填新数据。当前输入不一致提示只作说明，不代替后端科学校验或管理员理由。

- 故障属于证据转换遗漏、仅 record_key 映射、片段匹配静默 continue，以及缺少语义核对。依据 backend/api/rag.py、backend/ingest/scientific_drafts.py 与 Go 审核校验。
- 保留完整性要求，补上上传检查和人工语义裁决；删除约束不能解决无来源发布。
- 复用 RQ、Redis 与请求模型上下文，不增加基础设施；新规则任务上限三十分钟，模型单次读取九十秒，终态清理凭据。
- Go 保有审核事务，Python 提供只读核对准备，避免复制分类与批准逻辑。
- 源文本确定性复核与模型语义核对分别负责定位和支持程度。人工对疑点裁决，AI 不代表科学正确性保证。
- 模型调用复用现有 `backend.rag.llm.complete_json` 流式客户端；当前供应商的普通响应不可靠，直接假定返回 `.choices` 会失败。流式部分结果回调同时检查取消与总期限，不另建模型适配层。
- 上传核对结果落库时，必须 flush、重载后用数据库实际精度计算摘要。MySQL 的定点值与内存浮点值表示不同，直接散列写入前对象会导致内容未变也重复核对；统一十进制文本解决该问题。
- 管理员科学数据以正式详情为事实来源；审核快照只继续为既有分类回填服务。旧上传快照覆盖正式物性会把已经保存的多证据与编辑重新抹掉。
- 旧规则曾按用户、目标和版本短期缓存 Redis job_id；新规则以 MySQL 项级结果为恢复依据，Redis 只保留执行状态。
- 页码是来源元数据，不靠模型补猜。新分段传播跨片段页码；旧论文片段缺页码时明确显示未提供页码。原文唯一匹配可修复旧片段序号；文件不匹配、引句不存在、多个匹配或无来源文本分别解释。

## 用户反馈后的交互修正

用户明确要求证据选择由系统完成。原设计把手动原文候选暴露为默认选项，使已有 AI 原文的疑点也出现片段下拉框，混淆来源定位与科学裁决。取消该选择器及引句编辑，只读原文默认折叠；不展示内部文件、片段编号，缺页码诚实显示未提供页码。后台负责定位和关联，人工仅判断科学结论。

同时修复重新查找在无手动候选时复用旧疑点、没有创建任务的问题：显式重试跳过前端缓存短路，重新经三秒倒计时启动后台核对，不更改科学数据与权限约束。

后台进度以实际完成的原文组数计量，不估计模型 token 百分比，也不随等待时间虚增。排队阶段总工作量
尚未确定，显示动态等待条；已分组但首组未完成时明确显示 0/Y 和正在核对第 1 组。独立等待计时保证
长时间模型响应期间仍有反馈，不声称预计剩余时间。

模型返回的 JSON 可能在流式响应中截断，表现为 `JSONDecodeError`。证据任务对连接、超时和 JSON/运行时格式错误各自动重试一次；重试仍失败时返回 `evidence_model_format`，与凭据、服务不可用和超时错误分开提示。

## 2026-09-15 已确认修订（优先于此前设计）

原实现只覆盖 PropertyRecord、按用户缓存 Redis 任务、人工 UI 未接入字段位置，属于主路径缺失与原设计范围不足。改为通用核对项和 MySQL 持久结果，Redis 仅任务运行态；不采用延长 TTL 代替持久化。后台保存结果不能依赖 save-draft 前端回调。结果与证据摘要分离：补入已验证引句不改变科学断言。

永久出处区分论文引句、提交者附件和程序派生。已有 paper_evidences 强制当前 Chunk 外键，因此附件来源独立保存，不能伪造 chunk。结构元数据必须来自服务端校验；提供者只从真实认证/提交记录产生，不能推测作者。

Go 仍拥有批准事务；Python 统一科学断言和版本准备。临时结果在同事务中删除，避免 Redis 清理成功但数据库批准失败。历史 PropertyEvidenceCheck 只保留原有记录，不作为新规则缓存。

所有科学字段按当前表单和正式模型枚举；空值/unknown、内部 ID、展示排序、代表项等管理标志不构成科学断言。摘要、主要发现、方法、研究动机及科学分类属于核对范围，书目标题/作者/期刊/DOI 等不纳入。元素计数和单位转换通过确定性输入链校验。

每个模型请求最多八个科学项，完整遍历来源组。每组科学项扫描完成后立即保存检查点；后续模型批次失败只需处理未完成项。总期限随批次数确定，RQ 上限 1800 秒。显式重查仅处理选中项及派生依赖，不因为其他项目 missing 就重复调用。

新增 scientific_upload_drafts 保存已核对上传的当前草稿和任务状态；Redis 丢失后恢复正文定位所需状态与用户列表索引。必要原文仍使用受清理保护的原文件，不把大文件复制进数据库。结构内容按解析后的科学参数形成一致断言，上传候选和正式实体的 ID、时间及显示元数据不改变核对版本。

当前实验与计算条件从物性记录 payload 读取；已退役的 calculation_contexts/experimental_contexts 不作为新读取依赖。明确原始值和单位的压力、温度转换，以及元素计数由程序复核；不识别的单位或非标量原始值仍要求可核验的直接来源，不做推测转换。

## 红点、候选与独立审核

重复图标来自同一 DOM 控件被多个 fields/record 重复匹配，修复为控件级聚合，不删除关联问题。旧 suggestion 是说明，不能直接写原字段；新增 proposal 契约。复用 ScientificEvidenceCheck.resolutions 的按用户命名空间保存草稿，避免独立基础设施。Go/Python 两段保存不是批准事务：用户明确接受批准失败仍保留待审修改。拒绝前端直接声称新值已获 AI 支持，改为服务端按已接受值精确绑定并留存原判断。独立审核不再自动续提。

建议候选复用现有材料维度、晶系枚举和物性记录的版本化表单校验，不允许借候选编辑管理标志或结构身份。数值描述保留原始类型，摘要仍统一 canonical；深复制断言防止后续表单修改污染核对快照。接受历史仅记录接受/撤销转换，连续输入不重复扩增完整原值历史。浏览器回滚服务器将认证读取放在独立连接，避免认证会话关闭时回滚端点写入的测试假象。

## 说明文字替代红点

用户明确选择框左上角现有说明文字作为核对入口。共享标记层增强标签而不复制其文字，保持中英文和动态表单一致；移除额外图标、点击层与输入留白。无浮动标签的结构区域优先使用现有标题，无标题时提供文字按钮，避免失去核对入口。只改变前端交互，不改变科学数据、来源和提交职责。

## 材料名保存主路径缺失

本轮错误不是缺列复发：日志是空化学式触发 `normalize_formula` 的 ValueError。用户已确认名称或公式至少一项，因此选择可空关联，不把名称塞进公式，不生成假的 ChemicalSystem/Superconductor；稳定身份仍属于 MaterialState。公共同值比较遗漏名称及条件、重建遗漏结构家族均属于实现缺失，采用持久规则共用和恢复已解析目录关联修复。决策、先失败后通过证据及发布边界见 [保存闭环](material-name-save-flow.md)。
