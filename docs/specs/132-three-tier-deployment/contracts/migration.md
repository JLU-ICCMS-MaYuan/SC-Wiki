# 单机到两机的数据组迁移

**来源**：[Spec](../spec.md) FR-008、FR-009、FR-011、FR-012。生产实际执行需要明确目标机器、备份位置和维护窗口；本轮不执行。

## 前置核验

固定同一应用 release 和相同数据引擎版本；取得实际命名卷、目录与私网来源清单；确认 #131 的对象存储与历史引用迁移完成。不能把运行中的裸 MySQL/Neo4j/Qdrant 目录拷贝视为一致性备份。

目标须是明确为空的新数据命名空间。非空目标拒绝覆盖；已属于同一迁移的部分恢复依清单续跑。未知版本、不匹配 schema、存储空间不足、源目标身份相同或备份校验失败都阻断。

## 操作顺序

1. 切维护入口，阻止新写入；停止资讯调度和队列生产者，等待上传/证据/资讯运行及排队任务归零，再停止 API 与 Worker。无法排空不强杀后宣称成功，先记录失败或取消并征求运维处理。
2. 对 MySQL 做事务一致逻辑导出；Neo4j 使用固定版本支持的停库 dump；Qdrant 使用集合快照并保存配置/别名；S3 导出对象清单与内容；Redis 按业务白名单导出草稿、延迟清理元数据和必要状态，排除原始执行队列、会话、验证码和模型密钥。
3. 记录 [数据模型](../data-model.md) 的完整性清单，所有快照保存 SHA-256。文件与库之间在同一停写窗口保持一致。
4. 在 B 初始化空数据组并按固定版本恢复，校验表内容/行数、图数据、向量和对象。Redis 恢复按原到期时间计算剩余 TTL，已经过期的草稿不复活；延迟清理依据元数据以确定性标识重建且不重复调度。
5. A 保持原业务镜像，修改数据端点和凭据为 B 的私网配置；schema 只验证，不顺带升级。执行身份、就绪和业务冒烟，检查 API/Worker 均读取 B。
6. 核验无遗漏后开放入口，记录开放写入时间，保留旧 A 数据组停止状态及备份。

## 回退

开放 B 新写入前：停止新连接服务，恢复 A 原数据配置与固定旧制品，校验后开放。开放新写入后：先再次停写并评估增量回迁或前向修复，不能直接恢复旧备份。schema 和对象键格式发生变化时，须按 #131 及配套 schema 迁移的回退约束处理。

数据迁移本身不升级数据库引擎；备份成功不等于恢复验收通过；源数据退役/删除需独立操作。远程备份不包含云访问密钥、数据库口令及用户临时模型密钥。

## 验收记录

记录源/目标机器标识（不含秘密）、镜像 digest、schema、迁移清单、恢复和回退结果、维护实际时长。数据量未测量前不承诺固定停机分钟数；演练测得后用于安排真实维护窗口。
