# Feature 规格：修复探索页与社区页三处缺陷（默认选中、总结换行、跨来源读取）

**GitHub Issue**：[#65](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/65)

**创建日期**：2026-08-31

**状态**：已落地

## 背景与目标

以单质超导 Hg（`papers` id=9，1911 Onnes 原始报告）实测，探索页有三处缺陷。数据库与
API 侧数据完好，问题全在前端读取与渲染：

1. 探索页无 URL 参数时默认选中 La、H，并把 Formula 输入框预填为 `LaH`
2. 论文总结用普通 `Typography` 渲染，库中的真实换行被 HTML 折叠，分条结构被挤成一段
3. 关键物性表只读 `key_properties`、结构预览读已废弃的 `key_properties[].structure_text`，
   两者对 Hg 论文均恒空 —— 用户上传的 Tc 4.2 K 与 816 字节 CIF 完全不可见

其中第 3 项与 Issue #59 是同一问题的不同页面。#59 修正了详情页 `PaperEditView` 的读取
来源，但探索页与社区页各自留了一份旧实现，共三处重复。

**业务价值**：
- 可用性恢复：只报告 Tc 的实验论文（超导领域最常见的一类）在探索页核心数据不可见
- 检索正确性：默认选中特定体系会把检索静默限定，用户未必察觉
- 消除重复：把三处各写一份的读取逻辑收敛为单一模块，避免第四次遗漏

## 用户场景与验收

### 用户故事 1：研究者进入探索页做全库检索（优先级：P1）

研究者打开探索页，希望从零开始选择自己关心的元素，而不是接手一份别人预设的选择。

**优先级理由**：默认选中会静默限定检索范围，属于正确性问题而非偏好问题。

**独立验收**：无 URL 参数进入探索页时，「已选元素」显示「未选择」，Formula 框为空。

**验收场景**：

1. **假如** 用户直接访问 `/search`，**当** 页面加载完成，**那么**：
   - 「已选元素」显示「未选择」，Chip 为默认色而非 primary
   - 周期表中没有任何元素处于选中态
   - Formula 输入框为空，不预填 `LaH`

2. **假如** 用户访问 `/search?elements=Nb,Ti`，**当** 页面加载完成，**那么** 仍按参数
   预选 Nb 与 Ti —— 显式传参是用户主动选择，须保留。

### 用户故事 2：研究者查看论文详情的物性与结构（优先级：P1）

研究者从结果表格进入某篇论文详情，希望看到该论文报告的 Tc、计算参数与晶体结构。

**优先级理由**：这是探索页详情的核心价值，当前对常见论文类型完全失效。

**独立验收**：Hg 论文详情页展示 Tc 4.2 K 与 I4/mmm 结构预览。

**验收场景**：

1. **假如** 一篇论文只报告 Tc、没有普通物性（`key_properties` 为空数组），**当** 打开
   其详情，**那么**：
   - 关键物性表出现 Tc 行，数值为 `4.2 K`，材料为 `Hg`
   - 备注列显示判定方法「实验测量」
   - 不再显示「该论文暂无结构化物性数据」

2. **假如** 一篇论文的材料状态下有计算上下文，**当** 打开详情，**那么** λ、ωlog、μ*
   各自成行；数值为 NULL 的参数不产生空行。

3. **假如** 一篇论文有晶体结构（`structure_models` 表有记录），不再显示「该记录暂无结构数据」。 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。

4. **假如** 论文总结在库中含换行，**当** 打开详情，**那么** 分条结构保持原有换行，
   与详情页 `PaperEditView` 的 `pre-wrap` 行为一致。
   （核心发现与社区页的同类场景移交 [Issue #68](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/68)）

### 用户故事 3：社区页访客查看论文详情（优先级：P2）

社区页访客点击图表中的数据点，希望看到该论文的物性与结构。

**优先级理由**：与 US2 同一批根因，一并修复的边际成本极低；单独留待下次会造成同一
缺陷在两个页面表现不一致。

科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。

**验收场景**：

1. **那么** 关键物性表
   出现 Tc 行，且新增的「结构预览」区块渲染 3D 视图。 科学字段右侧栏功能设计、原话及历史已迁移至 [#221](../221-scientific-field-sidebar/spec.md)，本处不再独立维护。

### 边界与异常场景

- **论文无任何来源数据**：三张来源表均为空时，物性表显示「该论文暂无结构化物性数据」
- **论文为 null**：详情尚未加载完成时提取函数返回空数组，不抛错
- **结构文本为空串或纯空白**：过滤掉，不产生空白 3D 视图
- **缺少 `structures` 键**：视为无结构，不抛错
- **Tc 单臂区间**：只有下限时显示 `≥ 200 K`，不补造缺失的一端（Issue #54 入库语义）
- **`poscar` 格式别名**：`poscar` 与 `vasp` 都映射为 3Dmol 的 `vasp`

## 需求

### 功能需求

- **FR-001**：探索页在 URL 无 `elements` 参数时不得预选任何元素，Formula 输入框须为空。

- **FR-002**：探索页在 URL 显式带 `elements` 参数时须按参数预选，行为不变。

- **FR-003**：探索页详情的论文总结须以 `whiteSpace: 'pre-wrap'` 渲染，保留库中原有换行。

  **2026-08-31 范围移交**：本条只修了探索页 `summary` 一处。同类缺陷实际有四处
  （`summary` 与 `key_finding` 各在探索页、社区页），因未先枚举范围而漏了三处，本 Issue
  关闭后用户复测才发现核心发现仍被挤成一段。完整修复与回归测试见
  [Issue #68](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/68)
  （`docs/specs/68-preserve-multiline-text/`）。

- **FR-004**：关键物性表须覆盖三类来源，顺序为 Tc → 计算参数 → 普通物性：

  | 来源表 | API 路径 | 呈现 |
  | --- | --- | --- |
  | `tc_results` | `material_states[].tc_results[]` | Tc 行，备注为判定方法 |
  | `calculation_contexts` | `material_states[].calculation_contexts[]` | λ / ωlog / μ* 各成一行 |
  | `superconductor_properties` | `key_properties[]` | 按物性显示名成行 |

  Tc 排最前的理由：它是超导论文的核心结论，读者最先要看的量。

- **FR-005**：计算上下文中数值为 NULL 的参数不得产生表格行。后端返回全部记录（含数值
  全为 NULL 的，见 `calculationContextsToDict` 注释：读取侧不擅自判定哪条有效），
  但展示侧渲染空行对读者没有信息量。

- **FR-006**：结构预览须从 `material_states[].structures[]` 读取。不得读
  `key_properties[].structure_text` —— 该字段在 Go 侧标记 `gorm:"-"`，从不落库，
  `keyPropertiesToDict` 也不输出它，读它必然得到空列表。

- **FR-007**：社区页（`share.tsx`）须与探索页使用同一套提取逻辑，并新增结构预览区块
  （此前该页面完全没有结构预览）。

- **FR-008**：物性与结构的提取逻辑必须收敛为单一模块供多页面复用，不得每个页面各写
  一份（DRY）。此前同一读取错误在三个页面各存一份，Issue #59 只修了其中一个。

- **FR-009**：提取函数对 `null`、`undefined`、缺键、空数组均不得抛出异常。

### 不做的需求

- **NFR-001**：不修改后端 API 的字段结构。数据已完整返回，问题纯在消费侧。
- **NFR-002**：不改动详情页 `PaperEditView`。它在 Issue #59 已修正为正确来源，本次
  不动它以免影响 #59 的既有验收判据；后续若要统一，可让它也改用本模块。

### 关键实体

**关键物性行（PaperPropertyRow）**：
- 归一后的展示单元：材料、物性名、数值（含单位）、条件、备注
- 来源可以是 Tc、计算参数或普通物性，展示侧不需要再判断字段出处

**结构预览项（PaperStructureItem）**：
- 结构文本、格式、所属材料、空间群符号、压强
- 唯一来源是 `structure_models` 表，经 `material_states[].structures[]` 返回

## 成功标准

- **SC-001**：无参数进入 `/search` 时「已选元素」显示「未选择」，Formula 框为空。
  **已验证**：3 个 Vitest 用例覆盖无参、Formula 框、显式传参三种情况。

- **SC-002**：`key_properties` 为空但存在 Tc 的论文，物性表非空且 Tc 行数值正确。
  **已验证**：用 Hg 论文真实响应切片断言 `4.2 K`、材料 `Hg`、备注含「实验测量」。

- **SC-003**：λ / ωlog / μ* 各自成行，NULL 项不产生行。
  **已验证**：用例断言 `μ*`（值为 NULL）不在标签列表中，ωlog 为 `1120 K`。

- **SC-004**：Tc 排在普通物性之前。
  **已验证**：用例断言标签顺序为 `['Tc', '形成焓']`。

- **SC-005**：结构从 `material_states[].structures[]` 提取；即使 `key_properties[]`
  含伪造的 `structure_text` 也不得被当作来源。
  **已验证**：反向用例断言构造了 `key_properties[].structure_text` 时返回空数组。

- **SC-006**：探索页论文总结保留换行。
  **已验证**：库中 summary 经 `cat -A` 确认含 `\n`，渲染改为 `pre-wrap`。
  其余三处（探索页核心发现、社区页两字段）随 FR-003 移交
  [Issue #68](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/68)，并在那里补了断言
  computed style 的回归测试。

- **SC-007**：TypeScript 编译无错误，既有测试不回退。
  **已验证**：`tsc --noEmit` 通过；全量 104 例中 103 通过（唯一失败为 Issue #63 在建
  代码的 `news-feed.test.tsx`，与本次无关）。

- **SC-008**：真实环境下 Hg 论文的 Tc 与结构经 API 可达。
  **已验证**：`GET /api/papers/9` 返回 `tc_value_k: 4.2`、816 字节 CIF、`I4/mmm`。

## 假设与依赖

- 后端 `GET /api/papers/{id}` 继续按材料状态嵌套返回 `tc_results`、
  `calculation_contexts`、`structures`（Issue #57 已确立的契约）
- `structure_models` 表是晶体结构的唯一存储位置
- 前端改动需重建 dev 前端容器才会进入 bundle

## 范围外事项

- **不改后端**：见 NFR-001。
- **不动详情页 PaperEditView**：见 NFR-002。
- **不做 Tc 方法枚举的完整字典**：`TC_METHOD_LABELS` 只覆盖当前库中出现的取值，未命中
  时回退显示原始枚举值，不静默丢弃。补全字典需与后端枚举定义对齐，属独立事项。
- **不改结果表格的 Tc 列**：`SearchPage:282` 处结果列表展开 `key_properties` 的逻辑属
  搜索结果聚合路径，与详情页读取是不同链路，本次不触碰。
- **不新增 ErrorBoundary**：Issue #64 已记录该遗留事项。
