## 背景与目标

用户需要清楚知道：当前表单里的哪个字段填了什么、采用哪份证据、原文在哪里，以及为什么当前核对认为它成立。资料应一起可查，而不是让用户或程序从一大份旧来源清单猜测当前字段的依据。

当前 `backend/ingest/property_field_review.py::expand_property_fields` 会为子字段按 `field_path` 和来源关联筛选证据，同时仍携带拆分前记录的 `legacy_evidences` 与 `validation_record`。这些整条资料可提供核对背景，不等于其中每条都直接支持当前子字段。

当前 `backend/ingest/property_evidence.py::locate_with_reason` 负责核实引句与出处，模型核对负责判断字段值、对应关系及证据含义；两者已有不同职责。本需求整理其当前资料及归属，不声称现有系统完全没有来源定位，也不借此扩大主动单字段核对范围。

### 需求结论与变更取舍

- 将字段身份、当前值、证据与位置、采用理由、当前结果统一关联和读取，不要求另做一套页面。
- 区分直接支持当前字段的依据、对多个字段有效的共同依据，以及辅助理解的上下文。它们可以有联系，但不能把整组资料全部认定为每个字段的直接证据。
- 共享资料只按其真实适用范围使用，不把完整旧来源清单、完整科学校验对象逐字段重复永久保存。
- 保留已有前端表单与侧栏结构；删除“历史”页签及整稿快照页面另由目标 2、7处理，本 Feature 不先行改动。
- 保留 #177 的单字段核对边界：读取相关背景不等于把背景中的其他字段也加入本次核对、保存或通过清单。
- 原总草案中“字段保存覆盖配套资料／整稿覆盖整稿”不是本 Feature 采用的要求；局部覆盖范围由目标 4 单独定义。不得因整理证据而覆盖未修改内容。

## 用户场景与验收

### US1：准确看到当前字段及其依据（P1）

用户点击一个字段后，仍在原有侧栏查看它的当前依据，能判断这份资料属于哪个材料状态、哪个结果点、哪个字段，不必翻阅整条来源清单。

**优先级理由**：这是定位字段错误与修改依据的直接入口。

**独立验收**：使用包含多个材料状态、多个方法与结果点的隔离稿件，从字段进入侧栏；保存并重读后仍能找到相同字段及其资料。

**验收场景**：

1. **假如** 当前字段为某材料状态、某方法、μ*=0.13 对应的 Tc，**当** 用户查看来源，**那么** 系统显示这个字段的资料，不把 μ*=0.10 的依据错绑过来。
2. **假如** 只有文件和引句已确认、页码尚未知，**当** 显示出处，**那么** 如实表示未知，不补造页码或区域。
3. **假如** 当前字段尚无准确证据，**当** 用户查看它，**那么** 保留当前值及真实状态，不能用旧总清单冒充已找到本字段依据。

### US2：出处真实且科学对应正确（P1）

审核者既能确定引句来自哪里，也能知道它是否支持当前字段的值和对应关系。

**优先级理由**：防止把“找到相同数字”误当作“填在正确位置”。

**独立验收**：在同组多点夹具中，分别验证正确配对、相邻行错配、出处不存在和共有证据四类情形。

**验收场景**：

1. **假如** 原文为 μ*=0.10→230 K、μ*=0.13→220 K，表单却为 μ*=0.13→230 K，**当** 核对当前 Tc，**那么** 不能仅因准确定位“230 K”就认定当前配对受支持。
2. **假如** 同一表格确实支持多个结果点，**当** 多个字段使用这份表格，**那么** 可以共用证据，并分别保持自己的行、列、配对或必要范围说明，不强制重复上传。
3. **假如** 核对需要方法或计算条件作为背景，**当** 主动核对一个字段，**那么** 这些资料仅提供背景，不把其他字段顺带核对或自动通过。

### US3：修改、重排及版本读取不串资料（P1）

编辑者调整结果点顺序、删除其他点或保存稿件后，当前字段仍保持自己的证据；以后读取冻结快照时，不受工作稿变化影响。

**优先级理由**：字段身份和资料对应关系必须贯穿整个读写过程。

**独立验收**：删除首个结果点、重排方法与状态、局部修改证据并重读；快照能力接入时验证其冻结资料。

**验收场景**：

1. **假如** 第二个结果点已有自己的依据，**当** 删除第一个点，**那么** 原第二点的值、理由、依据及结果不能沿数组位置换到其他点上。
2. **假如** 仅一个字段的证据变化，**当** 保存成功，**那么** 其他字段的值与依据保持不变；失败时不清空当前输入。
3. **假如** 一份整稿快照已冻结，**当** 后续工作稿替换证据，**那么** 读取旧快照仍得到冻结时的内容。本 Feature 只定义字段资料的冻结读取约束，不独立实施快照生命周期。

### 边界与异常场景

- 直接记载、论文推断与通用知识推测保留原来源身份；共同使用不把推断升级成作者直接报告。
- 空可选字段、派生字段和结构只读字段继续遵守既有规则；不一律强制补造原文直接引句。
- 来源不在当前文件集合中、引句无法定位或归属不能确定时，如实显示缺口，不静默套用其他字段的依据。
- 字段被删除、稿件失权、核对期间当前字段或其依据真实变化时，旧结果不能写回错误目标；不以读取无关背景为由要求整篇草稿版本保持不变。
- 同一直接或共同证据的内容未变化时，不因组件对象重新创建而失效、重新核对或全量重绘。
- 旧记录中无法准确划分的资料保持可读且标明归属待明确，不通过打开页面自动批量修库。

## 需求

### 功能需求

- **FR-001**：每份当前字段资料必须关联稳定身份，能还原论文、材料状态、适用方法、结果点及具体字段；不适用的层级如实省略，不以数组序号作为唯一身份。
- **FR-002**：当前字段值及适用的类型、单位，必须与采用的证据、原文位置、必要理由、当前核对结果共同可查。
- **FR-003**：出处仅保存真实获得的来源文件、页码、片段、表格单元或原图区域等定位信息；未知位置不编造，原文与来源不截断丢失。
- **FR-004**：直接依据、共同依据和辅助上下文必须明确区分。拆分前科学记录的全部旧来源不能自动成为每个子字段的直接依据。
- **FR-005**：同一证据可支持多个字段，但每次使用须保留其适用对象与必要对应关系；不强制每个字段独立复制或上传相同证据。
- **FR-006**：共同证据与核对背景可共享并按需读取，不得把完整旧来源清单与完整校验对象逐字段永久复制；不通过删去独有证据来减少重复。
- **FR-007**：原文定位与科学支持分别判断；定位正确不能直接生成科学通过，证据必须支持当前字段内容及其必要对应关系。
- **FR-008**：核对需要的背景不得扩大主动单字段核对的清单、保存范围或通过范围；遵守 #177，当前字段与其采用依据的真实变化仍应被识别。
- **FR-009**：读写、送审和批准读取均保持字段、当前值、证据、理由及结果的对应；结果不能借用其他字段身份或不适用的依据。
- **FR-010**：冻结版本中的字段资料不得随当前工作稿修改、替换或删除而变化；本 Feature 不承担创建、交接或发布快照的流程。
- **FR-011**：保留既有前端表单、字段入口及侧栏布局，不新增永久堆放在主表单上的来源详情；不在本 Feature 删除或重新设计历史入口。
- **FR-012**：输入、查看来源、普通保存与自动保存不因本 Feature 新增模型请求、全量核对或整表扫描；同内容不因引用对象变化而连带失效无关项。
- **FR-013**：上传、返修、管理员和超级管理员四类宿主保持一致；局部更新、中文组合输入、中间数值、光标、只读及失败恢复不退化。
- **FR-014**：旧来源无法准确划分时，资料保留可读且不能自动被认定为当前字段的已通过直接依据；保留来源类型，不批量改写真实历史。
- **FR-015**：变更 PDF 字段生成或证据处理时，从真实正文／SI 和必要上下文定向重新提取受影响字段，复用与重跑步骤分清；覆盖相邻受影响字段，保留失败响应固定重放与真实提取两类证据。
- **FR-016**：受影响的保存、重读、来源显示、审核与表单契约回归必须通过；既有失败用独立基线说明，未完成真实模型验证时不能报告科学字段已通过。

### 关键实体

- **当前字段资料**：字段身份、值、单位／类型、采用证据、理由与有效核对结果；只有当前状态，不由本需求新增永久逐字段历史。
- **字段证据**：支持字段事实或对应关系的引句／原图及来源位置，可以被多个字段使用。
- **证据适用关系**：一份依据支持哪些对象，以及必要的结果点、表格位置和科学范围；不是复制整份父对象。
- **共享核对上下文**：理解当前字段时需要的材料、方法或计算资料，不自动成为其他字段的通过结论。
- **冻结字段资料**：整稿快照中固定的字段内容与依据；与当前工作稿读写隔离，其生命周期由目标 7 管理。

## 成功标准

- **SC-001**：含至少两个材料状态、两个方法及每方法至少两个结果点的隔离夹具，逐字段读写后身份、值、出处、理由和结果均保持对应；删除首点与重排后无串位。（FR-001、002、009）
- **SC-002**：正确配对、相邻行错配、原文不存在、共有表格四类案例均得到符合各自含义的结果；定位成功不使错误配对直接通过。（FR-003～008）
- **SC-003**：同一共同证据用于至少三个字段时，字段能完整读取所需依据，无逐字段永久复制整条来源清单或完整校验对象，独有依据保留完整。（FR-004～006、014）
- **SC-004**：上传、返修、管理员、超级管理员四类完整宿主验证通过；字段及侧栏布局保持，输入、查看与保存新增模型请求和新增整表扫描均为 0。（FR-011～013）
- **SC-005**：工作稿替换证据、保存失败、删除目标与旧结果迟到等场景不导致错绑或输入丢失；与快照流程联验时旧快照内容保持不变。（FR-009、010、013）
- **SC-006**：无法归属的旧清单不自动变为当前字段的通过证据，缺失位置不被编造；读取不自动批量改写旧稿。（FR-003、004、014）
- **SC-007**：有 PDF 字段或证据处理变更时，固定失败响应与真实来源重提均留证，并核验字段值、名称、归属、来源、保存及重读；没有真实调用证据不标通过。（FR-015、016）
- **SC-008**：受影响回归、`npm run test:form-contract --prefix frontend` 和 `npm run test:form-contract:mutation --prefix frontend` 按仓库适用要求通过；无关既有失败由独立基线证明。（FR-013、016）
