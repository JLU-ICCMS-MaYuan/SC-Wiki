# 设计决策与依据

## 独立入口

- 决策：使用 frontend/auth-demo.html 及现有 Vite 开发服务；不增加生产路由和构建入口。
- 理由：用户只授权先看 Demo，现有应用入口不能提前改变。
- 备选：直接加入 /auth，会让未评审页面进入正式用户流；独立脚手架则增加依赖和重复主题。
- 证据：frontend/src/App.tsx 目前全部路由位于 AppShell；AuthDialog 同时被 AppShell 与 UploadPage 使用。

## 动画构图

- 决策：白色画布、左侧标题和大幅椭圆透视轨道，右侧固定阅读宽度；紫色主色，青色仅作磁场辅助色。环形轨道用分段磁体构成，深紫圆片与轨道间保持明显间隙，投影贴轨道。
- 理由：用户选极简科学插画、安静循环并明确允许 SVG；轻量矢量能清晰适配不同屏幕。
- 备选：写实三维和温度滑块均不是已选方向；生成图片工具当前不可用，用户授权直接制作。
- 科学边界：只显示 T < Tc，不给材料或临界温度虚构数值；说明迈斯纳抗磁性，稳定悬浮沿轨通常还涉及磁通钉扎。没有物理有效性宣称。

## 认证演示

- 决策：每次页面挂载创建隔离的内存服务；复用用户名本地校验，不复用会请求真实 API 的 UsernameField 或 AuthProvider。
- 理由：需要能演示错误、注册和验证码；隔离比拦截生产请求更可靠。
- 证据：AuthContext 的 login/register/verifyEmail/resendVerification 均直接调用 /api/auth；UsernameField 失焦调用可用性接口。
- 默认：模拟延迟 450ms，验证码 123456，冷却 60 秒、有效期 5 分钟、最多 5 次错误；页面明确标记演示。该内存实现不作为安全后端。

## 正式接入边界

已有用户名、密码和邮箱验证要求保持；后续提取可复用表单再接 AuthContext，不将模拟账号和验证码带入生产路径。真实接口、投递及来源回跳另行验收。
