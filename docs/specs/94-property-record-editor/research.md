# 功能内设计决策

## 实验条件保留对象，内部使用 description

- 决策：新文本写入 payload.experimental_conditions.description。
- 理由：已发布 measured_tc 定义要求 Conditions 为对象，但允许其自由字段；保留对象能兼容现有校验、版本与数据库约束。
- 备选：改为字符串或新建 Schema 版本，都会扩大迁移范围，本需求无需采用。
- 证据：backend/data/form_definitions.v1.json、backend/ingest/property_modules.py。

## 历史对象只在界面边界投影

- 决策：无 description 时把旧六字段及其他非空字段转为可读文本；编辑只新增/更新 description，同时保留原对象中的证据和历史字段。
- 理由：结构化记录可能包含扩展字段与 Evidence，替换整个对象会丢失数据。新记录只生成 description；不为新数据重复填旧字段。
- 备选：批量改库或保存时丢弃旧对象，均无必要且会破坏历史证据。
- 证据：SchemaDrivenRecordForm、tests/fixtures/issue90/form-definition-matrix.json。
- 当前展示以显式 description 为准，包括空字符串；旧字段不反向覆盖新文本。

## 两阶段提取均强调每条记录独立条件

- 决策：CHUNK_SYSTEM_PROMPT 和 SUMMARY_SYSTEM_PROMPT 共用六方向提示；每条实验 tc_results 带 experimental_conditions.description，进入已有模块化转换。
- 理由：只在最终表单变更不能改善 AI 提取；只在汇总时提示可能丢失分段原文事实。
- 备选：增加一次独立 LLM 请求；增加成本且没有必要。当前流水线的内部 tc_results 中间产物继续使用，不扩展公共协议。
- 证据：backend/ingest/upload_jobs.py、backend/ingest/upload_contracts.py。
- 分段缓存契约随提示词升为 8，已有旧缓存会由现有版本判断重新提取，避免直接沿用缺少记录级描述的分段事实。

## 折叠在记录层实现

- 决策：PropertyModuleEditor 每条记录包裹独立 Accordion，默认展开，使用稳定键保留状态，标题显示类型/方法与结果。
- 理由：现有模块层折叠无法只隐藏一条记录；共享组件能覆盖上传、审核编辑和只读详情。
- 备选：按数组下标保存折叠状态会在删除/复制后串位，因此不采用。

## 规范 Tc 是唯一日常数值入口

- 决策：用户最新澄清取消独立原始记录，当前类型对应的值是唯一来源。兼容列随当前值生成，新记录不再填第二份值。
- 理由：双入口增加操作负担，旧提取值不应与人工更正值并存为当前科学数据。仅隐藏区域会留下旧内容和不可见的必填错误，必须同步前后端保存表示。
- 备选：从原始值自动解析及换算需要处理复杂原文，本次不引入。
- 证据：SchemaDrivenRecordForm 的原始值和数值事件、property_modules.validate_record、用户确认方案。
- 决策：临时非法文本留在组件，模型值为 null；保存前共享校验阻止请求。合法零值使用显式空值判断，不能用真值回退。
- 理由：上传和管理端使用按钮发起请求，不能仅依赖原生表单 validity；同时防止自动保存或核对完成提交旧数值。
- 前端在现有记录归一化及编辑边界同步，后端在记录校验和持久化边界重新生成兼容值。
  数值/范围单位 K，文本/布尔单位空；不更改稳定键、代表唯一性、版本失效及人工核对草稿规则。
  旧字段错误在界面映射到当前值控件，不能出现已删除控件的报错或核对入口。
- 核对候选不再提供 Tc 的 value_raw、unit_raw、canonical_unit 独立编辑。
  prepare/finalize 的预期内容也必须同步兼容表示；只在实际保存时更新 raw 会造成
  “保存成功但核对绑定失败”。该边界以 expected_claim 与真实保存后断言比对验证。

## μ* 范围复用现有扩展契约

现有 `scientific_contracts.normalize_parameters` 已将范围参数保存为 `parameters.extensions` 中的范围对象；不新设 μ* 数据列或修改已发布定义。规范端点为 Tc 小值配 μ* 大值，Tc 大值配 μ* 小值；界面只显示 Tc/μ*，且任意编辑顺序不拆散配对。可选 μ* 未填写不推算；历史标量表示本条记录的共用参数，显示在两组但未编辑不改写。

输入文本与持久化数字分离，非法可选参数必须有可校验表示，不能仅写 null 后当成合法留空。包装对象及其他扩展元数据保留；新范围扩展使用既有 key 与字段，明确过滤避免通用参数区域重复渲染。与重建参数对象相比，定向合并更能保护证据和来源。

配色从用户 IMG-002 原图取样：RGB(244,243,255)，即 #F4F3FF；两组相同，无分组外边框。窄屏采用已认可 Demo 的局部横向滚动，取代本功能旧的自动换列。

## US6～US9 的实施决策

- 通用控件采用可复用的字体测量宽度，最小 110px；固定条件行不换行，扩展每条独立滚动行。保留实际 schema 与原数组索引，避免 μ* 过滤后证据错位。
- 稳定性使用现有开放自定义定义的版本化 payload，按依据分别保存 cases，避免切换后误继承结论；不新增表或原地改发布定义。专用标记及模块/类型共同决定 renderer，不依赖可编辑名称。
- 共享工作区 #137 仍含未提交模型、迁移和 API。此次前端消费其正式端点但不提交其未完成代码；独立候选无需 SpectrumWorkspace 即可构建，接口未部署可明确降级。真实谱生成/采纳由 #137 验收，不把 mock 当成生产证据。
- 手改主操作复用 #138 保存链。旧完成按钮灰色是 stale 和证据 gate 的结果，上传截图的 ai_read_status 不在其禁用表达式内；新增解释和人工保存动作，而非删 stale 条件。

## 模块折叠使用原生 details

默认无 open 即折叠，DOM 内容仍存在，能保留 Tc 临时数字文本等组件内状态。稳定 module_key 保留原生展开状态，避免每次科学数据 onChange 后重置。模块标题和工具栏分开，键盘及只读不依赖编辑权限。复用同一包装覆盖仅谱模块，不增加存储偏好或数据库字段。

## 模块排序交互退役

历史依据为 #90 的 T014、validation 与 #94 的 US10。用户明确取消上下移动，因此删除按钮和未使用移动逻辑，保留已保存的 display_order 与数组顺序，避免把交互简化扩大为数据重排或接口迁移。删除模块仍需保持剩余模块顺序，此时 normalizeOrder 继续使用。

## US12 设计调研：来源类型与结构核处理

state_kind 的 mixed 来自 #32/#50 的来源分类；#84 允许同条件计算与测量共存。因此“理论与实验”原本不是物理状态枚举。按用户新答复，本轮 Demo 的新建菜单仅展示理论/实验/未说明，该旧答复已被最新“旧混合数据彻底放弃使用”取代，当前设计全面退役 mixed，不再保留旧类型兼容路线。

用户进一步选择“结构优化的核处理”，因此新增控件不采用 phonon_nuclear_treatment 的语义。#32 把结构 nuclear_treatment 与声子/EPC 处理分开；#90 的记录级方法归属继续有效。Demo 中 sscha 仅是本地交互标识，不向数据库新增同名核处理枚举。

普通结构优化在结构层通常记 classical_static；“简谐”属于振动近似，不能直接与普通结构优化画等号。本轮 AI 提议“经典静态优化（简谐基准）”与“量子非谐优化（SSCHA）”供用户看效果，未认定已确认其精确名称或多结构时的绑定规则。

## US13：固定框高优先于旧增高方案

已查到 #109 的 US9/FR-032、Plan 与 2026-10-12 验收明确允许长内容换行增高，但未找到证明用户要求允许增高的原话。不得将这一实现假设当成用户原始要求。本次以用户明确的固定高度为准，保留历史记录并标明被替代。

结构家族移到第三行获得整行宽度，新增标签向右延伸，超出时控件内部横向滚动。相比 flex-wrap，固定高度轨道能保证标签数不影响边框高度；输入/删除/键盘仍保留。该局部横向滚动是用户明确要求，属于预览通用窄屏不溢出规则的有界例外，不允许整页横向增长。

## 正式实施：单一规范几何与核处理

用户已确认每卡一份几何／一种核处理。#49 已实现结构等价比较和原胞／惯用胞导出，#77 保存确认候选的惯用胞 CIF；直接复用，不重做 3Dmol。不同优化结果不因宽松 StructureMatcher 容差而自动合并。多源候选保留来源，但同卡只能采纳一个，派生表示留在该候选内部。结构层显式列作为唯一事实来源，清除从 calculation_context.phonon_nuclear_treatment 推断核处理的旧逻辑。状态切到实验／未说明会清空理论核处理，避免隐藏值持久化；切回理论为未说明。数据库迁移遇旧 mixed 或多结构先中止，不删除证据。

实施使用 Demo 已认可文案，结构归属以最新明确答复为准。旧结构已有非 unknown 核处理时，迁移先中止等待明确归属，不能用新状态默认 unknown 静默覆盖。正式迁移不使用几何容差替代用户的分卡选择。

## US14：只简化 DOS 展示

现状的摘要标题、定义选择和证据摘要均来自共享物性组件，针对已有固定 dos_fermi 身份属于重复展示。采用代码与模块身份判断，不以可编辑名称 N(Ef) 判断。复用现有核心行而不复制四个输入；保留复制删除及数据校验，文本镜像值继续同步。其他类型的规范值有独立含义，保持原编辑入口，不通过隐藏字段或强制转文本丢弃数据。原始证据仍保存在记录内。

## US15：重复来源核查与阶段纠正

备份 c16cc627a0c04dc8ad4289624d1da80a-20261016T030851Z.json 的 167 GPa DOS 三条只差 record_key，其中两个 record-copy- 前缀与 clonePropertyRecord 一致。故本截图优先指向复制副本，无须猜测其来自重复 LLM 提取。其他组装代码以包含证据的全记录摘要做去重，属于未来唯一性设计需要检查的另一个入口，不能据此替代本例已取得的证据。

## US17：复制入口价值判断（2026-10-16，AI 提案）

当前复制对整条 `PropertyRecordDraft` 做深复制，替换记录键，并为自定义性质换键；数值、参数、条件及证据随副本保留。模块追加副本，表单尾部显示复制/删除。它是相似结果批量录入的便利操作，不产生新的科学依据。

建议取消逐条复制入口并让删除与数据同行：解析后校对是当前上下文，用户明确表示平时不用，历史备份中已有内容与证据完全相同的 DOS 副本。保留独立添加满足必要补录。本判断没有全体用户频率数据，不能写成“所有用户均不用”。

备选方案：保留原按钮、仅 DOS 隐藏、移入更多菜单。前者保持可发现性但占行，第二项仅处理 US15 的局部问题，第三项仍保留重复记录入口且增加菜单复杂度；本轮不为未证实的需求增设菜单。全部取舍等待 Demo 评审。

代码证据：`frontend/src/lib/propertyModules.ts:clonePropertyRecord`、`frontend/src/components/PropertyModuleEditor.tsx:cloneRecordByKey`、`frontend/src/components/SchemaDrivenRecordForm.tsx` 底部操作行。历史副本证据复用 `assets/fermi-dos-duplicate-audit.json`；未审计最新业务数据。

删除语义复用既有逐条删除，不新增确认、撤销、自动清理或持久化行为。独立 Demo 的“恢复示例”只恢复演示数据。正式组件何时移除内部工具函数，须在实施前核查其他调用方，不能依据一个按钮直接推断函数可删。

评审结论：用户答复“认可设计并同步 #94，暂不落地”，认可取消复制与同行删除的演示设计。已同步 #94，正式代码和真实数据保持当前行为；本节历史“等待评审”指建议形成时的状态，不作为继续阻塞同步的依据。

## US17 正式实现决策

用户最新明确要求“开始落地！”。沿已认可设计实现，不新增产品取舍：取消复制按钮和仅用于该入口的回调；底层深复制工具仍有数据契约测试，保留工具不等于保留用户入口。

三个主行分支（通用、Tc、稳定性）共享 `PropertyRecordRow` 的字段滚动与操作布局。删除按钮由上层记录表单持有，专用字段组件只接收 ReactNode 操作插槽，不读取模块列表或实现删除规则，避免把记录身份和删除规则复制到多个组件。

不使用固定/绝对定位：滚动、焦点、窄容器和内容增长均由正常布局处理；记录外层的字段定位和稳定键保留。删除元数据继续由 PropertyModuleEditor 生成，科学数据处理保持原路径。

## US15：已认可 Demo 的最小实施

## US16 正式数据决定

采用既有 records 数组逐点保存 Tc 与 μ*，而非新增数组 API 或把三个点挤入范围端点。payload.tc_group v1 的 group_key/method_key/point_key 仅用于表单身份；旧记录不因名称、材料或方法相同自动合组。旧范围在用户编辑组合或选端点时拆分，原表示留在 tc_range_origin，未明确配对的 μ* 不猜。

## US20 正式接入前调查

已认可Demo的主表单键值方框与右侧设置方式。当前 SchemaDrivenRecordForm.renderExtensions 已保存扩展字段名称、类型、值和单位；其新增逻辑立即产生空白字段，正式接入需要改为侧栏暂存、应用后新增，取消不产生记录。

固定计算条件依赖已发布定义的schema，不能以修改显示名替换科学key，也不能任意改类型/单位后写进原数值槽位。正式方案需区分固定字段的科学契约与显示设置，并保持只读、校验、来源定位及源值失效语义。本段为只读调查，不表示数据方案已定稿或正式功能已实现。


## US20 正式决定

用户已接受固定字段保留类型、补充字段可切换。采用既有开放payload中的field_settings保存名称和原始单位标注，避免改写已发布schema或把固定字段搬成无归属的新科学值。Tc/ωlog规范值依旧K，单位标注不隐式换算，侧栏明确说明。

共享一个字段方框和设置Drawer，计算条件与Tc参数各自负责现有数据适配；不把原业务表单复制为另一套Demo。打开设置时记录目标记录/字段值及元数据快照，应用前与当前props比较，防止覆盖同时发生的字段修改。扩展保存保留来源和稳定key，类型切换清理不活跃值槽位。隐藏结构优化扩展不从数据删除，不更改#139原任务。
