## 数据与接口决定

- 每个显式 Tc／μ* 组合是一条现有 `predicted_tc` 科学记录。方法、单值 Tc、标量 μ*、代表标记、定义及证据继续使用现有列和 payload；任意数量的结果通过 records 数组承载，不向范围塞第三端点，不新增数据库表或公共路由。
- `payload.tc_group` 版本 1 保存 `group_key`、`method_key`、`point_key`，仅组织表单。原本无分组元数据的记录各自成组，不能因为同材料或方法相同就合并科学条件。新增方法由用户在当前共同参数组内明确创建，共同 λ／ωlog／条件逐条保存；已有不同共同参数的分组不混用。
- 旧范围读取不改值；在编辑其组合、新增组合／方法或选择某个端点为代表时，机械拆分为两个单值。仅显式配对范围或已有共用标量 μ* 可还原两端 μ*，未配对的范围不猜端点。拆分保留原始数值／参数表示、来源、表行与其他 payload；范围原有代表标记不自动指定端点。
- 新增空白组合／方法不复制 Tc 数值、代表标记或结果证据。删除方法显式提交其全部已存记录键；删除某组只删除对应记录，不依数组下标串值。每组稳定身份跨保存、重开和导出保留。
- 一个材料状态最多一条预测代表结果，新分组代表记录必须具有明确的非负有限 Tc 和 μ*。选择时取消同状态其他预测代表；取消、删除或清空已选组合后不自动改选。后端同时验证跨方法唯一性，避免只靠 UI。
- 分组成员必须使用一致的共同参数和计算条件，同一方法行的定义／方法一致。元数据不替代科学记录；被编辑的原有来源关联随已有指纹机制失效，不把人工填写伪装成提取或来源核对通过。

## 组件与处理顺序

1. 独立的前端组合适配模块负责旧范围投影、显式拆分、增删和分组共同字段更新；共享方法组表单负责两行、任意组数、方法选择及逐点代表框。继续使用 SchemaDrivenRecordForm 显示计算条件和证据，不复制一套条件编辑器。
2. PropertyModuleEditor 按显式分组渲染，代表改选在整个状态的预测记录间处理；上传、管理员和只读通过现有共享入口受益，非预测性质保持原行为。
3. 后端在草稿转换和正式持久化边界验证新分组、明确代表身份及共同参数一致性；旧数据无新分组时继续可读，正式写入仍执行代表唯一性。不改已发布定义校验和。
4. #139 原任务补全独立备份和全源上下文读取，限制写入计算条件及其来源，保留当前 Tc／μ*／代表与人工值；应用前复查版本。不能把新任务或 UI 验证当作原任务已补全。
