# US16 补充：选择明确 Tc／μ* 组合为代表结果

关联 [Issue #94](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/94) 与 [现有 Spec](spec.md) 的 US16 多方法／多组 Demo。本轮只迭代预览，正式数据契约仍待设计；另存本增量，避免混入同期 DOS 实施的未提交文档。

## 原始需求记录

> 代表结果我觉得是选择预测方法里面的某一个 miu 对应的 Tc，所以代表结果那个方框应该在明确到使用哪个mu 的 Tc。可以先说明方框的意义，然后在每个 Tc 前面加一个小方框，如果勾选中了，就代表用它作为代表结果。

## 需求结论与演示行为

- **FR-063（Demo）**：方法行末的代表结果选框移除；每组 Tc／μ* 的淡紫色框内，在 Tc 前放置小方框。先说明“选中该方法、该 μ* 对应的 Tc 作为代表结果”，避免把整个方法或整段范围视作所选结果。
- **FR-064（Demo）**：同一材料样例跨方法最多选择一组；改选取消原选择，再次点击可取消全部选择。可见摘要明确显示预测方法、μ* 和 Tc。样例切换分别保留选择。
- **FR-065（演示取舍）**：先填写方法及有限非负 Tc／μ* 后才可选择；零有效。空白组合禁用选框。删除所选组合或方法、清空／破坏其数值时清除选择，不自动选另一组。只读保留选中状态并禁用修改。

这些规则替代 US16 之前的方法行级“代表结果”演示，不改写历史原话。尚未将此 Demo 的取舍标为正式系统数据约束；正式实现须将代表结果绑定到明确的逐结果身份，并设计保存、来源核对及导出，而非继续使用整条范围的一个标记来猜端点。

## 实现与验证

预览使用稳定组合 ID 及每个样例的代表组合引用，不依赖数组下标绑定。增删或重排渲染不会令选框转指另一组。独立 v3 预览键与 v1/v2 分离；刷新前已通过旧 Demo 的保存按钮保留当前旧版编辑，不把旧方法级标记自动转换成任意 μ* 的选择。

- **SC-051（Demo）**：选择两端中的任一组时，摘要精确显示该方法／μ*／Tc；同方法及跨方法改选始终只选一组；保存刷新保留正确组合。
- **SC-052（Demo）**：删除非代表组不影响当前选择；删除代表组／方法或清空 μ* 后清除选择；再次点击可取消；只读禁止修改。窄屏不撑宽页面，选框位于各组 Tc 前。
