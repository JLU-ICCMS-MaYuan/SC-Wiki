# 数据源退役规格

**GitHub Issue**：[维护事项 #104](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/104)

**创建日期**：2026-09-11

**授权**：用户已确认永久退役 Alexandria、HTSC-2025，并要求补齐 Spec 后完成交付。沿用已确认的 `type:maintenance` 分类；本次按用户要求为维护事项建立完整 Spec。

## 背景与目标

这两类外部数据集以后不再部署。旧入口、聚合搜索、模型和设计材料仍要求这些数据存在，增加维护负担并造成缺表错误。检索范围收敛为本地科研数据，同时保持其他功能的既有行为。

## 用户场景与验收

### US1：仅使用本地数据探索（P1）

研究者能够按元素或化学式查询已公开记录，继续筛选、翻页、读取论文和结构。

**独立验收**：无外部数据集时，本地查询与详情成功；检索页面无两类退役来源及全部来源选项。

1. **假如** 用户选择元素，**当** 使用精确、包含或组合模式搜索，**那么** 保留既有本地匹配语义。
2. **假如** 用户只输入化学式，**当** 搜索并收紧筛选、翻页，**那么** 使用本地结果与服务端分页。
3. **假如** 结果关联论文及结构，**当** 点击结果，**那么** 可查看论文、物性与结构；返回时保留查询状态。
4. **假如** 请求失败或结果为空，**当** 用户重试或重置筛选，**那么** 能继续操作且无外部数据依赖。

### US2：无需部署退役数据（P1）

维护者不再安装、挂载或兼容这两类数据。现有数据源专属实现、说明和旧原型与退役决定一致。

**独立验收**：专属接口不再提供数据，运行配置不再挂载文件；本地业务及其他代理接口继续可用。

1. **假如** 环境没有退役数据文件或表，**当** 查询本地记录，**那么** 不访问退役表且结果正常。
2. **假如** 客户端请求旧接口，**当** 请求到达当前部署，**那么** 返回未提供接口的响应，不聚合或伪造数据。
3. **假如** 开发者阅读功能总览与旧原型，**那么** 不会被要求恢复退役能力。

## 边界与异常

- 空值、无结构、无结果、请求失败、分页边界保持既有行为。
- 公开数据仍受审核状态和权限边界保护；未审核论文不会因清理暴露。
- 空间群结果列保留；仅移除原本对本地来源禁用的范围筛选。
- 历史数据库可能存在旧表，本项不执行实际数据删除或迁移。
- 未匹配路由仍由通用代理处理，代理故障时沿用其既有错误语义，不新建退役兼容层。

## 功能需求

- **FR-001**：检索入口仅查询本地数据，不提供两类退役来源或全部来源切换。
- **FR-002**：保留元素、化学式、既有筛选、分页、结果、论文详情、结构预览、空态及重试行为。
- **FR-003**：删除专属数据查询、聚合、记录适配、详情和运行模型，不保留自动恢复能力。
- **FR-004**：运行配置不再依赖退役数据文件，不删除实际数据库记录或改变保留数据的所有权。
- **FR-005**：功能总览、架构图、部署说明、旧原型与规划同步；允许 Spec 和退役断言引用历史名称。
- **FR-006**：保持上传、审核、社区、结构、物性和导出功能；回归测试不得跳过证据核对等现有业务门槛。
- **FR-007**：提供可重复的验收证据，通过适当验证后按仓库规则提交并完成 Issue 收尾。

## 成功标准

- **SC-001**：退役来源入口、专属查询和数据挂载的保留数量为零。
- **SC-002**：US1 的四类场景全部通过，包括真实本地查询与论文读取。
- **SC-003**：前端全量回归、Go 全量回归、相关 Python 回归及生产构建通过，无新增功能回归。
- **SC-004**：文档引用完整，所有需求有任务和证据对应，最终修改已提交且 Issue 收尾。

## 假设与依赖

- 本地 `papers`、材料状态、物性与结构是保留能力的事实来源。
- 先前已确认旧提交同样存在 8 项前端失败；本轮允许修正阻碍验收的过时测试替身，原业务断言仍须成立。
- Python 全量涉及本功能之外的长时间等待，不作为本项必须重复的全库验收；相关测试必须独立通过。

## 范围外事项

不新增数据源、不扩展筛选、不批量改数据、不调整上传/审核的业务规则、不执行生产部署或推送。

## 澄清记录

- 用户原始要求：两类数据今后不再部署，相关代码和内容可以移除，但不能破坏其他功能。
- 用户后续要求：继续写 Spec，然后完成功能；据此补齐设计、验收和提交收尾。
