# 数据源退役技术决策

## R1：删除专属路径，保留本地共享实现

- 决策：删除两个外部 Handler、三类模型、聚合搜索、专属详情与来源切换。
- 理由：用户明确永久退役，没有继续兼容的消费者需求。
- 备选：隐藏按钮但保留实现会留下缺表查询与维护负担；配置开关也保留了未使用能力，因此拒绝。
- 证据：本地结果使用 `/api/papers/search/records`；共享集合工具及详情另有调用方，必须保留。

## R2：不执行数据库清理

- 决策：只移除应用模型和数据挂载，不执行 DROP、DELETE、数据回填或 schema 迁移。
- 理由：本次目标是停止依赖数据，实际数据库删除既不必要，也不属于已确认操作范围。
- 证据：外部模型无本地实体外键或上传依赖；本地记录仍由现有模块化物性模型提供。

## R3：沿用通用未匹配路由代理

- 决策：旧 API 不注册新处理器；通用代理继续工作，健康的当前 Python 对取消的 POST 路径返回 404/405。
- 理由：代理还承担上传、证据、结构、RAG 等功能，不能为了退役数据源整体关闭。
- 备选：410 墓碑端点会新增专属长期代码，用户未要求，故不采用。

## R4：修正测试契约，不改审核规则

- 决策：测试分别模拟证据预检和最终提交；错误用例仅在被测试的最终端点注入异常。断言仍验证原始错误定位、分类提交和成功回调。
- 理由：前轮对照证明修改前后 8 个失败一致；#103 增加预检后，旧测试把所有 POST 当成提交，导致失败发生在错误边界。
- 其他假设：并发导致超时；业务错误解析回归。分别通过低并发运行、预检通过后验证原断言区分。
- 证据：`useEvidenceWorkflow` 先请求 `/api/rag/evidence/preflight`，现有通过的分类审核回归已按路径返回预检结构。
- 范围：只修正现有测试替身；如果原断言仍失败，重新调查，不放宽断言或变更本功能之外的业务规则。

## R5：两层验收

- 决策：交互测试证明请求参数与渲染；真实本地 HTTP/浏览器确认 Go、Python 代理和数据库链路。
- 理由：完全 Mock 的测试不能单独证明缺失外部表时的实际行为。
- 边界：真实验收只读，不运行上传、批准或删除；以已公开本地论文验证详情。记录源码与运行服务是否一致，不宣称生产已部署。
