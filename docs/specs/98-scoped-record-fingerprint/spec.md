# 物性记录来源指纹作用域修复

关联 [Issue #98](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/98)。本次修复 #90 持久化缺省身份生成缺陷，承接 #97 错误反馈。

## 用户故事与需求

- **US1 / FR-001**：同一论文的不同材料状态、不同模块可以各自拥有同名局部记录键；提交不得把它们视为重复。
- **US2 / FR-002**：重复保存或修改科学值时，已有记录的来源身份保持稳定；已有正式来源指纹不被重算。新记录显式携带的来源指纹保持既有语义。
- **US3 / FR-003**：多条记录可引用同一论文和同一 Evidence；修复不得合并记录、修改科学值或伪造来源。
- **US4 / FR-004**：来源身份冲突应报告系统内部身份问题，不要求用户填写隐藏字段；同模块记录键冲突与来源指纹冲突分别处理。

## 成功标准

- **SC-001**：真实 Sn 3.78 K、Pb 7.19 K、SnHg 4.29 K 草稿能进入待审核；三条记录分别保留。
- **SC-002**：同名键跨状态、跨模块不冲突；再次保存不增加记录，修改值不改变身份，已有显式和历史指纹保留。
- **SC-003**：共享 Evidence 的两条记录都保留引用；错误响应不泄露 SQL、不误指第一条记录、不提示用户修改内部键。

## 已确认范围

用户确认采用状态、模块和记录组成的完整身份生成缺省指纹，并授权在当前 scwiki 数据库尝试真实提交。不改数据库结构、不迁移历史记录、不改变论文和 Evidence 的共享规则。
