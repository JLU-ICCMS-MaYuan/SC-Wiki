# 实施计划

1. 在 `persist_property_modules` 新建记录时，以规范 JSON 数组 `[material_state_id, module_key, record_key]` 的 SHA-256 作为缺省来源指纹。用状态数据库主键消除缺失、重复或重排草稿状态键造成的歧义；模块键与记录键使用规范化后的值。现有记录直接保留数据库指纹，新建显式来源沿用输入。
2. 保留数据库的论文版本内指纹唯一约束；身份与数值、Evidence 解耦。同记录编辑不生成新来源。
3. `rag._scientific_integrity_error` 单独处理来源唯一约束；记录键冲突检测纳入状态索引，模块冲突也仅在同状态内比较。
4. 在用户授权的当前 MySQL 上使用外层事务和保存点重放 `_create_pending_paper`，测试结束必定回滚。仅替换会话工厂以控制事务，不替换持久化、约束或定义校验。最后通过真实上传提交入口完成授权任务，包含 Redis 状态及审核快照收尾。
