# 根因与设计决策

真实任务 `92127c24cf034ac79845a8055ccc90b8` 的 Sn 和 Pb 各含 `legacy-tc-0`；输入未携带来源指纹。旧持久化代码仅哈希记录键，生成同一个 `1f5fc7bf…`，第二次插入触发 MySQL 1062 `uq_property_records_source`。这是身份作用域遗漏，不是重复的科学观测。

采用完整状态、模块、记录身份生成缺省指纹，保留已存在指纹与迁移来源。当前指纹并不代表论文、段落或 Evidence；真正的出处由论文外键与 Evidence 关联表示。

不采用删除唯一约束：这会改变显式来源与迁移去重契约。不采用随机指纹：同一身份无法确定性重算。不采用科学值或证据哈希：编辑数据或共享证据不应改变记录身份。不采用仅拼接草稿索引：重排会改变身份。

现有记录优先保留数据库指纹，避免旧记录在普通编辑或导出再导入（导出不含指纹）时被重算。新 revision 创建的新状态具有新身份，唯一约束本身也按 revision 隔离。
