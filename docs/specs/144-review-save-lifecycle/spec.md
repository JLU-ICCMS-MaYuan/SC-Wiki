## 背景与目标

用户真正需要的是：完成一次有依据的核对后，正常保存、刷新、重开和继续编辑不应把同一事实重新变成待处理事项；真正变化时，系统应说明哪里变了，而不是反复要求用户补足系统自身的状态一致性。

#139 已定义科学规则并完成过指定145项核对，但没有证明用户真实操作的完整链路稳定。当前已复现空单位校验错误，并证实200 GPa同一旧草稿经新代码构造后版本摘要变化，继而新一次核对漏引软件证据。该缺陷跨越保存校验、证据有效性、版本兼容与错误恢复，因此单列 Issue，沿用 #139 的科学规则，不重新讨论 QE/VASP/SSCHA 的科学常识。

### 需求结论与变更取舍

**已确认规则（2026-10-21）**：用户阅读“放弃Tc数值变化使共用条件失效的依赖，保留结果是否属于该流程的检查”的建议后回复“认可你的建议。”当材料、物相、计算流程、条件及相关原文/规则未变，新增或修改Tc–μ*只核对该结果、配对及流程归属；已有共用条件继续有效。新结果归属确认后复用已有条件，归属不明只影响该结果的关联，不倒推撤销原有通过结论。软件、阶段、物相、近似、条件或来源真正改变仍须重新判断。此确认不等于本Issue全部设计或页面修改已获批准。

- 先前调查阶段已完成；用户最新授权执行建议。本轮实施保存校验、共用条件依赖与核对生命周期修复，真实数据只读验证优先，写入前必须有明确范围与备份。
- 修复目标沿用既有页面、布局、按钮及科学核对规则，不取消红框、不无条件恢复旧支持。
- 只有能重验科学语义、范围、原文和规则仍有效的旧结论才允许延续；真实改变必须失效。
- “系统处理失败”与“科学内容有问题”必须分别识别，不能让用户反复承担系统格式/兼容错误的核对工作。
- 论文最终批准保留；paper_inference、规则通过、人工确认不得混同。

## 用户场景与验收

### US1：合法表单能够保存并恢复失败操作（P1）

用户打开200 GPa SSCHA软件字段，保持当前值或合法修改后完成保存。

**优先级理由**：当前直接阻断用户操作。

**独立验收**：从真实页面执行保存，回读服务器持久化结果，刷新重开仍一致。

1. **假如** SSCHA软件值合法且没有单位，**当**原样保存，**那么**成功，不出现建议类型/选项无效。
2. **假如**数字、文本、范围或网格型补充字段含合法可空成员，**当**读取后原样保存，**那么**所有支持类型都通过相同校验；错误类型和身份/来源篡改仍被拒绝。
3. **假如**请求失败、超时或返回版本冲突，**当**失败结束或用户重试，**那么**输入保留，界面退出忙碌状态，能恢复或显示具体待解决事项，不无限重试。
4. **假如**科学核对仍有待处理项，**当**用户保存合法编辑，**那么**草稿保存结果与科学核对资格分别呈现，不能虚假显示已批准；批准/完成所需条件沿用原产品定义。

5. **假如** 普通N(EF)记录按文本保存，未使用的数值槽为空，**当**只修改名称并保存核对，**那么**不因未使用的value_number/value_min/value_max等空槽被拒绝；数值、单位、近似条件的科学争议仍独立处理，保存成功不代表科学核对通过。
6. **假如**普通物性记录分别采用文本、单值、范围或布尔类型，**当**保存合法输入，**那么**未启用值槽允许为空，启用值槽的必填及类型校验仍有效；不得用“全部字段一律可空”替代类型约束。

### US2：已核对结论跨正常操作可靠延续（P1）

用户已经接受共用规则，系统保存对应证据后，无需为表示形式变化再手工审核。

**优先级理由**：修复重复核对的系统性原因。

**独立验收**：在隔离副本上复现旧版本升级和编辑往返，逐项比较已核对范围的资格及具体失效原因。

1. **假如**值、软件、阶段、材料、物相、相关来源及规则均未变，**当**原样保存、刷新、重开或编辑无关字段，**那么**核对通过保持，零次新增人工确认请求。
2. **假如**仅内部表示或依赖算法升级，**当**加载旧通过记录，**那么**系统验证等价性及现有证据后有界延续；无法证明等价时明确指出具体兼容问题，不能直接改写旧摘要授信。
3. **假如**存在仍有效的完整核对证据，**当**另一次核对漏引软件段落、输出不完整或技术失败，**那么**保留核对尝试失败记录，已验证结论不因该失败被当作科学反证；原证据不能重验则停止授信。
4. **假如**出现有效新反证，或值/相关范围/来源/规则真正变化，**当**重新判断，**那么**撤回受影响通过资格，保留原因与历史，不能以旧通过优先掩盖冲突。

5. **假如**同一材料、物相和计算流程的共用条件已通过，**当**新增或编辑Tc–μ*组合而这些条件及其来源未变，**那么**只检查新增/改变的结果及配对，既有共用条件不连带失效。若新增结果流程归属不明，只对该结果及其关联保留疑问；不能倒推撤销原有已证明范围。
6. **假如**旧Tc范围需要展开、记录增加/删除/重排或代表点变更，**当**这些操作没有改变共用科学事实，**那么**其稳定身份与通过资格保持；不得因为第一条承载记录变化就认作全部条件变化。

### US3：一次修复覆盖实际操作链（P1）

用户在上传、返修和管理员审核中获得一致的核对资格，不依赖维护脚本再次批量刷通过。

**独立验收**：真实浏览器与后端/数据库集成共同验证，记录各服务代码版本、请求结果及回读状态。

1. **假如**当前200 GPa故障副本及其余145项基线，**当**完成打开、保存、完成、刷新、重开和重新核对，**那么**无错误降级、无空单位拒绝、无未结束保存状态。
2. **假如**新上传、旧草稿、返修及管理员采用同一语义与证据，**当**各自核对和保存，**那么**通过资格一致；角色权限及整篇最终批准不变。
3. **假如**规则自动通过且来源身份为论文推断，**当**完成保存接受，**那么**不会因非 paper_quote 被另一环节无条件降为人工待确认，也不会伪造 human_confirmed。

4. **假如**用户从实际问题页面新增Tc–μ*组合，**当**保存、核对刷新或侧栏开关交错发生，**那么**输入焦点和阅读位置保持合理且无非用户触发的导航；测试须覆盖真实页面入口、核对标记与异步回调，不得用只渲染组合编辑器的一次未复现证明问题不存在。

### 边界与异常场景

- QE原文未报告泛函：继续留空免审；来源不完整/读取失败不能伪装未报告。
- VASP/QE/SSCHA、采样/插值、截断能用途、物相及局部例外保持隔离。
- 扩展数组重排、空值序列化、显示名称变化需判断科学语义是否改变，不能按整个对象形式机械降级。
- SSCHA非谐归属的实际依赖仍需验证；不同近似、压力范围边界或原表结果变化不可一概视为无关。
- 陈旧请求迟到、重复保存、并发改值、页面切换、服务重启需保留最新输入和正确版本，不覆盖较新决定。
- 旧数据缺少足够证据时保留缺口；禁止猜测绑定或把旧规则自动视作当前规则。

## 需求

### 功能需求

- **FR-001**：当前合法字段读取后原样保存必须成功，涵盖SSCHA补充条件与N(EF)普通物性；所有支持类型及嵌套可空成员的规则必须一致，未启用值槽允许空值，启用值槽仍须满足类型与必填要求。
- **FR-002**：保存仍须拒绝非法类型、枚举和对稳定身份/来源的未授权改写，错误定位到具体成员及原因。
- **FR-003**：核对资格只受科学值、必要范围、相关来源和规则影响；无关编辑及语义等价表示变化不得触发重新人工审核。
- **FR-004**：对历史绑定/依赖版本提供有界验证和可审计处理；原历史不删除、不直接替换旧摘要掩盖变化。
- **FR-005**：每次失效可解释为具体输入/范围/来源/规则变化或证据缺口；不能仅复述通用“科学值或来源已变化”。
- **FR-006**：区分核对尝试的技术失败、证据遗漏与有效科学反证；有证据的有效旧资格可延续，新冲突必须撤回。
