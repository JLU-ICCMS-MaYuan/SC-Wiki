# 谱子图裁切与叠加调研（2026-10-23）

## 结论与当前问题

不需要 Java。现有前端已经用 JavaScript/React 和 SVG image/path 实现原图叠加；问题是取出的谱对应子图，显示的却是整张组合图，而且独立数据绘图使用宽画布与最大峰重新定范围，破坏原图比例。

实际 La–Sc–H SI 第 4 页源图为 802×948 像素，包含 A/290 GPa 与 B/350 GPa，每行又有声子色散、DOS、α²F/累计 λ。旧 α²F ROI 约 [637,50,790,434]，真正图框上边界在 y=16；直接按旧 ROI 截图会裁掉顶部和 λ 注记。不能简单扩大成整行，因为那会保留无关声子谱与 DOS。

## 当前裁切链路（已读代码核对）

1. backend/spectra/discovery.py::pdf_figures 根据 Document IR 图块、PDF 图注和内嵌图/矢量路径定位整图。相接的上下图片碎片会按 PDF 坐标合并；缺合适内嵌图时 get_pixmap(dpi=160, clip=...) 渲染。
2. 组合图送给读图模型，模型输出 state_key、曲线 roi、颜色、轴向、刻度和排除区。roi 用于数值提取，原图仍完整存储。
3. 旧详情以整张 source.size_px 作为 viewBox，叠加也在这个全局坐标中。因此坐标可能对得上，却因全图缩小而看不清，且包含其他压力/谱。
4. 本轮新增独立 display_bbox（显示框）合同；取数 roi 与显示框职责分开，仍使用原图绝对像素，不更换原始图片或平移已存数据。

## 已核查的公开资料

- [PyMuPDF：图像裁切与分辨率](https://pymupdf.readthedocs.io/en/latest/recipes-images.html)：get_pixmap 的 clip 可以只渲染指定区域，dpi/Matrix 决定分辨率。提高 DPI 只能改善采样清晰度，不能判断哪个子图属于 290 GPa。
- [PyMuPDF：矢量绘图路径](https://pymupdf.readthedocs.io/en/latest/recipes-drawing-and-graphics.html)：get_drawings 提供 PDF 线段、矩形与路径，可作为矢量论文中图框定位依据，优先于在低清图上猜坐标。
- [OpenCV：Hough 直线检测官方教程源文件](https://github.com/opencv/opencv/blob/4.x/doc/tutorials/imgproc/imgtrans/hough_lines/hough_lines.markdown)：可结合边缘检测、最小线长与最大间断检测图框直线。官网 HTML 本次返回错误，改读官方仓库源文件并验证 HTTP 200。
- [PDFFigures2 官方说明](https://github.com/allenai/pdffigures2)：明确说明图有多个 subfigures 时，输出会包含所有子图。因此整图提取器不能直接替代按材料状态的子图裁切。

以上来源于本轮实际读取，HTTP 200（OpenCV 使用官方仓库源文件）。本次没有安装新模型或调用收费读图模型，也未把资料中的能力直接当作本项目已经验收的效果。

## 推荐的完整自动化流程

1. **语义定位**：模型依据图注、A/B 标签、压力与谱类型，先确定材料行，再确定该行子图；共享频率轴可以读标定，但不能为保留它而把邻图一起裁进来。
2. **几何校正**：矢量 PDF 优先 get_drawings 的轴框；位图用长直线/边框检测，从模型 ROI 邻域吸附到真正图框。模型负责“哪一个”，程序负责像素边界。找不到足够证据时返回待核对。
3. **分开两个矩形**：roi 覆盖完整取数域；display_bbox 包含该子图边框、刻度和图例。显示框必须包住取数框、不能出图，也不允许无依据扩展到整行或其他压力。
4. **坐标不变**：保留 PDF→原图像素映射。显示用 viewBox/clipPath 裁切；原图 image 和数据 path 保持同一原图像素坐标，不在某一分支单独减偏移或再次缩放。
5. **裁后复核**：检查保留了本状态图例/单位/零频、排除了邻行邻列；将裁图和轨迹回绘并排核对。无法唯一定位时由用户确认候选框，不能用好看的裁图掩盖错材料归属。

双阶段的“裁后再次调用模型/OCR 确认压力和种类”、矢量框候选枚举与人工拖框确认属于后续增强方案，本轮没有把它们伪装成已经运行的能力。

## 本轮已实现

- 前端从旧真实 ROI 邻域寻找包围它的四条灰黑长边，确认当前子图框；没有可辨完整边框时明确退回已有 ROI，显示未独立确认提示。
- 显示范围只保留该框及很小的刻度/图例留白。过大的模型显示框候选不直接信任；找不到可信 ROI 时不声称已准确裁切。
- 290 GPa α²F 实图浏览器验证：图框顶部识别为 y=16，裁切底部小于 480，下一压力行从约 y=499 开始；左侧裁切大于 628，排除 DOS 和声子色散。DOS 同样只显示其子图。
- 三模式复用同一图框和全局像素路径；独立数据不按最大峰重排坐标。α²F 原幅值刻度未确认时不重新标上 λ 的 1、2、3。
- 叠加用红色提取线、白色细底线和强度滑块，既突出轨迹又能看原曲线。原图中的累计 λ 保留，因为它确实属于同一子图；不会把它当成 α²F 数据。
- 提示词已增加“先材料行、后谱类型”“完整取数框与显示框分开”“排除其他压力/邻图”“共享轴只读标定不扩大裁图”“绝对像素统一”；服务器校验 display_bbox 包含 roi 且不出图。未要求用户自行改提示词。
- 02/03 桌面左右排布，窄屏上下；三模式选项使用灰底紫色滑块动画，并支持减少动态效果偏好。

## 限制

本轮修改显示和后续标定合同，不改写已有科学点、不重新调用模型、不自动重提取业务谱。已有提取中的缺口、图例误识别或 α²F 幅值依据问题不会因裁图变正确。边框检测依赖已有 ROI 在正确子图附近，不能独立证明材料归属。新 display_bbox 提示词尚无新一轮真实模型推理验收。

## 分辨率与失败边界补充

本例来源元数据为 rendered_composite，源图由 PDF 内嵌图片碎片合成，不能仅凭截图假定是矢量图。应优先保留原始图像分辨率；若提高 DPI 或换用更高清原图，必须生成新来源版本并重新标定，不能把旧像素坐标直接贴到新图。深色完整网格、无边框或 ROI 已落入错误子图时，简单长边法可能无法可靠定位，需回到语义/几何复核；本轮不宣称任意论文都可自动裁准。
