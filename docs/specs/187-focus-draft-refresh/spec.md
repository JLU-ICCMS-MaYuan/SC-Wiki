# Feature 规格：切回标签页提示更新，点击后载入工作稿

## 原始需求记录

> 比如 A页面保存了，用户过了一会忘记自己在 A 页面编辑审核，跑到 B 页面编辑去了，在切到 B 页面的瞬间就把 A 页面的内容同步过来了。至于怎么同步，有没有可行性，我需要你来评估。

> 不能在 A 页面一边编辑，B 页面一边更新，必须保证切到了 B 页面，才更新 B 页面。也就是按需更新。或者可以切到 B 页面提示 A 页面更新了，让用户点击刷新页面的按钮。

## 背景与目标

同一稿件可在多个标签页打开。A 保存后，B 可能仍显示旧内容。用户希望切回 B 时能够发现更新并按需载入，同时避免后台持续同步、额外计算和输入被默默替换。

当前 `frontend/src/components/UploadTaskEditor.tsx` 已在部分上传入口监听可见性与焦点：没有本地未保存内容时读取整稿，内容不同便自动替换。该逻辑排除了 `draftOverride`、只读和返修入口，不能据此认为四类宿主均已支持本方案。

### 需求结论与变更取舍

- 采用已确认的“切回后检查，有变化就提示，点击才载入”，替代本范围内直接自动替换表单的行为。
- 后台页面不持续轮询、读取整稿或更新表单；输入、切换和载入不触发科学模型核对。
- 更新检查与正式载入分开：切回发现新版本只显示通知，不因本页没有未保存输入就自动载入。
- 有未保存内容时，载入前明确告知替换后果，允许保留本页；不以“共用数据源”为由静默抹去输入。
- 整稿保存的局部覆盖遵守目标 4／#185；本 Feature 不合并数据、不通过自动保存解决同步。
- 现有表单及侧栏不重设计，提示放在编辑器标题或保存操作区；自动保存间隔保持。

## 用户场景与验收

### US1：切回时知道另一个页面保存了新内容（P1）

用户离开 B 在 A 完成保存，再切回 B 时，可以看到更新提示；尚未点击载入前，B 的表单保持原样。

**优先级理由**：这是用户明确要求的按需同步入口。

**独立验收**：两页打开同一稿件，A 保存、B 后台等待，再切回 B，检查请求和表单变化。

**验收场景**：

1. **假如** A 正在编辑并保存，B 处于后台，**当** A 的保存完成，**那么** B 不持续读取整稿、不自动更新表单、不调用模型。
2. **假如** A 已保存新版本，**当** 用户切回 B，**那么** B 按需检查并显示“其他页面已保存新内容”和“载入最新内容”按钮。
3. **假如** 其他页面没有保存新版本，**当** 切回 B，**那么** 不显示错误的更新提示，也不替换当前内容。
4. **假如** 同一次切回同时触发可见性与焦点事件，**当** 系统处理这些事件，**那么** 不重复发起同一轮检查。

### US2：点击后载入完整且一致的最新稿件（P1）

用户选择载入时，页面更新为最新已保存工作稿，值、证据和当前核对结果来自同一内容版本。

**优先级理由**：只更新数值而继续显示旧证据会产生新的错误。

**独立验收**：A 同时保存科学值、证据及理由，B 点击载入后逐项核对版本一致性。

**验收场景**：

1. **假如** B 已显示更新提示，**当** 用户没有点击按钮，**那么** B 的当前表单保持不变。
2. **假如** 用户点击载入，**当** 读取成功，**那么** 显示最新已保存内容及对应字段证据、理由、有效核对结果，不触发模型或整页重载。
3. **假如** 载入请求失败，**当** 显示错误，**那么** 原有表单与输入保留，可以后续重试，不能假称已经载入。

### US3：未保存输入和权限仍受保护（P1）

用户知道载入会替换本页未保存内容，可以取消；迟到响应和旧页面不能越过输入及权限边界。

**优先级理由**：同步入口不能以丢输入或重新取得已失去的编辑权为代价。

**独立验收**：覆盖本地未保存、载入期间新输入、保存／提交在途、失权和冻结快照案例。

**验收场景**：

1. **假如** B 有未保存的数值或人工证据输入，**当** 用户点击载入，**那么** 明确提示替换后果，并提供“保留本页”和“载入最新内容”选择；取消后输入不变。
2. **假如** 读取期间本地又发生新编辑，**当** 旧响应返回，**那么** 不静默覆盖新输入，需重新确认是否载入。
3. **假如** 工作稿已正式交出，**当** 原经手人从旧页面点击载入，**那么** 不因此重新获得写权限。
4. **假如** 当前正在查看冻结快照，**当** 工作稿在其他页面保存新版本，**那么** 不把该快照替换为工作稿。

### 边界与异常场景

- 有未保存人工说明、证据附件或候选设置时，也属于需要保护的本页输入，不能只检查主表单的数值。
- 已保存内容未变化时，不因切页、组件引用变化或重复焦点事件制造更新提示、清空缓存或重核。
- 本页正在保存或提交时，载入不能与在途写入相互覆盖；不通过额外自动保存完成同步。
- 网络失败、目标不存在或权限变化时，保留输入并如实提示，不把失败结果当作空稿覆盖页面。
- 若检查提示后服务器又有更新，点击载入应读取当时最新的合法已保存稿件，而不是强制使用提示出现时的旧副本。
- 本页未点击载入前继续编辑和保存，仍适用 #185 的实际变化项写入规则；本 Feature 不强迫先刷新才能保存。

## 需求

### 功能需求

- **FR-001**：同一稿件的后台页面不得因其他页编辑或保存而持续读取整稿、轮询或自动替换表单内容。
- **FR-002**：页面重新可见或获得焦点时按需检查已保存内容是否变化；同一次切换产生的重复事件必须合并处理，不重复发起同一轮检查。
- **FR-003**：仅发现实际已保存更新时，在编辑器标题或保存操作区显示更新提示及“载入最新内容”按钮；没有更新时不制造提示。
- **FR-004**：只有用户点击并完成必要选择后才读取并载入最新已保存工作稿；即使没有未保存内容，也不得直接自动替换表单。
- **FR-005**：有未保存数值、人工说明、证据或其他本页输入时，载入前必须明确替换后果，让用户选择保留本页或载入最新内容；取消保持输入不变。
- **FR-006**：载入成功后字段值、证据、理由及有效核对状态必须对应同一份内容；不得混用新值与旧字段资料，也不能把保存成功视为审核通过。
- **FR-007**：检查或载入失败保留原表单及输入并显示真实错误；迟到响应不能悄悄覆盖请求期间产生的新输入或较新有效结果。
- **FR-008**：保存或提交在途时不能被载入操作交错覆盖；本 Feature 不自动保存、合并或提交本地输入来解决同步。
- **FR-009**：输入、切回检查及载入全过程不调用模型、不触发科学重核或浏览器整页重载；不因本 Feature 新增按键级整表扫描。
- **FR-010**：上传、返修、管理员、超级管理员四类工作稿宿主遵守同一交互；保持已有表单与侧栏布局、保存间隔、中文输入、中间数值及真实提示。
- **FR-011**：冻结快照不得参加工作稿更新替换；无权限或已交出目标不得借本入口恢复编辑权，不能将读取失败解释为空稿。
- **FR-012**：未载入最新内容前的本页保存仍遵守 #185 的实际变化项覆盖规则，不把本功能变成全面禁止旧页保存的冲突门。
- **FR-013**：实施后完成四类完整宿主、按需请求次数、输入恢复、版本资料一致性及受影响回归验证；执行仓库规定的表单契约与变异检查，既有失败用独立基线单列。

### 关键实体

- **已保存工作稿**：当前稿件持久化的内容，合法页面共用；与页面尚未保存的输入分开。
- **本页内容与未保存输入**：页面当前显示的稿件、人工记录及其他尚未保存编辑，载入前必须保护。
- **更新提示**：告诉用户存在其他已保存版本，不等于已读取或应用全部新稿。
- **载入操作**：用户明确发起的读取与应用最新已保存稿件行为，不是自动保存或模型核对。
- **冻结快照**：正式交出的不可变内容，不随工作稿更新替换。

## 成功标准

- **SC-001**：A 编辑、保存且 B 后台期间，B 的持续整稿读取、自动表单替换和模型请求均为 0；切回后才进行按需更新检查。（FR-001、002、009）
- **SC-002**：有更新、无更新、同轮重复焦点／可见性事件三类场景中，仅真实更新显示提示，同一轮检查不重复发起；不点击时当前表单始终保持。（FR-002～004）
- **SC-003**：点击载入后，科学值、证据、理由和有效核对状态均来自载入的同一稿件版本；不触发整页刷新或模型。（FR-004、006、009）
- **SC-004**：主表单未保存、人工说明未保存、证据未保存、读取期间新编辑四类场景均不静默丢输入；取消载入保持原内容。（FR-005、007）
- **SC-005**：请求失败、保存／提交在途与迟到响应场景不造成输入丢失、错报载入成功或旧内容覆盖新状态。（FR-007、008）
- **SC-006**：已交出旧页面和冻结快照均不能通过本入口恢复写权限或被新工作稿替换。（FR-011）
- **SC-007**：四类完整宿主及受影响回归、两项表单契约检查通过；既有布局、保存间隔及 #185 的实际变化项覆盖规则保持，既有失败单列。（FR-010、012、013）
