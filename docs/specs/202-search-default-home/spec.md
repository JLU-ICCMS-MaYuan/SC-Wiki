# 功能规格：搜索作为默认首页

**Issue**：[功能 #202](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/202)

**创建日期**：2026-11-02

**状态**：用户授权直接创建并实施。

## 原始需求记录

> 我希望把热点和搜索换一下位置，让整个页面一进去就是搜索的页面。这样更加直观，新建 issue 和 spec ，然后直接落地实现。

## 附件与推断来源

- 无用户附件或派生材料；图片索引：`images: []`。
- AI 理解：用户所说的搜索对应现有 `/search`，侧栏中文名称为“探索”。只交换入口位置，不重设计检索页面或修改名称。依据：`AppShell.tsx` 的导航项与 `SearchPage.tsx`。
- 认证无来源出口与退出登录属于默认首页的一致性调整；合法业务来源优先，不覆盖用户的来源页。

## 背景与目标

现有根路径跳转热点，用户需要再次点击探索才能开始搜索。本功能使网站入口直接提供现有检索能力，热点保留在第二个导航位置。

### 需求结论与变更取舍

在 #101 侧栏、#151 认证及 #178 检索行为的基础上，只替换首页归属与前两项顺序。搜索表单数据仍由原组件及 URL 持有；不改变请求触发、查询参数、结果页或权限。

## 用户场景与验收

### 用户故事 1：进入网站即开始检索（P1）

作为访客或已登录用户，我打开网站就能看到现有化学式与元素搜索入口。

**优先级理由**：直接满足用户主需求；本故事是完整 MVP。

**独立验收**：从根路径进入真实应用，确认 `/search`、搜索输入和探索活动态；点击热点及品牌验证往返。

1. 假如直接访问 `/`，当页面加载完成，那么进入 `/search` 并显示检索入口。
2. 假如侧栏展开或收起，当查看导航，那么探索在热点之前；点击热点进入 `/news`，再点击 SC-Wiki 回到搜索。
3. 假如退出登录或认证页没有合法来源，当返回默认首页，那么进入搜索；存在合法来源时返回完整来源，新注册没有来源时仍进入用户中心。

### 边界与异常场景

- 中英文、桌面及窄屏使用同一顺序，探索与热点各自的活动态和键盘访问有效。
- `/search` 原有查询参数、结果新标签页及 `/news` 直达有效。
- 认证非法外站来源仍被拒绝；只将回退目标改为搜索。
- 不改变折叠时正文挂载、输入与已选文件的保留行为。

## 需求

- **FR-001**：网站根入口、品牌及遗留首页组件都指向搜索。
- **FR-002**：全角色侧栏前两项为探索、热点，其余顺序与折叠、语言和活动态行为保留。
- **FR-003**：无合法来源的认证默认出口与退出登录回到搜索；合法来源及注册默认用户中心保留。
- **FR-004**：搜索、热点原有页面与 URL 契约保留，首屏按需加载直接服务于搜索。

**关键实体**：不新增或修改业务实体、数据库或存储；仅调整现有导航。

## 成功标准

- **SC-001**：桌面 1440×900 与窄屏 390×844 从 `/` 进入后均显示搜索入口，热点可点击且品牌可返回。
- **SC-002**：既有侧栏、认证、检索导航回归通过，完整应用浏览器检查无未捕获脚本异常。
- **SC-003**：生产构建通过；Overview 与实际入口一致。
