# 技术调研

## 设计来源追溯

Git 历史显示，`custom_property_key` 首次随 2026-09-07 的 #90 模块化物性设计落地。`70b478be` 明确了自定义性质保留和管理员提升身份，`dee68ac8` 将字段写入模块化记录和迁移契约。因此它不是某次旧上传的临时字段，而是论文内自定义性质的稳定身份。

## 故障证据

任务 `92127c24cf034ac79845a8055ccc90b8` 的 `1913 Pb Onnes.pdf` 在 2026-09-09 连续收到 400；草稿保存请求正常。失败问题为 `module[superconductive_properties].records[0].custom_property_key`，消息为“规范性质不能携带自定义键”。第 3 个材料状态的记录同时声明 `measured_tc`、`tc` 和残留自定义键。

## 备选方案

- **删除字段**：会破坏 #90 的自定义性质身份和管理员提升，排除。
- **后端无条件忽略键**：会掩盖客户端状态错误并改变校验契约，排除。
- **仅提示通用错误**：不能帮助用户修正表单，排除。
- **边界清理 + 完整路径**：保留权威校验，兼容历史草稿并让用户可定位，采用。
