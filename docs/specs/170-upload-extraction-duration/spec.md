## 背景与目标
让上传者在记录列表直接了解每个任务已消耗的解析时间，并查看完成后的固定用时。本次补充拟在同一用时旁展示本轮解析的 token 消耗，继续在 #170 内管理，不新建 Issue 或 Spec。

### 需求结论与变更取舍
采用已确认的“后台开始解析 → 等待校对”口径。覆盖正文提取、分段读取、汇总及解析阶段字段核对；人工等待暂停，恢复继续累计。上传、排队、后续人工校对与提交不计时。

以下 token 规则为本次补充草案，尚未获得最终确认：按同一轮解析统计模型服务实际返回的输入、输出与总 token；覆盖本轮自动解析实际发生的模型请求，包括自动谱处理、上下文摘要及重试中已返回的真实用量。读取已完成检查点不重复计入，后续人工核对或手动重提不计入。该补充不改变原计时口径；#211 的自动谱处理完成后终态和 #224 的停止、同轮继续行为沿用现有设计。

## 用户场景与验收
### US1：查看本轮内容提取用时（P1）
作为上传者，我希望在解析中和完成后看到任务用时。
**优先级理由**：直接满足本次需求。
**独立验收**：单条记录执行下列场景，无需新增其他业务功能。
1. 假如后台开始解析，当累计205秒，那么显示“提取内容用时：3 分 25 秒”，运行中继续增长。
2. 假如进入等待校对，当等待、刷新、重开或编辑草稿，那么用时不变。
3. 假如等待正文角色确认，当等待或重新排队，那么暂停；后台恢复后继续累计。
4. 假如解析失败、取消或发现重复，当任务停止，那么用时固定；重试按新一轮计时。
5. 假如历史记录没有可靠计时，当显示记录，那么显示“未记录”。

### US2：查看本轮解析 token 消耗（P1，补充草案）
作为上传者，我希望在最终解析用时旁看到本轮实际消耗的 token，刷新或重新打开后仍能查看。
**优先级理由**：直接满足新增的消耗记录需求，与 US1 共用同一记录行。
**独立验收**：同一任务完成解析后，核对真实模型用量、持久记录和列表显示。
1. 假如本轮有两次模型请求，分别返回输入1000/输出200及输入500/输出100，当解析完成，那么用时旁显示“解析 token：1,800”，并可查看输入1,500、输出300。
2. 假如已记录结果，当刷新、重新打开或后续编辑，那么 token 记录不变。
3. 假如部分模型请求没有返回用量，当显示消耗，那么展示已记录值并明确标注“统计不完整”；全部未返回或历史无记录时显示“未记录”，不得展示为完整的0或估算总数。
4. 假如暂停后同轮继续，当复用已完成请求，那么此前消耗保留且不重复累计；显式重试开始新一轮时按原计时轮次重新统计。

### 边界与异常场景
未开始的新任务显示“尚未开始”；时间缺失或无效不推算。多任务计时独立，长文件名不挤掉用时；窄屏换行。状态刷新失败保留错误提示，恢复读取服务端状态。

token 补充拟沿用相同的未开始提示；任务之间统计隔离，多文件任务统计整组。失败、取消或重复检测停止后保留本轮已记录消耗；未收到上游用量的中断请求不能宣称零消耗。只有确认本轮没有发起模型请求时，才允许显示真实的0。运行中可随现有状态读取更新已记录值，不新增每秒模型请求。token 记录是解析运行信息，不是科学表单标准字段。

## 需求
### 功能需求
- **FR-001**：每条记录文件名旁显示用时，窄屏允许换行。
- **FR-002**：仅累计本轮后台解析期间，上传、排队和人工等待不累计。
- **FR-003**：运行时按秒更新，完成或异常终止时固定，保留原状态提示。
- **FR-004**：刷新、重开恢复同一计时结果，后续编辑不改变结果。
- **FR-005**：重新解析开始新一轮计时，不混入上轮耗时。
- **FR-006**：缺失或无效记录显示“未记录”，不推算精确时长，适配现有中英文。
- **FR-007（待确认）**：在现有用时旁显示本轮解析总 token，并提供输入、输出明细；适配现有中英文和窄屏。
- **FR-008（待确认）**：仅按模型服务实际返回的用量累计本轮自动解析的请求，包含自动谱处理、上下文摘要和有用量回执的失败重试；不按字符数估算。本地缓存或检查点复用没有新请求时不重复累计；上游返回用量中的缓存命中token仍按其回执计入，不另加一次。
- **FR-009（待确认）**：记录随任务保存并可重读；完成后的刷新、重新打开和人工编辑不改变消耗，后续独立人工核对及手动重提不混入本轮。
- **FR-010（待确认）**：暂停及同轮继续保留累计，失败、取消或重复终止保留已记录消耗；显式重试新轮次重新统计，隔离旧执行的迟到回执。
- **FR-011（待确认）**：缺失或无效用量不得伪造为0；部分缺失显示已记录值和“统计不完整”，全部缺失或历史无记录显示“未记录”。

### 关键实体
上传任务及本轮解析计时记录；多文件任务累计整组用时。补充拟增加本轮模型 token 用量记录，包含输入、输出、总量及完整性；由后台拥有，与科学字段数据分开。

## 成功标准
- **SC-001**：累计205秒显示“3 分 25 秒”，运行中按秒更新。
- **SC-002**：等待校对后等待、刷新、重开和编辑均不改变用时。
- **SC-003**：人工等待暂停、恢复累计、失败/取消/重复停止及重试符合FR-003和FR-005。
- **SC-004**：历史记录不显示虚构用时；中英文、长文件名、窄屏可读，原打开、选择、取消正常。
- **SC-005（待确认）**：两次请求的输入1000+500、输出200+100在最终用时旁显示总计1,800，输入/输出明细为1,500/300；任务及多文件统计互不串位。
- **SC-006（待确认）**：完成后刷新、重开、编辑及持久状态恢复保持同一消耗；后续独立核对或手动重提不改变本轮值。
- **SC-007（待确认）**：同轮暂停继续不丢失或重复计量，重试新轮次不混入上轮；失败、取消、重复终止及旧执行迟到回执符合FR-010。
- **SC-008（待确认）**：缺失、部分缺失、真实0及无效用量展示有别；中英文、长文件名和窄屏可读，原计时与操作回归通过。
验证要求：后端状态转换与持久化边界、前端计时和状态刷新测试，真实页面的隔离浏览器验证及构建。

token 补充验证拟覆盖真实生产调用入口的用量回执、聚合、持久化/恢复和公开读取，并保留至少一次真实模型请求的服务返回用量与页面显示对照；固定回放覆盖失败重试、缺失用量、自动谱处理与摘要、停止/继续及迟到回执。若修改科学表单共享依赖，执行仓库规定的字段契约及四宿主表单/变异回归。未调用真实模型时明确记录验证缺口，不能以估算或固定回放冒充真实用量验证。
