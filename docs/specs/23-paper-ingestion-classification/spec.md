## 背景与目标

完善 PDF 上传、全文解析、AI 草稿校对和人工审核链路。原始 PDF 与解析后的 Markdown 必须持久保存；处理状态和未提交草稿属于 24 小时临时数据；用户提交后才把最终候选数据原子写入 MySQL。系统不得继续依赖 SQLite `dev.db`，也不得把后台失败伪装成上传成功。

## 用户场景与验收

### 用户故事 1：可靠上传与解析状态（优先级：P1）
普通用户上传 PDF 后可看到五个真实阶段：保存原始文件、提取论文正文、AI 分段阅读、AI 汇总草稿、等待用户校对。任一步失败都显示当前阶段和明确原因。

**验收**：上传后立即取得任务编号并轮询真实进度；刷新页面仍能恢复任务；失败后可只重跑失败或未完成段，也可转为手工填写。

### 用户故事 2：全文分类与解释（优先级：P1）
系统全文分段读取并汇总证据，生成全部论文元数据、分类、材料、方法和物性的 AI 草稿；每个关键判断和物性带章节/页码及原文片段。

**分类规则**：理论主导归 `theoretical`；实验主导归 `experimental`；理论和实验都重要且无法分主次时归 `experimental`；综述归 `review`。理论二级类型为 `calculation`、`method`、`theory`。

### 用户故事 3：材料类型建议与审核（优先级：P2）
用户可编辑 AI 草稿、每次停止输入 5 秒后自动保存，也可立即保存。用户可选择已有材料类型、采用 AI 建议或填写自由文本；提交前完成最低校验，提交后进入管理员审核。

### 用户故事 4：提交与审核（优先级：P1）

用户点击提交审核时，系统在一个事务中写入论文和物性；管理员查看用户最终值与临时 AI 证据后通过、保持待审核或拒绝。审核通过后仅保留共同确认的正式结果。

**验收**：任一数据写入失败时事务全部回滚并保留临时草稿；`approved` 后公开结构化数据并清理 AI 临时证据，PDF 与 Markdown 永不公开。

### 边界与异常场景
- 文本抽取失败或 LLM 超时：显示失败/无法判断原因，不伪造成功。
- 论文整体分类与每条物性数据的实验/理论属性分开。
- 未提交任务连续 24 小时无操作：清理 PDF、Markdown、Redis 草稿和 AI 临时结果。
- 相同 DOI：打开已有论文；相同文件哈希删除新副本；DOI 相同但文件不同保存为管理员候选附件。
- 扫描版 PDF：明确提示无法提取正文，本 Feature 不提供 OCR。

## 需求

### 功能需求
- **FR-001**：反馈上传、解析、分类当前状态及失败原因。
- **FR-002**：支持生产环境大 PDF 请求并传递代理错误。
- **FR-003**：全文分段读取论文，再汇总分类证据。
- **FR-004**：按核心贡献和理论/实验服务关系判断论文整体类型。
- **FR-005**：支持理论二级类型 `calculation`、`method`、`theory`。
- **FR-006**：显示分类理由和证据。
- **FR-007**：允许已有、AI 建议和用户自定义类型共同作为提交选项。
- **FR-008**：用户提交审核时可保留自由文本材料类型，不因未在已有建议中而阻塞提交。
- **FR-009**：管理员必须在单篇论文审核中确认、修改或拒绝最终材料类型文本。
- **FR-010**：论文整体类型与物性数据实验/理论属性独立。
- **FR-011**：修复 `paper_is_experimental`、`infer_sc_type`、`rebuild_from_clean_results` 导入、参数和错误传播问题。
- **FR-012**：原始 PDF、解析 Markdown 和审核期 AI 产物必须分别保存在持久化目录，路径与 Compose volume 一致。
- **FR-013**：处理状态与未提交草稿必须存入 Redis，采用 24 小时滑动过期，不写入 MySQL。
- **FR-014**：上传接口必须要求登录，返回 `202` 和任务编号；任务、草稿、文件和证据只能由上传者或管理员访问。
- **FR-015**：系统必须使用独立 Worker 执行五阶段处理，并支持从失败或未完成分段继续。
- **FR-016**：用户停止输入 5 秒后必须自动保存同一份 Redis 草稿，并能立即保存和提交审核。
- **FR-017**：用户提交时必须校验必填项，并在单一事务中写入正式候选数据；失败时全部回滚。
- **FR-018**：新审核动作只允许 `pending/approved/rejected` 三个状态；历史 `needs_revision` 只兼容读取并显示为旧的待审核状态。
- **FR-019**：LLM 调用必须通过统一的 OpenAI 兼容客户端，供应商、地址和模型由配置决定。
- **FR-020**：新论文必须使用统一整体类型与 `theoretical_subtype`；旧论文类型只兼容读取，不自动迁移。
- **FR-021**：草稿和待审核内容不得进入公开搜索、统计、Qdrant 或匿名论文详情。

### 关键实体
- 上传任务：任务编号、所有者、五阶段、进度、当前错误和 24 小时过期时间。
- 论文草稿：AI 建议、用户最终值和证据；审核完成前为临时数据。
- 论文分类结果：整体类型、理论二级类型和最终材料类型。
- 物性数据来源属性：每条物性数据独立标记实验或理论。

## 成功标准
- **SC-001**：上传、解析、分类失败均显示具体原因，零假成功提示。
- **SC-002**：分类读取完整论文文本，非固定前几页或固定字符数。
- **SC-003**：基准论文分类符合规则，且有理由和证据。
- **SC-004**：用户可提交新材料类型，管理员可完成审核闭环。
- **SC-005**：物性数据实验/理论属性不因论文整体分类改变。
- **SC-006**：容器重建后已保存的 PDF、Markdown 和待审证据仍存在，Redis 草稿可由 AOF 恢复。
- **SC-007**：用户提交失败时 MySQL 不产生半成品；未审核数据不会出现在公开检索中。
- **SC-008**：页面始终显示当前五阶段、分段进度和当前错误，禁止用前端计时伪造进度。

## 假设与依赖
- LLM API 由部署方提供；本 Feature 定义输入输出和失败语义，不绑定供应商。
- #19 负责上传链路基础错误；#22 负责缺失工具恢复；本 Feature 统一其契约。
- MySQL 只新增最终业务字段 `papers.theoretical_subtype`；处理状态、错误、进度和 AI 证据不进入 MySQL。
- 原始 PDF 保存于 `/data/upload_PDFs`，Markdown 保存于 `/data/parsed_markdown`，AI 临时产物保存于 `/data/review_artifacts`。
- Redis 开启 AOF；独立 Worker 与 API 使用同一 Python 镜像和共享目录。

## 范围外事项
- 实验论文二级分类暂不实现。
- 不建设全局材料类型目录、别名和批量合并；本次使用自由文本并由论文审核员确认。
- 不建设通用无限版本历史；已通过论文的异议修改使用临时修订 JSON，提出者不能自审。
- 不实现 OCR、旧论文批量重新分类、页数/调用次数/成本限制。

## 澄清记录

- 全文分段读取并汇总证据；页面显示判断理由。
- 材料类型由 LLM 全文判断；允许 LLM 或用户提出新类型，先入库并待管理员确认。
- 论文整体分类与物性来源属性保持分开。
- PDF/Markdown 永久保存但不公开；处理状态和自动保存草稿进入 Redis，AI 原值与证据进入临时 JSON。
- 用户提交前不写 MySQL；停止输入 5 秒后自动保存，仍保留立即保存按钮。
- 五阶段为保存原始文件、提取正文、AI 分段阅读、AI 汇总草稿、等待用户校对。
- 未提交任务 24 小时无操作后清理；失败任务可继续失败/未完成段或手工填写。
- 使用独立 Worker、Redis AOF 和可配置的多供应商 LLM 客户端。
- 旧类型只兼容显示；新论文使用整体类型加理论二级类型。
- 新审核只使用 `pending/approved/rejected`；不新增 `draft` 或 `needs_revision` 数据库状态。
